# outline-vs-shipped counts declared read-intent files as include_unrealised

## Context

On plan-170 the `outline-vs-shipped` aspect reported `include_unrealised: 2 of 15`, described in its own finding text as *"assessed CERTAIN_INCLUDE but absent from the realized footprint (may be a silent descope, or a forecast a later decision abandoned)"*. The two members were:

- `marketplace/bundles/plan-marshall/skills/plan-orchestrator/scripts/orchestrator.py`
- `test/plan-marshall/plan-orchestrator/test_expected_surface_single_reader.py`

Both are deliverable 1's declared **read-intent** files (`intent: read` in the outline's structured deliverable data, and both listed under `references.json` `read_intent_files`). Their absence from the diff is not a descope — it is the plan behaving exactly as declared. Every one of the aspect's `include_unrealised` members on this run was a false positive.

## Root cause

The aspect joins the assessment store against the realized footprint. An assessment records whether a file is **in scope** (`CERTAIN_INCLUDE` / `CERTAIN_EXCLUDE` / `UNCERTAIN`); it does not record whether the plan intended to **modify** it. A file the plan will read but not write is legitimately assessed `CERTAIN_INCLUDE` — it is in scope — and is then structurally guaranteed to be absent from a diff.

So `include_unrealised` is, by construction, `{read-intent files assessed in scope} ∪ {genuine descopes}`, with no way for a reader to tell which is which. The sibling aspect `check-artifact-consistency` already gets this right: its `affected_files_recall` explicitly reports `read_intent_excluded: 3` and reaches 100% recall on the same plan. The two aspects consume the same declarations and disagree because only one consults intent.

## Proposed action

- Subtract declared read-intent paths from the `include_unrealised` population before counting, exactly as `check-artifact-consistency` does. The intent data is already available on the outline's structured deliverable rows (`affected_files[].intent`) and mirrored in `references.json` `read_intent_files`.
- Publish the exclusion, matching the sibling aspect's shape: report `read_intent_excluded: N` alongside the count so the narrowing is visible rather than silent.
- If read-intent files are worth reporting at all, give them their own outcome class (`read_intent_unmodified`) at informational severity — that is a *confirmation* the declaration held, which is the opposite of the "possible silent descope" reading the current class carries.

Until fixed, `include_unrealised` on any plan declaring read-intent files should be read as an upper bound, not a count.

## Evidence

- aspect: outline_vs_shipped — `include_unrealised: {count: 2, denominator: 15, population: certain_include_assessed_paths}`, members as listed above.
- aspect: artifact_consistency — `affected_files_recall: {declared: 13, found: 13, recall_pct: 100.0, read_intent_excluded: 3}` on the same plan, same footprint.
- `manage-solution-outline list-deliverables` — deliverable 1 declares both files with `"intent": "read"`.
- `references.json` `read_intent_files` — lists both paths plus `test_orchestrator_corpus.py`.

## Recurrence — 2026-09-04, plan `domain-glob-seeding` (PR #1406)

**Second instance, and this one is a 100% false-positive rate.** `outline-vs-shipped` reported
`include_unrealised: {count: 3, denominator: 27, population: certain_include_assessed_paths}`:

- `marketplace/bundles/plan-marshall/skills/manage-config/scripts/_cmd_init.py`
- `marketplace/bundles/plan-marshall/skills/manage-config/scripts/_config_defaults.py`
- `test/plan-marshall/manage-config/test_cmd_domain_detect.py`

All three are deliverable 2's declared `intent: read` files, and all three appear verbatim in
`references.json` `read_intent_files`. **Three of three members were false positives** — the
class carried no genuine descope at all on this plan.

The sibling disagreement is reproduced exactly: on the same plan, same footprint,
`check-artifact-consistency` reported `affected_files_recall: {declared: 34, found: 34,
recall_pct: 100.0, read_intent_excluded: 4}` — a clean 100% recall, because it subtracts intent.

**A code-level check firms up the fix location.** `architecture search --content --literal
--pattern read_intent_files` returns 7 files, and `check-outline-vs-shipped.py` is not among
them — the script never reads the field. `read_intent_excluded` returns 5 files, of which
`check-artifact-consistency.py` carries 14 occurrences and is guarded by a dedicated test,
`test/plan-marshall/plan-retrospective/test_recall_read_intent_denominator.py`. So the working
implementation and its regression test both already exist in the same skill; the fix is to
reuse that helper in the sibling script, not to write new logic.

Note also that this lesson file carries **no `key=value` metadata header** — its `component`
and `category` read as empty in `manage-lessons list`, which makes it unaddressable by every
id-keyed verb (see lesson `2026-09-03-22-002`). This recurrence was therefore appended by direct
`Edit` rather than through the script surface, and the file should be given a header when that
lesson is applied.

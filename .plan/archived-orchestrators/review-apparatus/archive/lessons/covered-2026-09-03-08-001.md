title: "A bot status-summary body with no claim is stored as an actionable finding, driving pct_resolved_as_fixed to a false 0.0%"
content: "## Problem

A reviewer's `review_body` that carries **no claim about the code** is stored as an actionable
`pr-comment` finding, because classification has no positive test for \"this is a status summary, not
feedback\". Two shapes hit this on PR #1384, both from sourcery:

- `c590d4` — a budget-exhaustion **refusal** (*\"you've used your own review budget of 250,000 diff
  characters…\"*).
- `658f80` — a bare **approval** (*\"Sourcery assessment: **Approved.**\"*).

Neither states anything to fix, suppress or accept. Both entered the store as actionable, and both had
to be dispositioned by hand as `taken_into_account`.

## The measurable damage: a false 0.0%

`finalize-step-review-retrospective` computes `pct_resolved_as_fixed` over actionable findings. Sourcery
made **zero claims** on this PR, so the honest figure is *undefined*. What the metric reported was
**0.0% over 2 actionable findings** — a reviewer that raised nothing scored as a reviewer that raised
two things and got neither fixed.

It also inflated a second instrument: 2 of the 7 entries in the retrospective's escape delta were these
non-claims, so the escape count overstated real escapes by ~29%.

**One producer-side gap distorted two independent measurements**, and in the direction that makes a
silent reviewer look like a bad one — which is exactly backwards for a roster decision.

## Relationship to the sibling lesson

[[2026-09-02-22-001]] covers the **refusal** half and prescribes adding the phrasing to sourcery's
`refusal_patterns`. That fix is necessary and insufficient: it addresses `c590d4` and leaves `658f80`
untouched, because an approval is not a refusal and no `refusal_patterns` entry will ever match one.

The two halves share a root cause the refusal-only framing misses: **classification is a negative test.**
A body that matches no refusal pattern is credited as feedback by default, so every non-feedback shape
nobody has enumerated — approvals, run-status envelopes, \"already reviewed\" replies, rate-limit notices —
lands in the actionable bucket.

## Directive

Add a **positive review-shape test** rather than another pattern list: a `review_body` counts as
actionable only if it carries a finding-shaped payload (a claim, a location, a severity, or a
suggestion). A body that carries none is a status summary — record it as participation evidence and
exclude it from the actionable count and from `pct_resolved_as_fixed`'s denominator.

Then make the metric honest about the empty case: a reviewer with zero actionable findings must report
`pct_resolved_as_fixed: null` (or \"no claims\"), never `0.0%`. A rate over an empty denominator is
undefined, and rendering it as zero is the same confident-signal-over-an-unasked-question archetype the
plan that found this was fixing.

Derive the affected set rather than assuming it is sourcery-only: every registered bot emits status
summaries of some shape (CodeRabbit's run-status envelope and its \"Already reviewed the last commit\"
reply both surfaced on this same PR and were also hand-dispositioned as carrying no claim). The gap is
in the classifier, not in any one bot's registry entry."

# Declared write-set path no task targets escapes the files_exist gate

## Context

In plan plan-04-persona-behavior, Q-Gate finding `ad26fa` (4-plan, triage,
declared_set_closure) reported that deliverable 2 declared
`test/plan-marshall/persona-plan-marshall-agent/__init__.py` in its write-set
while no step of any task assigned to that deliverable named it as a target.

## Root cause

The declared set is not projected onto the task set: the `files_exist` check
iterates task STEP TARGETS, so a declared path no task targets is never
examined and its existence on disk is never even consulted. The omission is
invisible to every later gate.

## Proposed action

When a deliverable declares a write-set, project every declared path onto the
task set before leaving 4-plan: either add a step that writes the declared
path, or remove the path from the declaration. Treat `declared_set_closure`
as the authoring-time complement of `files_exist` — one guards paths nobody
will touch, the other guards intents against paths already on disk.

# D2's module_edges/content_search status-vocabulary change left four doc sites restating the superseded rule

Plan `architecture-store-query-truthfulness`'s D2 deliverable changed `cmd_capabilities`'s
`module_edges` decision rule to `derivable` if `(resolver_count or edge_producers)` —
where `edge_producers` includes the reserved non-resolver producers `declared` and
`sibling-cross-link` — and retired the `content_search` `available`/`unavailable`
per-row exception in favor of one shared `derivable`/`not_derivable` vocabulary
across all three capability rows. The plan's own self-review found four
documentation sites outside its declared footprint that still assert the
superseded rules, and could not fix them there (this plan forbids staging a path
no deliverable declared):

1. **`marketplace/bundles/plan-marshall/skills/manage-run-config/standards/run-config-standard.md`**
   (line 315, section "A disabled resolver is reported, never silently dropped") —
   states disabling every resolver always yields `module_edges: not_derivable`.
   False whenever a module carries a declared `internal_dependencies` edge with
   every resolver off: `resolver_count: 0` but `edge_producers` is non-empty, so
   the verb reports `derivable` with `producer_count: 0`. The identical sentence
   in `marshall-steward/references/menu-derivation-resolvers.md` WAS corrected in
   place under this plan's TASK-028, because that file was in D2's widened
   footprint — this file was not.

2. **`doc/user/configuration.adoc`** (line 776, section "Which derivation
   resolvers run") — the user-facing twin of (1), same false claim in operator
   guidance.

3. **`doc/user/code-search.adoc`** (line 198, section "Asking what the substrate
   can answer here") — still tells the reader `content_search` reports
   `available`/`unavailable`, the vocabulary D2 retired. Found only by
   re-deriving the consumer sweep on the retired LITERAL rather than the
   `content_search` identifier — the original 6-file "clean coverage" sweep was
   identifier-anchored and blind to this prose spelling ("content search", not
   `content_search`). Re-confirmed via `architecture search --content --pattern
   '[^n]available.{0,8}unavailable'` → `count: 1`, `file_count: 1` over 5480
   files scanned, unreadable/truncated/elided all empty — this file is the ONLY
   surviving carrier tree-wide.

4. **`doc/concepts/code-intelligence.adoc`** (line 262, section "Asking what is
   answerable: the capability report") — carries BOTH superseded claims at once:
   a three-state map asserting `not_derivable <=> producer_count: 0` (exactly the
   inference D2's own docstring forbids — `producer_count` stays resolver-scoped
   while the verdict also considers `edge_producers`), and the retired
   `available`/`unavailable` vocabulary for `content_search`, spelled in prose
   rather than as the retired literal, so also invisible to an identifier- or
   literal-anchored sweep.

## The lesson

An identifier- or literal-anchored "did we miss a consumer" sweep is blind to
every PROSE spelling of the same concept. A closing consumer sweep for a status-
vocabulary or decision-rule change must be re-run anchored on each of: the
identifier, the retired literal pair, AND a prose/plain-English rendering of the
same claim — three passes, not one. A future plan (or a widened footprint on a
follow-up) should correct all four sites to the D2 contract: `not_derivable`
requires `resolver_count == 0 AND edge_producers empty`; all three capability
rows share one `derivable`/`not_derivable` vocabulary.

# Audit a classifier's symmetric peers for the defect's SHAPE, not its text

## Observation

The target defect lived in `_classify_marketplace`: only an enumerated set of skill sub-directories was
recognised, so everything else classified as `None` and was invisible to the inventory.

Its symmetric peer `_classify_generic` — the classifier for non-marketplace projects — carried **the
same defect in a different idiom**: it recognised only `README*` / `CHANGELOG*` as documentation. Same
shape (an enumeration standing in for a category), different surface (filename prefixes instead of
directory names).

⛔ **A textual search for the buggy construct would not have found it.** Only the structural question
*"who else answers this same question?"* did.

## Rule

When fixing a classifier / dispatcher / resolver, enumerate its **symmetric peers** — the functions
answering the same question for a different input domain — and audit each for the **shape** of the
defect, not its text:

- Do not search for the literal construct you just fixed.
- Ask: *"what is the category-membership decision here, and what set stands in for the category?"*
- Apply the fix in the peer's own idiom.
- When the peer's narrower scope is **deliberate**, say so and **pin the boundary with an assertion**
  rather than leaving the narrowness silent. Here `_classify_generic` intentionally stayed
  extension-driven (path position carries no role guarantee in an arbitrary project), so it got an
  assertion that in-set extensions classify and a known out-of-set extension still returns `None`.

## Detector gap worth closing

`ext-self-review-plan-marshall`'s **symmetric-pair-function** candidate class is the deterministic
surface that should have produced this pairing. It ran clean over 39 candidates on this plan, yet the
peer was found during implementation rather than surfaced by the detector.

⇒ Check whether the pairing heuristic covers `_classify_marketplace` / `_classify_generic`-style pairs:
**shared verb prefix, disjoint input domain.** A clean verdict from a detector that does not cover the
pair is not evidence the pair is clean.

## Where to look

Every `_classify_*`, `_resolve_*`, `_detect_*`, `_dispatch_*` family. The recurrence signature: a fix
touches one member of a same-prefix function family and the sibling is never opened.

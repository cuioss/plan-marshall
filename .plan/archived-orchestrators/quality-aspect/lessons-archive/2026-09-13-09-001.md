# Seed a rate-window claim from the bot-stated ETA

Source: implement-plan-06-test-falsifiability-survey (tooling-truthfulness),
PR #1476.

## Problem

The `rate-window claim` verb defaults to a 3600s window when no ETA is
supplied. Twice in one run the bot's own rate-limit notice stated a much
shorter reset (3 minutes, 18 minutes), so the default claim overshot the real
reset by an order of magnitude. Both claims were released and re-claimed at
the stated ETA after the mismatch was noticed by hand-reading the PR comments.

## Guidance

Before claiming a rate window, read the latest refusal/rate-limit notice on
the PR for a stated reset interval and pass it as `--window-seconds`. Fall
back to the verb default only when no notice states one. A claim is a
reservation against a real reset clock, not a budget to spend.

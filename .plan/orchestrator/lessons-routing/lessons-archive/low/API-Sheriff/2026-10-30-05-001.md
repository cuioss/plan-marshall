# A guard test that parses a source language states the narrow input shape it accepts and refuses every other form loudly, naming the location

Source: PLAN-V02-51 (#538), candidate lesson 002; three guard tests, four code-review rounds and two CodeRabbit rounds (23 fix tasks).

## Observation

`MtlsLaneSelectionContractTest` (failsafe lanes in POMs), `BenchmarkScriptConfigContractTest` (k6 script routes) and the widened `LogMessagesCatalogueTest` (LogRecord catalogues) each began by trying to understand the full input language: Surefire include syntax, Maven layer inheritance, JUnit tag expressions, JS call forms. Any form the reader could not read fell through as "not matching", so it **failed open**. Every review round then found one more form the reader had silently misread, and each needed a fix task with a red and a green specimen. The class of finding stopped only when the include-pattern reader became an allowlist: `**/` plus one `.java` file name with `*` and `?` is evaluated, and every other form is refused with the lane and pattern named.

## Rule

- State the narrow input shape the guard accepts. Accept only the forms the real tree uses and that the guard can evaluate exactly.
- Refuse every other form loudly, naming the location, rather than evaluating it partially or skipping it.
- Give each refusal branch a specimen (a defective input the guard must reject). A refusal that is ever hit is cheap to widen; a reader that half-understands a wider language costs one review round per misread form and is wrong silently until then.

## Apply

Any new or changed guard that reads a POM, a glob, a script, a YAML or a Java source. Write the allowlist in the first draft, not after the third review round. Related: a guard whose green is not coverage (Open Defects 7, 9 and 14), and `doc/development/test-corpus-integrity.adoc`.

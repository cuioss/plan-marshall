# 2026-09-06-08-002 — Publish the population a signal-gate count was computed over, so a truncated count is distinguishable from an accurate one

## Context

During plan `domain-post-plan-narrow` (PLAN-03, epic `operator-ux`, PR #1422) the finalize
dispatcher forwarded `signal_script_failure_clusters_count: 1` to `lessons-capture`. Reading the
records behind the count showed **two** distinct failing notations under the documented
`[ERROR] … script_failure` marker class (github_pr argparse_rejection, review_completeness
argparse_rejection). Cluster definition is union-dedup by distinct notation: two, not one.

## Root cause

Undiagnosed, deliberately. Established instead: the count is published WITHOUT the population
it was computed over, so no consumer can tell an accurate `1` from a truncated `1`.

## Proposed action

Publish the population alongside the count (notation list + entry window). Same count-with-
denominator discipline as the corpus and inbox-list surfaces.

## Impact

The count is a gate; an undercount silently converts a non-zero signal into a skip. A run whose
only signal was a two-notation cluster reported as zero would skip lessons-capture entirely,
indistinguishable from clean.

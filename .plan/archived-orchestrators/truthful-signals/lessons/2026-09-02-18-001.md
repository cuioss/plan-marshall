# phase-6-finalize dispatch table omits the inline Step 1 surfacer run, so pre-submission-self-review is dispatched without its required candidates field

## Problem

`pre-submission-self-review` declares `requires_prompt_fields: [candidates]` in its frontmatter, and its workflow body splits the step explicitly:

> Step 1 (deterministic surface) and Step 4 (outcome bookkeeping) run inline in the manifest dispatcher's context; Steps 2–3 (contract cross-reference setup + the seventeen LLM cognitive checks) run in the dispatched envelope.

So the dispatcher owes TWO things before the spawn: run `pm-plugin-development:ext-self-review-plan-marshall:self_review surface --plan-id {plan_id}`, and forward its output as `candidates`.

**Neither obligation is visible at the dispatch site.** `phase-6-finalize/SKILL.md` Step 3's per-step dispatch table gives only:

```text
* default:pre-submission-self-review -> workflow: workflow/pre-submission-self-review.md | --phase phase-6-finalize (no --role)
```

The generic prompt-body template carries a `<plus every step-specific field the step declares in requires_prompt_fields>` slot, but a dispatcher working from the table has no signal that this particular step declares one, nor that the field's value comes from a script IT must run first. The declaration lives in the step's own frontmatter, which the dispatcher has no reason to open.

## Evidence

Observed 2026-09-02 on plan `dual-homed-hook-install-renders-identically`. The step was dispatched FOUR times without `candidates`. The envelope flagged it explicitly on two of those rounds:

> "`candidates` was absent from the prompt body although the workflow declares it required. Since the caller also forwarded the surfacer skill and `iteration: 1`, I read this as a full-step dispatch and executed Steps 0, 1, 1b, 2a, 3 rather than refusing."

The leaf self-served Step 1 each time and completed correctly, so the gap produced no wrong answer — it produced silent duplicated work: four surfacer runs inside level-5 envelopes instead of four cheap inline script calls. Each round cost ~190-290K tokens.

## Why it is a defect and not just an operator slip

The leaf's recovery is what hides it. A dispatched envelope that refused on the missing required field would surface the gap on the first round; one that helpfully self-serves it turns a contract violation into a cost regression with no failing signal. That is the same shape as the archetype this repo keeps finding — a confident green over an unasked question — applied to the dispatch contract itself.

Note the guard that exists does NOT cover this: `test_step_prompt_fields_contract.py` checks three surfaces (the step's own dispatch body where it has one, and its input table), but `pre-submission-self-review` is dispatched through the GENERIC template and has no dispatch body of its own, so nothing asserts the dispatcher actually fills the slot.

## Directive

Make the obligation visible where the dispatcher reads. In `phase-6-finalize/SKILL.md` Step 3's per-step dispatch table, annotate the `pre-submission-self-review` row with the Step 1 pre-dispatch call and the field it produces, the way other rows carry their `producer=` runtime input.

Then derive the rest of the class rather than assuming this is the only member: enumerate every step whose frontmatter declares `requires_prompt_fields`, and for each, check whether the value is dispatcher-computed (a script the dispatcher must run) or merely dispatcher-forwarded (a value it already holds). The dispatcher-computed ones are the members that need the same annotation — a forwarded field is discoverable from context, a computed one is not.

Consider also whether a leaf should self-serve a missing required field at all. Refusing would make the gap loud on round one; the current helpfulness is what let four rounds pass unnoticed.

content: "# A guard whose tests were authored from its implementation cannot report that its purpose is unmet

## What happened

`github_pr.py`'s `refusal_pattern_drift` guard emitted its diagnostic when **exactly one**
recognition layer matched (`len(_layers) == 1`). The condition it exists to detect is *not*
symmetric: drift means the **structural** arm matched and the **registry** arm did not. A
registry-only match is not drift — it is the designed correct state for an entire class of
refusals, because Sourcery's size refusal is invisible to the structural arm **by construction**.

The guard fired a live false positive **in the finalize run of the very PR that introduced it**:

```text
refusal_pattern_drift[1]: sourcery,registry_refusal_patterns
```

The correct predicate is unidirectional:

```python
if REFUSAL_LAYER_STRUCTURAL in _layers and REFUSAL_LAYER_REGISTRY not in _layers:
```

## The two failures worth carrying forward

**1. The predicate was never checked against the scenario the guard exists for.** A bidirectional
test was written for a unidirectional condition. Three places in the shipped source already said
so — the guard's own comment, `refusal_layers`' docstring, and `_is_refusal_notice`'s docstring,
which documents the registry arm as load-bearing *precisely because* the structural arm cannot
see a size refusal. The evidence was in the file the author was editing.

**2. The tests pinned the defect.** They were authored from the implementation, so they passed on
the false-positive behaviour and would have **failed** on the correct one. Fixing the guard
therefore required a mandatory test reconciliation plus a matched negative control (a
registry-only refusal must yield an empty drift list). ⛔ **A test written from the code cannot
falsify the code.** It can only confirm that the code still does what it did.

## The detection lesson, and it is the reusable half

**Our own gates did not catch it; an external reviewer did.** The false positive was emitted into
the run's own logs and passed through unremarked. It entered as a CodeRabbit inline comment.

⭐ **A guard emitting a diagnostic about the subject area the current change is modifying is live
evidence about that change** — the run produced its own counter-example and nobody read it.

## What to do

- **State the scenario in one sentence, then check the predicate is not broader than it.** Do this
  for every emitted diagnostic. \"Fires when exactly one layer matched\" versus \"fires when the
  structural layer matched alone\" is the whole defect, visible in that one comparison.
- **When a guard's diagnostic fires during the run that is changing that guard's subject area,
  treat the emission as a first-class self-review candidate.**
- **Write the guard's test from its stated purpose, never from its implementation**, and require a
  matched negative control naming the legitimate case that must NOT fire."

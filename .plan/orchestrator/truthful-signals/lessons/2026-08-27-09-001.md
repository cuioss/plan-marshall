# The display-timezone helper-only guard matches raw file text, so a COMMENT citing a helper name counts as reaching a timestamp

## Problem

`_scan_time_files` in `test_display_timezone_guard.py` matches **raw file text**, not parsed code. So a module that merely *names* a timestamp helper in a comment or docstring is pulled into the helper-only population, and then fails `test_helper_only_population_has_an_explicit_classification_entry` until someone records a verdict for it.

## Observed

PLAN-TRUTH-114, 2026-08-27. `git-workflow.py` obtains **no timestamp at all** — no call, no import. A single comment documenting the provenance of an archive-path glob cited another module's helper name, and that one line put the module in the population.

Established by running the guard's own `_derive_helper_only_population` detector:

```
raw: 35  helper: 19  helper_only: 13  declared: 12
UNDECLARED: ["marketplace/bundles/plan-marshall/skills/workflow-integration-git/scripts/git-workflow.py"]
```

Then locating the matching line: **1 helper-arm hit (the comment), 0 raw-arm hits.** Corroborated by an independent `architecture search --content` sweep over the timestamp-helper pattern set — `match_count: 1`, `truncated: false`.

Note the date-shaped glob (`[0-9][0-9][0-9][0-9]-...`) matches **neither** arm; no regex in the classification covers digit globs. The comment is the whole cause.

## Two consequences worth acting on

**1. The remedy available today is a classification entry, but the vocabulary is closed.** `test_helper_only_entries_are_well_formed` enforces a closed `{STORE, RENDER}` set, so a module holding no timestamp must be recorded as `STORE` — honest only *a fortiori* (it asserts the display knob must never reach the file, which is trivially true of a file with no timestamp). The entry then has to explain in prose that the match is incidental. A third "no timestamp" verdict would itself be a guard change.

**2. The perverse incentive.** The cheapest way to make the failure disappear is to **delete the comment** citing the helper name — trading a true piece of documentation for a quiet guard. That is the wrong trade, and it is the one a hurried fix will reach for.

## Directive

Consider teaching `_scan_time_files` to ignore comments and docstrings, or narrowing the helper arm to call-shaped matches. Both are shared-guard baseline changes needing their own verification, so surface rather than fold into an unrelated plan.

Until then: record the classification entry with prose stating why the match is incidental, and **do not delete the citing comment**.

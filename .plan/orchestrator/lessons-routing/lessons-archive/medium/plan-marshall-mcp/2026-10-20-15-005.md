# declared_scope_reconciliation reads a survey-only glob as an under-declared write set

## Defect

The Q-Gate mechanical check `declared_scope_reconciliation` (`plan-marshall:manage-tasks:qgate-mechanical-checks`) treats every glob that a deliverable declares as write scope. It expands the glob and reports each match that is missing from the deliverable's enumerated file list as an under-declared write set. A glob that names files to read and survey, which are not expected to change, is reported as a defect. The finding then needs a manual `accepted` disposition.

## Observed

Plan `question-corpus-public-datasets-2`, 4-plan finding `56c2a4`: deliverable 6 declared `test/model/verification/decision/**/*.json` to survey 24 decision items for retirement candidates. The check reported all 24 as missing from the write set. The finding was accepted as a documented exclusion, because only an item found at execute time would move into the task's mutation set.

## Corrective action

Let a deliverable state a glob's intent (read-only survey or expected modification), as the declared footprint of `manage-references` already separates modifications from read-only references. Have `declared_scope_reconciliation` reconcile only the write-intent globs. Until then, outline authors should list survey globs as read-only references rather than as affected scope.

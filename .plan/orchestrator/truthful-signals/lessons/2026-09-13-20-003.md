# Add a self-application pass when the plan's subject is a defect archetype

source_plan: plan-truth-127
source_pr: 1483
source_epic: truthful-signals

## Context

plan-truth-127 exists to stop a count being publishable when the code knows it failed to
enumerate something. It shipped that exact defect twice, inside its own fix.

**Instance one — the census verb it added.** `_status_query.py` carried two
`except OSError: continue` branches that dropped an un-stat-able directory entry without
crediting `unreadable_count`, then published `coverage: complete`. A cohort could assert
complete coverage over a population the code had already failed to enumerate — the verb's own
thesis, inverted, in the verb. Filed as qgate finding `af0a4d`, fixed with two positive cases
(one per discard site) and a matched negative control.

**Instance two — the count the census publishes.** `open_phase_count` used `len(records)`, so
it counted plans rather than phases. The census built to measure the two-open-phase bug
under-reported exactly that case. Found by CodeRabbit in review round 2, finding `9e4ff2`.

Neither reached the deterministic gates. `pre-push-quality-gate`, `plugin-doctor`, and CI were
all green on `8cdbd5487` when both defects were live. `pre-submission-self-review` examined
109 candidates over 16 files and reported **no check matched**; instance one was filed anyway,
by the reviewer judging an out-of-surface observation worth recording after the surfacer had
declined to produce it. Instance two was found by an external reviewer that explicitly reasons
outside the diff.

## Root cause

The self-review surfacer detects *structural* candidate families — regex pairs, symmetric
functions, source-of-truth duplicates, description-vs-body drift. "This new code publishes a
count over a population it did not fully enumerate" is a *semantic* property of the change
against the plan's own thesis. No structural family reaches it, and none can: the shape is
ordinary, correct-looking Python.

So on a plan whose entire subject is a defect archetype, the highest-yield check available is
one nothing currently performs: run the plan's own predicate against the plan's own new code.
The information needed is present and free — it is the plan's stated purpose — and the run in
question had it written down in the request, the outline, and seven deliverables.

## Proposed action

1. Add a **self-application pass** to pre-submission self-review, triggered when the plan's
   request or outline states a defect archetype (this plan's: "a published count must not
   outrun what was enumerated"). The pass takes one input — the archetype, in the plan's own
   words — and one instruction: apply it to every new or changed code path in the diff, and
   report per path rather than in aggregate. It is a judgement pass, not a new detector
   family; it does not belong in the deterministic surfacer.
2. Make the pass's population explicit in its report, in the shape this repository already
   requires elsewhere: *N of M changed code paths examined against the stated archetype*. A
   pass that examined nothing must say so rather than report clean.
3. Record, in the surfacer's own contract, that `no check matched` over a populated candidate
   set is **not** a clean self-review. On this plan the out-of-surface channel carried the only
   finding the step produced, while the headline read `109 candidates examined, no check
   matched` — a display detail that reads as a pass and was, in substance, a near-miss.

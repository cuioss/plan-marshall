# Self-review surfacer reports zero observations when it has no detector for the footprint's languages

## What happened

Across every review round of API Sheriff PLAN-22 (a Java + AsciiDoc change), the self-review surfacer
returned zero observations. The cause is that it carries no Java and no AsciiDoc detectors, so the rounds
were structurally incapable of finding anything. Separately, `references.json` carried no
`plan_creation_sha`, so the scope-creep check never measured anything either.

## Why it matters

A review step that reports "nothing found" for want of a detector is indistinguishable, in the record,
from one that looked and found the code clean. Three rounds of zero observations read as evidence of
quality; they were evidence of absent instrumentation. The same shape applies to the unmeasured
scope-creep check: a check with no baseline sha reports no creep.

## Suggested corrective rule

A surfacer with no detector for any language in the plan's footprint must report that fact distinctly
(`no_detector_for_footprint`) rather than an empty observation set, and a check whose baseline input is
missing must report `not_measured` rather than a clean verdict.

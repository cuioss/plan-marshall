# specification drift while the plan ran (orchestrator renamed to epic)

- Component: pm-mcp-core pm-core (WorkflowStatus, WorkflowStatusCodec) / pm-workflow (WorkflowEngine); process: plan-marshall:phase-6-finalize
- Suggested category: improvement
- Signal: automatic review (3 review-bot findings fixed in this run)

## Observation

The documentation repository renamed the phase `orchestrator` to `epic` (docs #43) while this plan
was running. The code still used `orchestrator`, so an epic status written by the engine would have
failed validation against the status schema. No step of the run compared the code with the current
specification. CodeRabbit found it.

## Suggested correction

A closed list in the code that mirrors a specification set gets a parity test against the
specification from the start. Before the PR is created, a plan that implements specifications re-reads
the specifications it implements at their current HEAD, because the documentation repository can
change while the plan runs.

# A no-echo assertion over a short generated string flakes when the message is plain English

## Pattern

A test asserts that an error or log message does not repeat a generated input value, in the form `assertFalse(message.contains(generatedValue))`. The message is fixed English prose. When the generator produces a short string of letters (1 to 8 characters), the value can be an ordinary word fragment such as `e` or `body`, and the fixed message then contains it by chance. The assertion fails even though nothing was echoed.

Because the generated value changes from run to run, the failure is intermittent. It is not tied to the change under test: here it first appeared as a red JDK 26 CI build on an unrelated pull request.

## Corrective action

Do not search a plain-English message for a short random value. Make the value something the fixed message can never contain:

- prefix (or wrap) the generated value with a marker that does not occur in any message text, for example a fixed token with characters prose does not use, and assert on the marked value; or
- generate values with a minimum length and a character set (digits, punctuation) that rules out an accidental match with the message.

The first is the simpler and the more robust: one marker covers every generator setting.

## How to recognise it next time

- A "does not contain the input" assertion fails on one JDK or one run and passes on re-run.
- The reported generated value is short and made of letters only.
- The value appears in the message as part of a normal word, not as the echoed input.

## Scope

Applies to every negative `contains` assertion over generated data, not only to this test: a no-echo check is only as strong as the guarantee that the probe value cannot occur in the expected output.

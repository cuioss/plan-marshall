# Evolving a shared script handler's argparse flag contract breaks synthetic-Namespace unit tests: use getattr for the new attribute and sweep the old required-flag contract tests

Script handlers in this meta-project are unit-tested by constructing `argparse.Namespace(...)`
objects directly and calling the handler, deliberately bypassing the real parser. That test
style has a sharp edge when the handler's flag contract evolves.

## The defect

A CI-abstraction change added a new optional flag (`--body-file`) to the `pr create` handler
and made a previously-required flag (`--plan-id`) optional. The handler read the new value with
direct attribute access — `args.body_file`. Against the real parser that is safe (argparse always
populates a default for every declared flag), but every **pre-existing synthetic `Namespace`** in
the test suite was built before the flag existed and therefore has no `body_file` attribute. The
direct read raised `AttributeError` at runtime — a genuine regression, not a test artifact. In the
same change, roughly a dozen tests broke because they encoded the *old* contract: a parser test
asserting `--plan-id` is required, help-text assertions, and `--head` forwarding tests.

## The rule

When you add — or make optional — a flag on a shared script handler:

1. **Read new/optional attributes defensively.** Use `getattr(args, "body_file", None)` (or the
   flag's default) instead of `args.body_file`. Direct attribute access on a shared handler is an
   anti-pattern precisely because that handler is exercised by synthetic Namespaces that predate the
   flag; `getattr` keeps back-compat without editing every fixture. The real parser path is
   unaffected (it always sets the default), so `getattr` costs nothing there.
2. **Sweep the tests that encode the old contract, proactively.** Changing `required=True` →
   `required=False`, or adding a mutually-exclusive body source, invalidates: parser-contract tests
   (`test_..._requires_plan_id`), help/usage-text assertions, and any flag-forwarding tests. Update
   them as part of the same change rather than discovering them as a wall of red.

## Why it's worth capturing

The failure is not "a gate missed it" — the existing tests caught it. The lesson is the *proactive*
posture: the synthetic-Namespace testing convention (used across the ~100 `manage-*` / integration
scripts) means a handler's argparse surface and its test fixtures are a coupled contract. Evolving
one side without the `getattr` back-compat read and the old-contract test sweep is a predictable,
repeatable self-inflicted break.

# Closing a fail-open on the key axis leaves the value axis open — and the next review round bills for it

## Evidence anchor

PR #1477 (plan-pr-046), CodeRabbit findings `c36544` (round 1, Major) and `5cf6c5` (round 2, Major).
Both are the SAME fail-open in `bot_registry.py`, found on two different axes, one review round apart.

## What happened

This plan's whole purpose was to close a fail-open: `participation_evidence_marker()` returns `''`
for an absent key, and `_is_participation_evidence()` reads `''` as *ungated*, so a shape-only
comment gets participation credit. CodeRabbit round 1 named the **key** axis — `_load()` stored any
parsed marker key without validation, so a typo (`issue_comments`) silently disabled the gate.
TASK-012 added load-time rejection of unknown keys and shipped.

CodeRabbit round 2 then named the **value** axis of the identical defect: the new validator checked
only keys, so `participation_evidence_markers: true` (a scalar where a map was expected) hit the
`not isinstance(markers, dict)` early return and was treated as the *absent* case, and
`issue_comment: true` passed key validation and then normalised to `''` — ungated again. The fix for
the fail-open reproduced the fail-open.

## The rule

When a validator is added because a fail-open default (`''`, `None`, `[]`, `absent`) was read as
permission, the validator must cover **every axis by which the record can still arrive at that
default** — key, value, and container type — not only the axis the reporter happened to name. A
reviewer's finding is a **sample**, never the population; treat the named axis as one instance of
"ways this record can still normalise to the permissive default" and enumerate the rest before
shipping.

Cheap structural test: after adding the guard, ask "what input still reaches the permissive default
through this function?" If the answer is non-empty, the guard is partial.

## Why it is worth a lesson

The plan that reproduced the defect was the plan whose entire subject matter was that defect class.
That is the strongest possible signal that "validate the axis the reviewer named" is the wrong
stopping rule, and it cost a second CodeRabbit round in a rate-limited window (1 review/hour).

## Related archetypes in the corpus

Sibling of `vacuous guards` and `derive completeness, never assert it`: all three are the same
failure to derive the population a guard claims to cover.

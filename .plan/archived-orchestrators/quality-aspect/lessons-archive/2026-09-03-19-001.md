# baseline-reconcile counts merge-tree informational lines as conflicted files

## What happened

`git-workflow baseline-reconcile` reported `conflict_count: 5` for a drift that has
exactly **one** conflicted file. The returned `conflicts[]` was:

```text
test/finalize-step-deploy-target/test_deploy_target.py
automatischer Merge von marketplace/targets/generate.py
automatischer Merge von test/finalize-step-deploy-target/test_deploy_target.py
KONFLIKT (Inhalt): Merge-Konflikt in test/finalize-step-deploy-target/test_deploy_target.py
automatischer Merge von test/plan-marshall/workflow-integration-github/test_refusal_recovery_arming.py
```

Only the first entry is a path. The remaining four are git's human-readable
informational messages, here rendered in the machine's locale (German).

## Root cause

`_detect_merge_conflicts` in
`marketplace/bundles/plan-marshall/skills/workflow-integration-git/scripts/_cmd_baseline_reconcile.py`
treats **every** line of `git merge-tree --write-tree --name-only` output after the
first as a conflicted path:

```python
if rc == 1:
    # Conflicts: line 1 is the tree SHA, subsequent lines are paths.
    lines = stdout.splitlines()
    return [p.strip() for p in lines[1:] if p.strip()], None
```

That comment describes only the first of the output's sections. On a conflicted
merge, `git merge-tree --write-tree` emits:

1. the OID of the written tree,
2. the conflicted-file-info section (under `--name-only`, bare paths),
3. a **blank separator line**,
4. an *Informational messages* section — `Auto-merging <path>`,
   `CONFLICT (content): Merge conflict in <path>`, and friends.

The parser skips the blank separator (`if p.strip()`) and folds section 4 into the
path list.

## Consequences

- `conflict_count` is inflated on every conflicted run — the caller cannot use it
  as a count of anything.
- The `--emit` path files one Q-Gate finding **per entry**, so a single conflicted
  file produces several findings, most of them titled
  `baseline-reconcile: merge conflict in automatischer Merge von <path>` with a
  `file_path` that is not a path.
- The noise is locale-dependent, so the corruption looks different on different
  machines while the inflation is present on all of them.

The three-way `classification` field is unaffected in direction (a non-empty
`conflicts` list still means `overlap_with_content_conflict`), so consumers that
branch only on `classification` or on `conflict_count > 0` still route correctly.
Consumers that report the number, or that consume `conflicts[]` as paths, do not.

## Fix

Stop reading past the informational-message separator: split the post-OID output on
the first blank line and keep only the first section. Add a regression test whose
fixture is real `merge-tree --write-tree --name-only` output including the
informational section, asserting `conflict_count` equals the number of genuinely
conflicted files.

Run git with a forced C locale (`LC_ALL=C`) for any output that is parsed, so a
future parsing regression is at least deterministic across machines.

## Detection

Any `baseline-reconcile` return whose `conflicts[]` entries are not all valid
repository-relative paths.

# test_wrapper_grace_is_strictly_below_the_supervisor_grace is order-dependent

## Observation

During plan lb-28-java-consumer-repos a narrow run `module-tests plan-marshall/script-shared`
failed on `test_build_execute.py:1505`
`test_wrapper_grace_is_strictly_below_the_supervisor_grace` with
`AttributeError: 'NoneType' object has no attribute '__dict__'`, while the same test passed in
the full `module-tests plan-marshall` run. The test loads `_marshalld_supervisor.py` with
`register=False`, so the module is never inserted into `sys.modules`; the `@dataclass`
decorator then cannot resolve the module (`sys.modules.get(cls.__module__)` is None). Whether
it fails depends on what earlier tests on the same xdist worker already imported.

## Directive

Make the test hermetic: register the loaded module in `sys.modules` for the duration of the
load (and remove it in teardown), or import it through the normal package path. Add a guard
that runs the test in isolation so the order dependency cannot return.

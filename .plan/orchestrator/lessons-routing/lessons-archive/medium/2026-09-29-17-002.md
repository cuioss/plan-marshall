# Re-sync affected_files to the realized footprint when scope grows

## Context

In plan `opencode-bootstrap-executor-fix`, `references.affected_files` stayed at the 37 paths declared at outline time. Meanwhile the branch grew to a realized footprint of 60 paths: `realized_footprint` in references.json, captured post-merge at 56add3faf. The additions came from PR-review fixes and from an operator-directed scope widening. They include `pm-plugin-development/skills/tools-marketplace-inventory`, `marketplace/targets/*`, three SKILL.md/contract docs and 8 test files. `project:finalize-step-plugin-doctor` scopes from `affected_files`, so a gate built from the list would have skipped the one skill that changed. In 5 re-fires the subagent widened the scope by hand with `git diff --name-only origin/main...HEAD`, going beyond its written workflow. `manage-metrics generate` also reported `files_modified: 37`, so every per-file ratio used the smaller denominator.

## Root cause

`affected_files` is written once, from the outline, and nothing re-syncs it when execute or finalize changes files outside the declared set. The finalize steps that read it therefore treat the declaration as if it were the footprint.

## Proposed action

- When a finalize commit adds paths outside `affected_files`, re-derive the list from the realized footprint (`manage-references compute-footprint`), or record the drift explicitly.
- Alternatively, have the scope-deriving finalize steps (plugin-doctor first) read `compute-footprint` directly instead of `affected_files`.
- Either way, report a declared-vs-realized mismatch as a finding at the step that consumes the list, not only in the post-merge retrospective.

## Evidence

- aspect: artifact_consistency — `affected_files_exact_match`: `references_only[23]` (realized, never declared), `outline_only[0]`.
- aspect: manifest_decisions — rule M6 `declared_vs_realized_set` fail: 0 declared-but-unrealized, 23 realized-but-undeclared.
- aspect: outline_vs_shipped — 55 of 60 realized paths carry no outline assessment.
- aspect: chat_history_analysis — plugin-doctor subagents: "Following the list strictly would have skipped the very change that caused this re-run", and "Any other finalize step that sets its scope from that list will check less than the branch actually changes".
- aspect: plan_efficiency — `files_modified: 37` against 60 realized files.

## Recurrence — 2026-10-03 (orchestrator-land-verbs)

### Context

During TASK-1 the operator widened scope ("this must be done while establishing the worktree ... fix it now"), and a seventh unit of work — the `worktree_setup_commands` seam, TASK-12/13 — was added to the plan. It never received an outline heading or a references update. Nine realized paths ended up undeclared: six deliverable-7 files (`.plan/marshal.json`, `marshal-json-reference.md`, `_config_defaults.py`, `data-model.md`, `prepare_execute.py`, `test_prepare_execute_worktree_setup.py`), two shared test fixture modules and `uv.lock`. The metrics denominator still reads 6 deliverables.

### Root cause

Same family, a new trigger: adding tasks for new scope during execute has no step that re-derives the declared footprint, so `affected_files` and the outline freeze at their 4-plan state while the realized footprint grows.

### Proposed addition

When execute appends tasks for operator-approved new scope, append a deliverable to the outline (or record the scope addition) and re-sync `affected_files` before the next commit.

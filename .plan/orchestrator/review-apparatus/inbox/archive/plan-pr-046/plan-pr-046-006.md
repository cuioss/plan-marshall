# Verb-paraphrase remains the dominant argparse rejection despite the recurrence checklist

component: plan-marshall:persona-plan-marshall-agent
category: anti-pattern
confidence: medium

## Context

The plan's script-execution log carries 9 argparse rejections, 7 distinct, across 4 scripts: `manage-logging read`, `manage-solution-outline get-deliverable`, three `ci --plan-id` placement rejections, one `ci pr prepare-comment` missing required flag, `manage-execution-manifest read`, `manage-config finalize-steps` with an invalid verb, and `architecture search` with an invented flag. The retrospective that produced this lesson then added an eighth in its own run, reaching for `manage-solution-outline extract-deliverables` where `list-deliverables` is what the parser declares. The recurrence-signature checklist that names exactly these five shapes was loaded in context at the time.

## Root cause

The checklist is loaded but is not consulted per call. It reads as background knowledge rather than as a pre-flight step, so a verb that names the goal ("extract the deliverables") is synthesized and issued without being checked against the declared `choices`. The failure is cheap to recover from — argparse rejects at exit 2 and prints the accepted set — which is exactly why it keeps recurring: it costs one wasted call and no correctness, so nothing forces the habit to change.

## Proposed action

The scripts already do the right thing on rejection: `manage-solution-outline` printed the accepted verb list and named `list-deliverables` as the fix. Extend that to the surfaces that do not — the three `ci --plan-id` rejections and the `architecture search` flag rejection produced usage dumps rather than a named correction. A rejection message that names the canonical call converts the habit problem into a one-call recovery; that is a better lever than more prose telling the agent to consult the checklist.

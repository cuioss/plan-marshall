# A late docs-only fix still pays for full CI and integration tests, because the docs-only skip reads the whole PR diff

## Pattern

Late in finalize, a one-word fix to an ADR was pushed to the PR. The commit touched only documentation, yet it set off a full CI build and a full integration-test run. The reusable integration-test workflow decides on its docs-only skip by comparing the whole PR diff against the base, not the commit just pushed. Once a PR contains any code, every later push, including a pure prose fix, pays for the full suite.

Two review-bot behaviours stretched the wait for the same fix further:

- CodeRabbit's hourly review quota was used up, so its re-review had to wait for the window to reset.
- PR-Agent does not re-review on push in this repository (`.github/workflows/pr-agent.yml` triggers only on opened, reopened and ready_for_review, plus on-demand `/review` comments). Its pass had to be requested explicitly.

## Rule

- Batch documentation and wording fixes into the last code-bearing push before CI starts. A docs-only push on a code PR is never cheap here.
- After pushing review fixes, post a `/review` comment so PR-Agent runs again. Do not wait for it to run by itself.
- When CodeRabbit reports its rate limit, plan the wait (see the unattended-run guidance) rather than polling.

## Suggested direction (for the orchestrator to classify)

- CI: let the docs-only skip also consider the diff since the last green run on the same PR, so a prose-only follow-up commit can skip the integration-test run.

## Provenance

Observed in plan `fix-four-audit-findings-and-bff-flaky-test` (PR #385) during the final review wait.

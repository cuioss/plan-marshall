# phase-2-refine stages module_mapping.toon to a fixed, non-plan-namespaced .plan/temp path — concurrent refine dispatches race

## Problem

`phase-2-refine/standards/refine-workflow-detail.md:746` instructs the refine phase to stage the rendered module-mapping TOON payload to a **fixed, non-plan-namespaced** path:

```text
.plan/temp/module_mapping.toon
```

and then persist it at line 760 via `manage-files write --content-file .plan/temp/module_mapping.toon`.

Because the staging path carries no `{plan_id}` component, two phase-2-refine dispatches running concurrently for **different plans** stage to the same file. Between the `Write` and the `manage-files write --content-file` read there is a window in which the second dispatch's payload overwrites the first's, so plan A can persist plan B's module mapping into its own `work/module_mapping.toon` with no error and no signal.

## Evidence

Observed 2026-09-02 during phase-2-refine for plan `dual-homed-hook-install-renders-identically`: `.plan/temp/module_mapping.toon` was overwritten mid-run by a concurrent refine dispatch for a different plan (its content referenced "planning-lane router" / "execution-manifest composer" deliverables belonging to no part of this plan). That run was unaffected only by timing — its `--content-file` read had already completed.

Confirmed structurally: `architecture search --content --pattern "temp/module_mapping.toon"` returns exactly one file, `refine-workflow-detail.md`, with two occurrences (the stage at :746 and the read at :760). No plan-id interpolation appears in either.

## Why it matters

The corruption is **silent**. `manage-files write` succeeds on whatever bytes are at the path, so a plan whose module mapping was clobbered proceeds through outline and plan phases against another plan's module surface. Nothing downstream re-derives the mapping, so the wrong scope is never contradicted — it is simply carried.

This is an instance of the parallel-throughput hazard the project otherwise designs around: every other per-plan artifact is namespaced under `.plan/local/plans/{plan_id}/`, and the CLAUDE.md rule "Temp files under `.plan/temp/`" says *where* temp files go but not that they must be *unique per plan*.

## Directive

Namespace the staging path per plan, e.g. `.plan/temp/{plan_id}-module_mapping.toon` (or `.plan/temp/{plan_id}/module_mapping.toon`), updating both the stage at :746 and the `--content-file` read at :760 in lock-step so the pair cannot diverge.

Then sweep `.plan/temp/` for the same shape: any other workflow doc that prescribes a fixed temp filename as a staging hand-off between a `Write` and a script read has the identical race. Derive that set from an enumeration (`architecture search --content --pattern "--content-file .plan/temp/"`), not from memory — a partial fix leaves the hazard in place under a claim that it was addressed.

# The pre-push-quality-gate footprint prune runs at plan time, when the footprint is always empty

## Context

Plan-170 composed its execution manifest twice, and on neither occasion could the `pre-push-quality-gate` prune predicate reach a meaningful verdict:

- **2026-08-30 compose**: `pre_push_quality_gate_inactive — kept pre-push-quality-gate on an unknown build verdict: plan footprint unresolvable — no materialized worktree carries evidence of what this plan changed`
- **2026-09-02 compose**: `pre_push_quality_gate_inactive — dropped pre-push-quality-gate from phase_6.steps: plan footprint is empty — no changed files to build`

On the second run the step was **dropped**, and survived only because an unrelated setting fired immediately afterwards: `ceremony_finalize selection — finalize.qgate=always, added pre-push-quality-gate to phase_6.steps`.

The plan went on to modify 15 files. The quality gate that would have built them was removed by a predicate reading an empty footprint, and restored by a setting that knows nothing about footprints.

## Root cause

`compose` runs during **phase-4-plan**, before any implementation has occurred. The plan's realized footprint at that moment is empty by construction — there is nothing in the worktree yet to diff. A prune predicate keyed on "did this plan change any files?" therefore evaluates against a value that is *structurally* empty for every plan, not just this one, and can only ever fire in the unsafe direction: dropping a build gate from a plan that will go on to change code.

The first compose shows the other failure mode of the same design: with no materialized worktree the footprint is `unresolvable`, and the code correctly refuses to prune on an unknown — but "unresolvable" and "genuinely empty" are two different states and only one of them is safe to act on. On the second compose the resolver returned *empty* rather than *unresolvable*, so the refusal did not engage.

## Proposed action

- **Do not prune a build gate on a plan-time footprint read.** Either defer the decision to finalize, where the footprint is real, or treat a plan-time empty footprint as `indeterminate` and keep the step — the same fail-safe the first compose took on `unresolvable`.
- Collapse the empty/unresolvable distinction at this call site: at compose time both mean "no evidence yet", and neither licenses dropping a gate.
- Do not rely on `finalize.qgate=always` as the safety net. It is an independent ceremony setting that happens to overlap; a project that sets it to anything else loses the gate silently with only a `[STATUS]` log line to say so.

# A dispatcher passes an invented --limit flag to manage-findings list

## Problem

A dispatcher called `plan-marshall:manage-findings:manage-findings list --limit N` and argparse rejected it (exit_code=2, argparse_rejection):

```
`--limit` is not declared for `plan-marshall:manage-findings:manage-findings list`: ['any-checkout', 'author', 'bot-kind', 'component', 'file-pattern', 'include-qgate', 'kind', 'plan-id', 'preference-admissible', 'promoted', 'resolution', 'type']
```

`manage-findings list` has no paging flag; `manage-logging read` does have `--limit`, which is the likely source of the paraphrase. It is an instance of the known "never invent script flags" recurrence class (a flag borrowed from a sibling script). The motive is real: the pr-comment output of `list` is very large (51 KB for this plan).

## Solution

Either add a `--limit` to `manage-findings list`, since its output is large enough to want one, or state in the script's canonical block that it has none. A caller should read the canonical invocation instead of carrying a flag over from a sibling script.

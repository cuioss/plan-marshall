# platform_runtime session + pretooluse hook consume 59% of all recorded script wall-clock (110k invocations, 4.3h) — per-tool-call subprocess overhead is the corpus's single largest script cost

## Observed

Surfaced by the `global-log-analysis` check of the full-corpus archived-plan retrospective audit
(115 plans, `.plan/local/logs/script-execution-*.log`, 2026-07-26). Corpus total recorded script
wall-clock: **25,867s**.

| Caller | Invocations | Wall-clock | Share of all script time |
|--------|------------:|-----------:|-------------------------:|
| `plan-marshall:platform-runtime:platform_runtime session` | 77,337 | 13,170s (3h39m) | **50.9%** |
| `plan-marshall:platform-runtime:claude_pretooluse_hook` (all duration buckets) | 32,413 | 2,217s | 8.6% |
| **combined** | **109,750** | **15,387s (4h16m)** | **59.5%** |

For comparison, the next-largest callers are `architecture find` (1,114 calls / 1,178s) and
`ci pr` (169 calls / 255s) — an order of magnitude smaller.

Each individual call is cheap (~0.17s for `session`, 0.05–0.26s for the hook). The cost is entirely
**frequency**: these fire per tool call, so they scale with session length rather than with work done.

## Impact

This is a **wall-clock** cost, not a token cost — but it is the largest single lever in the script
layer, and it is invisible in every per-plan view because no individual call is slow enough to trip
the 30s `slow_call` ceiling. It only becomes visible when aggregated corpus-wide, which is why it has
never surfaced in a per-plan retrospective.

## How to apply

- Treat per-tool-call subprocess hooks as a first-class cost surface: the optimization question is
  invocation COUNT, not per-call duration.
- Candidate directions (verify before choosing): coalesce/suppress `session` refreshes when the
  composed value is unchanged (the same shape as [[2026-07-22-12-001]], applied to the invocation
  rather than the log line); batch or short-circuit the pretooluse hook for tool classes it cannot
  affect; or move the title/session write off the per-call path entirely.
- General rule: a cheap-per-call, high-frequency caller can dominate total cost while never tripping a
  per-call slowness threshold. Detectors keyed on per-call duration are structurally blind to it —
  aggregate by caller before concluding a layer is cheap.

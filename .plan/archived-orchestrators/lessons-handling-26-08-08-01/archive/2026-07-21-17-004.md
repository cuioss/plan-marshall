# Outline pass 1 verifies declared paths exist but never that a declared set is complete

## Context

Plan `refactor-test-suite-pytest-standards` consumed an external remediation map (RU-0..RU-9) as its authoritative work list. Phase-3-outline's first pass produced 12 deliverables and reported every enumerated path as verified present on disk.

The Q-Gate then flagged 5 of 13 deliverables, including one BREAKING defect:

- **D1** deleted `test/plan-marshall/_pm_input_validation_fixtures.py` while **6 of its importers were unenumerated**. Had this shipped, pytest COLLECTION would have failed outright.
- **D2** enumerated "14 of 20 importing modules" and carried a wrong success-criterion count.
- D10 declared `depends: none` while its own prose stated an ordering requirement on D6.
- D12 bucketed a path pair `test_only` while D11 bucketed the identical pair `mixed_code`.
- D13's design notes named no permitted design model.

Remediating all 12 findings took a full extra outline pass and widened `affected_files` from 48 to 84. A third pass had already been spent applying operator answers. Phase-3-outline consumed 741K tokens — 20% of the plan total and the largest non-execute phase.

A fourth premise (RU-7's claim that a discover-modules integration tier covers the unit assertions) survived outline entirely and was refuted only in phase-5-execute, costing a task slot, an operator gate and a dropped deliverable.

## Root cause

The outline's verification step is shaped as *existence* checking: for each path the deliverable declares, confirm the path is on disk. That check passes trivially for a set that is correct-but-incomplete, because every path it does contain is real.

Nothing in the first pass computes the *closure* of a declared set. For a delete or relocate intent the load-bearing question is not "do these 14 files exist?" but "are these 14 files ALL the files that reference the target?" — a referrer-closure question the existence check cannot answer. Likewise, nothing tests semantic claims inherited from a consumed analysis artifact (RU-7's "the integration tier covers this"); those are accepted as given.

The Q-Gate does perform the completeness check, which is why it caught two of the four refuted premises — but it runs after a full outline has been authored, so every defect it finds is rework rather than prevention.

## Proposed action

1. Add a **referrer-closure assertion** to outline pass 1, not just to the Q-Gate: for every deliverable carrying a `delete` or relocate intent, compute the set of modules referencing the target and diff it against the declared `affected_files`. Emit the diff as an authoring-time failure. This is a deterministic, script-shaped check — see the companion proposal for an `architecture find-importers` verb.
2. Require that any deliverable premise **inherited from a consumed artifact** (analysis map, prior-plan report, scout output) be tagged with its provenance and marked `unverified` until an on-disk check clears it. A premise asserting that some code *does* or *does not* exist (RU-7's "integration tier covers this") must be discharged at outline, where refuting it costs one Read, rather than at execute, where it costs a task.
3. Treat a request that designates an external work list as authoritative as a signal to run the premise sweep eagerly — this plan's consumed artifact carried a 40% premise-defect rate (4 refuted of 10 units).

## Recurrence — 2026-07-22 (build-timeout-truthful-status)

The same closure gap recurred on a plan with NO delete or relocate intent, which widens this lesson beyond the referrer-closure case it was first filed for. Two independent instances in one outline pass, both caught by the Q-Gate as rework rather than by pass 1:

**Instance 1 — sibling exhaustive whitelists in the same module.** Deliverable 1 added a new field to a build-result record. It correctly identified `_build_format.EXTRA_FIELDS` (a hard-coded, exhaustive top-level field whitelist) and enumerated it. It missed a SECOND exhaustive whitelist ~100 lines below in the same file: `format_toon`'s tests-block projection, which hard-codes its own `OrderedDict` of rendered columns. The declared set was correct and every path in it existed — but it was not the closure of "every exhaustive projection that governs this record". The consequence was a silent cross-format divergence: the new field would have appeared on the JSON path (which passes `to_dict()` through) and vanished on the default TOON path, so the very same deliverable's own TOON and JSON format examples in the doc would have contradicted each other.

**Instance 2 — the sibling normative claim inside a single document.** Deliverable 1 corrected a failure-only framing in one prose heading of a standards doc, and missed the identical normative claim restated in that SAME document's Compliance checklist. The edit would have left the document internally contradictory — the field table saying one thing and the extension-facing obligation saying the opposite.

**What this adds to the root cause.** Existence-checking passes trivially in both instances. Neither is a referrer-closure question ("who imports this?"); both are *projection*-closure questions:

- *Code*: when adding a field to a record, the closure is every exhaustive whitelist / hard-coded projection that renders that record — one per output format. A record with N serializers has N whitelists, and updating one is indistinguishable from updating all until the formats are diffed.
- *Docs*: when changing a normative claim, the closure is every restatement of that claim, including restatements inside the SAME file (headings, field tables, compliance checklists, worked examples). Intra-document duplication is the easiest to miss precisely because the file is already in `affected_files`, so no path-level check fires.

**Generalized rule.** Extend the pass-1 closure assertion beyond delete/relocate intents: for any deliverable that adds a field to a record or changes a normative claim, enumerate the projections/restatements of that record or claim and diff them against the declared change set. Two cheap, script-shaped discriminators exist and should be preferred over prose review — (a) a deliverable's own multi-format examples MUST agree with each other, which mechanically exposes a missed serializer, and (b) a same-file grep of the changed claim's phrasing, which exposes an intra-document restatement. Marking the file as touched is NOT the check; the check is enumerating the edits WITHIN the file.

## Recurrence — 2026-07-22 (pyproject-routing-integration)

Third instance, and the cheapest-to-detect one yet: the closure gap surfaced as a **self-contained internal inconsistency between two artifacts of the same deliverable**, requiring no codebase knowledge at all to spot.

**What happened.** A deliverable's success criterion named the maven, gradle, and npm call sites as the surface it changed — an explicit, enumerated set of three. Its `affected_files` listed only two of those three. The Q-Gate's `scope_criterion_validator` caught the mismatch. As in the prior instances, existence-checking passed trivially: both declared files were real, and pass 1 had nothing to say about the third.

**What this adds to the root cause.** The two earlier instances required *external* knowledge to detect the gap — you had to know who imports the deleted module, or that a second serializer existed 100 lines down. This one did not. The criterion prose and the file index are two projections of the SAME declared scope, authored side by side in the same deliverable, and they contradicted each other on their face. The check is a pure set-difference between two things the deliverable already states:

> **claim-vs-index closure**: when a success criterion (or design note, or any deliverable prose) enumerates a set of N call sites / modules / formats / rules, `affected_files` MUST contain a member for each of the N. A criterion naming three build systems and an index listing two is a defect visible without opening a single file.

**Why this is the highest-value discriminator of the three.** It is fully deterministic, needs no repo traversal, and is a natural pass-1 authoring-time assertion rather than Q-Gate rework: parse the enumerated nouns out of each criterion, diff against the declared `affected_files`, fail on a non-empty difference. This is the same "index must enumerate every member of the set it indexes" obligation the agent-behavior rules already state for authored tables — applied here to the criterion/`affected_files` pair, which is exactly such an index.

## Recurrence — 2026-07-26 (orchestrator-queue-row-field-setter)

Fourth instance. Same claim-vs-index closure gap as the third, but through a
**universally-quantified criterion rather than an enumerated one** — which
defeats the very discriminator the third recurrence proposed.

**What happened.** Deliverable 3's success criterion read:

> "No direct-`status.json`-edit instruction remains anywhere in the surveyed tree"

The deliverable's own *Files to survey* scope statement defined that tree as
`SKILL.md`, `workflow/*.md`, `templates/*.md`, plus `orchestration-model.md`. A
directory enumeration over that stated scope returns **14** files.
`affected_files` listed **7** (`SKILL.md`, `analyze.md`, `landing-analysis.md`,
`decompose.md`, `orchestrate.md`, `resume.md` as write-replace,
`orchestration-model.md` as read). Seven files inside the deliverable's own
declared survey scope were absent entirely — not even listed as read:
`workflow/init.md`, `workflow/close.md`, `workflow/archive.md`,
`workflow/lessons-handling.md`, `templates/epic.md`, `templates/workstream.md`,
`templates/plan-spec.md`.

Caught by the phase-4-plan Q-Gate `scope_criterion_validator` (finding `89f1b5`,
`under_coverage`) and resolved in-run by extending `affected_files` with the 7
read-only survey targets, mirroring onto TASK-005 and re-persisting
`references.json`.

**What this adds to the root cause.** The third recurrence's discriminator is
"parse the enumerated nouns out of each criterion, diff against
`affected_files`". That parse yields **nothing** here — the criterion enumerates
no nouns at all. Its scope is a universal quantifier ("anywhere in the surveyed
tree") whose domain is stated in a *different field* of the same deliverable and
whose extension must be **materialized by a directory enumeration** before any
set-difference is possible. A pure noun-extraction pass reads this criterion as
scope-free and skips it, so the highest-value discriminator is silently
inapplicable to exactly the criteria that claim the widest coverage.

There is a second, aggravating property. A whole-tree sweep criterion is a claim
of *absence* ("no instruction remains"). Absence is only verifiable over a
materialized domain: a file never opened cannot be shown to lack the pattern.
Under-scoping an enumerated criterion produces an incomplete edit; under-scoping
a universally-quantified absence criterion produces a **criterion that is
structurally unprovable and will nonetheless be marked satisfied**, because every
file that was actually swept does satisfy it. The defect is invisible at
verification time by construction.

**Added rule — materialize the quantifier before diffing.** Extend the
claim-vs-index closure check with a quantifier branch:

1. **Classify each success criterion as enumerated or quantified.** Trigger the
   quantified branch on scope words — `anywhere`, `no ... remains`, `every`,
   `all`, `across the tree`, `throughout` — and on any criterion naming a *scope*
   rather than a *list*.
2. **For a quantified criterion, resolve its domain from the deliverable's own
   stated survey scope and ENUMERATE it** (glob the stated directories/patterns).
   That enumeration — not the prose — is the index the criterion must be diffed
   against. `affected_files` must contain a member for every file in the resolved
   domain, as `write` where the file changes and explicitly as `read` where it is
   only swept.
3. **A swept-but-unchanged file belongs in `affected_files` as `read`.** This is
   what makes an absence claim auditable: the read entries are the record of what
   was actually examined. Omitting them is indistinguishable from never having
   looked, and collapses the criterion into an unfalsifiable assertion.
4. **Otherwise, narrow the criterion to the subset actually swept.** The
   remediation is symmetric — either widen the index to the criterion's domain or
   narrow the criterion's wording to the index. Leaving a whole-tree claim over a
   partial index is the one outcome that must not ship.

## Recurrence — 2026-07-27 (retire-gemini-registry-ground-pr-agent-standard)

Fifth instance, and the first where the quantified-absence criterion actually
**shipped unsatisfied**. The fourth recurrence's rule predicted this case
precisely; it was not applied, and the predicted failure mode occurred verbatim.

**What happened.** Deliverable D3's acceptance criterion read:

> \"Acceptance: a repo-wide case-insensitive search for `gemini` returns only
> intentional historical records (ADRs, archived plans, landing records — which
> are audit history and MUST NOT be rewritten). Name the surviving set explicitly
> in the PR body so 'all references are gone' is a checked claim, not an
> assertion.\"

The criterion is universally quantified over a domain it names as *repo-wide*.
The domain was never materialized. The sweep that was actually executed covered
`marketplace/`, `test/`, `doc/` and `.github/` — the four roots the plan's
grounding section had enumerated by hand — and never touched `.claude/`.

Post-merge verification of the landed commit found three surviving hits in
`.claude/`, and the first is live operative machinery, not history:

```text
.claude/skills/audit-archived-plan-retrospectives/scripts/audit.py:2717
  _QC_BOT_RE = re.compile(r\"gemini|copilot|bot|automated\", re.IGNORECASE)
.claude/skills/audit-archived-plan-retrospectives/scripts/audit.py:2665   (comment)
.claude/skills/audit-archived-plan-retrospectives/checks/quality-chain.md:26 (contract prose)
```

`_QC_BOT_RE` is the discriminator that classifies a `pr-comment` finding as
`auto-review` vs `human-review`. It still names the retired bot, and names NONE
of the three enabled bots (`coderabbit`, `sourcery`, `pr-agent`) — they match
only incidentally through the generic `bot` token. By the plan's own D1
taxonomy this is class-(a) operative machinery, exactly what D2 was chartered to
remove. Four further hits are live fixture payloads in
`test/plan-marshall/audit-archived-plan-retrospectives/test_audit_checks.py`
(lines 2318, 2414, 2450, 2512) that D3's re-point-not-delete rule covered and
that were never re-pointed.

**What this adds to the root cause.** The prior four instances were all caught by
a Q-Gate as rework. This one was caught by **nothing** — it passed outline,
plan, execute, whole-tree quality-gate, whole-tree plugin-doctor, self-review,
CI, and merged. The reason is the structural property the fourth recurrence
identified: an absence claim over an unmaterialized domain is **self-confirming**.
Every file the sweep did open satisfies \"no gemini remains\", so the criterion
reads as met. Widening the sweep is the only thing that can falsify it, and
nothing in the pipeline forces the widening.

Two aggravating specifics worth naming:

- **The domain was inherited from the plan's own OBSERVED grounding block, not
  computed.** The grounding said \"**42 files** carry the string `gemini` across
  `marketplace/`, `.github/`, `doc/`, and `test/`\" — a hand-run search whose four
  roots then silently became the definition of \"repo-wide\" for the acceptance
  criterion downstream. A count presented as evidence hardened into a scope
  boundary without ever being restated as one.
- **The same grounding block carried a checkable factual error that also went
  unchallenged**: it asserted `.github/workflows/pr-agent.yml` had \"**0 hits** —
  the filename matched the earlier search, not the content\". The file carries two
  content hits. (Both are legitimate — they refer to the Google Gemini *model*
  PR-Agent runs on via Vertex AI, not the retired review bot — so the preserve
  decision was right, but for a reason nobody checked.)

**Added rule — for a retirement/removal sweep, the domain is `git ls-files`, not
a hand-listed root set.** Concretely:

1. A criterion using the words *repo-wide*, *anywhere*, *all references*, or
   *zero residue* MUST resolve its domain by enumerating tracked files
   (`git ls-files`), not by reusing whatever root list an earlier exploratory
   search happened to use. `.claude/`, `.github/`, and any other dotted directory
   are inside a repo-wide claim by definition.
2. **An exploratory-search root set is evidence, never scope.** When a grounding
   block reports \"N files across {roots}\", that is a measurement under a stated
   filter. Promoting it to the acceptance domain silently narrows the claim. If
   the sweep is meant to be bounded by those roots, the criterion must say so —
   \"across marketplace/, test/, doc/ and .github/\" — and drop the words
   *repo-wide*.
3. **Prefer a script to a criterion.** \"Search returns only intentional
   historical records\" is mechanically checkable: walk `git ls-files`, match the
   token, subtract an explicit allowlist of intentional-history path globs, and
   fail on any residual. Executed as a script it is exhaustive by construction;
   executed as an LLM instruction its scope is re-chosen, unrecorded, every time.
4. **Distinguish provenance-comment residue from live residue before declaring
   victory.** Of the surviving hits here, the eight
   `\"Regression guard for PR #NNN gemini-code-assist finding …\"` docstring
   attributions across eight test modules ARE intentional history and correctly
   preserved. The failure was not that hits survived — it was that nobody
   partitioned the surviving set, so a live regex sat undetected among them.

## Recurrence — 2026-07-27 (refusal-recognizer-generalizes-phrasing) — the outline declared the sweep CLOSED and forbade re-running it

Sixth instance. The closure gap is the same as always; what is new is the
**instruction the outline attached to it**. This is the first recorded case where
the outline did not merely under-scope a sweep — it explicitly certified the
sweep as authoritative and directed the downstream phase not to repeat it,
removing the one remaining chance to catch the omission.

**What happened.** Phase-3-outline recorded a consumer sweep of
`_is_rate_limit_notice` and `fetch_pr_reviews_with_commits`, presented the
resulting consumer set as closed, and instructed phase-5 not to re-run the
discovery. Within that sweep it did check one test module —
`test/plan-marshall/workflow-integration-github/test_re_review_strategy.py` —
and correctly reported it carried no whole-dict equality assertions. It never
examined `test/plan-marshall/workflow-integration-github/test_github_ops.py`,
a sibling module in the same test package, which carried two:

```python
assert result['reviews'] == [
    {'user': …, 'state': …, 'submitted_at': …, 'commit_sha': …}
]
```

D3 added a `body` key to that projection. Both assertions broke. The whole-tree
test run caught them, and the repair landed as a separate follow-up commit
(`087d99992 test(github): align review-projection expectations with additive
body key`) after the D3 fix commit (`80c584788`), which had updated only
`test_re_review_strategy.py`.

**What this adds to the root cause.** Prior recurrences describe an outline that
*failed* to materialize a domain. This one describes an outline that materialized
a **proper subset**, then **published the subset as the domain**. The two are not
the same failure:

- An unmaterialized sweep leaves the question open, and a later phase may
  re-ask it.
- A sweep declared CLOSED **answers** the question, and the closure directive
  converts the downstream phase from a second detector into a consumer of the
  first detector's blind spot. Every stage after it is now reasoning from a
  premise it has been told not to test.

The aggravating detail is that the outline's partial sweep produced a *positive
finding* — "`test_re_review_strategy.py` has no dict-equality assertions" — and
that finding is true. A true statement about one member of a set was carried
forward as a true statement about the set. This is the same vacuous-authority
shape the plan's own production fix addressed, committed by the artifact
describing the fix.

**Added rule — a sweep may be declared closed only when its domain was
enumerated, and the enumeration must ship with it.**

1. **No closure directive without an enumeration.** An outline may instruct a
   downstream phase to skip re-discovery ONLY when it attaches the materialized
   file list the sweep covered. "I swept the consumers" is not a closure; "I
   swept these N files, here they are" is. Without the list, the downstream phase
   MUST re-run the sweep regardless of what the outline says.
2. **A sweep over a package must enumerate the package, not sample it.** Checking
   one module of `test/plan-marshall/workflow-integration-github/` and reporting
   on "the consumers" is a sample presented as a census. Glob the package; list
   every member; state the per-member verdict or state that it was not examined.
3. **A per-member positive finding must be scoped to that member in the prose.**
   Write "`test_re_review_strategy.py` has no dict-equality assertions", never
   "the tests have no dict-equality assertions". The generalization is where the
   subset becomes the domain, and it happens in the sentence, not in the search.
4. **Additive-key changes have a mechanical consumer set.** For a change that
   adds a key to a dict a function returns, the closure is every whole-dict
   equality assertion (`== {…}` / `== [{…}]`) against that function anywhere in
   the test tree. That is a deterministic, script-shaped query and should never
   be answered by reading a chosen file or two — the same argument recurrence
   five makes for preferring a script over an LLM-executed criterion.

**Extended recurrence signature.** In addition to the existing signature, treat
as this defect any outline that (a) instructs a downstream phase to skip a
discovery step, AND (b) does not attach the enumerated domain that discovery
covered. The tell is a fix commit followed by a separate "align tests" /
"update expectations" commit for a file the outline never named.

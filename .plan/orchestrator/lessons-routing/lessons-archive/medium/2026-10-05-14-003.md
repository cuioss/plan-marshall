# Commit first, then verify: a dirty-tree green does not count for the committed tree

A verify build ran while the worktree still had uncommitted changes. After the commit, the freshness check (ledger-verified basis keyed on the worktree tree hash) treated the earlier green verify as stale, and verify had to be re-run on the committed tree. One full build was spent twice.

## Solution

Commit first, then run the verify that the freshness gate will consult. A verify run against a dirty tree does not count as evidence for the committed tree.

## Impact

Cost class (repeated build), not correctness — but a full double build per occurrence.

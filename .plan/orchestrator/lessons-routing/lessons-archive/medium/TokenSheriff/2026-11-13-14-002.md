# Build wrapper files npm and Jest console noise from a passing run as build-error findings

The npm/Jest output parser must file a build-error only for a line that belongs to a real failure (a failing test, a non-zero npm exit with an error marker, a lint error); warnings and informational console output from a passing run are not build errors.

## What happened

In plan client-authorization-request-seam, the build wrapper stored ordinary npm and Jest console output from the frontend module built inside the Maven reactor as `build-error` entries although nothing had failed. False build-error entries inflate the error signal, can feed the script-failure and findings counts, and cost triage time on non-defects.

## Rule

- Classify a line as a build error only inside a real failure context.
- Console noise from a passing run (warnings, informational lines) is never filed as build-error.
- Add a parser fixture holding a passing Jest run with console output and assert it yields zero build-error entries.

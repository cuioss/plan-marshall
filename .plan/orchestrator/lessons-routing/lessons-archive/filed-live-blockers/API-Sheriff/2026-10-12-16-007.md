# Prescribed phase-5 yields are recorded as error by the deterministic no-progress rule


Source: observation from the orchestrating session of plan `jwks-unknown-kid-refresh` (PR #430).

During phase 5 several hand-offs ended in a yield that the workflow itself prescribes: the step hands control back so the main context can do something only it can do. The deterministic no-progress rule recorded those hand-offs as `error`.

The rule cannot tell a prescribed yield from a hand-off that stalled. Both return without the progress marker it looks for, and both are reclassified the same way.

## Candidate lesson

A yield the workflow prescribes is a correct outcome and must not be recorded as `error`. The no-progress rule needs a way to recognise it, for example a declared return signal the workflow emits on a prescribed yield and the rule exempts.

Until that exists, an `error` recorded by the no-progress rule on a phase-5 hand-off is not evidence that the hand-off failed. Check what the hand-off returned before treating it as a failure or retrying it.

## Impact

The plan's record overstates failures: steps that behaved as designed are listed as errors. These reclassifications also count toward the script-failure signal that decides whether lessons capture runs at all, so the same false errors can trigger this step on a plan that had no real failure. Which of this plan's recorded errors were prescribed yields was not enumerated by this step.

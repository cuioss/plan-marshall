# Outline and plan subagents moved the phase status themselves, leaving phase metrics half-stamped

## Pattern

The subagents running phase 3 (outline) and phase 4 (plan) moved the plan's phase status forward on their own instead of handing back to the main-context orchestrator for the transition. Phase metrics stamp their boundaries at the orchestrator's transition. So the start or end mark of the affected phases was missing or recorded at the wrong point. The metrics were only reconciled when the plan was resumed.

## Why it matters

- Per-phase durations and token counts are unreliable for that plan until someone reconciles them by hand.
- When the status moves without the orchestrator, the orchestrator's own transition steps, such as the boundary stamps and the handshake checks, run against a phase the status says is already finished.

## Rule

- A dispatched phase subagent finishes its phase's work and returns the phase's declared signal. It does not call the phase-transition verb itself. The transition belongs to the main-context orchestrator.
- On resume, check that each completed phase has both metric boundaries before trusting the totals. If one is missing, reconcile it before going on.

## Suggested direction (for the orchestrator to classify)

- Tooling: reject a phase transition that comes from inside a dispatched envelope, or have the transition verb stamp the metrics boundary atomically, so the two cannot drift apart.

## Provenance

Observed in plan `fix-four-audit-findings-and-bff-flaky-test` (PR #385). The phase-3 and phase-4 subagents moved the status themselves, and the metrics boundaries were reconciled when the plan resumed. This is plan-marshall tooling behaviour. It is filed in this store because it was observed here.

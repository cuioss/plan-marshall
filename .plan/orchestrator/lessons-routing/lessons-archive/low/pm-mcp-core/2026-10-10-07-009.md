# The first fix round failed the Sonar quality gate again with a bug the fix itself introduced

## Source

Review-bot finding 63920a (sonarqubecloud notice on PR #18, reviewed commit 3144ca4), resolved `fixed`. The notice text is third-party content; it is summarised here, not quoted.

## What happened

After the first fix round was pushed (3144ca4), the Sonar notice on the pull request reported the quality gate as failed: reliability rating C on new code, required A. The cause was java:S5855 (redundant alternative in a regular expression) in `AsciiDocValidator.java` line 55, Sonar finding 9cd6ba. That expression was the block-delimiter alternation the first fix round had extended to cover the open block and the comment block. Two more issues came with the same push: java:S5843 (expression complexity 24, allowed 20; finding 7f094a) and java:S4144 (a test method identical to `acceptsText`; finding 750c1d).

So the fix for review findings 2976ee and 836326 produced three new Sonar issues, one of them gate-failing, and none was visible to a local build.

## Fix applied

TASK-14 replaced the alternation by separate simple checks per delimiter kind, which removed the expression altogether; TASK-15 merged the duplicated test method into the shared parameter source. After that Sonar reported 0 new-code issues.

## Proposed rule

A fix that extends a regular expression is re-read against the Sonar regex rules (redundant alternatives, complexity limit) before it is pushed; when an alternation grows past a handful of members, prefer separate checks over a longer pattern.

## Relation

This is the concrete record behind the wider observation that the Sonar gate is evaluated only in CI (a separate candidate of this run).

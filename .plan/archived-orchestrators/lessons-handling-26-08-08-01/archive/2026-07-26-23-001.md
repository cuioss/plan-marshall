# extract-chat-signal self-reports a healthy Tier 1 reduction while the reduced transcript is dominated by skill-document bodies misclassified as user turns plus empty turns

**Context:** Plan `test-suite-quality-unit-testing-residue` (PR #1012), finalize-step
`plan-marshall:plan-retrospective` running aspect 14 (chat-history) with
`--session-id edbca49d-8a84-4ce0-ab2c-4f7b6a2fe262`.

## Symptom

`extract-chat-signal run --transcript-path {session}.jsonl` returned a verdict that
reads as a healthy Tier 1 result:

```toon
reduced_turn_count: 199
reduced_bytes: 292884
read_budget_bytes: 2097152
no_signal: false
over_budget: false
```

Per the two-tier degradation path in `references/chat-history-analysis.md`, `no_signal
== false AND over_budget == false` is exactly the Tier 1 branch: feed `reduced_transcript`
to the LLM analysis prompt. Nothing in the envelope signals degradation.

Inspecting the 292,884-byte `reduced_transcript` shows it is not a reduction of the
conversation at all:

1. **Skill-document bodies are emitted as `user:` turns.** The second turn is the entire
   `plan-marshall/SKILL.md` body, prefixed `user: Base directory for this skill:
   /Users/oliver/.claude/plugins/cache/.../skills/plan-marshall`. The
   `phase-6-finalize/SKILL.md` body appears in full later — roughly 3,000 lines of
   instruction text (loop-back contracts, dispatch tables, canonical-invocation blocks)
   presented to the analysis prompt as things the operator said.
2. **Empty turns are emitted as content-free rows.** The transcript tail carries ~98
   consecutive turns that are literally `user: ` with no body — roughly half of the
   199-turn count.

The genuine operator conversation — the originating `/plan-marshall` invocation and any
mid-plan corrections — is a small minority of the payload.

## Root cause

The reducer's turn filter keys on the transcript's role field alone. On this platform a
skill load and a slash-command expansion both arrive as `user`-role entries, so the
reducer cannot distinguish operator utterance from injected instruction payload, and it
applies no emptiness predicate before emitting a turn.

The consequence is worse than a plain quality dip because the failure is **silent and
inverted**: the more skills a phase loads, the larger `reduced_bytes` grows, which makes
`no_signal: false` *more* certain to hold. The health signal strengthens as the actual
signal degrades. An analysis fed this payload reasons over the skills the run loaded
rather than over what the operator said, and reports its conclusions with no degradation
marker — so a downstream reader cannot tell an unrefuted "zero operator interventions"
from a proven one.

## Corrective rule

`extract-chat-signal.py` MUST apply two deterministic content predicates before a turn
enters `reduced_transcript` — both pure string tests, no LLM:

1. **Drop skill-load payloads.** A turn whose body begins with the skill-load preamble
   (`Base directory for this skill:`) is an injected skill document, not conversation.
   The same applies to slash-command expansion wrappers (`<command-message>` /
   `<command-name>` blocks) once the `<command-args>` payload has been extracted — the
   args are the operator's request and are worth keeping; the surrounding expansion is not.
2. **Drop empty turns.** A turn with no content after whitespace-stripping MUST NOT be
   emitted, and MUST NOT count toward `reduced_turn_count`.

More generally: a signal-extraction pre-pass whose health verdict is computed from
**volume** (`reduced_bytes`, `reduced_turn_count`) must first establish that the volume
is *signal*. A size-derived health check over an unfiltered payload measures the
instruction corpus, and reports louder the more diluted it gets. Where the filter cannot
guarantee it, the envelope MUST carry the composition it actually produced (e.g. a
`signal_turn_count` distinct from `reduced_turn_count`) so the consumer can apply its own
floor rather than trusting a volume proxy.

## Impact

Every chat-history aspect run on this platform. The aspect either analyses instruction
text as if it were operator intent, or (as in this plan, where the running section
registry had no `chat-history-analysis` key) is dropped entirely — in both cases the
retrospective's only channel for operator-intervention signal reports nothing while
declaring itself healthy. Component: `plan-marshall:plan-retrospective`
(`scripts/extract-chat-signal.py`).

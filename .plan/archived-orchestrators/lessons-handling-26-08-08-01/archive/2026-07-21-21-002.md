# Root-module footprint (marketplace/targets/**) falls through the per-bundle quality-gate sweep un-gated

## Residual concern

`marketplace/targets/**` is production Python matched by a registered `build.map`
glob, but it belongs to no bundle — it is the multi-target generator, which lives
at the repo root and resolves to module `default`. The per-bundle
`pre-push-quality-gate` sweep therefore never lints it: the derivation surfaces
those paths in its `unresolved` list and emits a diagnosable `[WARNING]`, but the
warning explicitly says *"these are not gated as a bundle"* — the generator's own
production code still receives no local mypy/ruff pass before push.

Not-silent is not the same as gated. The remaining gap is a **coverage** gap, not
a derivation gap.

## Corrective action

**Give the root module a gate of its own.** Either add a `default` / root-module
target the per-bundle sweep can invoke, or have the step escalate to a whole-tree
`quality-gate` whenever the footprint touches a non-bundle module. The originating
run's manual workaround — running whole-tree `quality-gate` with no module argument
— is a strict superset of the per-bundle sweep and passed in 7s, so the escalation
path is known-cheap.

## Recurrence signature

A plan whose footprint includes `marketplace/targets/**` (or any other
`build.map`-matched path outside `marketplace/bundles/`) completes
`pre-push-quality-gate` green while those files were never linted. The
`[WARNING] ... resolved to no bundle` line in `work.log` names exactly the paths
that went un-gated.

## Recurrence — 2026-07-26 (test-suite-quality-unit-testing-residue) — the test tree, not just marketplace/targets

Hit again during the finalize of `test-suite-quality-unit-testing-residue`
(PR #1012, merged `ae0d8d79b`). Same signature, different un-gated paths:

```
[WARNING] (plan-marshall:pre-push-quality-gate) Footprint paths matched a
build_map glob but resolved to no bundle: test/conftest.py and
test/integration_common/__init__.py - proceeding, these are not gated as a bundle.
```

**What this recurrence adds — the un-gated set is not confined to
`marketplace/targets/**`.** The original framing treated the root generator as
the one known non-bundle production surface. Here the offenders are two files in
the **test tree** (`test/conftest.py`, `test/integration_common/__init__.py`), so
the real predicate is broader than the lesson's title implies: *any*
`build.map`-matched path outside `marketplace/bundles/` falls through, and the
test tree is a large, routinely-touched instance of that class. The "Recurrence
signature" section above already states the general form — the title and the
"Residual concern" prose should be re-read as `marketplace/targets/**` being one
example, not the definition.

**Aggravating detail:** both offending files were created or edited **by this very
plan** (deliverable D2's integration-tier revival). So a plan's own new files
landed in the gate's blind spot on the same run that created them — the coverage
gap is not confined to pre-existing untouched surfaces.

**Partial mitigation now in place (same plan, deliverable D4):** the pre-push gate
gained a whole-tree `test-compile` (`mypy test`) pass, which DOES type-check
`test/**` including these two files. So the mypy dimension of the gap is closed for
the test tree specifically. The **ruff and SPDX** dimensions of `quality-gate`
remain un-run for any path that resolves to no bundle — `test-compile` is mypy-only.
The corrective action above (a root-module target, or whole-tree escalation when the
footprint touches a non-bundle module) is therefore still open, now scoped to the
non-mypy dimensions.

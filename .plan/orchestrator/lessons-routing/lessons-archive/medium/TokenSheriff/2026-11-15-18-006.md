# The create-pr Test Plan must cite recorded execution evidence at the pushed HEAD, never a pass claim the step did not observe

The create-pr workflow must build the PR Test Plan only from recorded execution evidence at the pushed HEAD (execution-manifest `record-step` entries and the ledger-verified build for that HEAD, cited with command, HEAD SHA and outcome), and must write an explicit "not run by this step" line where no such record exists, never a pass claim.

## What happened

In plan client-refresh-verification-discovery-cache the create-pr envelope (12:43:37Z to 12:44:31Z, under a minute) wrote the PR #907 body. Its Test Plan ticked "Verification command passed" for `maven run --command-args "verify -pl token-sheriff-client -am"`. The create-pr agent had not run that command; the claim was carried over from earlier phase output, not observed by the agent that wrote it. The pre-push quality gate had completed at 12:43:04Z, so the command may well have been green at some point, but the body presented it as checked evidence and nothing tied it to a recorded run at the pushed HEAD. Two later fix commits (the cdc31c fix and TASK-011) then advanced HEAD past it.

## Why it matters

- A reviewer relies on the Test Plan; a pass claim with no recorded run behind it is a false-evidence defect.
- It is harmless only while the cited run matches the pushed HEAD, and it goes stale silently after a later fix commit.

## Rule

- Cite command, HEAD SHA and outcome from a recorded run, or write "not run by this step".
- Recheck the Test Plan when a later fix commit advances HEAD.

# Wall-clock boundary tests need wide margins and a cache-hit assertion before the boundary

## Problem

Two new cache-hit regression tests in `AccessTokenValidationPipelineTest` (plan-03, PR #833) had two weaknesses. The time margins were 1-3 s, so a 2 s stall before the priming call could expire the token early and fail the first assertion instead of testing the cache-hit rejection. And both passed if every cache lookup missed, because the uncached path rejects the token with the same event and counts it once.

## Solution

For tests that cross a wall-clock boundary, leave several seconds of margin before the priming call and keep the wait below the shared boundary-wait bound. When a test claims to cover the cached path, assert a valid cache hit (for example a hit counter of 1) before the boundary, so a regression that turns every hit into a miss fails the test. Generic for any test where the cached and uncached paths produce the same observable.

## Impact

Without the hit assertion the regression test does not protect the thing it is named for; without the margin it is flaky under load.

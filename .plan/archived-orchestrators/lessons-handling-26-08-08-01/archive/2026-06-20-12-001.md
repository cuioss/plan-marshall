# Phase-4-plan task descriptions drift from the deliverable outline by inventing CLI shapes not in the outline

When phase-4-plan derives `TASK-*.json` from the solution-outline deliverables, the
task `description` field is authored by the LLM as free prose. That prose tends to
embellish the deliverable's canonical command/flag shape with editorial,
plausible-but-wrong tokens that never appeared in the outline — inventing CLI
subcommands and flags by analogy rather than quoting the outline verbatim.

## Signature

During `phase-4-plan-adr-consultation` (a surgical, one-file doc plan that adds an
ADR-consultation hook to `phase-4-plan/SKILL.md`), the phase-4-plan Q-Gate raised one
`tip`/`warning` finding (`hash_id=85b465`):

> Description drift: TASK-1 uses structural token `--plan-id` not present in deliverable outline.
> Description mentions `manage-adr list --plan-id {plan_id}` but the deliverable outline uses
> `manage-adr scan --affects {module}` (no `--plan-id` flag). The flag was added editorially.

Two distinct drifts in one description:

1. **Wrong subcommand** — `manage-adr list` substituted for the outline's `manage-adr scan`.
2. **Invented flag** — `--plan-id {plan_id}` appended where the outline's `scan --affects {module}`
   form carries no `--plan-id`.

The description also asserted a spurious "Step-5 optional-skill-matching" claim absent from the
deliverable. The finding was caught-and-fixed in-run, so it surfaces only as a resolved-in-run
Q-Gate signal (the highest-value lesson class: slipped, then caught).

## Root cause

The task-description authoring step treats the deliverable text as a goal to paraphrase rather
than a contract to quote. When the deliverable references a `manage-*` command, the LLM reaches
for the *shape it remembers* for that script family (`list --plan-id …` is the dominant shape
across `manage-*` scripts) instead of the *exact shape the outline wrote* (`scan --affects …`).
This is the same invented-CLI-shape failure class that `dev-agent-behavior-rules` § "Never invent
script subcommands" warns about, but occurring one layer earlier — at task-description authoring
time rather than at call time.

## Corrective discipline

When phase-4-plan writes a `description` that references a `manage-*` (or any other) command:

- Quote the command/flag tokens **verbatim from the deliverable outline**. Do not normalize a
  `scan --affects {module}` reference into the more-familiar `list --plan-id {plan_id}` shape.
- Do not append structural flags (`--plan-id`, `--project-dir`, etc.) that the outline did not
  write — their presence/absence is load-bearing and varies per subcommand.
- Do not add claims (extra steps, optional behaviours) that the deliverable does not state.

The phase-4-plan Q-Gate `tip` rule that flags "structural token not present in deliverable
outline" is the existing automated guard for exactly this drift and correctly fired here — the
fix is to honour the outline at authoring time so the guard has nothing to catch.

## Impact

Description drift is warn-only (the task still executes), but a drifted description misleads the
executing agent about the canonical command shape, re-seeding the invented-CLI-shape failure
downstream. Quoting the outline verbatim at task-derivation time keeps the deliverable→task→call
chain consistent and prevents the drift from propagating into phase-5 execution.

## Recurrence — 2026-06-20 (call-time facet; finalize of the freshness-gate lint-only-exemption plan)

The **call-time** sibling of this authoring-time drift recurred at scale during one
full plan run (lesson `2026-06-15-20-003` → PR #720): **six distinct phase sub-agents
each invented a non-existent `manage-*` subcommand or flag at invocation time**, every
one an `exit_code=2 argparse_rejection` that bypassed the script body. An Explore
investigation of `marketplace/bundles/` + `.claude/` confirmed the **assumed source for
all six is agent improvisation — none of the wrong shapes appears in any workflow doc,
standards doc, or agent prompt** (item 5 below is the strongest case: the wrong shape is
*explicitly warned against* in the owning SKILL.md, yet the agent still tried it). So
there were **no doc-driven call sites to fix** — this is pure runtime invention.

| # | Phase / agent | Wrong shape | Canonical shape | Source |
|---|---------------|-------------|-----------------|--------|
| 1 | phase-2-refine | `manage-files path …` | one of `read/write/exists/list/…` (no `path` verb) | improvisation |
| 2 | phase-3-outline | `manage-status phase-handshake …` | separate script `plan-marshall:plan-marshall:phase_handshake capture/verify/…` | improvisation |
| 3 | phase-3-outline (qgate fix) | `manage-findings … --resolution-detail` | `manage-findings resolve … --detail TEXT` | improvisation |
| 4 | phase-4-plan | `manage-execution-manifest set-envelope-count` | `--envelope-count N` is a `compose` input flag, not a verb | improvisation |
| 5 | finalize-step-whole-tree-gate | `manage-plan-documents read …` / `request {plan-id}` | `manage-plan-documents request read --plan-id PLAN_ID` (doc explicitly warns against top-level `read`) | improvisation |
| 6 | ci-verify | `manage-ci-artifacts persist` (missing required args) | `persist --plan-id … --run-id … --head-sha … --pr-number … --provider …` | improvisation |

**Why this matters here:** this lesson is the *authoring-time, phase-4-plan-scoped* facet
(only item 4 above is phase-4-plan); the other five are call-time across five different
agents. The phase-agnostic owner of the call-time class is
`dev-agent-behavior-rules` § "Never invent script subcommands" (with its 4-signature
checklist).

**Disposition — accepted as noise (no action).** The six rejections are agent
improvisation with **no doc-driven call site to correct** (confirmed by source sweep),
so the only "fix" available would be a structural runtime guard (e.g. validating an
intended `manage-*` call against the executor mapping before issuing it). That is exactly
the overengineering [[feedback_fix_calls_not_runtime_guards]] rules out: when there are no
call sites to fix, the accepted disposition is to **treat the rejections as noise**, not
to build enforcement. They self-correct in-run (each agent retried with the right shape;
the plan shipped clean), and the hard rule already documents the recurrence signatures.
Recorded here once, as a recurrence on the nearest invented-CLI-shape lesson, so the
investigation isn't repeated — not as a backlog item.

# Strict phase handshake main_dirty invariant fails within seconds when concurrent orchestrator sessions write .plan/orchestrator/** on main

## Observation

While several orchestrator sessions (review-apparatus, truthful-signals, code-intelligence-substrate, …) were writing `.plan/orchestrator/**` on the main checkout, every `phase_handshake verify --strict` for plan `org-empty-review-guard-too-broad` failed with `main_checkout_dirtied_during_plan` (144 → 195 → 229 dirty files across minutes). The operator had to approve `capture --override --reason …` at every boundary, and each post-dispatch clean-main assertion had to be hand-scoped to exclude `.plan/orchestrator/**`.

## Impact

Git-tracked orchestrator ledger writes are routine and never a plan output, yet they make the strict gate unusable whenever an orchestrator session runs in parallel — the gate either blocks progress or trains operators to override it.

## Directive

Exempt `.plan/orchestrator/**` (ledger-owned, written by orchestrator sessions, not plans) from the `main_dirty` invariant and from the post-dispatch clean-main assertions, alongside the existing `main_dirty_exempted` inbox-archive paths — keeping every other path strict.

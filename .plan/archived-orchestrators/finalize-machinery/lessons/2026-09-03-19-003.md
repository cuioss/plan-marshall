# Make ci pr prepare-body reject a router-position --plan-id by name

## Context

Plan `always-on-is-not-a-resolve` recorded two argparse rejections against
`plan-marshall:tools-integration-ci:ci pr prepare-body`, both at
2026-09-03T17:38:29Z, with the stderr:

```text
usage: ci.py pr prepare-body [-h] --plan-id PLAN_ID [--for {create,edit}] [--slot SLOT]
ci.py pr prepare-body: error: the following arguments are required: --plan-id
```

The caller supplied `--plan-id`. It was consumed by the `ci` router, which reads
that flag before the provider subparser is built, so `prepare-body` — which
declares its own required `--plan-id` after the verb — never saw it and reported
it as missing.

## Root cause

`ci` declares `--plan-id` at two levels with opposite position requirements: the
router consumes it ahead of the first verb for the read verbs, while
`prepare-body` / `prepare-comment` declare a required `--plan-id` after their own
verb. Which position is correct depends on the verb, and the error message names
neither. This is documented by name in
`persona-plan-marshall-agent/standards/agent-behavior-rules.md` as recurrence
signatures 2 and 4, and it recurred anyway — documentation alone has not held.

## Proposed action

Make the failure self-correcting at the point it fires, the way the router's
mirror case already does: when a `prepare-body` / `prepare-comment` invocation is
missing its subcommand `--plan-id` **and** the router consumed one, reject with a
message that prints the caller's own invocation with the flag moved after the
verb. The router already holds the swallowed value, so the corrected form is
constructible without guessing.

A structural alternative worth weighing: stop the router from consuming
`--plan-id` when the resolved verb declares its own.

## Second verb, same split — merged from the same run

Message `always-on-is-not-a-resolve-009.md` recorded the same trap on a **second** verb minutes
later, and is folded here rather than filed separately:

```text
[17:38] ci.py pr prepare-body: error: the following arguments are required: --plan-id
[17:39] ci.py pr edit:         error: the following arguments are required: --plan-id
```

So the affected set is `pr prepare-body`, `pr prepare-comment` and `pr edit` — every
body-consumer verb — against the router-scoped read verbs (`checks` reads, `pr view`,
`pr list`, `pr wait-for-comments`). A pre-verb `--plan-id` is swallowed by the router and the
subparser then reports it missing, which is the observed message and is actively misleading:
the caller DID supply the flag.

⛔ The recurrence is the argument for fixing the message rather than the docs. This split is
documented by name in `agent-behavior-rules.md` (recurrence signatures 2 and 4) and was hit
twice in one run anyway — **including by the main orchestrator session itself**. A rule that
its own author violates while holding the document open is not going to be saved by restating
it more emphatically.

## Recurrence — 2026-09-18, plan-07-session-identity (folded from inbox -006, no new surface)

4 exit-2 rejections, one shape: a router-scoped flag appended after the verb (`ci checks
--plan-id`, `build_server preflight --plan-id`, `platform_runtime runtime-info
--plan-id`). Each retried in-band; none blocked the run. Callers guess the position; the
ci note states the rule (router flag before the verb) but nothing enforces it at dispatch
time. Proposal carried (unenacted): pre-dispatch argparse dry-run validator rejecting
misplaced router-scoped flags before execution, or a single documented placement table for
router-flag scripts. Expected surface unchanged by this fold (adds no file surface).

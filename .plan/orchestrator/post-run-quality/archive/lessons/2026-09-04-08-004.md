# Add a landed-commit tier to the footprint resolver for post-merge retrospectives

**Carried out of the `review-apparatus` epic inbox** — message `review-packs-become-published-artifacts-002.md`, sender `review-packs-become-published-artifacts`, promoted by the orchestrator drain of 2026-09-04.

## Context

Three retrospective aspects consume a realized footprint: `check-manifest-consistency`, `check-routing-decisions` and `check-outline-vs-shipped`. Each accepts `--diff-file` and otherwise recovers the footprint through the shared resolver's declared `RESOLVING_TIERS`.

On this plan every tier failed, because all of them are worktree-bound and the worktree no longer existed. `branch-cleanup` removes the worktree and prunes the branch refs, and it runs well before `plan-retrospective` at `order: 995`. The footprint had to be hand-built with a `git diff --name-only` against the squash-merge commit before any of the three aspects could produce a measurement rather than an `inconclusive`.

## Root cause

The finalize step ORDER guarantees the failure rather than making it incidental: the step that destroys the resolver's only evidence source runs before the steps that need it. The resolver has no tier that reads git history, so once the worktree is gone there is nothing left to resolve from — even though the landed content is permanently recorded in the merge commit.

The same condition was already visible at phase-4: `manage-execution-manifest compose` logged "pre_push_quality_gate_inactive — kept pre-push-quality-gate on an unknown build verdict: plan footprint unresolvable — no materialized worktree carries evidence of what this plan changed".

## Proposed action

Add a landed-commit tier to `RESOLVING_TIERS` that derives the footprint from the merge/squash commit recorded in plan status (the PR merge sha stamped at `branch-cleanup`), by diffing that commit against its first parent. This tier is the only one that still works after worktree removal and is also the correct tier for archived-plan audits, which have the same problem permanently.

Order the new tier after the worktree tiers so a live plan keeps its current behaviour.

## Evidence

- aspect: manifest_decisions — required `--diff-file`; `diff.base` reports `file:footprint.txt`, a hand-built input
- aspect: routing_decisions — `footprint_source: diff_file`
- aspect: outline_vs_shipped — `footprint_source: diff_file`; without it, `comparison` would be `inconclusive` and the three counted outcome classes withheld
- aspect: llm_to_script_opportunities — recorded as the highest-repetition scripting candidate for this run
- decision.log — phase-4 `compose` already recorded the unresolvable-footprint condition

# Scoped finalize plugin-doctor (touched-skills-only) misses a whole-tree rule violation that CI's whole-tree run catches

## Context

`finalize-step-plugin-doctor` runs the plugin-doctor quality-gate scoped to
the skills the plan touched, switching to whole-tree only "when a
plugin-doctor/plan-doctor rule changes or the scope read is indeterminate."
During the `marshall-orchestrator` run that promoted `agentfile-hygiene`
rules to build-failing (hardening-sweep, PR #910), a subsequent finalize run
in the same plan hit a divergence: the whole-tree plugin-doctor
`no-historical-prose-in-skills` rule fired **in CI** (the PR's whole-tree
run) but the local, scoped finalize step — bounded to the touched-skills set
— never surfaced it, so the lint issue reached CI red instead of being
caught before push.

## Root cause

The scoped/whole-tree switch is triggered by "a plugin-doctor/plan-doctor
rule changes," which correctly widens scope on a run where the rule itself
is edited. It does **not** widen scope for a run where a rule was *already*
build-failing (landed in an earlier commit within the same plan) and the
current commit's touched-skills set simply doesn't include the file that
trips it. The offending prose lived outside this run's touched-skills
computation, so the local scoped gate had no way to see it — the trigger
heuristic keys on "did I just change a rule," not "is a build-failing rule
active whose violations could exist anywhere in the tree regardless of what
I touched this commit."

## Corrective action (do X, not Y)

- **Do** widen the whole-tree trigger to also fire for the remainder of a
  plan once ANY commit in that plan has promoted a plugin-doctor/plan-doctor
  rule to build-failing — not just the commit that made the promotion. The
  scope-widening condition should be "a build-failing rule was added or
  changed anywhere in this plan's history," not "a rule changed in this
  specific commit's diff."
- **Do not** assume touched-skills-only scoping is safe once a plan has
  already flipped a filesystem-walking rule to build-failing — the newly
  gating rule's blast radius is the whole tree, not the plan's own diff, and
  every subsequent finalize run in that plan inherits that widened blast
  radius until the plan closes.

## Impact

A locally-green finalize run that still goes CI-red on structural lint
costs a review round-trip and erodes confidence in the scoped fast-path.
The fix is a one-line widening of the whole-tree trigger condition in
`finalize-step-plugin-doctor`, not a change to the underlying analyzer.

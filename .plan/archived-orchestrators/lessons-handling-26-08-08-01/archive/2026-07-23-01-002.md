# A gate that skips items lacking the very key it enforces (if key is None: continue) is vacuous for exactly the misconfigured items it exists to catch — the missing declaration must fail, not skip

A compose-time gate whose job is to enforce a property declared by a frontmatter
key must treat a **missing** declaration as a violation, not as a reason to skip
the item. When the guard is written `if step.mutates_source is None: continue`,
the steps most likely to be misconfigured — the ones that never declared the key
at all — are exactly the ones the gate cannot see. The predicate is vacuous for
its highest-risk input.

## Concrete incident

`_analyze_mutates_source_order.py` (the `mutates-source-step-post-merge-order`
plugin-doctor gate) resolves the merge-gate order dynamically and flags any
`mutates_source: true` finalize step ordered at/after the merge gate. It looked
correct, yet `finalize-step-preference-emitter` slipped through at `order: 80`
(after `branch-cleanup` at 70, which merges the PR) writing a tracked source
file (`.plan/project-architecture/default/enriched.json`). Its write could never
ride the plan's own PR — it landed as an uncommitted diff on main.

Two compounding root causes, both required to reproduce:

1. **Order defect** — a `mutates_source` step placed *after* the merge gate. Its
   output is physically unable to ride the plan's PR.
2. **Omission hole (the vacuous guard)** — the step's own doc declared no
   `mutates_source` key at all. The gate's `if step.mutates_source is None:
   continue` skipped it, so the gate that existed precisely to catch this
   misplacement never evaluated it. An absent key also defaults to read-only in
   the dispatcher's commit instrumentation (SKILL.md item 5f), so even at a legal
   order the write would have stayed uncommitted.

## Corrective action

- For any gate keyed on a frontmatter/config declaration, make the **absence** of
  the declaration a hard failure for the items in scope — do not `continue` past
  `None`. Require an explicit declaration (here: `mutates_source: true|false`) at
  minimum for every finalize step ordered at/after the dynamically-resolved merge
  gate. A defaulted-when-absent semantic and a gate that skips-when-absent
  together produce a silent, un-gated hole.
- Place any `mutates_source: true` finalize step **before** the merge gate
  (`branch-cleanup`) so its write commits onto the plan branch and rides the PR.
  The fix reordered `preference-emitter` from `80` to `61` (between
  `lessons-capture` 60 and `adr-propose` 62, still before `branch-cleanup` 70)
  and declared `mutates_source: true` explicitly.
- Invert any test that pins the defect. A regression test asserting the step must
  *follow* the merge gate encodes the bug as a contract; rewrite it to assert the
  invariant (the step runs *before* the merge gate) and add a test that a step
  omitting the key at/after the merge gate fails the compose-time check.

## Generalization

This is the recurring **vacuous-guard** archetype (predicate never fires for the
inputs it targets): saturated markers, scope_creep_check, roster-count, and now
the `None`-skip omission hole. Whenever a guard filters its own scope by the same
attribute it is meant to validate, verify the filter cannot exclude the failing
case — a guard that only inspects well-formed input is not a guard.

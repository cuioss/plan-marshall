# Rebasing after other PRs landed collided ADR numbering per directory

- Component: pm-mcp-core (module documentation, ADRs); process: plan-marshall:phase-6-finalize
- Suggested category: improvement
- Signal: plan-24-plan-instance, rebase after other PRs landed

## Observation

ADRs are numbered per directory (`{module}/doc/adr/{package}/NNN-{slug}.adoc`). The plan allocated its ADR
number while it ran. Other PRs landed on `main` meanwhile, and after the rebase the number was taken: `core-store/024`
had been used by #69, so the plan's ADR had to be renumbered to 028 (and every reference to it with it).

The number is chosen at authoring time against a snapshot of `main`; a long-running plan turns that snapshot
into a collision as soon as a parallel plan adds an ADR to the same directory.

## Suggested correction

- After a rebase onto a `main` that moved, list the ADR directories the plan touches and compare the numbers
  before resolving anything else. A collision is a renumbering, plus every cross-reference, the README index of
  the module and the developer guide that links the ADR.
- Check the ADR directories of `main` right before the PR is opened, not only at authoring time, and take the
  next free number then.
- Reference an ADR by its slug as well as its number in prose, so a renumbering touches one place.

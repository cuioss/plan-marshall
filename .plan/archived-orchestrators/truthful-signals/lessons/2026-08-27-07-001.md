# scope_creep_check can never fire: plan_creation_sha has readers and tests but no writer

## Problem

`phase-5-execute`'s `scope_creep_check` returns `could_not_look` / `no_baseline_sha` on **every plan**, so the scope-creep guard has never measured anything.

`references.json`'s `plan_creation_sha` has **readers and tests but no writer**. An inventory-wide sweep (`architecture search --content --pattern plan_creation_sha`, `files_scanned: 5248`, `unreadable: 0`, `truncated: false`) returned 10 occurrences across 5 files:

- 4 reads in `phase-5-execute/scripts/scope_creep_check.py`
- 2 in `phase-5-execute/SKILL.md`
- 4 across three test files (`test_scope_creep_check.py`, `test_scope_creep_could_not_look.py`, `test_qgate_persist_contract.py`)

Zero writers. `phase-1-init` Step 6 seeds `branch` and `base_branch` into `references.json` but never a creation SHA.

## Why it went unnoticed

The guard is **not** a false green. `could_not_look` is a designed, tested, fail-closed unknown state (ADR-009), pinned by `test_scope_creep_could_not_look.py`, and it correctly omits `residual_count` rather than publishing a zero.

That is precisely why it survived: **an honestly-reported unknown reads as benign**, so a guard that is 100% inert looks identical to a guard that had nothing to report. Every plan sees `could_not_look`, nobody reads it as alarming, and the check never fires.

## Consequence observed

During PLAN-TRUTH-114, `test/plan-marshall/manage-run-config/timestamp_render_classification.json` was committed by a deliverable-4 fix but declared by no deliverable, so it was missing from `references.affected_files`. That is exactly the residual `scope_creep_check` exists to catch — and it could not look. It surfaced only incidentally, from `baseline-reconcile`'s in-flight file list.

## Directive

Seed `references.json` `plan_creation_sha` at `phase-1-init` — the main HEAD SHA at plan creation is already captured by `phase_handshake` as `main_sha`, so no new resolution is needed.

If that is not done, state plainly in `phase-5-execute/SKILL.md` that `scope_creep_check` is inert until a writer exists, so its `could_not_look` is not mistaken for a check that ran.

## Archetype

Vacuous guard whose honest unknown state masks total inertness. An unknown that is *always* returned is a dead check, not a cautious one — a guard that can never reach its measuring path should say so, or be removed.

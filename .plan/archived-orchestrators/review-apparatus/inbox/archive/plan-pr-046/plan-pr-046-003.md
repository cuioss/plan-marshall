# Permission-prompt aspect returns an empty list from a channel that cannot carry prompts

component: plan-marshall:plan-retrospective
category: bug
confidence: high

## Context

The permission-prompt-analysis aspect is declared conditional on a `--session-id` being present, and one was present for this plan. Its only reachable input is the reduced transcript produced by `extract-chat-signal`, which on this run kept 5 turns out of 1810. The reduction's documented predicate keeps operator-authored turns and gate decisions recovered from the tool-result channel. A permission prompt is neither, so it cannot survive the reduction under any circumstances. The aspect therefore always has an empty prompt population to report, and its natural output — `prompts[]` empty, no findings — is indistinguishable from a plan that genuinely raised no prompts.

## Root cause

The aspect's declared input (the session transcript, per its Inputs section) and its actually-reachable input (the reduced transcript) are not the same artifact, and the reduction filters out precisely the class of turn this aspect exists to find. The skill correctly forbids the aspect from reading a raw session JSONL, so there is no fallback channel — the aspect is structurally unable to observe its subject while still being dispatched as though it can.

## Proposed action

Either give the aspect an input that can carry prompts — a prompt-bearing counter or a prompt-retaining reduction mode on `chat extract-signal`, keyed separately from the operator-provenance predicate — or make the aspect declare `coverage: not_evaluated` unconditionally with a reason, so a zero is never rendered as a clean pass. The second is the smaller change and closes the false-clean immediately; the first is what makes the aspect useful again. Do not leave it emitting a bare empty list.

## Evidence

- aspect: permission_prompt_analysis — `coverage: not_evaluated`, prompts list empty because the population was never examined
- aspect: chat_history_analysis — `raw_turn_count: 1810`, `reduced_turn_count: 5`, `operator_turn_count: 5`, `gate_decision_count: 5`
- reference: chat-history-analysis.md — the reduction's operator-provenance predicate is owned by the platform-runtime `chat extract-signal` contract

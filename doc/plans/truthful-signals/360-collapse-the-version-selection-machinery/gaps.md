## G1 — Widen the D6(d) marker-write guard beyond its single AST shape

- **Kind:** missing-test
- **Severity:** high
- **Where:** `test/plan-marshall/tools-script-executor/test_marker_free_resolution.py:238` — `_writes_marker` (consumed by `test_no_production_source_writes_the_shared_marker` at `:269`)
- **What is wrong:** the detector flags a `write_text`/`write_bytes` call only when the `.orphaned_at` string literal sits inside that call's own target expression — i.e. exactly `(version_dir / '.orphaned_at').write_text(...)`, the shape the deleted `_mark_superseded_version_dirs` used. Both detectors were **executed** on the same six synthetic shapes (the current `_writes_marker`, and `analyse_source` from the retired module recovered via `git show d01edfdf^:…`); the result table is:

  | shape | current `_writes_marker` | retired `analyse_source` |
  |---|---|---|
  | `(version_dir / '.orphaned_at').write_text(…)` — the pre-fix shape | caught | caught |
  | `marker = version_dir / '.orphaned_at'` … `marker.write_text(…)` | **missed** | caught (`_assigned_alias` / `_check_alias_uses`) |
  | `(d / ORPHAN_MARKER_NAME).write_text(…)` | **missed** | **missed** |
  | `open(version_dir / '.orphaned_at', 'w')` | **missed** | caught (`_CONTENT_PARSE_CALLS`) |
  | `(version_dir / '.orphaned_at').touch()` | **missed** | **missed** |
  | a write inside an emitted-code template string constant | **missed** | caught (`_embedded_code_tree` descent) |

  So the replacement lost **three** shapes the retired test caught — alias-bound, `open()`, and template-embedded — and both detectors miss the named-constant and `.touch()` spellings. The named-constant spelling is not hypothetical: `_plugin_pin_trap.py:554` writes `marker = entry / ORPHAN_MARKER_NAME` (alias **and** named constant in one), and the detector's own host file writes markers that way at `test_marker_free_resolution.py:86`, `:95`, `:112` — three writes inside the very module that asserts no write exists, invisible to its own detector because the fixtures spell the marker as `_MARKER_NAME`.
- **Why it matters:** report-01.md § Deliverables D2 states the retired test's "no marker write" guarantee is "**re-established, not dropped**". It is not. A reintroduced marker write in any of five plausible spellings — including inside `_CLAUDE_RESOLVER_TEMPLATE`, the constant whose body ships into every generated executor on every user machine — passes CI green. That is a guard that reports a guarantee it does not enforce, which is the exact class this epic exists to catch.
- **Fix:** in `_writes_marker`, (1) resolve alias bindings — when a `.orphaned_at` path expression is assigned to a `Name`, treat `write_text`/`write_bytes`/`touch`/`open(..., 'w')` on that name within the same scope as a write; (2) resolve module-level string constants whose value is `.orphaned_at` so `ORPHAN_MARKER_NAME`- and `_MARKER_NAME`-style indirection is covered; (3) add a template descent — for each module-level `Assign` whose value is a string Constant containing `.orphaned_at`, `ast.parse` that string and run the same detector over it, labelling hits with the enclosing constant's name. Items (1) and (3) can be ported from `d01edfdf^:test/plan-marshall/script-shared/test_orphan_marker_existence_only.py` (`_assigned_alias` at `:338`, `_check_alias_uses` at `:348`, `_embedded_code_tree` at `:366`, `_template_label` at `:387`); item (2) and `.touch()` coverage must be **written new** — the retired module missed both, so a verbatim port alone does not close them. If the fixtures at `:86`/`:95`/`:112` are left spelled via `_MARKER_NAME`, exclude the test tree from the production sweep explicitly rather than relying on the detector's blindness to it. Add a negative-control test asserting the detector flags each of the five currently-missed shapes on synthetic source (the retired test had one at `:793`).
- **Done when:** a unit test over synthetic source asserts `_writes_marker` returns a hit for the alias-bound, named-constant, `open()`, `.touch()`, and template-embedded shapes, and `test_no_production_source_writes_the_shared_marker` still passes over the real tree.
- **Module/topic:** `plan-marshall` / `tools-script-executor` — marker-free resolution test suite.

The staleness is residue rather than a defect introduced here: the docstring was written by #1213 (`git log -S` on the phrase returns `4ac41326` only) and was accurate then; #1223 invalidated it without touching the file. Separately, `:368-372` still raises `SHAPE_1_SATURATION` ("repair before the fuse burns") as a `fail`-contributing GC exposure, though our resolver no longer consults the marker at all, so saturation can no longer affect which version a session loads. Left as is, a detector that exists to catch false-green pin states carries a stale model of the code it audits, and escalates a condition — full marker saturation — that after #1223 is a pure foreign-GC observation with no bearing on load safety. - **Fix:** rewrite the `loader_selected_version` docstring (`:270-275`) to state the actual post-#1223 model and to **name its own approximation**: the real selector picks the numerically-newest dir satisfying a caller-supplied *eligibility* predicate and never consults `.orphaned_at`, while `VersionDir` carries only `name` and `marked` and cannot evaluate eligibility — so this function models newest-*overall*, an upper bound on the selector's answer, and diverges from it exactly when the newest dir on disk is ineligible. Then re-rank `SHAPE_1_SATURATION`: keep it as a reportable GC-exposure observation but demote it out of the "repair before the fuse burns" tier (`:106`) and out of the load-safety `fail` conjunct, since the loader no longer reads the field. Update the module docstring at `:2-44` accordingly, and rename/re-comment the two stale tests at `test/pm-plugin-development/plugin-doctor/test_plugin_pin_trap.py:268-271` and `:274-277` (e.g. `test_loader_ignores_marker_on_the_newest_dir`, `test_loader_with_every_dir_marked_still_returns_newest`) — their assertions and fixtures stay as they are.

## G6 — Restore a non-vacuity floor to the D6(d) population sweep

- **Kind:** vacuous-test
- **Severity:** medium
- **Where:** `test/plan-marshall/tools-script-executor/test_marker_free_resolution.py:269-287` — `test_no_production_source_writes_the_shared_marker` (population built at `:276` from `_SOURCE_GLOB`, `:36`)
- **What is wrong:** the test iterates `_BUNDLES_ROOT.glob(_SOURCE_GLOB)`, collects offenders, and asserts `not offenders`. Nothing asserts that the population is non-empty, that it contains the files the marker actually lives in, or how large it is. **Demonstrated by mutation:** with `_SOURCE_GLOB` changed to `'**/skills/**/scripts-NOPE/*.py'` — a pattern matching zero files — all six tests in the module still pass (`6 passed in 0.15s`). The file was confirmed clean with `git diff --quiet` before the edit and restored from a byte snapshot afterwards (`git diff --quiet` exit 0). The retired `test_orphan_marker_existence_only.py` had this floor explicitly: `TestPopulationIsNonVacuous` (`d01edfdf^:…:514-540`) asserted a non-empty population *and* that it contained both code consumers and docstring-only mentions, and `_population_summary` (`:453`) published the file count in every assertion message so "it can never pass vacuously from an empty scan". That guarantee was dropped with the file and not replaced.
- **Why it matters:** this is the failure mode the plan's own D6(c) exists to forbid one level down — a check that always finds *something* is bad, and a check that always finds *nothing* is worse, because green is the answer it reports. A broken `_BUNDLES_ROOT`, a renamed `scripts/` convention, a future glob narrowing (G4 is one that already happened), or a `conftest` change to `PROJECT_ROOT` all silently reduce the sweep to zero files, and the suite reports the D6(d) guarantee as enforced. verification.md's own "the guard is **not vacuous**" reads on the current tree only; it is not a property of the test.
- **Fix:** in `test_no_production_source_writes_the_shared_marker`, bind `population = sorted(_BUNDLES_ROOT.glob(_SOURCE_GLOB))` and add, before the offender assertion: (1) `assert len(population) >= 300, …` (a floor well under the 412 the recursive glob yields, so ordinary bundle churn does not trip it); (2) `assert {p.name for p in population} >= {'marketplace_bundles.py', 'generate_executor.py', 'cache_retention.py', '_plugin_pin_trap.py'}` — the four files that mention the marker today, so the sweep provably reaches the marker's actual sites; and (3) include `len(population)` in the offender assertion's message. Add one companion test asserting the population is non-empty and naming the count, mirroring `TestPopulationIsNonVacuous`.
- **Done when:** setting `_SOURCE_GLOB` to a pattern that matches no files makes the module **fail**, and the unmutated module still passes.
- **Module/topic:** `plan-marshall` / `tools-script-executor` — marker-free resolution test suite.

# Three sites named the wrong shared function as api_init's write path

Source: Q-Gate finding f7022f (6-finalize; fixed in 8acc3c607).

Three sites — save_module_document, _save_module_document, and
architecture-persistence.md — all claimed api_init calls save_module_document. It does
not: it calls sync_module_index directly.

## Solution

One false claim, mirrored three times, with no single site that a reader could check the
other two against. The structural lesson is that a "who calls whom" claim about a shared
persistence helper is exactly the kind of statement that drifts silently, because nothing
executes it. Where three sites restate one call graph, at most one should state it and
the others should point at that one.

## Impact

Compounded with the neighbouring writer-enumeration drift in the same document (see
finding 488191), the persistence contract described a call graph the code did not have.

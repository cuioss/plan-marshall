## Objective

Make the reviewer read each repository's own declaration at run time — and make that declaration
**opt-in**, so a repository that says nothing keeps exactly the review it has today.

## What was VERIFIED FIRST-PARTY at staging (2026-09-14)

Three facts, each read rather than recalled, because the whole plan rests on them:

- ⛔ **The consumer side does not exist yet.** `cuioss-organization`'s
  `reusable-pr-agent-review.yml` (pinned here at `v0.27.0`) contains **ZERO** references to
  `project.yml` or to `packs/` — grep count 0 over the whole file. Its own header states that tuning
  lives centrally in `pr-agent-settings/.pr_agent.toml`, *"NOT here"*.
- ⭐ **The producer side is complete.** `cuioss/pr-agent-settings` `main` now carries `packs/` — eight
  artifacts, 12,534 bytes total (`spine.md` 2,847 B; `plugin.md` 2,413 B; `docs.md` and `reqs.md`
  728 B each) — landed by `PLAN-PR-065` D1/D10.
- ⚠ **This repository's `pr-agent:` block is therefore INERT CONFIGURATION**: it declares
  `packs: [python, plugin]` and nothing reads it. A declaration with no consumer is indistinguishable
  from an absent one, which is what makes the enable flag below meaningful rather than cosmetic.

⭐ **Generation needs no LLM and is not in scope**: the packs are a deterministic derivation
(`## Enforcement` bullets harvested per domain, capped at `MAX_DOMAIN_RULES = 12`), regenerated by CI
on every qualifying push. This plan changes **consumption only**.

## Operator rulings (settled at staging — do not re-litigate)

1. **An enable flag in `.github/project.yml`. Absent ⇒ DISABLED.** No repository is opted in by a
   deployment.
2. ⛔ **Disabled means "the charter it has today", NEVER "no charter".** The flag governs whether
   **pack-based assembly** applies — it is not a switch that can leave a repository reviewed against
   nothing. That is the one correction made to the proposal, and it is the same rule the spine already
   enforces one level down.
3. **The spine stays unselectable.** `packs:` names domain artifacts only; a project can neither
   select nor deselect the spine, which is why `additional_rules` is append-only.

**D7 — The enable flag, with absent meaning disabled.** Extend the `pr-agent:` block with an `enabled`
key and make the workflow branch on it. ⭐ **Shape it exactly like the existing `sonar.enabled` key in
the same file** — the convention is already in `.github/project.yml` and a second spelling for the same
idea is a defect, not a choice. Semantics, stated as a closed set so no fourth state is invented:

| Declaration | Behaviour |
|---|---|
| no `pr-agent:` block | **disabled** — today's central `.pr_agent.toml` charter, unchanged |
| `pr-agent:` present, `enabled` absent | **disabled** — same as above. ⛔ Absence is never consent |
| `enabled: false` | **disabled**, explicitly |
| `enabled: true` | **pack assembly** — D1–D5's path |

*Done when:* all four rows are exercised by a test, a repository with no block reviews exactly as it
does today, and ⛔ **no configuration reachable through this key can produce a review with no charter**
— pinned by a negative control, not by reading the branch.

**D8 — This repository is the pilot, and its block is the reference example.** `plan-marshall`'s own
`.github/project.yml` gains `enabled: true` beside its existing `packs: [python, plugin]`, and one real
pull request is reviewed through the assembled charter with the composed text visible in the run log
(D5's surface). *Done when:* the log shows the spine plus both selected packs, and the review that
lands is demonstrably the assembled one rather than the central file.

**D9 — Roll out by DERIVED population, opting in deliberately.** Using D0's enumeration, record for
every repository on the reviewer workflow: whether it declares a block, and whether it opts in.
⭐ **The rollout is cheap precisely because absent means disabled** — no repository needs a change to
keep working, so the fan-out is opt-in per repository rather than a fleet migration. *Done when:* the
report names every repository in the population with its state, and every opt-in is one reviewed
change, not a sweep. ⛔ **Do not enable a repository whose domain packs nobody has read** — an
unreviewed charter switch is the failure mode this plan exists to avoid.

⛔ **Boundary — names the upstream tool reads itself STAY**: `.pr_agent.toml`, the `PR_REVIEWER.*` /
`VERTEXAI.*` env keys, the container image, and the tool's own output markers (e.g. `## PR Agent
Walkthrough`). Test-local Python identifiers that name the TOOL whose output they parse (`pr_agent`
variables, `test_…_pr_agent` names in the automatic-review / workflow-integration-github /
review-retrospective suites) also stay — they describe the software, not the identity, and renaming them
buys nothing but collisions with sibling plans. Historical records (`doc/analyzis-cloud-plan/`) are
records and stay.

⛔ **No silent break for existing declarations** — the `bot_kind` rename (#1392) invalidated consumer
config fleet-wide with no propagation mechanism, and this must not repeat. A legacy `pr-agent:` block
found by the workflow is **reported loudly** (a run-log error or a failed check — warn-vs-fail chosen at
outline), never read as "absent ⇒ disabled", because that would silently discard a declaration its
owner believes is live. The same D0 population names every repository carrying a legacy block.

*Done when:* a whole-tree search of every owned surface above returns no `pr-agent` naming outside the
stated boundary (derived, with the population searched — `.github/**` included, see Claim Labels); the
renamed repository, workflow and label resolve for every repository in D0's population; and a legacy
`pr-agent:` block is exercised by a test that shows the loud report.

**D12 — Rewrite the settings repository's documentation as it is today (operator direction, requested
at `PLAN-PR-065` and never delivered).** ⛔ **This is a REWRITE, not a relocation.** `PLAN-PR-065` D6
specified moving sections into `doc/` "**verbatim**" — which contradicts the actual ask and is why it must
not be re-used as the brief. The ask, stated by the operator:

1. **Remove all historic content.** No learnings logs, epoch narratives, experiment histories, retracted
   reasoning or "we tried X" passages. Document the repository **as it is**, per the documentation
   standards (current state only, no version history, no timestamps).
2. **Decompose the monolith into a `doc/` module.** Topics get their own documents.
3. **`README.adoc` becomes an overview** — what the repository is, what it contains, how a consumer uses
   it — and **references** each `doc/` document by an explicit link rather than restating it.
4. **`.pr_agent.toml` carries configuration, not narrative** (carried from `PLAN-PR-065` D8, also never
   delivered): rationale and history in its comments are removed or, where still true and useful,
   rewritten into the relevant `doc/` document.

Written under the repository's final name (D11), so it is authored once. D10's consumer page is one of
the `doc/` documents. ⭐ A binding decision that still governs behaviour is current state, not history —
keep it, stated as the rule, without its derivation story.
*Done when:* `README.adoc` is an overview that links every `doc/` document; no document in the repository
carries historic narrative (verified by reading, and by the absence of dated/epoch/learnings sections);
every statement is true of the repository at the landing commit; and `.pr_agent.toml`'s comments
describe configuration only.

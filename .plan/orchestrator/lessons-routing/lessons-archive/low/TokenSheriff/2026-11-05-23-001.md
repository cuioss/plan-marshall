# Fix a documentation-wording defect as one sweep per statement shape, not one occurrence per review round

## Problem

Plan-22 (PR #863) was a documentation-wording plan and finalize converged slowly. Each review round (functional review, code review, security audit, bot review) fixed the one occurrence of a statement shape it had found, and the next reviewer found the next occurrence of the same shape (for example "cleared" / "rethrown unchanged" / "the rule covers every path"). The decision log shows the loop-backs: set-phase 6-finalize -> 5-execute at 13:15, 13:53, 14:36, 15:54, 17:14, 18:08, 18:39, 20:28 and 21:12 on 2026-11-05, with fix tasks TASK-15 to TASK-28 added one wave at a time.

A second cause: each round's review scope was a delta over the last commit only (round_kind=delta, deliverables in scope 3 then 7, files in scope 31). A statement outside the delta (class Javadoc versus method Javadoc, ADR Risks bullet versus ADR Decision, older ClientLogMessages Javadocs) was only found one round late, and several were finally left as advisories (decision-log entries at 17:38, 20:56, 21:44).

## Solution

When a review finds a defect in a documentation statement, treat the finding as a statement SHAPE, not an occurrence. Write one sweep task per shape, and put the sweep into the fix-task description: list every surface to check (operator docs, ADR Decision and Risks sections, class Javadoc and method Javadoc, LogRecord description templates, test comments and assertion messages, commit-message-derived PR text) and say how the surfaces are enumerated (a content search for the key words, e.g. "cleared", "unchanged", "every", "always"). Mark the sweep done only with the list of hits and what was done to each.

Do not let a delta-scoped review be the only check of a sweep: widen the next review round to the full set of files the sweep touched, or re-read the class-level text of every class a method-level fix touched.

## Impact

The slow convergence cost nine finalize loop-backs on a single docs-and-tests plan. A shape-level sweep up front bounds the loop count by the number of distinct statement shapes rather than the number of occurrences.

# Check required-bot PR size caps before create-pr and split by dependency, not by file group

## Context

PR #1691 (plan `cross-repo-telemetry-archive-and-analyze`) carried 151 files. Required reviewer
CodeRabbit refused it outright on its 100-file cap; optional Sourcery refused on its
150,000-character cap. The refusal surfaced only AFTER `push`, `create-pr` and `ci-verify` had
already run, so the whole pre-PR chain was paid before anyone learned the PR was unreviewable.

The operator chose a split. #1691 was closed unmerged, part 1 (#1692) was cut as a cherry-pick of
the test-mirror deletion, and part 2 (#1694) carried the remainder. Part 1 then needed **two extra
fix commits**, because the still-registered era-stamp step's `verdict_inputs` and a live import kept
two of the mirror files (`test_audit_check_era_model.py`, `_audit_fixtures.py`) alive — they could
not be deleted in part 1 at all and shipped in part 2 instead. The run cost `create-pr` twice and
`ci-verify` three times.

## Root cause

Two independent gaps:

1. **Nothing compares the planned footprint against the required bots' published size caps before a
   PR is opened.** The caps are known and published; the footprint is known from `phase-4-plan`
   onward. The check simply does not exist, so the cap is discovered by refusal.
2. **The split was cut by file group rather than by dependency.** "All the test files" looks like a
   clean seam and is not one: files still referenced from the other part — registered step
   `verdict_inputs`, imports, fixtures — cannot leave in the earlier PR.

## The rule

Before `create-pr` — or better, at `phase-4-plan`, where the footprint is already known — compare
the in-repo changed-file count and total diff size against each **required** bot's cap. When a cap
would be exceeded, propose the split up front rather than after the refusal.

Then validate the proposed cut before committing to it: **no path in part 1 may still be referenced
by code that only changes in part 2.** Check registered step `verdict_inputs`, imports and test
fixtures specifically — those are the references that a by-file-group split misses, and each one
costs a fix commit on an already-open PR.

⛔ A cap refusal from a *required* reviewer is not a review comment to triage — it is a structural
block that no amount of re-review clears, so it must be designed around, not retried.

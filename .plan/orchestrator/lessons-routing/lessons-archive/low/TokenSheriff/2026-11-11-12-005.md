# Write control, separator, blank and bidi code points in test literals as unicode escapes, never as the raw character

## Problem

`InsufficientScopeChallengeParserTest` held raw U+2028 (LINE SEPARATOR) characters inside Java string literals (`shouldEscapeDescription` and `shouldEscapeLineSeparatorInRealm`, lines 244 and 254 at the PLAN-26 merge), and the new Unicode-blank tests added in PLAN-28 used a raw U+2003 literal. Raw separators and blanks are invisible in a diff and in review, and they break line-based tooling: the raw U+2028 in the base file is the likely cause of the test-integrity parsing artefact that reported 27 phantom assertion removals three times in PLAN-28 (the cause is the lane's inference, not reproduced). Q-Gate finding 3c578d (functional-review residual D8.R1); fixed by TASK-018, which escapes each one.

## Solution

Write test literals for control, separator, blank and bidi code points as `\uXXXX` escapes, never as the raw character. A review or a guard test can search for the escape; nobody can see the raw character. Consider a repository check (a grep or a guard test over `src/test`) that fails on raw U+2028, U+2029, U+0085 and the bidi controls U+202A to U+202E and U+2066 to U+2069 in Java sources.

## Impact

A defect class that is invisible by construction, produced a false integrity finding three times and one fix task.

# A closure invariant that checks completeness never checks correctness

## What happened (motivating instance — now CLOSED; the rule below is not)

`phase-6-finalize/standards/dispatch-inline-split.md` declares itself the single source of truth
for which finalize steps dispatch and which run inline. It classified
`default:architecture-refresh` as **dispatched** — wrongly: the step's own doc said inline, and
gave the binding mechanism (Tier-1 `prompt` mode requires `AskUserQuestion`, which a dispatched
leaf cannot fire).

The roster was guarded by `test/plan-marshall/phase-6-finalize/test_dispatch_roster_closure.py`,
which was **green throughout**. Every assertion it carried was a **completeness** property —
coverage of the registry, roster disjointness, absence of count claims, dispatch-branch
accounting. None was a **correctness** property. The test could prove each step had exactly one
classification and never that the classification was right, because it never read the step's own
standards doc — the document carrying the actual mechanism.

The divergence survived three independent observations. On the third, an executing plan hit the
contradiction mid-finalize and resolved it by **counting documents** (two say inline, one says
dispatched) rather than by the precedence the SSOT doc itself declares. It reached the correct
behaviour by the wrong method: applying the stated SSOT-wins rule instead lands on `dispatched`,
i.e. on a configuration where the documented Tier-1 prompt mode is unreachable.

**This instance is fixed** — the roster now classifies the step inline with its mechanism, and the
closure test gained a derived, mutation-guarded cross-document assertion comparing each step doc's
own self-classification against the roster. ⚠ **The instance closing does not close the class.** The
anti-pattern below is a general verification-design rule and remains fully live everywhere else: no
sweep has audited the codebase's other closure/completeness guards for the same blind spot.

## Why it matters

A green closure test reads to every subsequent maintainer as "this split is settled." The stronger
and more thorough the completeness guard looks, the more confidently it launders an incorrect
entry. Coverage guards are cheap to write and feel like verification; they are inventory.

The failure is invisible by construction — the roster is internally consistent, matches the
registry, and is fully covered. Nothing in the guarded artifact disagrees with anything else in the
guarded artifact. The contradiction lives **between** documents, which is exactly where a
single-document invariant cannot look.

## How to apply

- When a document declares itself a single source of truth, ask what test would fail if one of its
  entries were **wrong** rather than **missing**. If the answer is "none," the SSOT is unguarded no
  matter how green its coverage test is.
- A classification whose ground truth lives in another document needs a **cross-document**
  assertion. Derive the comparison over the whole population; never hand-write a pin per step (a
  hand-maintained mirror of a derived set is its own recurring defect).
- Treat a single discovered mismatch as a **sample**, not the finding. Derive the population before
  patching the instance.
- When two documents contradict and one claims precedence, resolving by majority vote is not
  resolution — it discards the precedence rule the system actually documents. Escalate the
  contradiction instead of silently picking a side; a reader who follows the stated rule will reach
  the opposite conclusion.

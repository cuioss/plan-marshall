title: "CodeRabbit rate_limit_eta_patterns miss the 'Next included review available in N minutes' wording, so a stated ETA reads as unknown"
content: "## Problem

CodeRabbit refused a review on PR #1425 with a notice that **states its own reset ETA**:

```text
Review limit reached … Next included review available in 59 minutes …
You've used all free OSS reviews for now.
```

The producer nonetheless reported `eta: \"\"`. The three `rate_limit_eta_patterns` in
`marketplace/bundles/plan-marshall/skills/automatic-review/standards/coderabbit.md` all require
wording this notice does not use:

```text
- \"wait ([0-9]+ minutes? and [0-9]+ seconds?) before requesting another review\"
- \"wait ([0-9]+ (?:minutes?|seconds?|hours?)) before requesting another review\"
- \"([0-9]+ (?:minutes?|hours?)) before (?:the )?(?:rate )?limit resets\"
```

This is **not** `refusal_pattern_drift`. The `refusal_patterns` arm matched correctly on
`\"Review limit reached\"`, so the refusal itself was recognised. Only the ETA extraction failed.

## Why it matters

An empty `eta` is indistinguishable from *\"the notice stated no ETA\"*, when in fact the notice
stated one and the registry could not read it. The consequence is operational, not cosmetic: the
rate-window recovery's Branch 2 omits `--window-seconds` when the ETA is unknown and claims a
default-length window instead of the stated 59 minutes. The claimed window is then a guess wearing
the shape of a measurement, and a wait sized from it can under- or over-shoot the real reset.

The same shape as the surrounding plan's subject: a value that was never established renders
identically to one that was established as absent.

## Directive

Add a pattern covering the observed wording, e.g.:

```text
- \"Next included review available in ([0-9]+ (?:minutes?|hours?))\"
```

Do not stop at the one string. Establish which reset-notice wordings CodeRabbit actually emits and
whether the three existing patterns still match any of them — a registry whose patterns match no
current wording is worse than one with a known gap, because each miss is silent.

Separately, consider whether an ETA the extractor could not read should be distinguishable from an
ETA the notice did not state. They are different facts, and the consumer currently cannot tell them
apart.

## Verification

Assert against the real notice text, not a synthesised one: a fixture carrying the verbatim
`Next included review available in 59 minutes` line must yield `eta: \"59 minutes\"`. Add a matched
negative — a refusal notice genuinely carrying no ETA must still yield the empty value — so the test
proves the extractor discriminates rather than merely that it fires."

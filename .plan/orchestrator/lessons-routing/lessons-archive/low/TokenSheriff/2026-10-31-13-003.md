# Installed scripts lag the skill docs: check a verb against --help before calling it, never invent or paraphrase one

## Problem

Agents follow the loaded skill docs and call verbs or flags that the installed scripts do not register, so each call fails with an argparse rejection (exit 2). Seen in this repo: `pre_merge_gate record-merge` and `consequence-text` (the `branch-cleanup` docs name them; only `merge` is registered); `review_completeness roster` (rejected six times in one plan; registered: check, deficit, size-caps, trigger-bot); `ci pr list --state merged` (valid: open, closed, all); `manage-findings query` (the read verb is `list`); `manage-findings pr-comment` (use `list --type pr-comment`); `manage-config effort resolve-target --step` (undeclared flag); `ci_complete_precondition resolve` and `ci_verify run` missing required flags; `architecture --plan-id P search --content` (cause unconfirmed: the failure marker keeps only the argv, not the argparse error). A recovery action also returned `close_and_reopen` where the doc says `generate_trigger`, and the executor drift probe returned `drift=unknown`.

## Solution

Before calling a verb the docs name, check it against `--help` of the installed script. Never invent a subcommand or paraphrase a flag value from GitHub CLI habits. When a documented verb is missing, record the step through the sanctioned fallback (`mark-step-done` with the same facts) and report the gap. Tooling fixes to consider: keep installed scripts and skill docs in step, and make the failure marker for every notation record the raw argv and the argparse error text.

## Impact

Wasted calls and retries in every plan, steps recorded through a workaround, and no trace of the real cause for some rejections.

# Finalize footprint and self-review surfacer diff against local main, which is stale after the branch is rebased onto origin/main


## Observed (API-Sheriff, plan-23-session-route-scope-parity, 2026-10-01)

`finalize-step-sync-baseline` rebased the branch onto `origin/main` (6bb90765, nine upstream
commits). The local `main` ref of the main checkout stayed at 48fa7d0a, one commit behind, and was
deliberately not fast-forwarded by the run (another session may be using that checkout).

The tools that run after the rebase still diffed against the local ref:

- `compute-footprint` reported 85 files against `base_ref=main`. Seven of them were files of the
  upstream commit #367 that the plan never touched. The plan's real change surface was the 78 files
  `baseline-reconcile` had reported (decision 5f755a).
- The self-review candidate gate measured `files_in_scope=87` against the same stale ref, and 3 of its
  32 candidates sat in those upstream files (decision e36622).

The orchestrator noticed the mismatch by comparing the two counts and handed the review steps the
78-file surface and `origin/main` by hand. Nothing in the tool output flagged it.

## Root cause

The diff base is the branch name `main`, resolved locally. After a rebase onto the remote tip the
branch contains commits that the local `main` does not, so every upstream commit in between is counted
as the plan's own change.

## Directive

- Footprint and surfacer tools should diff against the commit the branch was last rebased onto (the
  merge base with `origin/{base}`), not against the local branch ref. `sync-baseline` already knows that
  commit and could record it for the later steps.
- When the local base ref is behind its remote, report it instead of computing a footprint from it.
- Until the tool changes: after `sync-baseline` reports `action=rebased`, pass `origin/main` as the
  diff base to every later finalize step, and compare the footprint count with the `in_flight_files`
  count from `baseline-reconcile` before trusting it.

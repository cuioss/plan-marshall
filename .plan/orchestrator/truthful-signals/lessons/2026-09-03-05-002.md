# self-review --base-branch resolves against local main, overstating files_in_scope by every unpulled upstream commit

## Observation

The pre-submission-self-review surfacer's default `--base-branch main` resolves against the
**local** `main` ref, not `origin/main`. In a finalize run the local ref is routinely behind:
`finalize-step-sync-baseline` (order 3) rebases the worktree onto `origin/main` without
moving local `main`, so every commit absorbed by that rebase re-enters the diff as if it
were the plan's own work.

Observed on plan `misconfigured-reviewer-name-reads-missing-review` (PLAN-PR-044): the
surfacer reported `files_in_scope: 82` when the plan's own footprint was **34**. The other
48 were the absorbed upstream commit `80da16e30` (#1383, a parser-derived-namespace test
refactor), already merged on main.

## Why it matters

Two costs, one of them silent:

1. **Wasted review.** The reviewer adjudicated ~2.4x the files it needed to. Most of the
   `touched_claims` and `user_facing_strings` volume, and the sole `source_of_truth` entry,
   came from already-merged content.
2. **A confident wrong number.** `files_in_scope` is reported in the step's own return and
   reads as the plan's surface. Nothing in the output distinguishes "this plan touched 82
   files" from "this plan touched 34 and the diff base is stale". Both self-review rounds on
   this plan reported 82.

The reviewer caught it both times only because it partitioned the footprint against the
upstream SHA by hand. That is not a property of the tool.

## Directive

Resolve the diff base against `origin/{base_branch}` rather than the local ref — the same
ref `finalize-step-sync-baseline` rebases onto, so the two agree by construction. Failing
that, report both figures (`files_in_scope` and a base-relative `plan_footprint_count`) so
a stale base is visible in the output instead of having to be inferred. A scope figure that
cannot be wrong in a detectable way is the shape this repo keeps finding defects in.

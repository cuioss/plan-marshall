# A derived population still needs the non-vacuity guard, because this repo has re-introduced that gap inside its own fixes

Source: PR #1489 CodeRabbit inline finding ac4d0e (resolution=fixed, TASK-040).

test_documented_verb_set_drift_population.py:347 declared a literal set of six
_mod.SKIP_* constants while `_mod` was already imported at the assertion site. If the
analyzer adds a skip reason the current tree does not reach, the test stays green with an
incomplete vocabulary. The authoritative population was reachable in-process, so no new
registry was needed.

## Solution

Derive the set via a `vars(_mod)` walk filtered on the SKIP_ prefix and str values —
AND keep the non-vacuity assertion:

    assert declared, 'the analyzer declares no SKIP_* vocabulary'

That guard is not optional. A derived population that can come back EMPTY is the
vacuous-guard archetype this repository has re-introduced inside its own fixes for that
archetype before. Deriving a set replaces one failure mode (stale literal) with another
(silent empty) unless the emptiness is asserted against.

## Impact

Pairs with the capabilities-table finding; together they define the cheap-derivation case
and its mandatory guard.

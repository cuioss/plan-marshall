# A multi-throwing assertThrows lambda slipped every local gate and was caught only by server-side Sonar analysis (java:S5778)

## Observation

New test code added by plan `parameter-value-linebreak-carve-out` —
`cui-http-core/src/test/java/de/cuioss/http/security/validation/DecodingStageTest.java:1546` — put
more than one possibly-throwing invocation inside an `assertThrows` lambda. Sonar flagged it on
PR #239 (finding `59814c`, `java:S5778`, MAJOR/CODE_SMELL): "Refactor the code of the lambda to have
only one invocation possibly throwing a runtime exception."

The defect was caught and fixed inside the same run — the wait-region triage opened TASK-006, phase
5-execute was re-entered (loop-back iteration 2 of 3), the fix landed as commit `1faa0bd`, and the
finding resolved `fixed`. Net cost: one full loop-back cycle through execute and the whole
settle-plus-wait band again.

## Why this is lesson-bearing

Every local gate passed the code first:

- TASK-004 and TASK-005 verification builds: green
- phase-5 final quality sweep: pass
- `verify -Ppre-commit` (whole tree, 8116 module tests): green
- pre-push quality gate: `outcome=done`
- pre-submission self-review: `outcome=done`

Only the server-side Sonar analysis caught it. The rule is a well-known JUnit 5
assertion-precision rule: a multi-throwing lambda inside `assertThrows` means the assertion cannot
prove WHICH call threw, so the test asserts less than it appears to — a false sense of coverage
that reads correctly on inspection.

## Corrective

When writing `assertThrows`, keep exactly one possibly-throwing call inside the lambda; hoist setup
calls out ahead of it. This makes the assertion prove what it claims. This rule is cheap to state
up front in the JUnit test-authoring standard and cheap to check locally (a grep for multiple method
calls inside an `assertThrows(...)` lambda body is a plausible local detector) — a local catch here
would have saved an entire loop-back iteration, one of the plan's three.

## Scope

Any test authored under `pm-dev-java-cui:cui-http-testing` conventions using `assertThrows`.
Candidate home: the JUnit core/CUI testing standard's assertion-authoring section, alongside
existing AAA-pattern guidance.

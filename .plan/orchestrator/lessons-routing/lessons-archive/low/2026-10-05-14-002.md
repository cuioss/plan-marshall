# mark-step-done rejects ambiguous short SHAs; resolve the full SHA first

`mark-step-done --head-at-completion <short-sha>` was rejected with `unknown_head_at_completion`, forcing a re-issue with the full SHA. The resolver (`_cmd_mark_step.py:_resolve_head_to_commit`) runs `git rev-parse --verify {sha}^{commit}`: unambiguous abbreviations resolve, but ambiguous ones (and blobs, trees, fabricated strings) fail — and the failure reads exactly like a wrong SHA, so the caller cannot tell "ambiguous" from "wrong".

## Solution

Callers must resolve the full SHA (`git rev-parse HEAD`, not `--short`) before passing `--head-at-completion`. The step docs that construct this call should say "full SHA" explicitly.

## Impact

Every `mark-step-done --head-at-completion` call built from a short SHA. One failed call plus a re-issue per occurrence.

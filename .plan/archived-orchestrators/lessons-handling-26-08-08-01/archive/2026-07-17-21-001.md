# Lazy self-triggering migration on a read path must contain EVERY failure its side effects raise - rename races (FileExists/FileNotFound/EEXIST, EXDEV fallback) and persist OSError alike - never propagating into the credentials-resolution boundary

When a plan moves machine-level state to a machine-global home root (this plan
introduced `~/.plan-marshall/` and migrated the credentials directory), the
migration is performed **lazily at first-touch** rather than by a one-shot
installer. That means the migration code runs inside every session, CLI
invocation, and (eventually) `marshalld` daemon — i.e. concurrently. A migration
implemented as a bare `os.rename(old_dir, new_dir)` (or `shutil.move`) is a
classic check-then-act race: two processes can both observe the old dir present
and the new dir absent, then both attempt the move. The loser crashes with an
unhandled `FileExistsError` / `FileNotFoundError` / `OSError` — a hard failure at
the very boundary (credentials resolution) that must never fail.

Every in-house gate was green (module-tests, quality-gate, verify). The race is
invisible to the single-process test harness because nothing exercises two
migrators against one home root at once. Only the adversarial PR review bot
(gemini-code-assist, HIGH) flagged it on PR #923 at `_providers_core.py:309`.

## Root cause

A first-touch lazy directory migration under a *shared* root is inherently
concurrent, but was written as if it owned the filesystem exclusively. The
"already migrated" terminal state was only reached by the happy path, not by the
lost-race path — a lost race is functionally identical to "already migrated" and
must resolve to the same successful outcome, not an exception.

## Rule — do this instead

A lazy directory migration under a machine-global (multi-process) root MUST treat
a lost race as success and MUST handle cross-filesystem moves:

```python
try:
    os.rename(str(old_dir), str(new_dir))
except (FileNotFoundError, FileExistsError):
    # Lost race: a concurrent migrator already moved old_dir or created new_dir.
    return 'already_migrated'
except OSError as exc:
    if exc.errno in (errno.EEXIST, errno.ENOTEMPTY):
        return 'already_migrated'
    elif exc.errno == errno.EXDEV:
        # Cross-filesystem: shutil.move copies then removes the source only
        # after a successful copy. Re-guard the same race exceptions.
        try:
            shutil.move(str(old_dir), str(new_dir))
        except (FileNotFoundError, FileExistsError):
            return 'already_migrated'
        except OSError as move_exc:
            if move_exc.errno in (errno.EEXIST, errno.ENOTEMPTY):
                return 'already_migrated'
            raise
    else:
        raise
```

Key points:

- `FileNotFoundError` and `FileExistsError` both mean "another migrator won" —
  return the already-migrated result, do not raise.
- `EEXIST` / `ENOTEMPTY` are the same lost-race signal surfaced as a raw `OSError`.
- `EXDEV` is NOT a race — it is a cross-device move (home on a different mount);
  fall back to `shutil.move`, and re-guard the identical race exceptions there
  because `shutil.move`'s internal rename hits the same window.

## Impact

Applies to any first-touch/lazy state migration that will run under the new
machine-global root, and directly to Rung 2 (`marshalld`), where multiple
concurrent sessions plus the daemon guarantee simultaneous first-touch. Add a
concurrent-migration test (two migrators, one root) — a single-process test can
never reproduce this class.

## Recurrence — 2026-07-22 (credentials-key-normalization, PR #978)

Second instance, same module and same seam family, different OS-failure class —
and this time the new migration was written *explicitly modelled on* the one this
lesson was filed against, yet reproduced its containment gap.

The plan normalized `credentials_config` keys in `marshal.json` and added
`_migrate_credentials_config_keys_if_needed()` to `_providers_core.py`, a lazy
self-triggering migration on the `credentials_config` access path. Its docstring
names the precedent verbatim — *"Mirrors the `_migrate_credentials_home_if_needed`
precedent in this module: guarded, self-triggering ... idempotent, and
**best-effort**"* — but the `_save_marshal(config)` call on the `migrated` path
was left unwrapped. `read_provider_config` catches only
`(json.JSONDecodeError, KeyError)`, so a genuine `OSError` (disk full, read-only
FS, permission denied) from that persist would propagate straight out and convert
a previously resilient read — which degrades to `{}` — into a hard crash at the
credentials-resolution boundary. Same terminal property as the original instance:
the boundary that must never fail, made to fail by an unguarded side effect on
the migration path.

Same slip signature as the original: every in-house gate green (quality-gate,
module-tests, whole-tree plugin-doctor, pre-submission self-review reporting
"28 candidates examined"), caught only by the CodeRabbit PR review, then fixed
in-run under the loop-back TASK-007 (wrap the persist in `try/except OSError`,
warn to stderr, still return `'migrated'`).

### Generalized scope — containment, not just race-safety

The original framing was *race*-safety (`FileExistsError` / `EEXIST` / `EXDEV` on
a concurrent rename). This instance widens the rule to the general property that
framing was a special case of:

**A lazy, self-triggering migration that runs on a read path must contain EVERY
failure its side effects can raise — not only the concurrency-derived ones — and
must return one of its declared status values rather than propagating. The read
path's own `except` tuple is not a safety net: it is narrow by design and was
written before the migration was grafted onto it.**

Operational checks when adding or reviewing such a migration:

- Enumerate every side effect on the migration path (rename, write, persist,
  chmod) and confirm each is individually guarded — a guard on the *primary*
  side effect does not cover a second one added later.
- When a docstring advertises **"best-effort"**, that word is a contract: read
  the code for an unguarded call before accepting the claim. An advertised
  resilience property contradicted by the implementation is the cheapest possible
  review catch and should never reach a PR bot.
- Re-read the caller's `except` tuple. Grafting a migration onto an existing
  resilient read silently widens the exception surface that caller must absorb.
- Mirroring a precedent means mirroring its **containment surface**, not just its
  trigger/idempotence shape — the cross-cutting sibling-invariant family recorded
  in lesson `2026-06-30-20-001`, here recurring inside this module.

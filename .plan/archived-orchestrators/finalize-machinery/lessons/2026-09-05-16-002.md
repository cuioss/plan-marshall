# 2026-09-05-16-002 — A down daemon silently removes cross-plan build serialization, so concurrent suites exhaust memory and the harness kills them

component: plan-marshall:manage-build-server
category: bug
status: moved-to-epic (OPEN — staged in PLAN-06; corpus original retained until that plan ships)
source: corpus lesson 2026-09-05-16-002, copied into finalize-machinery per operator direction

## Context

Two full builds killed for memory pressure ~4h apart; top consumers were sibling plans'
`pytest -n auto` workers. Root cause one level deeper: `marshalld unreachable since
11:08:41Z, 4 builds degraded to in-process` — with no daemon there is no build queue,
so nothing serialized concurrent full suites. The fallback is designed to keep a single
plan working; what it silently drops is the cross-plan property no single plan can
observe. Per-build INFO routing lines never state the consequence; repeat suppression
quiets it further. Trap found while recovering: starting the daemon from a worktree
resolves a binary path that vanishes at finalize — start from main.

## Proposed action

Escalate the message class (state what was lost: no queue, no cross-plan
serialization); do not suppress repeats before heavy builds; ping liveness before
orchestrator-tier builds; consider a machine-local advisory lock as fallback's fallback.

# Surefire -Dtest takes comma-separated classes; a plus-joined list matches no test and fails the build

## Pattern

A deliverable's verification command named several test classes as `-Dtest=ClassA+ClassB+ClassC`. Surefire does not read `+` as a separator. It treats the whole value as one pattern, matches nothing, and fails the build with "No tests matching pattern". That looks like a test or compile failure. It is a malformed command.

## Rule

- Separate classes in `-Dtest` with commas: `-Dtest=ClassA,ClassB,ClassC`. A method goes after `#`: `-Dtest=ClassA#method`.
- Write verification commands in the outline and the plan with commas from the start, so execute does not inherit the wrong form.
- A "No tests matching pattern" failure is a command error. Fix the selector before you change any code.
- Leave `-Dsurefire.failIfNoSpecifiedTests=false` off unless the `-pl` target has upstream modules with their own tests (see CLAUDE.md, Targeted test). If it is set, a wrong selector runs zero tests and passes.

## Provenance

Observed in plan `fix-four-audit-findings-and-bff-flaky-test` (PR #385). The deliverable verification commands used the plus-joined form and had to be rewritten with commas in execute.

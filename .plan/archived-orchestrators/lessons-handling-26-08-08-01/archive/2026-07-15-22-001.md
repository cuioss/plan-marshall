# Best-effort cleanup in a finally block must swallow its own exception or it masks the primary operation's failure

The `upgrade-regen-safety` plan hardened `generate_executor.py` with an
atomic write-replace path (write to `{name}.tmp`, then `os.replace` onto the
real executor) guarded by a `py_compile` self-check, so a malformed
generation can never overwrite a working executor. The initial implementation
performed the tmp-file cleanup as a bare `unlink` sitting after the
write/replace. All in-house gates (module-tests, quality-gate, whole-tree
verify) passed. Only the review bot (gemini-code-assist, PR #908 inline at
`generate_executor.py:838`, fixed via TASK-012) flagged that if the cleanup
`unlink` raised — e.g. because the tmp file had already been moved by
`os.replace`, or was unlinkable — that cleanup exception would propagate and
**mask the real exception** from the primary write/replace it was meant to be
cleaning up after.

## Rule

When adding best-effort cleanup (`unlink`, `close`, temp-artifact removal) in
a `finally` (or trailing `except`) block after a primary operation, the
cleanup call itself MUST be exception-swallowing so it can never mask the
primary operation's failure. Wrap the cleanup in a narrow `try/except` that
catches the cleanup-specific error class and passes:

```python
tmp_executor = real_executor.with_name(real_executor.name + '.tmp')
try:
    tmp_executor.write_text(content, encoding='utf-8')
    os.replace(tmp_executor, real_executor)
finally:
    try:
        tmp_executor.unlink(missing_ok=True)
    except OSError:
        pass
```

Do **not** leave a bare `tmp_executor.unlink(...)` as the last statement of the
protected region — a cleanup failure there overwrites the traceback the caller
needs to diagnose the actual write/replace failure.

## Why it slipped

The masking only manifests when the primary op fails *and* the cleanup also
fails — a two-fault path no unit test exercised, so every in-house gate stayed
green. This is the recurring "only the PR bot caught it" robustness class: the
happy path and single-fault paths are covered, but the cleanup-masks-primary
interaction is invisible to coverage-driven in-house verification.

## Scope

Applies to any script author adding atomic write-replace, temp-file, or
resource-teardown cleanup in this repo's script surface — not just
`generate_executor.py`. Distinct from `2026-07-08-09-001` (unlink-before-copy
through a stale symlink): that defect is about *what* gets written; this one is
about a cleanup exception *masking* the primary write's exception.

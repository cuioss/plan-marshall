# A test that drives production code which prunes a shared temp root can delete the running session's own tmp_path

## What happened

`test_build_cmd_coverage.py` captures the argv that `build.py`'s `cmd_coverage`
hands to pytest. To do that it calls `cmd_coverage` for real, with only `run`
and a couple of path resolvers stubbed. `cmd_coverage` also calls
`_prepare_session_basetemp`, which prunes the shared
`.plan/temp/pytest-basetemp/` root — the exact root the pytest session executing
the test is writing into.

The prune walks newest-first and stops at the first session directory it cannot
measure inside the remaining entry budget, retaining nothing past that point. A
live session that has already grown beyond `PYTEST_BASETEMP_MAX_ENTRIES` is
therefore unmeasurable, retains zero, and is itself `rmtree`d. Every subsequent
`tmp_path` / `tmp_path_factory.mktemp` in that run raises `FileNotFoundError`.

## Why it was invisible

The damage is a function of **when** the module runs, not of what it asserts.
Early in a session the live root is still small and survives the prune, so the
test passes and nothing is lost. Late in a session it does not. Under default
collection order this module runs early, so the suite was green for a long time
with the hazard fully present.

Reverse collection order moves it to the end, and the same unchanged test then
took out roughly 1500 later tests with setup errors — attributed, at the point
of failure, to whichever tests happened to run afterwards. The blast radius
lands nowhere near the cause, which is what made it expensive to find.

## The rule

When a test invokes production code for a side effect it wants to observe, ask
what **else** that code does before deciding what to stub. Argv capture wants
the argv; it does not want the filesystem work performed on the way there.
Specifically:

- A production function that prunes, rotates, or garbage-collects a **shared**
  directory must be stubbed by any test that calls it, unless that pruning is
  the subject under test. "Shared" includes any path the running test session
  itself uses — a temp root, a cache, a log directory.
- Put the stub in the **single helper every sibling test goes through**, not in
  each test. Four assertions here each built their own stub stack, three of them
  without the prune stub; the shared capture helper is what makes it impossible
  to reintroduce the unstubbed call by copying a neighbour.
- Reach for the pure part when there is one. The per-session basetemp path is
  derived from pid and uuid and needs no filesystem at all, so the capture never
  had a reason to touch disk.

## The detection signal

Codified, and no longer carried here: the order-moving failure set, the two
symptoms (mass setup-time `FileNotFoundError`; a failure count that differs
between two runs of the same tree), and the `PM_TEST_ORDER=reverse` standing
check now live in `plan-marshall:persona-module-tester`
`standards/testing-methodology.md` § "Restore Captured State on Both Arms, Never
Under a Presence Check" → Detection signal.

What remains open is **The rule** above — stubbing production code that prunes a
shared directory — which no standard states and no check enforces.

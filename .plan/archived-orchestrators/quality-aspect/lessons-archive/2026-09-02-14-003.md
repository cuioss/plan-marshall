# The user_facing_strings detector cannot see a module docstring or an `async def` docstring, so those sites survive every round

## The defect

`_detect_user_facing_strings` emits a `docstring` candidate only for a triple-quote
line that IMMEDIATELY FOLLOWS a `def` or `class` line. In
`marketplace/bundles/pm-plugin-development/skills/ext-self-review-plan-marshall/scripts/_self_review_detectors.py`
(lines 157-174) the emission is gated on `prev_def_or_class`, and the only thing that
sets that flag true is:

```python
if _DEF_OR_CLASS.match(content):
    prev_def_or_class = True
    continue
```

A **module-level docstring follows no `def` and no `class`** — it is the first
statement in the file. `prev_def_or_class` is therefore False when its triple-quote
line is reached, and the site is never emitted. It is not scored low, not truncated,
not deduplicated away: it is structurally unreachable.

## Second reach gap in the same predicate

`_DEF_OR_CLASS` in `_self_review_patterns.py:37` is:

```python
_DEF_OR_CLASS = re.compile(r'^\s*(def|class)\s+\w+')
```

It does not match `async def`. The sibling pattern on line 159 of the same file,
`_DEF_OR_CLASS_HEADER`, does (`r'^\s*(?:async\s+def|def|class)\s+\w+'`), and three
other detectors use that one. So a coroutine's docstring is invisible to this
detector for the same reason a module docstring is. This is live, not latent —
`manage-build-server/scripts/marshalld.py` carries six `async def` sites.

## Evidence it costs real rounds

Plan `domain-over-provision` ran seven self-review rounds over one change set. Two
module docstrings carried the same false universal through all of them and were each
caught only by manual reading:

- `test/plan-marshall/manage-config/test_cmd_domain_detect.py:9` — Q-Gate finding
  `192b91`, round 5. Its own note: *"a module-level docstring is structurally
  invisible to the user_facing_strings detector, which requires a triple-quote
  following def/class — a reproducible surfacer gap."* That one site survived five
  rounds.
- `test/plan-marshall/manage-config/test_cmd_domain_detect.py:7` — Q-Gate finding
  `3bc8c3`, round 6, the residue of round 5's partial deletion of the same paragraph,
  which restates the point.
- `_cmd_domain_detect.py:18` (`1d785c`, `3ae5bb`) and `_cmd_domain_detect.py:7`
  (`065a1e`) are module docstrings in the same cohort.

A module docstring is among the highest-value contract statements in a Python file —
it is where a module's invariants get asserted, and it is exactly where a stale
invariant hides. The detector's declared purpose (`prose_contract` family) covers it;
only the implementation does not reach it.

## Proposed fix

Both gaps close in the predicate, not in the emission logic:

1. Emit a triple-quote line as a `docstring` candidate when it is the first statement
   of a `.py` file, not only when it trails a `def`/`class`. A `module_docstring`
   context value would keep the two distinguishable downstream.
2. Have `_detect_user_facing_strings` use `_DEF_OR_CLASS_HEADER` rather than
   `_DEF_OR_CLASS`, matching the three sibling detectors and picking up `async def`.

The second is a one-token import change. Note that the two patterns coexisting in one
module, differing only in `async def` coverage, is itself the kind of near-duplicate
this surfacer's own `source_of_truth` family exists to flag.

The list of intentional cross-module test pairings in this repository.

== Who reads this list

The module-mapping check of the plan-time quality gate reads the table below. That check expects a task's test file and the implementation file it covers to belong to the same architecture module, and reports a pair whose modules differ. A row here tells it that one such pair is intended. The check, the shape of a row and the rule by which a row covers a pair are defined in link:../../marketplace/bundles/plan-marshall/skills/plan-marshall/workflow/q-gate-validation.md[`q-gate-validation.md`] § 2.11 Module-Mapping Validator; this document holds only the data.

A row is warranted when a test must live in one module while it reads files owned by another. It is not a way to silence a finding about a test that was placed in the wrong directory: such a test is moved, not listed.

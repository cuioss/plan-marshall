# Compare assertions before deleting a duplicate test; a weaker survivor is not a cover

## What happened

The plan removed duplicate test pairs. For each pair one test was deleted and the other was declared the covering test. In commit 70273c4f (TASK-6, 21 pairs in the validation module) a test in `BaseTokenContentTest` was removed in favour of `TokenContentTest#shouldGetClaimByName`. The removed test asserted equality of the whole `ClaimValue`; the surviving test compared less. `TokenContentTest.java` was listed as read-only in the plan, so the task did not strengthen it, and the deletion shipped with a weaker assertion.

The gap was not found by the task, by its build, or by the before/after JaCoCo comparison: line coverage was identical, because both tests execute the same code. It was found afterwards and fixed in a separate commit (cc9c4854) on operator instruction, which restored the whole-`ClaimValue` equality in the surviving test (decision log 2026-10-09T19:49:42Z, work log 2026-10-09T19:52:12Z).

## Rule

Before deleting a test as a duplicate:

1. Put the assertions of both tests side by side. The survivor must assert at least everything the removed test asserts.
2. If the survivor asserts less, carry the missing assertions into it first, in the same commit as the deletion.
3. If the survivor is read-only for the task and asserts less, stop and report. Do not delete.
4. Do not use identical coverage as proof. Coverage shows which lines ran, not what was checked.

## Scope

Applies to every duplicate-removal or test-consolidation change in any module, not only `token-sheriff-validation`.

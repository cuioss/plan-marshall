# Unsorted filesystem traversal feeding analyzer or discovery output is non-deterministic across runs, no in-house gate catches it and only the PR bot does

`enumerate_skill_files()` in `marketplace/bundles/pm-plugin-development/skills/tools-marketplace-inventory/scripts/_dep_index.py` iterated `base_path.rglob('.claude-plugin/plugin.json')` directly and emitted one `SkillFile` per discovered bundle in raw filesystem order. `Path.rglob` (like `glob`, `iterdir`, `os.listdir`, `os.walk`) returns entries in filesystem-dependent order — the order is not guaranteed and varies across machines, filesystems, and runs. Because this sequence feeds the plugin-doctor analyzer input, the analyzer could process bundles — and therefore emit findings — in a different order on different runs, making output non-reproducible and any order-sensitive comparison or golden-file diff flaky.

## Detection

No in-house gate caught it. `module-tests`, `quality-gate`, and `verify` all passed during PR #808 (plan `plugin-doctor-framework-refactor`) — none of them exercise cross-run ordering stability, so a non-deterministic traversal is invisible to them. The CodeRabbit review bot flagged it as a functional-correctness finding ("Sort bundle discovery before iterating. `base_path.rglob(...)` can yield bundles in filesystem-dependent order"). It was remediated in-run by wrapping the traversal in `sorted(...)`. This is the same slipped-then-caught defect class as the determinism bugs in `2026-06-24-14-003` (ranking/scoring needed a deterministic tie-break; in-house verify missed it, only the review bot caught it) — but the mechanism here is filesystem-traversal order, not tie-break order.

## Corrective action

Do X instead of Y:

- **Y (avoid):** iterating the raw result of a filesystem-traversal primitive — `Path.rglob`, `Path.glob`, `Path.iterdir`, `os.listdir`, `os.walk`, `os.scandir` — when the resulting sequence feeds analyzer output, discovery enumeration, report generation, or anything whose output order is observable or compared. Filesystem order is not stable.
- **X (do):** wrap the traversal in `sorted(...)` at the iteration site, e.g. `for plugin_json in sorted(base_path.rglob('.claude-plugin/plugin.json')):`. Sort on a stable key (the path itself is fine for `Path` objects). This makes the emitted sequence — and every downstream artifact derived from it — deterministic across runs and machines.

The fix belongs at the discovery/traversal site, not downstream: sorting once at enumeration guarantees a single deterministic order for every consumer, whereas a downstream `sorted()` only fixes that one consumer and leaves siblings exposed.

## Impact

Affects every discovery/enumeration helper in the plugin-doctor + marketplace-inventory framework that walks the bundle tree to build analyzer input. Any unsorted `rglob`/`glob`/`iterdir`/`os.walk` whose output is observable is a latent non-determinism bug that no local gate will catch. Audit traversal sites in discovery code and sort at the source; treat "feeds analyzer/discovery/report output" as the trigger to add `sorted(...)`.

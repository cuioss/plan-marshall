title: Sourcery budget-exhaustion refusal is filed as review feedback and credits the bot as participated
content: "## Problem

Sourcery answers a review request it cannot serve with a `review_body` comment declining it:

```text
you've used your own review budget of 250,000 diff characters for the last 7 days.
You can request another review in 2 days and 19 hours by commenting `@sourcery-ai review`.
```

That phrasing is not in sourcery's `refusal_patterns`, so the producer classified it as ordinary
review feedback. On PR #1384 it was **stored as a `pr-comment` finding** (`c590d4`) and sourcery was
**credited in `participated_bots` as `sourcery,review_body`**, with every refusal channel reporting
empty:

```text
count_skipped_refusal: 0
refused_bots[0]:
unrecognised_refusal[0]:
refusal_pattern_drift[0]:
```

So the participation guard read `sourcery: participated` for a bot that had explicitly declined to
review, and a decline entered the findings store as feedback to triage.

## Why it matters — a false-clean quorum

On this PR the damage was bounded: `required_bots=pr-agent` and sourcery was optional, so the quorum
did not depend on it. **Had sourcery been in `required_bots`, the merge barrier would have read a
satisfied quorum over a diff sourcery never looked at** — a confident participation signal covering
an unasked question, which is exactly what the participation guard exists to prevent.

Note the guard's own contract already disclaims review *quality* (`proves: participation_only`). This
defect is one level below that: not \"participated but reviewed poorly\", but \"did not participate and
was recorded as having participated\".

## The unrecognised-refusal channel did not fire either

`unrecognised_refusal[]` and `refusal_pattern_drift[]` are the surfaces meant to catch a refusal whose
phrasing the registry does not know. Both came back empty, because classification never reached them —
the comment matched no refusal pattern at all, so it fell through to the ordinary-feedback path rather
than to the drift-reporting one. **A refusal the matcher does not recognise is currently
indistinguishable from a review**, and the channel designed to make it distinguishable is downstream
of the match it never gets.

## Directive

Add the budget-exhaustion phrasing to `refusal_patterns` in
`marketplace/bundles/plan-marshall/skills/automatic-review/standards/sourcery.md`, with a `quota`
cause and the `rate_limit_class` that suits a multi-day window — the recovery ladder must NOT treat a
\"another review in 2 days and 19 hours\" window as awaitable, so `hard_quota` (escalate, never wait) is
the likely fit rather than an awaitable window.

Then address the structural half, which is the more valuable one: **a bot comment that matches no
refusal pattern currently proves nothing about whether it is a review.** Consider a positive
review-shape test (does the body carry findings / a verdict?) so that a non-matching, non-review-shaped
body routes to `unrecognised_refusal` instead of being credited as participation. Without that, every
future refusal phrasing any bot invents lands in the same false-participation path, and the registry
can only ever catch the phrasings someone already wrote down.

Derive the blast radius rather than assuming this is sourcery-only: check each registered bot's
`refusal_patterns` against its provider's current decline phrasings. This one surfaced because it
happened to fire on an optional bot in a run that was watching; the same gap on a required bot is
silent by construction.

Related: [[project_pr_agent_third_reviewer]] records that only `ci pr comments` is evidence of
participation — this lesson narrows that further: a comment's PRESENCE is not evidence its CONTENT was
a review."

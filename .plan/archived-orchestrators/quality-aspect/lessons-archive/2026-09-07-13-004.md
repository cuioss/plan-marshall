# A retired references key is still named as a step input, and its documented fallback is unavailable at that order

## Context

Observed on plan `plan-04-autonomy-gate-defaults` (epic `operator-ux`, PR #1437) and, per the
reporting step, on **all three runs it was measured over**.

`finalize-step-lessons-housekeeping` Step 3 names `references.modified_files` as its input. That key
was retired with the change-ledger, so the read returns `field_not_found` every time. The step's
documented fallback is the retrospective report — which does not exist at that order, since the
retrospective runs later in the finalize sequence.

**Both documented inputs are simultaneously unavailable by construction**, so the step has no
reachable input at all and has never had one since the retirement.

## Root cause

A key retirement removed the producer and left every consumer's documentation naming it. The
fallback was authored without checking the order it would be read at, so the recovery path is
unreachable for the same structural reason the primary is.

⛔ Nothing failed loudly: `field_not_found` is a soft outcome, the fallback silently produced
nothing, and the step reported normally three runs running.

## Proposed action

1. Give the step a reachable input — either restore an equivalent produced before its order, or
   re-point it at the realized footprint `manage-references` already captures at branch-cleanup.
2. A retirement is not complete until every documented consumer is re-pointed; a grep for the
   retired key at retirement time is the cheap check that was not run.
3. Where a step has a primary and a fallback, assert at authoring time that the fallback is
   produced at an EARLIER order than the step that reads it. A fallback later in the sequence is
   not a fallback.

## Impact

Three measured runs with a step doing nothing while reporting normally. The wider point is the
retirement discipline: this key's consumers were never swept, so any other consumer of
`references.modified_files` is in the same state and nobody has looked.

⚠ Filed under `plan-marshall:manage-references` — the retired key's owner and where the retirement
sweep belongs. The *reading* step is the project-local `finalize-step-lessons-housekeeping`, which
the lessons store refuses as a foreign bundle (`error: wrong_store`); that refusal is correct and
was not overridden.

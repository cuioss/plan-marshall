# execution.md's termination-cause block is fixed but still unguarded by any documented-set contract test

## Closed — the argparse half

`baseline_drift` is a member of `DISPATCH_TERMINATION_CAUSES` in `manage-metrics.py`, and the manage-metrics restatement sites moved with it in the same change: the `record-dispatch-boundary` command block, the bullet list and the Canonical-invocations block in `manage-metrics/SKILL.md`, the `termination_cause` enum in `manage-metrics/standards/data-format.md`, and the cause enumeration in `plan-retrospective/references/logging-gap-analysis.md`. A drift return no longer fails at `exit_code: 2`, and the boundary row is written.

## Closed — the execution.md block

`plan-marshall/workflow/execution.md`'s inline `record-dispatch-boundary` Bash block now offers `baseline_drift`, so it agrees with the termination-cause table directly above it (`fix(plan-marshall): offer baseline_drift in the execute record-dispatch-boundary block`).

**Deliberately NOT folded in: the six script-only values.** The earlier revision of this lesson asked for `step_complete`, `blocked_user_review`, `blocked_session_restart`, `task_batch_complete`, `agent_returned` and `returned_with_findings` to be added there too. That ask was over-broad and was not acted on. Those six are phase-6-finalize and phase-4-plan causes; the block in question is `--phase 5-execute`, and its adjacent table declares exactly the seven phase-5 causes. Offering a phase-6 cause in a phase-5 invocation would invite a caller to record a value that does not apply to the dispatch being recorded — trading one wrong-bucket defect for another. The correct target for that block is its own table, not the whole tuple.

## Residue — the site is still unguarded

The recurrence mechanism is untouched. The documented-set-equals-declared-set contract tests in `test/plan-marshall/manage-metrics/test_manage_metrics.py` discover occurrences in `manage-metrics/SKILL.md`, `standards/data-format.md` and `plan-retrospective/references/logging-gap-analysis.md`. `execution.md` is guarded by none of them, which is exactly why this site drifted unobserved and why a content sweep keyed on the token `DISPATCH_TERMINATION_CAUSES` did not surface it — that site carries the values, not the symbol.

## How to apply

Add a guard covering `execution.md`'s block. Note it cannot be the existing set-equality assertion: the block legitimately carries a **subset** of the tuple, because it is phase-scoped. The assertion that fits is two-sided —

- every value the block offers is a member of `DISPATCH_TERMINATION_CAUSES` (no invented causes), and
- the block's set equals the set its own adjacent termination-cause table declares (no silent omission).

The second half is what would have caught this defect; the first half is what keeps the fix from over-correcting into the whole tuple.

A generalisation worth weighing at the same time: a search for enumeration drift keyed on the declaring SYMBOL misses every site that restates the VALUES without naming it. A sweep for the value tokens themselves (e.g. `clean_exit_queue_empty`) finds those sites, and is the cheaper detector for this defect class.

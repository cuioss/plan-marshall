# A hardcoded list mirroring a set defined elsewhere silently corrupts stored config on round-trip

## Recurrence — 2026-10-10 (fix-test-duration-findings)

The same root cause reappeared in documentation rather than code. PR #644 added a module tree to `e-2-e-playwright/README.adoc` that stated an exact file count and an exhaustive inventory of `e-2-e-playwright/utils/`. Both are hand-maintained copies of a set defined by the directory itself and would go stale with the next utility-file change.

The review bot flagged it (finding `94bcd8`), citing the path instruction derived from this lesson. Fixed in the run: the counts were removed and the listed entries are marked as principal files rather than a complete inventory.

**Scope broadened**: the rule applies to documentation as well as code. A count or a complete listing in a README that mirrors a directory, a registry or an enum is the same defect, unless it is generated from that source. Prefer naming representative entries and pointing at the source.

Note: at the time of this recurrence the lesson had a title but no body; this section is its first content.

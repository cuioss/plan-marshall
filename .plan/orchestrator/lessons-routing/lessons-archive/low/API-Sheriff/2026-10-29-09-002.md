# A `file:line` citation in documentation goes stale with the next edit on the branch: re-verify every citation before the PR and cite the symbol beside the range

Source: PLAN-V02-50 (#532), candidate lesson 004 (the citation half); five CodeRabbit findings fixed in-run.

## Observation

Several CodeRabbit findings were stale `File.java:NNN-MMM` line-range citations in documentation. Code edited earlier in the same branch had shifted the lines the document pointed at, and nothing in the build noticed.

## Rule

- Before opening the PR, and after any later code edit on the branch, re-check every `file:line` citation the branch adds or touches against the final code.
- Cite the method or symbol beside the range, so drift is visible to a reader and a reviewer.
- Prefer a symbol name alone where the line adds nothing.

## Apply

Any plan that writes ADRs, architecture or development documentation that points into source. Do the check as the last step before the push, not before the last code edit.

# assert_test_identifiers cannot report that it could not look

## Context

Observed during plan `plan-04-autonomy-gate-defaults` (epic `operator-ux`, PR #1437).
`assert_test_identifiers` returns a two-valued result: the identifiers held, or they did not. It has
no third outcome for *the check could not be performed* — an unreadable target, an unresolved path,
an empty population — so an evaluation gap renders identically to a clean pass.

## Root cause

A two-outcome contract over a three-outcome reality. The verb is a gate, and at the boundary a gap
resolves to the permissive value, so a caller that never looked is indistinguishable from a caller
that looked and found everything in order.

## Proposed action

Give the verb the same three-outcome shape `manage-config domain-narrow` shipped in this epic
(PR #1422): held / did-not-hold / **could-not-evaluate**, with the third carrying the reason. A
caller then has something to branch on, and a report can say which zero it is.

## Impact

Silent. Nothing fails, and the run proceeds as verified. This is the same class the epic has now
recorded in four other components — `2026-09-02-13-004` (an unmeasured channel as a clean zero),
`2026-09-03-06-003` (`should_emit` cannot declare it could not look), `2026-08-25-09-011` (a
metacharacter query returns a false zero), `2026-09-04-17-012` (an unsweepable lint root) — and is
filed separately because the fix site is `execute-task`'s own contract, which none of those reach.

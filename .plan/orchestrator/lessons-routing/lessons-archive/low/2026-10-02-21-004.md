# Reject a display_detail that breaks the 80-char ASCII contract

## Context

The step-record summary `display_detail` is contracted to at most 80 characters, plain ASCII, no trailing period, and the output renderer does not truncate. In plan `unified-sync-all-harnesses` three strings broke that contract, and each was caught, if at all, by a reader:

- `automatic-review` stored `2 comment(s) found — 1 reviewed, 1 empty, 1 refused-structural (unified triage pending)`: 87 characters with an em dash. The leaf passed the workflow's documented template verbatim and reported the breach itself.
- `project:finalize-step-era-stamp-fill` stored `no PR-PENDING sentinel — nothing to fill`: an em dash.
- The sync step's new success template rendered at 85 characters. Self-review round 1 found it, and two further rounds were spent on length arithmetic for its replacement.

## Root cause

`manage-status mark-step-done` stores whatever string it is given. The contract lives in two standards documents and in each author's attention, so a template that breaks it is accepted every time it is used.

## Proposed action

1. Check length and character set in `mark-step-done`, where the string is stored. Reject with a message that names the limit and the offending length or character. If a rejection is too disruptive mid-finalize, store the string and return a non-success status the caller must report.
2. Fix the two templates that fail today: the `automatic-review` Branch A detail and the `era-stamp-fill` no-sentinel detail.
3. Add a test that renders every documented `display_detail` template with realistic values and asserts the contract, so a new template fails at authoring time.

## Evidence

- status.json `phase_steps["6-finalize"]`: the two stored strings quoted above.
- chat_history_analysis: the automatic-review leaf, "The string is 87 characters and contains an em dash ... `manage-status` accepted it"; self-review round 1 finding 1, "mark-step-done does not enforce the length, so this is a documented-contract violation, not a runtime failure".
- chat_history_analysis: self-review rounds 2a and 3a each carry a hand-computed length table for the sync step's templates.

# The Maven executor's test count reports the last reactor module only, not the whole tree

## Pattern

The Maven build executor (`plan-marshall:build-maven:maven run`) ends with a one-line summary, "N test(s) executed", and a `tests_run` field. On a multi-module reactor build these report the Surefire total of the last module in the reactor only. In this plan's full verify the summary said 202 tests: that is the `benchmarks` module's count, while `api-sheriff` alone ran 4706 tests in the same build.

Read as the whole-tree count, the number is wrong by more than an order of magnitude. It also looks like a large drop in tests, which can send a reviewer looking for removed tests that were never removed. The reverse risk is worse: a module whose tests did not run at all is invisible in a count that only ever shows the last module.

## Corrective action

- Do not use the executor's `tests_run` / "N test(s) executed" as the test count of a reactor build.
- When the test count matters (to confirm that a change's tests ran, or to compare against a baseline), read the per-module Surefire "Tests run:" totals from the Maven log the executor names in `log_file`.
- For the tool itself (plan-marshall `build-maven`, for routing by the lessons mode): sum the totals across reactor modules, or report them per module, and label the field so that a single-module number cannot be mistaken for a reactor total.

## How to recognise it next time

- The summary count is the size of a small module's suite (here `benchmarks`, 202) after a build that ran the whole reactor.
- The count does not change when tests are added to an earlier module in the reactor.

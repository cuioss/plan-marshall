# Authoring a fix for a defect class does not immunize the authoring against that class

## Context

Plan `domain-post-plan-narrow` (PLAN-03, epic `operator-ux`, PR #1422) existed to add a
three-outcome contract to a new `manage-config domain-narrow` verb, under the rule *"a verb that
could not look must never render as a verb that looked and found nothing"*.

**Nine instances of that exact failure class were introduced by the plan's own output** and fixed
during the run:

- **3 by pre-submission self-review** — unreachable-report-sink claims, where prose asserted a
  consumer that provably does not exist. `cd0783`: `phase-3-outline/SKILL.md` claimed the
  orchestrator surfaces `domain_narrow_report`, and an inventory-wide literal sweep (5375 files,
  clean coverage) found the token in two files, both producers. `399e28`: the light-lane mirror of
  the same claim. `7f14d3`: the symmetric fourth site a round-5 three-site fix missed.
- **5 by CodeRabbit on the PR** — including `b96f45`, where the synthetic `system` domain is
  dropped by an *evaluation gap* rather than by the safety bound agreeing, so `claimed_by: []`
  would have recorded a look that never happened; and `1a4922`, where the consumer parses the
  module's deliberate three-outcome contract at two outcomes, reintroducing the collapse at the
  consumer site.
- **1 introduced into the remedy for the class itself** — a strip-check asymmetry where the
  sibling guard written in the SAME commit tested `.strip()` while this one stopped at truthiness.

## Root cause

The nine are not nine independent defects; they are one fact. **Authoring a fix for a defect class
does not immunize the authoring against that class.** This run demonstrates the strongest form of
it: the author held the rule in working memory for the entire run and still emitted it nine times,
once inside the remedy.

The corpus already carries several single *instances* of the class in other components —
`2026-09-02-13-004` (permission-prompt-analysis reports an unmeasured channel as a clean zero),
`2026-09-03-06-003` (let `should_emit` render a fragment that declares it could not look),
`2026-08-25-09-011` (a metacharacter-bearing `search --content` query returns a false zero),
`2026-09-04-17-012` (an unsweepable lint root). None states the meta-fact, so a reader learns the
class exists but not that **authoring against it is itself a high-risk site**.

## Proposed action

A plan whose declared subject IS a defect class should run one self-review pass whose **stated
proposition** is *"does this change exhibit its own subject class?"*, rather than relying on the
generic detector set to surface it.

The evidence that the generic path is insufficient is the ratio: self-review caught **3 of 9**,
and the external reviewer caught more than self-review did.

This is the actionable pair to `2026-09-02-14-002` (*a self-review round is clean only on the
proposition it happened to ask, and nothing obliges it to enumerate the propositions*): that
lesson says the propositions are unenumerated; this one names one proposition that is derivable
from the plan's own subject and is therefore never a guess.

## Impact

Six of the nine reached the PR. Five were caught by an external reviewer whose participation is
not guaranteed — on the immediately preceding plan in the same epic (`domain-glob-seeding`,
#1406) CodeRabbit refused on quota and filed nothing, and that PR merged with zero review
substance. Had this run drawn that same refusal, five of the nine would have shipped.

## Recurrence — 2026-09-06, plan `every-test-runs-and-the-suite-does-not-slow-down` (PR #1426)

**Second independent instance, one day later, in a different epic and against a different subject
class — and this time the plan's own gates caught none of it.**

That plan's declared subject was removing false-clean signals from the test surface: a `parse`
verb reporting `build_status: SUCCESS` over 16 collection errors, and a suite whose skips were
unaccounted for. Two instances of exactly that class were introduced by the plan's own output and
reached the PR:

- `319ce5` (CodeRabbit, Major) — the skip gate the PR exists to add compared only nodeids and
  never compared the recorded skip *reason* against `_SKIP_EXCEPTIONS`, so an approved nodeid that
  began skipping for a **new** cause would keep the session green. A false-clean hole in the very
  instrument built to close false-clean holes.
- `af4595` — a guard that asserted its tree existed while never asserting its population was
  non-empty: a sweep that could pass having checked nothing.

**The ratio moved the wrong way.** In the first instance self-review caught 3 of 9. Here it caught
**0 of 2**: `pre-submission-self-review` fired three times and `pre-push-quality-gate` four, and
neither surfaced either defect. Both were caught by CodeRabbit.

**The contingency the Impact section above reasons about actually occurred on this run.** That
paragraph asks what would have happened had the run drawn the quota refusal `domain-glob-seeding`
(#1406) drew. On #1426 it partly did: `sourcery-ai` resolved to `refused_hard` with cause `quota`
and an ETA of "1 day and 10 hours", and `cuioss-review-bot` resolved to `participated_but_empty`,
filing nothing, and only after three manually-issued re-review triggers. The whole catch therefore
rested on a single bot whose plan allows one included review per hour and which reported
`0 remain` after each of its two reviews. Had CodeRabbit drawn the refusal instead of Sourcery,
both defects would have shipped **inside the instrument built to prevent them** — the same
instrument every later run would then trust.

Two runs in a row have now had the plan's declared subject class survive the plan's own gates and
be caught only externally. That moves the Proposed action's subject-class self-review pass from
"worth adding" to the only mechanism either run demonstrated could work without an external
reviewer being both present and un-refused.

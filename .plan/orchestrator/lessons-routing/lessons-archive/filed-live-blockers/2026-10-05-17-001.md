# github re-review matcher ignores the requested bot's author

`github_re_review re-review --bot-kind cuioss-review-bot` returned `matched: true`, but `matched_review.user` was `coderabbitai[bot]` — a CodeRabbit review satisfied a re-review scoped to cuioss-review-bot. A wrong match tells the caller the requested bot re-reviewed when it has not, and the pre-merge participation barrier then reads a different bot's review as fresh for the requested bot.

## Solution

Filter candidate reviews by the requested bot kind's `author_login` before reporting `matched: true` (the registry already maps author→kind in `bot_kind_for_author`, `github_re_review.py:1129`). Add a test with two bots reviewing the same head, where only the non-requested bot has a fresh review.

## Impact

Any re-review awaited for a specific bot on a multi-bot PR — a false fresh stalls nothing but certifies nothing.

title: "A review-pipeline detector defect found mid-finalize is carried forward to its epic, not fixed in the landing PR"
content: "## The rule

A review-pipeline detector defect discovered **mid-finalize** is carried forward to its owning epic as an `accepted` finding — with the mechanism, the live observation and a remedy direction recorded on it — rather than fixed in the landing PR.

The condition that makes carry-forward the right call is specific: **the fix would advance HEAD and restart the mandatory re-review cycle.** Where that holds, the containment cost outweighs the defect. Where it does not, fix it in place.

## Why this is a standing preference, not a one-off triage call

The recurrence cleared the per-plan threshold (`preference_min_recurrence: 2`): the same finding class — a detector/predicate defect in the automated-review pipeline, observed live during a plan's own finalize — took the same `accepted` disposition twice, each time for the same stated reason.

The disposition is attributed to a concrete module (`plan-marshall`, via component `plan-marshall:automatic-review`), so it clears the attribution gate.

## What the carry-forward MUST carry

⛔ `accepted` here is not a dismissal, and it is only defensible when the finding leaves with enough to act on later: the **mechanism**, the **live observation** that exhibited it, and a **remedy direction**. A carry-forward recorded as a bare disposition is indistinguishable from a defect that was dropped.

Worked instance — PR #1473 carried two forward, both still live on main when it merged:

- `852b0f` — `review_completeness.py`'s fresh-edit currency arm credited a thread ACKNOWLEDGEMENT as a fresh review, returning `participation_complete: true` at a head where the reviewer's own walkthrough carried an explicit quota refusal. A false green on a merge-gating predicate.
- `658eec` — `pr wait-for-comments` samples each bot's newest comment by creation time, so an in-place refusal EDIT is invisible; `rate_limited_bots[]` under-reported and a caller would pick the wrong recovery.

## The cost half, which is the actual argument

That run paid **three ~90-minute CodeRabbit quota waits** inside finalize. Fixing either defect in place would have advanced HEAD and bought a fourth. ⇒ The quota window does not merely slow a run down; it **selects which defects get fixed at all**, and the defects it prices out are disproportionately defects *in the review apparatus itself*. Record that consequence with the disposition — it is the reason the disposition is defensible, and it is also the argument for fixing the window.

## Owed side effect

This preference is the discover-after-merge carrier for an owed `architecture enrich insight --module plan-marshall` call. `default:finalize-step-preference-emitter` is `mutates_source: false` and `post_run_review: true`, so it must not write `enriched.json` itself — that write would land tracked source on `main` as an uncommitted diff after the merge gate. The enrich is performed by the orchestrator or routed into a plan that may write source.

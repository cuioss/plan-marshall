# A plan fixing an accumulate-vs-replace defect can reproduce it in its own run - self-check before finalize

## Observation

A plan whose entire purpose was fixing phase-boundary stamps that **REPLACE** the prior value instead of
accumulating onto it reproduced that exact defect shape **during its own run**.

A 3-outline re-entry (the operator-directed feedback cycle) spent roughly **120 k tokens after the
3-outline → 4-plan boundary had already been stamped once at 446 k**. Re-stamping at the end of the
re-entry would have overwritten the 446 k figure with 120 k rather than accumulating the two — silently
corrupting the very measurement corpus the plan exists to protect.

## Why the fix does not protect its own run

**The fix lands at finalize; the plan's own mid-flight re-entries happen earlier.** So the fix and the
reproduction genuinely coexist in one run — this is structural, not carelessness. Any phase-boundary or
checkpoint-stamping write path that is *touched by* but *not in scope for* such a plan is a live
candidate for the same corruption during that plan's own execution.

## Rule

When a plan's deliverable is *"stop phase X's write path from clobbering prior accumulation"*, add a
self-check late in that plan's own run (self-review or pre-finalize) that inspects whether the **plan's
OWN** phase-boundary stamps — 3-outline re-entries, loop-backs — exhibited the pre-fix
replace-not-accumulate behaviour. Shipping code that fixes the general case going forward is not
evidence that this run's own measurements are intact.

Also ask the scoping question the narrow PR does not force: does phase-boundary stamping **across the
whole plan lifecycle** share the same write-path pattern, rather than only the subsystem the PR
touched?

## Archetype

This is the recurring *"a plan reproduces its own target defect during its own run"* shape — previously
seen when PLAN-86's self-review caught a dropped finding-persist at a call site **that plan itself had
created**. Worth tracking as its own instance because here the domain match is **exact**
(accumulate-not-replace, phase-boundary stamping), not merely structural.

⚠ **Generalisation for reviewers**: when the defect class under repair is one the plan-lifecycle
machinery itself performs, the run executing the repair is inside the blast radius. Check the run, not
just the diff.

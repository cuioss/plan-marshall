# pytest basetemp lives under .plan/temp, which the repo hard rule reserves for agent scratch

## Context

Plan-170 hit the same catastrophic-looking test failure twice, in two different phases, from the same cause.

- **Phase 5**: `module-tests` reported 16663 setup errors.
- **Finalize**: `module-tests plan-marshall` reported 4351 passed / 0 failed alongside **15210 setup errors**, every one a `FileNotFoundError` on `.plan/temp/pytest-basetemp/...`.

Both times the agent had written scratch scripts under `.plan/temp/`. Both times, moving those files to the session scratchpad made the identical command green — the finalize re-run passed 19560 tests.

## Root cause

The test suite roots its temporary trees inside the repository at `.plan/temp/`: `test/conftest.py` line 41 sets `TEST_FIXTURE_BASE = PROJECT_ROOT / '.plan' / 'temp' / 'test-fixture'`, and the pytest basetemp resolves under the same `.plan/temp/` parent. Something in the run clears or recreates that parent, so an unrelated file appearing there mid-run destroys the basetemp out from under the workers.

`CLAUDE.md` independently instructs, as a hard rule: *"Temp files under `.plan/temp/` — Use `.plan/temp/` for ALL temporary and generated files."*

So the project's written guidance directs every agent to write into precisely the directory the test suite requires to be untouched. This is a shared-machinery conflict, not a plan defect — any agent following the documented rule while a test run is in flight reproduces it.

The failure signature is the expensive part: thousands of setup errors read as a broken suite or a broken change, not as a scratch-file collision. Two separate diagnoses were spent on it in one plan.

## Proposed action

Resolve the conflict in one direction and make the other side enforce it. Options, in preference order:

1. **Move the suite's temp roots out of `.plan/temp/`.** Point pytest's basetemp and `TEST_FIXTURE_BASE` at a dedicated path the hard rule does not claim (e.g. `target/pytest-tmp/`, already gitignored), leaving `.plan/temp/` genuinely free for agent scratch as documented.
2. **Carve out a subdirectory in the hard rule.** Amend `CLAUDE.md` to direct agent scratch to `.plan/temp/scratch/` and have the suite own only `.plan/temp/pytest-*`, ensuring neither sweeps the other's tree.

Either way, add a guard that fails fast with an intelligible message: when the basetemp parent contains unexpected entries at session start, report *"scratch files present in the pytest temp root"* rather than emitting thousands of `FileNotFoundError`s.

# ci-verify red-CI path emits needs_triage producer strings that verification-feedback rejects as unknown_producer

## Defect

On a red CI check, `phase-6-finalize` `standards/ci-verify.md` returns `outcome: needs_triage` with producer strings such as `ci-verify-policy` and tells the dispatcher to run `plan-marshall:plan-marshall` `workflow/verification-feedback.md` once per producer string. `verification-feedback` accepts only `build-runner`, `sonar`, `pr-comment`, `plugin-doctor`, `pr-state` and `finalize-feedback`, and refuses every other value with `error: unknown_producer`.

So the red-CI path has no working triage route: each producer that `ci-verify` emits is one that `verification-feedback` refuses.

## Observed

Plan `question-corpus-public-datasets-2` (PR #92 in plan-marshall-mcp): a red CI check reached `needs_triage`, the dispatcher passed the producer strings to `verification-feedback`, and each call failed with `unknown_producer`. The dispatcher had to handle the findings by hand.

## Corrective action

Make the two producer sets agree. Either add the producer strings that `ci-verify` emits to the accept-set of `verification-feedback`, or map them in `ci-verify` to a producer it already accepts. Add a contract test that every producer `ci-verify` can emit is accepted by `verification-feedback`.

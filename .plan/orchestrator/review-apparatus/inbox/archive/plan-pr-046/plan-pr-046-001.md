# Two refusal-detector defects, observed live on PR #1477

Both were found by plan-pr-046's own finalize while it spent six 90-minute
operator waits obtaining a CodeRabbit review. They are carried out of that plan
rather than fixed in it — neither is in its declared scope.

## 1. A stale rate-limit notice is reported as a current refusal

`rate_limited_bots[]` samples each bot's NEWEST comment, so a notice whose
stated ETA elapsed hours ago is indistinguishable from a live refusal. The
distinguishing evidence sits in the same fetch and is unused: the notice's
`created_at` / `updated_at`, and the ETA stated in its own body.

Observed cost: finalize iteration 1 escalated on a notice posted at 20:31Z and
never edited, and the operator spent a full 90-minute wait before anything
tested whether the window had reopened. Only the next iteration's trigger — and
the refusal it drew, carrying that trigger's own invocation hash — established
that the quota was genuinely spent.

Remedy: before classifying a notice as a current refusal, compare its timestamps
and stated ETA against now. A refusal is current when it answers a trigger this
run posted (the invocation hash matches) or when its stated window has not
elapsed.

Source finding: `2fa992` (plan-pr-046, type bug, component
`plan-marshall:workflow-integration-github`, file
`marketplace/bundles/plan-marshall/skills/workflow-integration-github/scripts/_github_pr.py`).

## 2. `rate_limit_eta_patterns` does not match CodeRabbit's current wording

CodeRabbit's notice states `Next included review available in 48 minutes`, yet
`refusal_eta` came back empty on BOTH the `pr wait-for-comments` and the
`github_re_review` returns across every one of seven refusals. The window
duration had to be read out of the comment body by hand each time.

Remedy: add that phrasing to `rate_limit_eta_patterns` in
`marketplace/bundles/plan-marshall/skills/automatic-review/standards/coderabbit.md`.

Source finding: `fe6347` (plan-pr-046, type improvement).

## 3. Two further observations from the same run, recorded not filed

- **A trigger RESETS the rate window rather than shortening it.** Three separate
  triggers each moved CodeRabbit's stated ETA outward (20 -> 48 -> 52 minutes).
  A recovery that re-triggers when its own claim clock expires therefore spends
  an attempt to learn nothing and pushes the window further away. The claim's
  `expired: true` says the CLAIM ran out, not that the bot is ready.
- **The declared `recent_review_start` marker is ABSENT from CodeRabbit's live
  summary comment on #1477.** The `issue_comment` gate plan-pr-046 ships is
  therefore currently unexercised in production, and its canonical layout is
  pinned by no observation. This is the fail-CLOSED direction: a verdict comment
  that does not carry the marker resolves a clean review `absent`, which blocks
  a merge. It is also why that plan DECLINED CodeRabbit's "anchor the marker"
  Major twice — tightening an unanchored match against a layout nobody has
  sampled is the larger, less reversible risk.

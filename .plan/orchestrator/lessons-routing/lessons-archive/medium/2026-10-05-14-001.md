# verification-feedback rejects producer=ci-verify-policy as unknown_producer

On red CI, the ci-verify step dispatched verification-feedback with `producer=ci-verify-policy`. verification-feedback returned `unknown_producer` because that token is not in its accept-set (`build-runner`, `sonar`, `pr-comment`, `plugin-doctor`, `pr-state`, `finalize-feedback` — verification-feedback.md:30,59-63), so no triage ran and the finalize dispatcher had to diagnose inline by hand.

## Solution

The producer token ci-verify emits must be in verification-feedback's accept-set, or ci-verify must emit an accepted token. A test pinning the ci-verify producer value against the verification-feedback accept-set would catch this contract drift.

## Impact

Any red-CI triage path through ci-verify → verification-feedback. Without the pin, producer/consumer drift fails closed into a manual diagnosis.

# An argparse rejection repeated verbatim across a retry boundary is never flaky

## Observation

One plan's run (#1056) produced **12 non-zero-exit script calls, 10 unique**. The distribution is not
uniform — one script absorbed a third of them:

| script | rejections | invented shapes |
|--------|-----------:|-----------------|
| `manage-solution-outline` | 4 | `deliverables` (paraphrase of `list-deliverables`), `--deliverable 1` (should be `--deliverable-number`), a missing required `--deliverable-number`, one worktree-resolution error |
| `manage-findings` | 2 | `--resolution-detail` (should be `--detail`), one qgate-add shape error |
| `manage-architecture` | 2 | `--module X` at top level, `--field skills_by_profile` |
| `automatic-review:review_completeness` | 2 | **the same rejection twice, 16 minutes apart** |
| `manage-logging` | 1 | `read --level ERROR` |

Each rejection is a wasted round trip inside a dispatched envelope, recoverable only by re-reading
`--help`.

## Two distinct causes

1. **Verb-paraphrase and flag-paraphrase.** The invented name reads naturally in workflow prose but is
   not in the argparse `choices`. `manage-solution-outline` is disproportionately affected because its
   verb set contains `read`, `list-deliverables` **and** `get-deliverable`, so the "obvious" short name
   is wrong three different ways.
2. **A blind retry across a loop-back boundary.** The identical malformed call was re-fired 16 minutes
   later with byte-identical stderr.

## Rules

⛔ **An argparse rejection repeated verbatim across a retry boundary is never flaky.** Exit code 2 from
argparse is a **pure function of the argv** — re-running it is guaranteed to fail identically. A
loop-back that re-fires a step MUST NOT replay a call that failed with `exit_code: 2` on the previous
iteration. This is provenance-before-retry at its cheapest instance: the ground truth is one `--help`
call away.

For the paraphrase half, either add argparse aliases for the natural short forms (the way
`manage-lessons read` / `manage-tasks get` / `manage-status get` already do), or have the workflow docs
that call the script **xref its `## Canonical invocations` block** instead of restating the command —
restating is where the paraphrase enters.

## Where to look

`manage-solution-outline` is the highest-value target (4 of 10 unique failures, concentrated in the
phase-3-outline and phase-4-plan workflows). The `automatic-review` loop-back path is the retry half.

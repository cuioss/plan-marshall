# A source-tree commit in 6-finalize must carry its sanction (--step, loop-back task or inline-correction record) before the commit verb runs

A source-tree commit in 6-finalize must carry its sanction before the commit verb is called, not after the refusal: pass `--step` with the composed phase-6 manifest step id that owns the fix (for review-bot fixes, the triage / verification-feedback step), open a loop-back fix task, or record the review-rubric section-6 inline correction.

## What happened

In plan client-native-image-registration (PR #898), after automatic-review surfaced two actionable review-bot findings, the fix edits were committed through git-workflow in 6-finalize without a sanction. git-workflow refused with exit 1 (`script_internal_failure`, `reason: no_sanction`, `step: null`): no step id from the composed phase-6 manifest, no open loop-back fix task and no inline-correction record. The run recovered and the fix landed, with ci-verify, automatic-review and sonar-roundtrip re-firing green.

## Rule

Check that the verification-feedback workflow names the `--step` value its commits need, so a review-bot fix commit carries its sanction the first time. Candidate fix site: the finalize fix-path guidance.

# Report three-valued head_sha evidence instead of a bare head_sha_verified bool

## Context

`github_re_review re-review` returns `head_sha_verified` as a two-valued bool. `automatic-review/SKILL.md` documents `matched: true` + `head_sha_verified: false` as an **incremental-review decline** and mandates: "Add `{bot_kind}` to the accumulating `{declined_bots}` set", where it resolves to the blocking `declined` member of the participation taxonomy.

PR #1382 produced two `head_sha_verified: false` returns in eleven minutes, and **neither was a decline**:

- `2026-09-03T00:27:15Z` — coderabbit at `head_sha=1574890d`. The matched `issue_comment` was CodeRabbit's review-**IN-PROGRESS** marker naming the range `421f6c8a..1574890d`. Positive evidence it was reviewing that head, mid-flight.
- `2026-09-03T00:38:37Z` — pr-agent at the same head. The matched comment body stated `Review updated until commit .../1574890d7eddba8673daeeee6ecac67a154a0dbd` — it **names this head**, in prose the `issue_comment` matcher has no field to read it from.

Both were refuted by an agent reading the comment body and decision-logging the refutation. Following the documented contract literally would have entered two bots into `declined_bots` and blocked the merge on declines that did not occur.

## Root cause

One bool is carrying three distinct conditions: (a) the bot answered without reviewing this HEAD (a real decline), (b) the bot is mid-review and published a progress marker, (c) the bot named the HEAD in prose the matcher cannot parse. The `issue_comment` arm has no reviewed-commit field by construction, so it returns `false` for all three. The consumer is then instructed to treat `false` as (a).

## Proposed action

Replace the bool with a three-valued `head_sha_evidence` on the `github_re_review re-review` return: `verified_field` (the review arm supplied a reviewed-commit SHA), `named_in_body` (the producer scanned the matched comment body and found the head SHA), `absent` (neither). The producer already holds the body, so the scan costs one substring search and removes the LLM adjudication entirely. Then narrow `automatic-review/SKILL.md`'s decline arm to `absent` alone, and route `named_in_body` to the same proceed path a verified review takes. Keep `head_sha_verified` as a derived alias only if a consumer needs it.

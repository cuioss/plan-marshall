# baseline-reconcile parses git merge-tree prose lines into synthetic file_path entries

Source: Q-Gate finding b95a9d (2-refine, resolution=taken_into_account).

A finding was filed with file_path literally equal to
"Auto-merging marketplace/bundles/plan-marshall/skills/manage-locks/SKILL.md".
That is not a path — it is a line of git's human-readable merge-tree output. The
baseline-reconcile parser split ONE conflicted-file text block (the path line, the
Auto-merging line, the CONFLICT line) into MULTIPLE findings, each carrying a
different fragment as its file_path.

## Solution

Parse git merge-tree output by extracting the path from the structured conflict
record, not by treating every line of the block as a path. Until then, a
baseline-reconcile conflict count over-reports by roughly 3x and the extra rows carry
file_path values that resolve to nothing.

## Impact

Inflates the conflict count every refine run reports and forces manual de-duplication
of the reconciliation work.

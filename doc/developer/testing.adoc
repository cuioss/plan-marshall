How marketplace scripts are tested.

== Overview

Tests use https://docs.pytest.org/[pytest] via the Pyprojectx wrapper. The full suite runs as part of `./pw verify`; isolated test directories can be run with `./pw module-tests {bundle}`.

[source,bash]
----
./pw module-tests                  # pytest test/
./pw module-tests plan-marshall    # pytest test/plan-marshall
./pw module-tests -p               # pytest test/ --parallel
./pw coverage                      # pytest with coverage (to .plan/temp/htmlcov/)
./pw coverage pm-dev-frontend      # coverage for single module
----

For workflow-resolved invocations, see xref:build.adoc[Build] — never hard-code `./pw` in workflow code.

== Test infrastructure

[cols="1,3", options="header"]
|===
|File / class |Purpose

|`test/conftest.py`
|Shared fixtures and utilities loaded by every test file.

|Fixture: `fixture_dir`
|Per-test scratch directory under `pytest`'s `tmp_path`.

|Fixture: `plan_context`
|`PlanContext` context manager that sets `PLAN_BASE_DIR` and gives the test a writable plan directory. Use unique `plan_id` per test to prevent cross-test contamination — the dedup logic in some manage-* scripts (notably `manage-findings.add_qgate_finding`) makes shared `plan_id` values unsafe.

|Fixture: `build_context`
|Per-test build-system scaffolding for tests that exercise build invocations.

|Base class: `ScriptTestCase`
|Inheritable base for tests that drive marketplace scripts via subprocess. Resolves scripts via the executor convention (`{bundle}:{skill}:{script}`) using `get_script_path(bundle, skill, script)`.
|===

=== Coverage-fixture duplication is a closed decision, not an open item

Coverage fixtures are duplicated across build backends. This was assessed and the duplication is **deliberately retained**; it is recorded here so it stops reading as an open watch item.

*A 4-way share is impossible.* `test/plan-marshall/build-pyproject/fixtures/coverage/` ships `high-coverage.xml` (blob `ed37316`) and `low-coverage.xml` (blob `4125fab`), both **Cobertura** — a `<coverage line-rate branch-rate>` root over `<packages>/<package>/<classes>/<class filename>`. The gradle, maven and pm-dev-java fixtures are **JaCoCo** — a `<report>` root under the `-//JACOCO//DTD Report 1.1//EN` doctype with `<counter type=…>` elements. One file cannot serve both parsers, so no 4-way consolidation exists at any price.

*The residual candidate is a 3-way JaCoCo dedup, not a 2-way one.* `build-gradle/fixtures/coverage/high-coverage.xml`, `build-maven/fixtures/coverage/high-coverage.xml` and `test/pm-dev-java/coverage/jacoco-report.xml` are the same blob (`e2e65fc`) under three names. The low trio is likewise 3-way: gradle, maven (`low-coverage.xml`) and `test/pm-dev-java/coverage/low-coverage.xml` are all `395b3d9`. `test/pm-dev-java/coverage/high-coverage.xml` (`d1bf934`) is a genuinely different JaCoCo fixture and is not part of the duplicate set.

The duplication is of *content*, not of *plumbing*: each backend's test module declares `FIXTURES_DIR = Path(__file__).parent / 'fixtures' / 'coverage'` and passes it into the shared `build_test_helpers.run_coverage_report_case`. The gradle/maven divergence in `custom_threshold_report` / `custom_threshold` is parameterization, not fixture divergence, so it is no obstacle to sharing.

*Where a future consolidation belongs.* `test/plan-marshall/extension-api/fixtures/coverage/` already stores fixtures organised **by format** rather than by consumer — `cobertura-high.xml`, `cobertura-low.xml`, `jacoco-high.xml`, `jacoco-low.xml`, `jest-high.json`, `jest-low.json` and `sample.lcov`, all distinct blobs. It is the natural destination. `test/plan-marshall/build-npm/coverage/` and `test/pm-dev-frontend-cui/coverage/` hold JSON and lcov, not XML, and are out of scope for an XML-fixture consolidation.

*Why the cheap 3-way dedup was previously deferred, and why it no longer is.* The blocker was structural: the fixtures are `.xml` files under `test/`, and the only `classify_paths()` predicates claiming anything under `test/` were `build-pyproject`'s `test/**/*.py` / `test/*.py` (Maven claims `**/pom.xml` and nothing else there). A `.xml` path under `test/` was claimed by no registered extension, so a deliverable carrying one resolved to the `unknown` file-type bucket and was hard-blocked at plan time.

That blocker is gone: `build-pyproject`'s `classify_paths()` now claims non-Python test-fixture content under the pytest roots, `test/**/*.xml` included, so such a deliverable resolves to `test` rather than `unknown`. The dedup is landable; it is simply not yet done.

== Patterns

=== Resolve scripts via `get_script_path`

`get_script_path(bundle, skill, script)` resolves to `marketplace/bundles/{bundle}/skills/{skill}/scripts/{script}`. Always use it rather than hand-built paths so tests stay portable across worktrees.

=== Pass `PYTHONPATH` when wrapping `subprocess.run`

Custom `subprocess.run` wrappers MUST pass `PYTHONPATH` with `_MARKETPLACE_SCRIPT_DIRS` from `conftest.py`, otherwise scripts cannot find shared modules such as `toon_parser`.

=== TOON parsing in assertions

* Use `from toon_parser import parse_toon` and `parse_toon(stdout)` rather than `json.loads(stdout)`.
* `parse_toon()` only captures the first line of TOON quoted multiline values — assertions for multiline content (e.g. formatted commit messages) should check `stdout` directly instead of `result['field']`.
* TOON parser returns ints for numeric strings (`'123'` → `123`). Use `str(result['field'])` when comparing against expected string values.

=== Worktree fixtures need `.gitignore`

Test repos exercising `git worktree remove` with a dropped shim must commit a `.gitignore` containing `.plan/`. Without it, non-force remove refuses because the shim is "untracked" in fresh fixtures.

== Quality gate

Run BOTH the test suite and the quality gate before any commit that touches scripts or tests — mypy and ruff errors slip through tests-only runs:

[source,bash]
----
./pw module-tests
./pw quality-gate
----

The architecture-resolved equivalents are:

[source,bash]
----
python3 .plan/execute-script.py plan-marshall:build-pyproject:pyproject_build run --command-args "module-tests"
python3 .plan/execute-script.py plan-marshall:build-pyproject:pyproject_build run --command-args "quality-gate"
----

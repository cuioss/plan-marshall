# Resolve a bound from the live config, never from the default a document states

## Context

During plan `plan-04-autonomy-gate-defaults` (epic `operator-ux`, PR #1437) the orchestrator read
`phase-6-finalize.max_iterations` as **3** — the value the documentation states as the default — and
propagated "the ceiling is spent" into **three separate dispatches** before a unified triage caught
it. This project's live `.plan/marshal.json` sets it to **17**.

No decision was reversed, and the orchestrator self-caught and logged it. The same run also stamped
a `head_at_completion` SHA it had composed rather than read; the retrospective folded both into one
recurrence class.

## Root cause

A documented default and a live value are different facts, and the documentation is the more
available one — it is in the skill the agent is already reading, while the live value needs a
`manage-config` call. Under time pressure the available fact substitutes for the true one.

The failure is asymmetric and that is what makes it dangerous: reading the default as the live value
**understates** a ceiling (3 against 17), so the run concludes it is out of budget when it has 14
iterations left. A halt is quiet. Nothing fails, nothing is logged as an error, and the run simply
stops doing work it was entitled to do.

## Proposed action

1. Any bound that gates a control-flow decision — iteration ceilings, timeouts, budgets — is read
   from the live config through its `manage-config` accessor at the point of use, never quoted from
   a standard. A default stated in prose is documentation of the seed, not a reading of the state.
2. Where a workflow doc names a default inline, mark it as the seed value and name the accessor
   beside it, so a reader cannot mistake it for the live one.

## Impact

Three dispatches carried a false premise. More generally this is the exact class
`plan-04-autonomy-gate-defaults` deliverable 4 shipped a parity test for — the documented default
set versus the declared default set — and it recurred three times *inside the run that was fixing
it*, which is the strongest available evidence that holding the rule in mind does not prevent it.

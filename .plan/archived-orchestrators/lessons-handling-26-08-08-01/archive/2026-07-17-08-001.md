# Whole-output .strip() before splitlines() on git --porcelain shifts the fixed-column XY status field, so line[3:] eats the first path character

Surfaced during the `finalize-commit-integrity` plan (TASK-10, commit `fb6da8`) — the plan's own newly-added porcelain-parsing guard tripped over this exact slicing bug.

## Symptom

A helper that parses `git status --porcelain` (or `--porcelain=v1`) output to enumerate changed paths dropped the **first character of the first path** in its result. Every subsequent line parsed correctly; only the leading line lost a character, so a path like ` M scripts/foo.py` was reported as `cripts/foo.py`.

## Root cause

The parser `.strip()`-ed the **whole command output** before `.splitlines()`:

```python
# WRONG
for line in output.strip().splitlines():
    path = line[3:]        # assumes fixed columns: XY<space>path
```

Porcelain v1 lines are fixed-column: byte 0 = staged status `X`, byte 1 = worktree status `Y`, byte 2 = a single space, path from byte 3. A modified-in-worktree file emits `" M path"` — the line **begins with a space** (X is blank). `output.strip()` removes that leading space from the very first line only, shifting its columns left by one, so `line[3:]` starts one character into the path. Lines 2..N keep their leading space because `strip()` only touches the two ends of the whole blob.

## Do this instead

- Never `.strip()` the whole porcelain blob before splitting. Split first, then strip **trailing** newline only per line — never leading whitespace, which is load-bearing column data:

  ```python
  # RIGHT
  for line in output.splitlines():          # no whole-blob strip
      if not line:
          continue
      x, y, path = line[0], line[1], line[3:]
  ```

- Treat any `--porcelain` field extraction by fixed index (`line[3:]`, `line[:2]`) as column-sensitive: the leading blank status byte is significant and any pre-strip that can touch column 0 corrupts it.
- Prefer `--porcelain=v1 -z` (NUL-terminated) when robust path handling matters — it also sidesteps quoting of paths with spaces/unicode.

## Why it matters

The corruption is silent and position-dependent: it only ever mangles the first entry, so a test fixture whose first changed file happens to be staged (`X` non-blank, no leading space) passes while worktree-modified-first cases fail. In-house tests can pass by fixture luck; the defect surfaces only on real trees where a worktree-modified file sorts first.

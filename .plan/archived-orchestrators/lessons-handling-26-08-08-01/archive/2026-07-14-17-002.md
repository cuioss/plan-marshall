# finalize executor-regen uses the pre-regen executor to run generate_executor, so a plan that changes generate_executor.py's OWN emission format ships a broken executor

## Symptom

During `finalize-lane-materialization` finalize (PR #896, which changed BOTH the executor template `{{SHARED_MODULE_DIRS}}` contract AND `generate_executor.py`'s emission logic — D4), the `project:finalize-step-sync-plugin-cache` step's on-main executor regeneration (`.plan/execute-script.py plan-marshall:tools-script-executor:generate_executor generate`) produced a **broken executor** with a `SyntaxError` at the bootstrap block: the NEW template's `_BOOTSTRAP_SKILL_DIRS = [ ... ]` list wrapper filled with OLD-format `sys.path.insert(0, '...')` statement lines instead of `('skill', 'dir'),` tuple entries. Every subsequent `.plan/execute-script.py` call then failed.

## Root cause

The regen runs `generate_executor generate` **through the pre-regen executor proxy**. That proxy's embedded SCRIPTS mapping resolved `generate_executor.py` to a stale (pre-D4) copy whose `shared_module_lines` emission still produced `sys.path.insert` statements, while the template it read on disk was already the merged NEW (D4) version carrying the `_BOOTSTRAP_SKILL_DIRS = [` wrapper. Script-vs-template version skew → broken output. This is a bootstrap chicken-and-egg specific to a plan that changes `generate_executor.py`'s OWN output format: the tool used to regenerate the tool is the stale tool.

## Fix applied (recovery)

Re-ran the regeneration directly with the consistent freshly-synced version's script, bypassing the stale proxy:
`python3 ~/.claude/plugins/cache/plan-marshall/plan-marshall/0.1.1113/skills/tools-script-executor/scripts/generate_executor.py generate` — this produced a correct executor (script + template both at 0.1.1113).

## How to apply

When a plan changes `generate_executor.py`'s emission format and/or the executor template contract, the finalize `sync-plugin-cache` regen must run the POST-merge `generate_executor.py` (from the freshly-synced cache version), not the pre-regen proxy's stale copy. Candidate structural fix: have `finalize-step-sync-plugin-cache` invoke the freshly-synced `generate_executor.py` directly (by resolved cache path) rather than through `.plan/execute-script.py`, OR add a post-regen executor self-parse smoke check (`python3 -c "compile(open('.plan/execute-script.py').read(), ...)"`) that fails loud and triggers a direct-script re-regen. Same defect family as [[project_manifest_repo_root_cache_bug_pr888]] and D4's own executor-bootstrap-resilience work.

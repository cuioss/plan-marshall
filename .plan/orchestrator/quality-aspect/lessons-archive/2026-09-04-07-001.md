# baseline-reconcile mis-parses localized git merge-tree output as extra conflicts

component: plan-marshall:workflow-integration-git
category: bug

## Observation

On plan `unreviewed-merge-gate-holes`, `git-workflow baseline-reconcile` reported
`conflict_count: 12` against upstream commit `cc5ea40a1`. Only **3** were real
conflicting files (`automatic-review/SKILL.md`, `test_review_completeness.py`,
`test_github_pr.py`). The other 9 entries were artifacts of parsing `git merge-tree`
output on a machine whose git speaks **German**: lines such as

```text
automatischer Merge von <path>
KONFLIKT (Inhalt): Merge-Konflikt in <path>
```

were read as additional conflicting-file entries rather than as the status prose they
are. The parser is written against the English `Auto-merging <path>` /
`CONFLICT (content): Merge conflict in <path>` forms.

## Why it matters

`conflict_count` and `classification` are load-bearing, not cosmetic:

- `phase-6-finalize:branch-cleanup` gates its Pre-Rebase Confirmation Gate on the
  classifier verdict, with `auto_rebase_threshold: no_overlap_only` by default. An
  inflated count cannot flip `no_overlap` to `overlap_*` on its own (a real conflict
  is needed for that), but it does inflate the operator-facing figure the gate and
  its prompts report.
- The phase-5-execute baseline-drift branch routes on `conflict_count > 0`, and the
  drift-recovery loop is capped at 3 consecutive iterations. Phantom entries consume
  operator attention and Q-Gate triage effort on files that never conflicted — on this
  plan, 9 findings had to be individually resolved as `suppressed`.
- The failure is silent and locale-dependent: it cannot reproduce for an
  English-locale developer or in CI, so it looks like a real conflict set to the one
  person who hits it.

## Directive

Make the `merge-tree` parse locale-independent rather than translating the prose:

- Run the underlying git invocation with the locale forced to a stable value
  (`LC_ALL=C` / `LANG=C` in the subprocess environment) so git emits its English
  strings regardless of the developer's shell locale. This is the standard remedy for
  parsing porcelain-adjacent git output and needs no pattern maintenance.
- Prefer machine-readable output where the command offers it — `git merge-tree
  --write-tree` reports conflicted paths in a structured section rather than as
  free prose, so keying on that avoids string-matching status lines entirely.
- Add a regression test that feeds the parser a localized fixture (the German forms
  above are a sufficient control) and asserts the conflict set equals the real one.
  Without a non-English fixture the suite cannot see this class of defect at all.

Do NOT fix this by adding German patterns to the matcher: the set of locales is open,
and every added language leaves the next one broken.

## Evidence

- Plan `unreviewed-merge-gate-holes`, phase-2-refine baseline-drift re-cycle
  (iteration 1 of 3), against upstream `cc5ea40a1`.
- Reported `conflict_count: 12`; verified real conflicting files: 3.
- The 9 phantom findings were resolved `suppressed` with per-finding detail.

# Functional-review verdict ids must follow the frozen criteria snapshot, not the renumbered outline

Functional-review verdict ids must be keyed by the frozen criteria snapshot's positions, never by the current outline's positions, and an operator-authorised removal must mark the snapshot entry removed or waived instead of silently renumbering the rest.

## What happened

In plan client-authorization-request-seam, the operator authorised removing one criterion from deliverable D2. The current solution outline renumbered the remaining criteria. The functional-review verdict graded a criterion as D2.C5 using the outline's new position, while the frozen criteria snapshot still held the same criterion as D2.C6. The snapshot's D2.C6 stayed ungraded and an open Done-when finding was raised against a criterion that had been met.

## Rule

- Key verdict ids by the frozen snapshot (the reviewed contract), never by the outline's current ordinal.
- When a criterion is removed by operator authorisation, mark the snapshot entry removed or waived rather than letting ids shift.
- Map a verdict to its criterion by snapshot id, or by criterion text, not by position.

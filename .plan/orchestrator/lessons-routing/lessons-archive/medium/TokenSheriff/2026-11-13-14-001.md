# ci_verify records stub logs and dangling finding paths and files a Sonar quality-gate failure as a build failure

ci_verify must classify a failing check by its provider (a SonarCloud quality-gate failure is a quality-gate finding, not a build failure), persist the real job log or record explicitly that none was retrievable, and never file a finding whose artifact path does not resolve.

## What happened

In plan client-authorization-request-seam (PR #901), phase-6-finalize ci_verify persisted stub logs instead of the real job output, recorded findings that pointed at artifact paths that did not exist, and filed a SonarCloud quality-gate failure as a build failure. The misclassification sends triage down the build-fix path when the real remediation is a Sonar issue fix; the stub logs and dangling paths make the finding non-actionable and non-auditable for a retrospective.

## Rule

- Classify a failing check by the provider that reported it: a Sonar quality gate becomes a quality-gate/sonar finding, never a build finding.
- Persist the real log content, or record explicitly that none was retrievable. A stub is not a log.
- Do not file a finding whose path does not resolve.

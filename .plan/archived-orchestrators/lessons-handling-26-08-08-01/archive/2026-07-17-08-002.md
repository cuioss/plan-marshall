# A new fail-loud production precondition that breaks a pre-existing test means the fixture never seeded the now-required state — fix the fixture, not the guard

Surfaced during the `finalize-commit-integrity` plan (TASK-12, commit `a4dd89`).

## Symptom

Adding a new fail-loud precondition to production code (a `git worktree remove` "move the plan directory back to main first" guard) broke an **unrelated, pre-existing** test that had nothing to do with the change under test. The failing test was green before the plan and was not touched by it.

## Root cause

The pre-existing fixture set up its scenario without ever establishing the state the **new** guard now requires — it never seeded the moved-out plan directory the precondition asserts on. The test was latently incomplete: it only passed before because no code path had ever demanded that state. The new invariant made the latent gap observable.

The tempting-but-wrong reflex is to read a red pre-existing test as evidence the new guard is too strict and to relax/relocate the guard so the stale fixture passes again. That weakens a correct invariant to accommodate an incomplete fixture.

## Do this instead

When a newly-added fail-loud precondition/invariant breaks a test that the plan did **not** author or modify:

1. Establish provenance of the *failure*, not just the test: the guard is new, the test is old, so the fixture is the stale party — it never seeded the now-required state.
2. **Fix the fixture** to establish the precondition the guard legitimately requires (seed the moved-back directory / required state), keeping the guard intact.
3. Only weaken or relocate the guard if the invariant itself is genuinely wrong on its own merits — never merely because a pre-existing fixture didn't anticipate it.

## Relationship to the inverse case

This is the mirror image of lesson `2026-07-16-16-006` ("check whether the plan introduced the failing assertion before touching product code"). There, the **plan's own test** was at fault and the corrective was *don't patch product code*. Here, the **plan's own production guard** is correct and the corrective is *don't relax the guard — fix the stale fixture*. The shared discipline: on any test failure, first decide which side (production change vs test/fixture) is authoritative by provenance, before mechanically making the red go away.

## Why it matters

Relaxing a correct invariant to satisfy an incomplete fixture ships a weaker guard and leaves the real fixture gap unfixed, so the next state that the invariant was meant to catch slips through silently.

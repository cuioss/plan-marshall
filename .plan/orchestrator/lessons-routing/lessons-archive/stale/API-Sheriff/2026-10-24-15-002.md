# A LogMessages.adoc row added by a plan needs a test that the record is emitted

# A catalogue row needs a test that the record is emitted

Source: PLAN-V02-23 (#515), finalize code review finding. `doc/LogMessages.adoc` catalogued a WARN id for new refusal paths that no code emitted. The row promised an operator-visible signal that did not exist, so an alert built on it would never fire.

## Rule

- Every `doc/LogMessages.adoc` row a plan adds or widens is backed by a test that captures the record on that path (CUI JUL log assertions).
- Code review cross-checks each touched catalogue row against an emitting call site.
- Same shape as `declared-limit-assertion-coverage.adoc`: a documented control is not an acting control until a test goes red when it is removed.

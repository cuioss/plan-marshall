# sonar fetch_findings returns internal_error instead of unconfigured when the sonar provider has no credentials_config

## Observation

During plan lb-28-java-consumer-repos (PR #1750) the `default:sonar-roundtrip` step ran
`sonar fetch_findings --project cuioss_plan-marshall --pr 1750` in a checkout whose
marshal.json carries no `credentials_config` entry for the sonar provider
(`credentials list-providers` lists only github and git), while a global sonar token exists.
`get_authenticated_client` built the client with an empty URL, and the HTTPS guard in
`_providers_core.py` (~line 741) rejected it. The verb returned
`status: error, error: internal_error, message: "HTTPS required when authentication is configured"`.
`credentials verify` failed the same way with a ValueError.

## Directive

The `workflow-integration-sonar` SKILL documents a typed `unconfigured` status for a missing
provider config. Return that status (not `internal_error`) when the sonar provider has no
url/project_key config, so `sonar-roundtrip` can route to its "Sonar not configured" branch
from the producer's own status instead of the step re-deriving it from side evidence.
Add a test pinning the unconfigured return for a token-present / config-absent checkout.

# Keep each firing's result when a re-fire overwrites a step record

## Context

In plan `unified-sync-all-harnesses` the step `project:finalize-step-lessons-housekeeping` fired four times. The first firing removed lesson `2026-10-02-10-006` and recorded "1 rm, 0 promo, 0 adapt, 17 keep". The three re-fires each found nothing to do and recorded "0 rm, 0 promo, 0 adapt, 17 keep", and each wrote its record over the previous one. The step record that the finalize summary renders now says no lesson was removed.

The removal is still in the tombstone and in decision-log entry `a220d4`, but not in the place a reader of the finalize output looks. The housekeeping subagent pointed this out on its second and its fourth firing.

## Root cause

`mark-step-done` replaces `display_detail` (and `facts`) with the latest firing's values. The `prior_firings` list it keeps holds only each earlier firing's `outcome`, so what an earlier firing did is dropped from the record as soon as a later firing does nothing.

## Proposed action

- Keep `display_detail` (and the facts that carry counts) for every entry of `prior_firings`, not only the outcome.
- For a step whose firings each do work, render the step in the finalize summary from all firings: either the first firing that did work, or a stated total across firings. Say in the rendered line that it spans N firings.
- Add a test: a step fires twice, the first firing reports work and the second reports none; assert the first firing's detail is still readable from the step record.

## Evidence

- status.json: `project:finalize-step-lessons-housekeeping` has `display_detail: "0 rm, 0 promo, 0 adapt, 17 keep (main_anchored corpus)"`, `firing_count: 4`, `prior_firings[3]{outcome}: done, done, done`.
- work.log 2026-10-02T17:36:05Z: "1 removed, 0 promoted, 0 adapted, 17 retained over 18 lesson(s)"; 18:08:11Z, 18:19:10Z, 18:25:05Z: "0 removed ... over 17 lesson(s)".
- decision.log `a220d4`: the removal of `2026-10-02-10-006`.
- chat_history_analysis: housekeeping re-fire reports, "The step record now reads 0 rm. The overwrite replaced the first firing's 1 rm" and "the plan-wide total remains 1 removed".

The same overwrite applies to `finalize-step-simplify` (first firing 3 edits, final record "0 edits, 0 findings").

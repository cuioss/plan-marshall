# Relocation is not repair: the failure message changed but the verdict did not

A narrowly-framed question produces a narrowly-scoped answer, and a partial fix reads as a fix
because the observable output changed.

**Observed instance (API-Sheriff, PR #123).** The deliverable was *"the job runs to completion
and is green."* The question actually asked was *"why is this one goal unreachable?"* The answer
fixed that goal. The job stayed red. Because the failure message changed, it read as progress.

## Two disciplines, in order

1. **Frame the question at the DELIVERABLE, not at the symptom.** A question scoped to one
   observed symptom returns an answer scoped to that symptom. The symptom is where you look; the
   deliverable is what you are asking about.
2. **After a fix, re-check the ACCEPTANCE CRITERION, not the symptom.** The check is never
   *"did the thing I touched change?"* but *"does the stated acceptance criterion now hold?"*

## The recurrence signature

**The failure message changed but the pass/fail verdict did not.**

That is relocation, not repair. It should immediately re-open diagnosis at a wider frame rather
than being recorded as partial progress. Treat a changed-message-same-verdict result as evidence
the frame was wrong, not as evidence the fix was incomplete — those lead to different next
actions, and only the first one converges.

## Why this matters here

This is the generalized form of a pattern this repo hits repeatedly under a different name: a
signal that moved is mistaken for a signal that improved. The discipline is the same one the
truthful-signals theme asks for everywhere else — check the thing you claimed, not the thing you
touched.

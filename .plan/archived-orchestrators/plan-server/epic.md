## Vision

plan-marshall today asks the Claude session to own expensive long-running work (builds, tests),
but the harness reaps `run_in_background` jobs — so the wait *is* the build and losing it destroys
real work (90 kills / 23d / 2 repos), and 3 projects × 5 slots run 15 uncoordinated builds on one
machine with no shared mutex. This epic moves that ownership to a machine-level owner: an opt-in
Python asyncio daemon (`marshalld`) that supervises builds/tests as its own PID-1-reparented
process, so a killed session-side `wait` re-polls a surviving job instead of destroying it. Scope is
strictly a **build server** (a job belongs in marshalld IFF killing its waiter destroys local work OR
it contends for local CPU — CI-waits stay on bounded `ci:wait` primitives). "Done" = Rung 2 shipped:
registration-as-enable-signal (no config knob), `async submit`/`async wait` bounded-long-poll client
skill, verify-not-resolve submit security model, WSL2-only Windows support, and the as-built docs
landing with the daemon.

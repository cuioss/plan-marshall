# Declare a file as expected-to-mutate from a value-pin check, not a keyword hit

## Context

Plan `pre-push-gate-mutation-coherence` declared an 8-file mutation footprint and
realized an 8-file footprint. The two sets share only **4 files** — a 100%
symmetric difference at equal size, which reads as a healthy count on any
cardinality check and is half wrong in both directions.

Deliverable 1 declared seven `write-replace` files. Four were never touched:

| Declared write-replace, never touched | contains literal `mutates_source` |
|---|---|
| `test/plan-marshall/manage-config/test_config_defaults.py` | yes (2) |
| `test/plan-marshall/finalize-step-preference-emitter/test_preference_emitter.py` | yes (9) |
| `test/plan-marshall/finalize-step-sync-baseline/test_finalize_step_sync_baseline.py` | yes (3) |
| `test/plan-marshall/manage-execution-manifest/test_manage_execution_manifest_compose.py` | yes (1) |

Every one contains the field name; none pins **this step's value**, so none
needed editing. In the other direction,
`marketplace/bundles/plan-marshall/skills/automatic-review/scripts/review_gate_delta.py`
— which *did* pin the value in production prose and had to be modified twice —
was declared by no deliverable, while its test mirror
`test/plan-marshall/automatic-review/test_review_gate_delta.py` **was** declared
`write-replace`.

The under-declaration was not merely a planning miss. It became CodeRabbit finding
`da38dd`, whose diagnosis was literally *"The plan had de-counted only the test
mirror"*. The escaped defect was pre-recorded in the outline's own declaration
list, four hours before review found it.

`check-artifact-consistency` reported this as `affected_files_recall 50% — below
70% threshold`, an `error`. The recall number was correct and the shape of the
error — keyword-seeded selection — was not visible in it.

## Root cause

The declared mutation set was seeded by **co-occurrence of the field name**, a
text-match over the inventory, rather than by the semantic question the change
actually poses: *does this file pin the value I am changing?* A keyword predicate
over-selects (every file that discusses the field) and under-selects in exactly
one place (a file whose relationship to the change runs through a mirror rather
than through the keyword's own spelling).

The two errors have one cause, so fixing only the over-declaration — trimming the
four unused tests — would have left the one that reached review untouched.

## Proposed action

When phase-3-outline declares a file as expected-to-mutate:

1. Promote a keyword hit to a **declared mutation** only after checking that the
   file constrains the value being changed — a pinned literal, an assertion on the
   specific step, a restatement of the specific claim. A file that merely names
   the field is a `read` intent at most.
2. For every declared test file, ask what production file it mirrors, and
   evaluate that file for declaration too. A declared mirror whose subject is
   undeclared is the specific asymmetry that escaped here.
3. Treat equal-cardinality declared and realized sets as **no evidence at all**
   of agreement. `manage-references`' three-way reconciliation already compares by
   symmetric difference in both directions; read that, not the counts.

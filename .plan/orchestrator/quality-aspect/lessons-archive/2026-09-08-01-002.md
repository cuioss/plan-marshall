# Dedup keys on component spelling, so one defect was filed four times

## Context

The active lessons corpus currently holds **four** lessons describing the same defect —
`baseline-reconcile` scraping localized `git merge-tree` prose and manufacturing spurious
conflict findings:

| id | component as filed | title |
|----|--------------------|-------|
| `2026-09-03-19-001` | `plan-marshall:workflow-integration-git` | baseline-reconcile counts merge-tree informational lines as conflicted files |
| `2026-09-04-07-001` | *(empty)* | baseline-reconcile mis-parses localized git merge-tree output as extra conflicts |
| `2026-09-04-17-011` | `plan-marshall:workflow-integration-git` | baseline-reconcile parses localized git prose as file paths and files spurious blocking findings |
| `2026-09-07-21-001` | `plan-marshall:workflow-integration-git:baseline-reconcile` | baseline-reconcile conflict parser misreads localized git merge-tree output |

Four runs, four filings, one unfixed defect. The fourth was filed by plan
`sweep-preambles-shipped-accessors`, whose Gate 1 dedup pass did not match it against any of
the three that already existed.

## Root cause

Gate 1 classifies a candidate by **component + root cause** (`references/dedup-analysis.md`).
The root cause is identical across all four. The component is not — it has been written three
different ways for one script:

- `plan-marshall:workflow-integration-git` (the skill)
- `plan-marshall:workflow-integration-git:baseline-reconcile` (skill plus script segment)
- the empty string

The empty-component pair is a separate, already-known failure: lesson `2026-09-03-22-002`
records that lessons carrying YAML frontmatter are listable but unaddressable by every id-keyed
verb, and six lessons in the corpus currently list with an empty `component`. Those are invisible
to a `--component`-filtered dedup query by construction.

So the gate's key has two independent ways to miss: a legitimate spelling variation between the
two-segment and three-segment component forms, and a corpus of records whose component field does
not survive listing at all. Both were exercised here.

The corpus-wide consequence is that a lesson's most valuable property — that a recurrence
*reinforces* an existing record rather than adding a new one — silently degrades into duplication,
and the duplication is invisible at the filing site. Four separate records also split the evidence:
no single one of them shows that this defect has now cost four runs.

## Proposed action

1. **Normalize the component before comparing.** Dedup should compare candidates on the *skill*
   component (`bundle:skill`), truncating any `:script` third segment, rather than on the literal
   string. A defect in `bundle:skill:script` is a defect in `bundle:skill`.

2. **Do not let an unreadable component silently narrow the dedup population.** When any active
   lesson lists with an empty `component`, Gate 1's `--component`-filtered query has not seen the
   whole corpus. Either include such records in every comparison, or report the gap so the caller
   knows the classification was made over a partial corpus — the same could-not-look discipline the
   rest of this system applies to a zero.

3. **Add a title/root-cause similarity fallback.** Component equality is a cheap primary key, not a
   sufficient one. When the component key misses, a secondary comparison on the candidate's root
   cause would have caught all three prior filings here — the four titles share
   `baseline-reconcile` and the localized-merge-tree cause verbatim.

4. **Consolidate the existing four.** `supersede` three of them into one canonical record so the
   recurrence count is visible on a single lesson, and so the eventual fix retires one entry rather
   than four.

## Why this matters beyond the one duplicate

The corpus is the system's memory, and 141 active lessons is already past the size where a human
reads all of it. A dedup gate that misses on a spelling variation converts every recurrence into
corpus growth instead of corpus signal — the exact opposite of what the gate exists to do. It also
makes the retire-on-fix path unreliable: fixing `baseline-reconcile` now requires finding and
retiring four records under three different component keys, and missing one leaves a stale lesson
asserting an already-closed defect.

## Context

Three finalize steps acted on one defect in sequence and left it neither fixed nor documented.

1. An early triage round adjudicated the `compute_fingerprint` timeout gap and chose to DOCUMENT it in the docstring rather than change the behaviour, on the grounds that the raisable floor bounds the consequence.
2. A later self-review round filed Q-Gate c4e309 against that same docstring: the sentence asserted a false completeness bound. It was resolved by DELETION — correctly, on its own terms.
3. CodeRabbit then filed 1002a8 (Major) on the surviving paragraph, and the run's own reply stated the position plainly: the deletion left the paragraph \"resting on a mitigation that covers only ONE of the two cases\", and \"a second doc-only pass would repeat the first one failure\". The remedy became a code change routed to TASK-10.

Step 2 removed the artifact that step 1's decision consisted of, and nothing in the pipeline noticed a triage decision had been voided.

## Root cause

Two compounding gaps.

First, a doc-only remedy has no representation the pipeline can protect. The decision \"document rather than fix\" produces a sentence indistinguishable from any other sentence, so the next pass that grades sentences on accuracy can delete it on entirely correct grounds — and does.

Second, the guard that exists for exactly this is vacuous. `review_commitments reconcile`, whose purpose is catching a later step reversing a review decision made earlier in the same run, returned `verdict: clear` over `commitments_considered: 0` in a run that had just resolved four self-review findings as fixed (recorded this run as finding d4501c). A `clear` computed over an empty population cannot distinguish \"no conflict exists\" from \"nothing was loaded to compare against\". The finalize-step-simplify agent re-checked by hand and was right, but the guard supplied no evidence for that conclusion.

## Proposed action

Make a doc-only triage remedy carry a commitment record naming the file, the claim, and the finding it discharges, so a later pass that deletes that text has something to collide with.

Fix the vacuous guard as a precondition: publish `commitments_considered` on every return and treat a zero population as indeterminate rather than clear, per the population-derived-detector rule this codebase already applies elsewhere.

Consider refusing a doc-only remedy outright for a behavioural gap when the documenting sentence would be the only thing standing between the gap and a consumer. This run reached that conclusion by hand, on the second pass, after the first pass had already been undone.

## Evidence

- Q-Gate c4e309 — deleted the asserted-completeness sentence that step 1 had written as its remedy
- pr-comment 1002a8, CodeRabbit Major — its disposition text reconstructs the whole three-step sequence and explicitly reverses the earlier call
- finding d4501c — `review_commitments reconcile`: `verdict: clear`, `commitments_considered: 0`, `deletions_considered: 2`
- The defect being circled is itself a re-entry, through a different mechanism, of the dropped-timeout defect an earlier fix on the same branch existed to remove"

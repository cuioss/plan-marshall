# affected_files_recall counts delete-intent and foreign-checkout paths into a same-repo diff denominator

## Context

`check-artifact-consistency`'s `affected_files_recall` check compares a plan's declared
modification-intent files against its realized footprint. It already excludes read-intent
declarations — 37 of them on plan `misconfigured-reviewer-name-reads-missing-review` — because
a path the plan declared it would only read can never appear in a diff.

It does **not** exclude two further intent classes that are equally incapable of appearing in
that diff. On this plan the check reported `recall_pct: 89.5` (34 of 38) and raised an
`info` finding for the set mismatch. All four "missing" paths are the unexcluded classes:

| missing path | declared intent | why it cannot appear |
|---|---|---|
| `/Users/oliver/git/API-Sheriff/.plan/marshal.json` | `write-replace`, `foreign: true` | another repository |
| `/Users/oliver/git/TokenSheriff/.plan/marshal.json` | `write-replace`, `foreign: true` | another repository |
| `/Users/oliver/git/cui-http/.plan/marshal.json` | `write-replace`, `foreign: true` | another repository |
| `.../automatic-review/standards/pr-agent.md` | `delete` | a present-paths footprint holds no deleted file |

The plan did each of those four things **correctly** — the file was deleted, the token was
propagated — and was scored down for it. Per-deliverable coverage against the realized
footprint is 100 % for D2, D3 and D4, 96 % for D5 (27 of 28, the one miss being the delete),
and the in-repo half of D6 is complete.

## Root cause

The denominator is "declared modification-intent paths" but the numerator is "paths present in
this repository's diff". Three intent values — `read`, `delete`, and any declaration carrying
`foreign: true` — are structurally absent from that numerator. Only the first is excluded.

`plan-retrospective/references/request-result-alignment.md` already states the principle for
the read case: counting a path the deliverable declared it would only read "caps achievable
coverage below the 70 % bar **by construction**, grading the declaration style rather than the
execution". The same sentence applies verbatim to `delete` and to `foreign: true`; the rule was
written for one class and never generalised to the other two.

## Proposed action

1. Exclude `intent: delete` and `foreign: true` declarations from the `affected_files_recall`
   denominator, alongside the existing read-intent exclusion.
2. Report them as their own **counted, named** classes rather than dropping them silently —
   `delete_intent_excluded: N`, `foreign_excluded: N`, beside the existing
   `read_intent_excluded: 37`. A foreign-checkout declaration is real work whose evidence lives
   elsewhere (this plan's D6 routes it to per-checkout merged-PR references); the retrospective
   should say "3 declarations are unverifiable from this repository" rather than "3 misses".
3. Derive the exclusion set from the intent vocabulary rather than hard-coding a second literal
   list, so a fourth non-diffable intent is covered when it is added.

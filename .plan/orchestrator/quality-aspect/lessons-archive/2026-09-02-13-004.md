# permission-prompt-analysis reports an unmeasured channel as a clean zero

## Context

The permission-prompt aspect declares two inputs: a session transcript "when `--session-id` provided — visible prompt screenshots and user reactions", and the chat-history aspect fragment's pre-identified `permission_prompts` entries.

On this plan a `session_id` was present and Tier 1 applied, so the aspect ran with its full nominal input. It emitted `prompts[0]`.

That zero is not a measurement. The only channel actually available is the `extract-chat-signal` reduction, which by construction retains **operator-authored turns and recovered gate decisions** — 9 kept turns out of 1,287 raw, `operator_turn_count: 5`, `gate_decision_count: 5`. A harness permission prompt is neither: it is a tool-boundary event, so it never survives the reduction. The aspect cannot distinguish *"no prompt fired"* from *"this channel cannot see prompts"*, and it emits the same `prompts[0]` in both cases.

Screenshots are not available to a dispatched leaf at all, so the screenshot half of the declared input is unreachable in finalize-step mode — which is the only mode this aspect runs in automatically.

## Root cause

The aspect has no `status` discriminator for an unmeasured channel. Every sibling aspect in this skill has one — `outline-vs-shipped` withholds its counts behind `comparison: inconclusive`, `check-dispatch-audit` publishes `evaluated_population` per block and reports `not_evaluated` with a reason, `log-analysis` publishes `change_attribution: measured | unavailable`. This aspect alone reports a bare zero.

Its own interpretation rules make the consequence worse: they state a severity **floor** of `warning` / `confidence: high` because *"prompts are objective state ... there is no inference chain whose confidence could reasonably be below high"*. That reasoning holds only for a prompt the aspect actually saw. Applied to a channel that cannot see prompts, the floor dresses an unmeasured zero as a high-confidence observation.

## Proposed action

Add the discriminator the rest of the skill already uses:

- publish `channel: screenshots | chat_reduction | none` and `measured: true | false`;
- when no channel can carry a prompt, emit `status: not_evaluated` with a reason rather than `prompts[0]`;
- state in the aspect's Inputs section that the chat reduction drops tool-boundary events, so the screenshot channel is the only one that can substantiate a zero — and that a dispatched leaf has no screenshot channel.

Cross-plan aggregation over this aspect currently counts every plan as "zero permission prompts", which is the same absent-read-as-measured swap the neighbouring aspects were hardened against.

## Evidence

- aspect: permission_prompt_analysis — `prompts[0]` with `screenshots_available: false`
- `extract-chat-signal` — `raw_turn_count: 1287`, `reduced_turn_count: 9`, `operator_turn_count: 5`, `gate_decision_count: 5`; the reduction's retention predicate is operator provenance
- contrast: `check-outline-vs-shipped` (`comparison: inconclusive`), `check-dispatch-audit` (`status: not_evaluated` + `evaluated_population`), `analyze-logs` (`change_attribution: unavailable` + reason)

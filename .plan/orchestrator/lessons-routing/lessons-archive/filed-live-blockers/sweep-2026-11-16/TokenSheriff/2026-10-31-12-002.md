# List every writer of both slots before fixing any one race in a two-slot update

## Problem

A two-slot update in the client (the token store plus the rotation-family map, plan-02, PR #832) needed five successive code-review rounds to close its races: stale re-store, adopt-unknown-token, in-flight re-login, store/family pairing, `applyRefresh` teardown, refusal teardown. Each fix exposed the neighbouring writer that still bypassed the newly introduced lock.

## Solution

Before fixing any single race on state held in two coordinated slots, list EVERY writer of BOTH slots (store, family map, teardown, refusal, re-login and adopt paths) and route all of them through the one lock or one pairing helper in a single change. Treat "one more writer bypasses the lock" as the default failure mode of a partial fix, and have the implementer and the first review round verify the writer list.

## Impact

Avoids repeated review rounds for an invariant that spans two slots but is enforced at only some of their write sites.

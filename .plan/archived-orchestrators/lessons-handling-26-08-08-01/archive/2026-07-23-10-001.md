# A per-session pytest --basetemp placed inside the repo tree breaks isolation tests that assume tmp_path is outside any git repo/marketplace — upward-walking boundary resolvers escape the nested fixture and resolve into the real repo

A per-session pytest `--basetemp` was introduced (as part of the
test-suite-measurement-protocol capstone) to relocate pytest's scratch root
from the shared `pytest-of-{user}` directory into a per-session directory under
the repository — `.plan/temp/pytest-basetemp/...`. The motivation was sound: a
shared basetemp lets concurrent/killed sessions race on `rm_rf` cleanup, and
under `filterwarnings=["error"]` that race is promoted into a session-killing
exception on an otherwise green suite.

The trap: moving basetemp **inside the repository tree** silently invalidates
every isolation test that relied on `tmp_path` (a child of basetemp) being
located *outside any git repo / marketplace tree / plan root*. Those tests
assert boundary behaviour — "not a git repo", "no marketplace", "returns None
outside a repo", "fails closed on a non-git worktree" — by pointing a
production resolver at a `tmp_path` directory and expecting the negative
result. Once `tmp_path` is a **descendant** of the real repo, every
upward-walking resolver escapes the fixture and resolves into the real repo,
so the negative assertion flips to a positive one.

## Symptom cluster (one root cause, ~30 tests)

All failed with the same shape — expected error/None/empty, got success/real
path/real SHA — because the resolver walked up out of the nested `tmp_path`
into the surrounding worktree:

- `script-shared` — `_find_plan_root_from_cwd()` returned the worktree instead
  of `None`; `find_marketplace_path` returned the real `marketplace/bundles`;
  `resolve_main_anchored_path` did not raise.
- `worktree_sha` / `manage-change-ledger` — `worktree_sha` of a "non-git"
  directory returned a real digest instead of `None`/error.
- `manage-references compute-footprint`, `manage-status`
  `test_git_status_failure_fails_closed` — resolved real dirty files
  (`build.py`, ...) instead of the expected empty/`not_a_git_worktree`.
- `plan-marshall` handshake helpers — `git_head(tmp_path)` returned the repo
  HEAD SHA instead of `None`; worktree assertion returned `worktree_path_stale`
  instead of `not_a_git_worktree`.
- `marshall-steward` `is_worktree_repo_root` / determine-mode — a fabricated
  "main-checkout" under `tmp_path` was seen as a worktree.
- `tools-file-ops`, `tools-script-executor`, `platform-runtime`,
  `workflow-integration-git`, `manage-providers` — same escape (real base dir,
  real executor path, real marshal.json, real SCRIPTS mapping, discovered
  providers instead of empty).

## Rule — do X instead of Y

- When relocating pytest's `--basetemp` into the repo tree, treat it as a
  **breaking change to boundary/isolation tests**, not a transparent infra
  tweak. Sweep every test that asserts an "outside a repo / no marketplace /
  returns None / fails closed on non-git" negative and repair it in the same
  change.
- Boundary/isolation tests must NOT assume `tmp_path` is outside any repo.
  Make the isolation explicit at the fixture, one of:
  - plant an isolating sentinel so the upward walk terminates inside the
    fixture (e.g. `git init` a throwaway repo, or create the `.plan/local` /
    marketplace marker the resolver stops at), then assert against *that*
    controlled boundary; or
  - monkeypatch the resolver's starting point / boundary env var so the walk
    cannot reach the real repo; or
  - assert the resolver's behaviour against an injected root argument rather
    than an implicit cwd/`tmp_path` walk.
- Do not "fix" these failures by weakening the assertion to accept the leaked
  positive result — that deletes the very isolation guarantee the test exists
  to prove. Fix the fixture's boundary, not the assertion.

## Detection note

The failures were environment-shaped: they surface only when basetemp is
nested inside a repo (the worktree case) and can "auto-resolve on a green
re-run" when a later run's basetemp lands elsewhere — so they read as flake.
The tell is the uniform signature across unrelated modules: every failure is a
boundary resolver returning the *real* repo's value from a supposedly-isolated
`tmp_path`. That uniformity is the fingerprint of a basetemp-location change,
not of many independent test bugs.

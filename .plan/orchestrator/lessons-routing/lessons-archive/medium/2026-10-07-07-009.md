# Reconcile the WORKTREE dispatch contract with what the dispatcher sends

## Context

The `execution-context` envelope's prompt-body contract defines `WORKTREE` as a "repo-relative working-directory path ... NEVER absolute", with `.` for the main checkout. During finalize of plan `plan-pr-078-review-bot-fleet-opt-in`, two dispatched leaves (`finalize-step-simplify` and `create-pr`) reported that `WORKTREE` arrived as an absolute path and that they used it verbatim. The dispatch of this retrospective also carried an absolute `WORKTREE` (`/Users/oliver/git/plan-marshall`) where the contract value would be `.`. Nothing failed as a result.

## Root cause

The contract and the dispatcher disagree, and the envelope does not validate the field's shape, so the disagreement is invisible unless a leaf mentions it. The finalize entry status line itself hands out absolute `worktree_path` / `main_checkout` values, which is the natural thing for the dispatcher to forward.

## Proposed action

- Decide which side is right. Either the dispatcher forwards the repo-relative value the contract names, or the contract is changed to say an absolute path is accepted.
- Add the shape check to the envelope's Step 1 contract validation so a mismatch is an explicit error or an explicit accepted form, not a per-leaf judgement call.

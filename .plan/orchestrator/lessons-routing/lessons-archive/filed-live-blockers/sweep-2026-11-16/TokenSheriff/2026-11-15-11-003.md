# A parameterized test that covers every failure case of an enum excludes the known-good members instead of listing the failures

When a parameterized test must cover every failure case of an enum, exclude the known-good members (`@EnumSource(mode = EXCLUDE, names = {...})`) instead of listing the bad ones, so a new member is covered by default.

## What happened

In plan jwks-loader-gateway-needs (PR #906), `HttpJwksLoaderUnknownKidAttackTest.shouldIgnoreFailingResponse` used `@EnumSource(names = {"SERVER_ERROR", "SLOW", "OVERSIZED", "MALFORMED", "EMPTY_KEY_SET"})`, which repeats every failure member of `UnknownKidJwksDispatcher.Mode`. A failure mode added to the dispatcher later would have been left out of the attack test with no warning. CodeRabbit raised it (finding a76cf9); TASK-13 switched to `EnumSource.Mode.EXCLUDE` with only the two successful modes (`DEFAULT_KEY`, `ROTATED_KEY`).

## Rule

- A test that claims to cover every failure case lists the successes it excludes, not the failures it includes.
- Pair it with the positive control so the excluded members are still asserted to succeed.

## Context

- Component: token-sheriff-validation tests (JUnit 5 `@EnumSource`).

# PR body goes stale after loop-back fix tasks: regenerate it before the reviews run again

## Problem

The PR body is written at create-pr time. After loop-back fix tasks change the scope, it goes stale and the functional review flags it as a false self-report. PLAN-01 (PR #830): "Known, deliberately unfixed" items had been fixed by TASK-5, TASK-7 and TASK-9 while the body still called them open, and the Changes and Summary sections omitted the Quarkus disposer, the public `FailureReason` accessor and the terminal absent-issuer behaviour. The squash merge uses this body as the commit message.

## Solution

After every loop-back that adds fix tasks to an open PR, regenerate the PR body through the ci body verbs from the current task set and diff before the reviews run again, instead of waiting for the functional review to catch it.

## Impact

A wrong commit message on the base branch and an extra review finding per loop-back.

# files_exist flags a delete target that an earlier task of the same plan creates

## Defect

The Q-Gate mechanical check `files_exist` (`plan-marshall:manage-tasks:qgate-mechanical-checks`) tests every step
target with intent `delete` against the files on disk at 4-plan time. It does not consider that an earlier task of
the same plan creates the file (intent `write-new`) and that the deleting task depends on it. A plan that creates
temporary code, uses it, and removes it before the merge therefore gets one warning per file, and each needs a
manual `accepted` disposition.

## Observed

Plan `question-corpus-ask-rate` (PR #97 in plan-marshall-mcp), phase 4-plan: six `files_exist` findings
(c84779, 4f2e39, bff81e, 82e446, bd3b12, 066ab1) for the experiment classes under
`pm-e2e/src/test/java/de/planmarshall/e2e/experiment/askrate/`. TASK-001 creates them (write-new), TASK-003
("Experiment code removed before the merge") deletes them, and TASK-003 depends on TASK-002, which depends on
TASK-001. All six were accepted as expected by design.

## Corrective action

Before reporting a missing delete target, walk the task's transitive dependencies: when an upstream task of the
same plan targets the same path with intent `write-new`, the file will exist when the delete runs, so emit no
finding. A test should declare a write-new in TASK-1 and a delete of the same path in a dependent TASK-2 and
assert no `files_exist` finding.

## Until fixed

When a `files_exist` finding names a delete target that an upstream task of the same plan creates, resolve it
`accepted` with that reason; do not change the intent or the path.

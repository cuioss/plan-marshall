# Define the persistence artifact whenever a rule requires cross-turn memory

## Context

In plan plan-04-persona-behavior, review-bot finding `fc622e` (PR #1556,
inline by coderabbitai on `agent-behavior-rules.md:305`) reported that the new
rule requires agents to record and consult active corrections across turns but
defines no artifact, record format, invariant-class key, or read/write lookup
procedure. The existing `status.json` contracts cover coverage metadata and
session IDs, not correction records. Resolved `fixed` in-run; the fix rides
TASK-3 on the plan branch.

## Root cause

A behavioral rule that demands persistent cross-turn state without naming the
artifact that holds it, the key it is looked up by, or the procedure that
reads and writes it leaves conformance untestable: the reviewer verified this
by searching the tree for every candidate mechanism (correction memory,
deviation audit, invariant class, status/session stores) and finding no owner
for correction records.

## Proposed action

Whenever a rule requires memory across turns, define in the same change: the
persistent artifact that owns the records, the record format and lookup key,
and the read/write procedure agents must follow — or cite the source
mechanism that already owns it. Extend the rule's tests to validate that
contract (presence plus read/write shape), so an undefined mechanism fails at
authoring time instead of at review time.

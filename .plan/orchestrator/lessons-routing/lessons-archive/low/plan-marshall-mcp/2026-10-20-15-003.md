# pre-push-quality-gate assumes a module-tests canonical that a Maven project does not resolve

## Defect

`phase-6-finalize` `standards/pre-push-quality-gate.md` is written around the pyproject build and its `module-tests` / `resolve-test-scope` seam. On a Maven project no `module-tests` canonical resolves. The architecture resolver offers `verify`, `quality-gate`, `compile`, `install`, `package` and `coverage`. The module-tests arm therefore cannot run as written.

## Observed

Plan `question-corpus-public-datasets-2` (Maven, plan-marshall-mcp): the module-tests arm was recorded as degraded, although `verify -Ppre-commit` had run 98 tests. The gate's record understated the test coverage that actually ran.

## Corrective action

Make the gate independent of the build system. When no `module-tests` canonical resolves, take the test-running canonical the build system has: on Maven, `quality-gate` or `verify`, which run the tests. Count it as the tests arm rather than as degraded. Or state in the standard which canonicals stand in for `module-tests` for each build system.

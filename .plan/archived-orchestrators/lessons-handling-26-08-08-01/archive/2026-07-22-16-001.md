# A read-only reference file listed under a deliverable's Affected files flips the execution-manifest footprint bucket and the module declaration

A deliverable's `**Affected files:**` block is a **mutation declaration**, not a
reading list. Listing a file the deliverable only *reads* — a reference test, a
sibling contract doc consulted for context, a fixture inspected but not touched —
silently changes two downstream machine-consumed derivations that are computed
from that list, with no signal at authoring time.

## Root cause

`manage-execution-manifest compose` derives the plan's footprint bucket by
classifying every declared affected file through the domain extensions' path-role
claims and aggregating the roles. `plan-marshall:build-pyproject` claims
`test/**/*.py` under the `test` role, and the aggregator returns `test_only`
whenever **any** file carries a test role. So a single read-only test path in an
otherwise documentation-only deliverable flips the bucket
`documentation_only → test_only`, which in turn selects a heavier verification
set — an extra composer-emitted holistic verification run that the change does
not need.

The same list also feeds module derivation. The stray test path resolves to
module `plan-marshall`, while the deliverable had (correctly) declared module
`default`, producing a module-declaration mismatch on top of the bucket flip.

Both consequences are invisible in the outline prose: the file list *looks*
accurate, because the deliverable genuinely does depend on that file — just not
by writing it.

## Recommended action

- When authoring a deliverable, admit a path to `**Affected files:**` only if the
  deliverable will **create, edit, or delete** it. If the file is consulted,
  quoted, or asserted-against without being modified, keep its substance as prose
  in the deliverable body (e.g. "the read-only baseline in `test/.../test_x.py`
  establishes N") and leave it out of the list.
- Apply the same discipline when a Q-Gate loop-back or a scope correction *adds*
  a path to the list mid-outline — the addition inherits the same bucket/module
  consequences.
- Sanity-check the derived bucket against intent: a deliverable that writes only
  markdown should compose as `documentation_only`. A `test_only` (or heavier)
  bucket on a docs-only deliverable is the tell that a non-mutated path leaked
  into the list.

## Evidence

Plan `arm-pytest-gates-remeasure-yardsticks`, 3-outline Q-Gate finding `c3505d`
(severity `error`, resolved `fixed`). Deliverable 1 listed a read-only test file
among its Affected files. Consequences observed: footprint bucket flipped
`documentation_only → test_only` (via build-pyproject's `test/**/*.py` role
claim, which the aggregator promotes on any test-role presence), and the declared
module `default` mismatched the test path's resolved module `plan-marshall`.
Fixed by removing the read-only file from the Affected files block and retaining
its substance as prose in the deliverable body.

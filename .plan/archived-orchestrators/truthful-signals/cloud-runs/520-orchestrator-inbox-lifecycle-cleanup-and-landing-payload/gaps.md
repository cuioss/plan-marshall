## G8 — `_marker_indices`' docstring states a return contract the function does not implement

- **Kind:** stale-statement
- **Severity:** low
- **Where:** `marketplace/bundles/plan-marshall/skills/plan-orchestrator/scripts/orchestrator.py:2072-2078` — `_marker_indices`
- **What is wrong:** the docstring says "``(-1, -1)`` when either marker is absent, or the end precedes the begin." Neither clause holds. Executed over five layouts: both markers → `(0, 2)`; **begin only** → `(0, -1)`; end only → `(-1, -1)`; **end before begin** → `(2, -1)`; neither → `(-1, -1)`. The function returns `(-1, -1)` only when `BEGIN` is absent; with `BEGIN` present and `END` missing or preceding it, the begin index is returned unchanged. ⚠ **Pre-existing** — the same sentence is at `git show 9038b8c6e^:…orchestrator.py:2003`, so this landing did not introduce it. It is recorded here because it is the docstring of the function whose partial-marker-pair behaviour is exactly what CodeRabbit's CR-1 — "the single most valuable finding of the review" — turned on, and the CR-1 fix passed directly over it.
- **Why it matters:** no behaviour is wrong. Every caller guards with `begin_idx < 0 or end_idx < 0` (`_replace_block:2114`) or `begin >= 0 and end >= 0` (the test helper), so the partial pair is correctly treated as absent. But a reader who trusts the docstring concludes a `(begin, -1)` return is impossible and may write a caller that unpacks and uses `begin` alone — which is precisely the reasoning that produced CR-1's blind spot in `_abstained_sections`, where marker **presence** was scanned instead of a resolved pair.
- **Fix:** restate the contract as what the code does: "`begin` is `-1` when the `BEGIN` marker is absent; `end` is `-1` when no matching `END` follows it — including when an `END` appears before the `BEGIN`. A usable block requires **both** to be non-negative, and every caller must test both: a `(begin, -1)` return is a PARTIAL pair, which is `markers_absent` to `_replace_block` and a blind spot to the abstention report."
- **Done when:** the docstring's stated return values match what the function returns for all five marker layouts, and it names the partial-pair case explicitly.

title: First-match selection over an evidence set manufactures the negative verdict the predicate exists to detect
content: "## The rule

When a boolean verdict is derived from **one record selected out of a set of matching records**, the selector must prefer a record that can **satisfy** the predicate — not the first record that merely passes the eligibility filter.

⛔ Otherwise the selection strategy **manufactures the exact negative the predicate exists to detect truthfully**, and the verdict is a property of ordering rather than of evidence.

## The instance

PR #1477 (`plan-pr-046`), CodeRabbit finding `45ee84` — Major, `workflow-integration-github/scripts/github_re_review.py`.

`_match_bot_comment()` returned the **first** eligible comment, and `await_fresh_review()` then derived `head_sha_verified` from that one record alone. So when a bot had published several eligible comments, **an earlier comment naming no commit SHA hid a later comment naming the current HEAD**, and the envelope published `head_sha_verified: false`.

The consequence is not cosmetic: a spurious `head_sha_verified: false` is what the sibling review arm's own docstring calls *\"a manufactured decline — the one failure on this path that blocks a merge.\"*

## The test-coverage trap that hides it

⛔ **A first-match implementation passes the favourable comment ordering by accident**, so single-ordering test coverage is **green over a broken selector**. The fix therefore had to add regression coverage for *both* comment orders.

⭐ The generalisation: whenever a test exercises a selector over a set, the ordering of that set is an input. A suite that fixes one ordering is not testing selection at all — it is testing one arrangement, and it will stay green through exactly the defect the selector was written to prevent.

## Status

**Fixed in PR #1477 itself** (TASK-013), with both-orderings regression coverage. Recorded here for the rule, not as open work.

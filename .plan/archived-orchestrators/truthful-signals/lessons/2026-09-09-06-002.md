# Freshness coverage is a per-row test, so separately-run compile/lint/test arms never satisfy it

## Problem

The `pre-commit-verify-freshness` coverage dimension asks its question **once per ledger row** and
never unions across rows. `_freshness_crosscheck._row_refusal` tests

```python
if not required.analyses <= performed:
    return ROW_CANONICAL_TOO_WEAK
```

where `performed` is `CANONICAL_ANALYSES[row.canonical]` for that one row. For a footprint
containing any `.py` path, `required_coverage` returns `{compile, lint, test}`
(`_freshness_crosscheck.required_coverage`). Against the canonical vocabulary in
`script-shared/scripts/build/_build_examined.py`:

| canonical | analyses performed | covers `{compile, lint, test}`? |
|---|---|---|
| `test-compile` | `{compile}` | no |
| `quality-gate` | `{compile, lint}` | no |
| `module-tests` | `{test}` | no |
| `verify` | `{compile, lint, test}` | **yes** |

So `verify` is the **only** canonical in the vocabulary that a `.py`-bearing footprint can be fresh
against. Running the three arms separately produces three rows that each refuse with
`canonical_performs_too_few_analyses`, `scope_check_candidates` finds no covering row, and the gate
returns `stale` / `build_scope_narrow` — even though all three are green, all three are at the same
`worktree_sha`, and their union is exactly the required set.

## Observed

Plan `pre-push-gate-mutation-coherence`, 2026-09-08. Self-review's loop-back fixes were committed by
hand as `426982695`, moving HEAD out from under the earlier build. To re-establish freshness the run
executed three arms between 20:03Z and 20:08Z — whole-tree `quality-gate` green, whole-tree
`test-compile` green, `module-tests plan-marshall` green (20777 passed / 9 skipped) — and recorded in
`decision.log` at 20:08:36Z that "the push freshness gate is therefore satisfied by a real build at
this tree". It was not. The `default:push` step then ran a fourth build at 20:17:13Z–20:26:24Z
before it could complete at 20:26:57Z. The three arms cost ~5.5 minutes and bought nothing.

This is the second recorded instance. `PLAN-PR-044` reached the same refusal and recorded the
REFUTED remedy of re-running `module-tests`, which cannot work for the same reason.

## The reason token points a reader at the wrong dimension

`REASON_SCOPE_NARROW = 'build_scope_narrow'` is the single aggregate token for **both** per-row
refusal kinds — `canonical_performs_too_few_analyses` (the row analysed too little) and
`scope_narrower_than_change` (the row analysed the right things over too few modules). They are
different facts with different remedies: the first needs a stronger canonical, the second needs a
wider scope. A reader handed `build_scope_narrow` after three whole-tree arms goes looking for a
scoping problem that does not exist, and the obvious next move — re-run the same weak canonical over
a wider scope — fails identically.

The truth is already in the payload: `row_scopes[]` carries the per-row token. The aggregate throws
it away. This is the same fold the module refuses on its **attribution** dimension, where
`REASON_RESOLVER_UNIMPORTABLE` and `REASON_RESOLUTION_FAILED` are deliberately named apart with the
argument that folding them "would cost nothing at the gate and everything to a reader trying to find
out why the cross-check never corroborates anything". That argument applies verbatim here and was
not applied.

## Directive

**For a caller, today.** After any event that moves HEAD mid-finalize (a hand commit, a rebase, an
amended fix), re-establish freshness with **one whole-tree `verify`**. Do not compose it from arms.
Composing costs the arms' wall-clock and still refuses.

**For the tool, to be decided on the merits.** Two independent changes:

1. Settle whether the coverage dimension should union `performed` across all candidate rows sharing
   the current `worktree_sha` before comparing against `required.analyses`. Three green rows at one
   sha genuinely do establish `{compile, lint, test}` of that tree, and per-row testing is what makes
   them worthless. If the answer is **no** — e.g. because a citable row must satisfy scope *and*
   attribution jointly and a union has no single row to cite — state that reasoning in
   `_freshness_crosscheck`'s module docstring and in `manage-tasks/SKILL.md` § "Pre-Commit Verify
   Freshness", so the next caller stops rediscovering it by refusal.
2. Split the aggregate reason. Emit a distinct token when every readable row refused with
   `canonical_performs_too_few_analyses` (analysis coverage) versus `scope_narrower_than_change`
   (blast radius), and name the canonical that would satisfy the requirement. Add a regression test
   asserting that a candidate list of three whole-tree rows with weak canonicals does not report a
   *scope* reason.

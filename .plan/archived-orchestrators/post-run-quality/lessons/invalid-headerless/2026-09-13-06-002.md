# Nothing consumes reconcile-scope, so a scope expansion never re-syncs the footprint

## Context

Plan `the-foreign-gate-population-and-branch-f-recovery` declared 14 files across two deliverables
and shipped all 14. Mid-finalize, the run's own review pipeline surfaced two defects in
`automatic-review`, and the operator answered the gate question *"What should happen to them?"* with
**"Fix in this PR"**. Fourteen more files landed. PR #1473 merged with 28 changed paths.

`references.affected_files` still reads 14. The three-way reconciliation says so precisely:

```text
a_source: references.affected_files   a_count: 14
b_source: outline.declared_mutation_intent   b_count: 14
c_source: realized_footprint   c_count: 28
a_b_state: agree
a_c_state: disagree   c_not_a_count: 14
```

So the declared record and the outline agree with each other and are both half the size of what
shipped. Every finalize step that scopes itself from `affected_files` — plugin-doctor's gated skill
set, the self-review candidate surface, the quality-gate bundle list — scoped to the original 14 and
never saw the 14 added under the operator's own instruction.

The decisive point is that **the measurement already exists and already runs correctly**.
`manage-references reconcile-scope` computed the disagreement on demand during this retrospective,
after the merge, with no new code. It is simply never called during finalize, and no step gates on
its verdict.

## Root cause

Scope expansion is a legitimate, operator-sanctioned event with no corresponding footprint-maintenance
step. `manage-references sync-affected-files` and `capture-footprint` exist, but they are invoked at
execute-time boundaries; nothing re-invokes them when a finalize step commits outside the declared
surface. Because the declared record is only ever *written* early and only ever *read* later, the
divergence is invisible at both ends: the writer has already finished, and every reader gets a
plausible, well-formed, smaller answer.

This is the same shape as an under-recorded denominator generally — the value is not absent (which
would be noticed), it is quietly stale (which is not).

## Proposed action

Two changes, the second cheap and the first cheaper still:

1. **Consume the verdict that already exists.** Call
   `manage-references reconcile-scope --plan-id {id}` once before `push`, and surface a non-zero
   `a_c_symmetric_difference_count` as a step signal. This needs no new detector — only a caller.
   On this run it would have reported `14` at push time, before the PR was opened.
2. **Re-sync after an out-of-footprint commit.** Any finalize step that commits paths outside the
   declared footprint should call `manage-references sync-affected-files` so the declared record
   follows the sanctioned expansion, rather than leaving it to drift.

Do not treat the disagreement as a blocking gate. An operator-directed expansion is a legitimate
outcome; the defect is that the record does not follow the decision, not that the decision was made.

## Evidence

- aspect: request-result-alignment — `scope_creep: 14`, classified
  `operator_directed_mid_finalize_expansion`, with the gate answer quoted from the session transcript
- aspect: artifact-consistency — `affected_files_recall: 100%` over the stale 14-file denominator,
  a clean-looking pass that measured the wrong set
- aspect: outline-vs-shipped — `touched_but_unassessed: 15 of 28 realized_footprint_paths`
- `manage-references reconcile-scope` on the merged tree: `a_c_state: disagree`,
  `c_not_a_count: 14`, computed post-hoc with no new code

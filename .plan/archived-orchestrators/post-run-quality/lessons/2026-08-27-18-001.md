# A review false positive filed as accepted makes the false-positive rate read zero

## Directive

When triage **refutes** a review finding, disposition it `rejected`, not `accepted`.

The two are not interchangeable:

| Disposition | Means |
|---|---|
| `accepted` | The reviewer said something **valid** that triage absorbed without a code change |
| `rejected` | The reviewer said something **false** |

## Why it matters

The review-retrospective's deterministic `false_positives_count` counts only `rejected`. Filing a refuted finding as `accepted` makes the metric read **0** over a store that demonstrably contains false positives — a confident zero computed from a mislabelled population.

## Observed

PR #1361, 2026-08-27. Two findings were dispositioned `accepted` with resolution details whose **opening words were literally "False positive"**:

- a claimed occurrence-count error, refuted by re-derivation (the document's figure was correct; the reviewer's hand itemization missed a parenthetical)
- Ruff S603/S607, raised under the flake8-bandit `S` ruleset — which is not in the project's `select` list at all, so the project's own gate cannot raise those rules on any file

The aggregator reported `false_positives_count: 0` while the substantiated rate was **2 of 8 inline (25%)**.

**The aggregator was faithful to the store. The store was wrong.** That is the important half: there was no bug to fix in the metric, and reading the metric as a reviewer-quality signal would have been reading a labelling error.

## Corollary — worth checking whenever a reviewer-quality metric reads clean

Confirm the disposition vocabulary was actually **used as defined** before trusting a zero. A metric keyed on one disposition value silently under-reports when callers reach for a neighbouring one, and nothing in the pipeline flags the substitution — the resolution detail says "false positive" in prose while the machine-readable field says `accepted`.

## Archetype

A correct aggregate over an incorrectly-labelled population. Distinct from a broken detector: every component behaved as specified.

# A prose instruction telling the agent to escape untrusted text is not an injection control

## Evidence anchor

PR #1477 (plan-pr-046), CodeRabbit finding `f0931a` — Major, Security & Privacy, CWE-78
(OS command injection), reachability External.

## What happened

`automatic-review/SKILL.md` had an ARMED decision-log template that interpolated `{body}` — the
refusal excerpt published by a review bot, i.e. untrusted external text — into a single-quoted
`--message` shell argument. The document did carry a mitigation: prose at SKILL.md:540-543
instructing the agent to rewrite any embedded single quote.

That control fails on its own terms. It is prose addressed to an LLM asking it to escape untrusted
text at composition time, and the character that breaks the quoting is an **apostrophe** — ordinary
English punctuation that appears in routine bot prose. So the failure mode fires on normal input,
not only under adversarial input, and the only thing standing between a bot's message and shell
syntax is whether the model remembered to apply a documented escaping step.

## The fix that was taken (and why it generalises)

TASK-011 did not harden the escaping. It **removed the `{body}` placeholder from the template**,
because SKILL.md already carried the same four facts as a structured `rate_window_arming[]` row on
the returned envelope — a surface that needs no shell quoting and is what a resumed run actually
reads back.

## The rule

Untrusted external content (bot comment bodies, issue text, web page text, Sonar messages) must never
reach a shell argument vector, and **a documented escaping instruction addressed to the agent does not
make it safe**. Two acceptable remedies, in order of preference:

1. **Delete the interpolation.** If a structured, non-shell surface already carries the same facts,
   the shell-bound copy is redundant — remove it rather than quoting it.
2. **Use a file/stdin input path**, so the payload never becomes an argv element.

Hardening the quoting is the *third* option and should be justified, not assumed.

## Detection heuristic for reviewers

Any template of the form `--flag '{placeholder}'` where the placeholder is filled from external
content is a finding, regardless of what mitigation prose sits near it. Grep the surrounding document
for "rewrite", "escape", "quote" — the presence of such prose is a signal that the author already knew
the value was dangerous and chose the weakest control.

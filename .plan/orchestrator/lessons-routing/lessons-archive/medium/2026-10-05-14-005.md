# A loop-back fix must re-check the same file for other statements of the changed rule

A loop-back fix rewrote one doc section ("Request Body Validation": validate individual values, not the serialized document) while the "Security Checklist" in the same file still said the opposite ("All request bodies validated with URLParameterValidationPipeline"). The self-review re-fire caught the same-document contradiction before merge, at the cost of an extra loop-back round.

## Solution

When a loop-back fix changes a normative statement, search the same file (and its sibling summaries) for every other statement of that rule before committing — e.g. search for the pipeline or API name the fix stopped recommending, and update each hit in the same commit. Most likely in long files that restate one rule in several places (package-info checklists, summaries, "see also" lines).

## Impact

One extra loop-back round per occurrence when caught; a shipped self-contradiction when not.

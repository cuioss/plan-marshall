# AsciiDoc PlantUML-to-SVG migration: three recurring review-caught defect classes to pre-empt

During the `doc/` PlantUML-to-SVG diagram migration, three distinct defect
classes were each caught in review rather than at authoring time. A future
SVG/AsciiDoc migration should pre-empt all three — they are deterministic,
mechanically checkable, and recur independently of diagram content.

## Defect class 1 — SVG filename must match its actual diagram content

Several hand-authored SVGs were committed under a filename describing a
*different* diagram than the one they contained:

- a component diagram saved as `*-merge-sequence.svg`
- a HATEOAS-links diagram saved as `*-status-lifecycle.svg`

The `image::` reference resolved and the doc rendered, so nothing failed the
build — the mismatch was only visible by opening each SVG and comparing its
content to the filename's implied subject. Do **not** trust that a resolvable
`image::` target is the *right* target.

**Do X instead of Y**: after authoring each SVG, open it and confirm its
content matches the name; the filename is a claim about content, not just a
path. Verify content-vs-name for every migrated diagram, not just spot-checks.

## Defect class 2 — comma-bearing image alt text MUST be double-quoted

`image::` (and `image:`) alt text containing a comma is split by Asciidoctor
into positional attributes, truncating the visible alt text at the first
comma. Example of the failure and the fix:

```asciidoc
// WRONG — alt text truncated at the comma, rest parsed as attributes
image::diagram.svg[Request flow, gateway to issuer]

// RIGHT — commas preserved by double-quoting the alt text
image::diagram.svg["Request flow, gateway to issuer"]
```

**Do X instead of Y**: double-quote any alt text that contains a comma (or
any other AsciiDoc attribute-significant character). Quote defensively for all
migrated image macros rather than auditing which ones happen to contain a
comma.

## Defect class 3 — `:imagesdir:` is document-global and breaks sibling refs

Adding a document-level `:imagesdir:` directive to consolidate the new SVG
references silently rebased **every** image in the document — including
pre-existing sibling UI screenshot references (`ui-*.png`) that lived in a
*different* directory. Those screenshot `image::` targets then resolved
against the wrong base directory and broke.

**Do X instead of Y**: do not add a doc-level `:imagesdir:` to a document that
already references images from more than one directory. Either keep explicit
per-image relative paths, or move all images under a single tree first. When
`:imagesdir:` is introduced, re-verify every *other* image reference in the
same document, not only the ones being migrated.

## Impact

All three are cheap to check at authoring time and expensive to catch in
review (each was a separate review round-trip). A pre-migration checklist —
(1) open-and-compare every SVG to its filename, (2) double-quote every
comma-bearing alt text, (3) audit sibling image references before touching
`:imagesdir:` — pre-empts the entire recurring set.

# Contract-change prose mirrored across N locations: grep the stale phrasing and sweep all occurrences in one self-review pass, not one-at-a-time

A deliverable changed a behavioural contract (the aspect-drop rule: an absent `--aspect`
now self-reads `status.metadata.request_aspect` instead of being an unconditional no-op).
The OLD, now-wrong description of that contract was duplicated across FOUR mirrored prose
locations: a SKILL.md parameter-row summary, the SKILL.md detailed section, an in-code
comment, and a test docstring. The code diff touched only ONE of them.

## Defect

The pre-submission self-review surfaced the stale mirrored copies **one at a time**,
across three separate re-dispatches (whack-a-mole) — fix location 1, re-run, surface
location 2, re-run, surface location 3. Worse, none of the in-house passes caught that the
prose was ALSO factually wrong on a second axis (full-vs-partial clear of the aspect);
CodeRabbit found that inaccuracy post-push.

## Corrective action

When a change alters a contract whose description is mirrored across multiple prose
locations, treat the stale phrasing itself as the search key: **grep the old phrasing
across the whole tree and sweep every occurrence in ONE pass**, rather than fixing only
the location the code diff happened to touch and letting an incremental surfacer rediscover
the rest one-at-a-time. Two concrete disciplines:

1. **Fix-side (author)**: after changing any contract, extract the distinctive stale
   phrase(s) from the old wording and grep them repo-wide (param rows, detailed sections,
   in-code comments, test docstrings, xref'd sibling docs). Update all hits in the same
   commit.
2. **Review-side (surfacer)**: a duplicate-phrase / stale-contract surfacer should batch
   ALL occurrences of the same stale phrase into ONE surfacing so the fix is one pass, not
   N re-dispatches to the ceiling.

Also re-read the changed prose for **semantic** accuracy, not just presence of the stale
token — a mirrored copy can be stale on more than one axis (here: both the no-op-vs-self-read
claim AND the full-vs-partial-clear behaviour), and a pure phrase-match sweep catches only
the axis it keys on.

## Relationship to existing corpus

Distinct from `2026-06-29-16-001` (plans under-scope the mirror contract surface at
plan/outline time): that lesson is about estimating the surface up front; this one is about
the fix/review discipline once a contract actually changes — sweep by stale-phrase grep in
one pass instead of iterating.

## Impact

Any contract-altering change in a codebase that mirrors contract prose across SKILL rows,
detailed sections, code comments, and test docstrings. Incremental one-at-a-time surfacing
wastes self-review re-dispatch cycles and still misses non-phrase-keyed semantic drift.

## Recurrence — 2026-07-19 (finalize-queue-enforced-enqueue)

The enforced-enqueue finalize change added a `use_merge_queue` conditional to the
interactive "Yes, merge" gate in `phase-6-finalize/standards/branch-cleanup.md`, but left
the **semantic mirror** of that same merge-routing authorization — the non-interactive
auto-merge bypass text a few lines above — stating `pr safe-merge` was authorized
*unconditionally*. Result: the same flag value (`use_merge_queue == true`) was documented
as authorizing two mutually-exclusive routes (queue enqueue AND direct safe-merge).
CodeRabbit (finding f29119) caught the contradiction post-push; a parallel gemini comment
(f-5ca57c) flagged the conditional-template syntax on the same edit.

### Broadening — mirror sites need not share phrasing

The original lesson keys the sweep on the *stale phrase* (grep the old wording). This
recurrence extends it: the two mirror sites were **phrased differently** — the interactive
gate reads "Yes, merge → `pr safe-merge`" while the bypass reads "`merge_consent =
explicit_yes` authorizes the `pr safe-merge` poll-then-merge path". A stale-phrase grep
would NOT surface the sibling, because no shared token spans both. When a change gates a
*normative decision* (a routing/authorization directive) on a flag, the search key must be
the **semantic contract** (every place that authorizes the routed action / states the
flag-conditional behaviour), not just the literal phrase — enumerate the flag-guard pair
(interactive gate + non-interactive bypass, prompt + auto-path) and gate every member in
the same pass. `ext-self-review-plan-marshall` already enumerates "flag-guard pairs" and
"same-document normative directives" as candidate classes; this is exactly the class the
self-review should batch, and it slipped here because the fix touched only the prompt half.

## Recurrence — 2026-07-22 (build-decision-oracle-consolidation, PR #985)

A retirement sweep — collapsing the build/no-build decision oracle from a seven-row matrix
to six rows (`build_map` as the single oracle) — needed THREE successive passes to converge,
each one finding MORE survivors than the pass before it:

1. **Phase-5 execution** swept the files it touched and believed the retirement complete.
2. **The pre-submission self-review gate** (which already runs the `stale count-prose`
   candidate class from `ext-self-review-plan-marshall`) found 4 more hits — stale
   row-count prose ("seven-row matrix" left standing after the row was removed) — and fixed
   all 4.
3. **CodeRabbit**, post-push, still found additional survivors neither prior pass caught:
   test names/docstrings/assert messages naming the deleted matrix row, in files that were
   **not part of the diff at all** (pure consumers of the retired vocabulary, never touched
   by the retiring change), plus a doc cross-reference that contradicted a guardrail the
   SAME plan had just added.

### Broadening — diff-scoped sweep vs whole-tree sweep

The original lesson's corrective action ("grep the old phrasing across the whole tree, not
just the location the diff touched") is the exact fix for this recurrence too, but this
instance sharpens *why* two in-house passes still weren't enough: both phase-5 execution and
the self-review gate operate primarily over the **changed footprint** (the diff and the
files it names), not a whole-tree grep for the retired term. A vocabulary-retirement sweep
is a strict superset of a mirrored-prose sweep — the survivors are not limited to prose that
mirrors a description, they include ANY reference to the retired name at all (identifiers in
test names, docstrings, assert-message strings, and doc cross-references), and by
construction those references live disproportionately in files the diff never touches
(consumers of the old name, not producers). The corrective action from the original lesson
therefore generalizes: for a rename/retire sweep specifically, grep the retired term against
the WHOLE TREE (not the diff, and not only the self-review gate's per-diff detector scope)
before treating the sweep as complete — successive incremental passes (execution →
self-review → external bot) converging on the answer is evidence the whole-tree grep was
skipped, not a substitute for running it.

# Three plan-tooling script failures in one run while marshal.json trailed the installed plugin - check the version gap before a plan

## What happened

Plan `fix-test-duration-findings` hit three distinct failing plan-tooling scripts in one run. During the run, this project's `marshal.json` was at version 0.1.1607 while the installed plugin was at 0.1.1890.

1. **`plan-marshall:manage-references:manage-references`** - in the outline phase, the `domain-narrow` step proposed dropping all five domains the user had selected, and its follow-up `set-list --values ""` call was rejected by the argument parser (exit 2).
2. **`plan-marshall:plan-marshall:phase_handshake`** - returned `status: drift` after a quality-check finding had been accepted following the handshake capture.
3. **`plan-marshall:manage-solution-outline:manage-solution-outline`** - called with `--number`, which the script does not declare; 4 occurrences.

## What is and is not established

- The version gap was noted during the run as the **likely** cause of failure 1. This was not verified.
- Failures 2 and 3 are not known to be related to the version gap. Failure 3 has the shape of a caller passing a flag the script does not have; the correct flag was not determined in this step.
- None of the three blocked the plan: all were worked around and PR #644 merged.

## Rule for this project

- Before starting a plan, compare the version recorded in `marshal.json` with the installed plugin version. When the project config trails the plugin, reconcile it first (the steward's upgrade flow) rather than discovering the gap through mid-run failures.
- When a narrowing step proposes removing every item the user explicitly selected, treat that as a defect signal and stop - do not apply it.
- Before calling a plan-tooling script with a flag taken from memory or from prose, confirm the flag in the script's `--help`.

## Not filed here

The three failures point at behaviour of the plan tooling itself. This repository's lessons store refuses records for a bundle it does not own, so no tooling-side lesson was filed under `plan-marshall:*` components. They need to be raised in the tooling's own repository if they are to be fixed there.

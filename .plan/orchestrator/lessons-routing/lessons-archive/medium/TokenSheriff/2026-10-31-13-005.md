# Outline quality: evidenceable criteria, docs listing a closed set, declared file sets, and pre-fix evidence collected during execute

## Problem

Four outline and plan-quality gaps surfaced late. PLAN-04: a success criterion about the PR body ("the PR body records whether the hypothesis was refuted") can never be evidenced, because the functional review grades the head before `create-pr` runs; both findings needed an operator acceptance. PLAN-04: the outline missed the docs that list a closed set (health-check status values) the deliverable extended; the outline Q-Gate caught it. PLAN-02: a fix-task agent added a log record and a `doc/LogMessages.adoc` row outside its declared files, leaving the outline's "no LogMessages change" note stale. PLAN-03: a "regression tests fail before the fix" criterion had no evidence until the review; it was closed by overlaying the tests on the base commit, and for a signature-changing fix the pre-fix proof is a compile failure.

## Solution

Phrase success criteria about artifacts that exist before the grading gate (change ledger, outline, a doc or ADR in the tree), never the PR body or merge state. When a deliverable adds a value to a closed, user-visible set (status markers, error codes, problem types, config keys), search the docs for the set's members and add every doc that lists them to the affected files. A task must declare, or stop and amend, any file outside its set, and reconcile the footprint at that moment so negative outline claims do not outlive the work. Collect "fails before the fix" evidence during execute (overlay the tests on the base commit and record it); for a signature change expect a compile failure, and use an API stable across the fix if a runtime red/green is wanted.

## Impact

Findings that only the late review or an operator acceptance can close.

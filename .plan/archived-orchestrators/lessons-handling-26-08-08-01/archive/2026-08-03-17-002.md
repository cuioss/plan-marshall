# The orchestrator-tier yield boundary lets a task's own newly-authored tests ship unexecuted

## Observation

On PR #1086 a task authored new tests and **yielded to the orchestrator tier before running them**.
The tests shipped unexecuted — and **the one that did ship was wrong.**

⛔ **The gap is structural, not a slip**: the yield boundary sits between *authoring* and
*execution*, so a task that ends at the boundary has produced test code that nothing has run. CI is
then the only covering gate, and CI runs after the merge decision is already in motion.

## Why the usual defences do not catch it

- **The task reports success** — it did what it was asked: it wrote the tests.
- **The suite is green** — because the new tests were never in it at the time it was measured.
- **A reviewer sees test code added**, which reads as increased coverage. ⭐ **Added test code is a
  coverage CLAIM, not coverage** — the same shape as a frontmatter declaration standing in for an
  enforced property.

## Rule

- **A task that authors a test MUST execute it before yielding**, or must declare explicitly that it
  did not and name what will. A yield boundary between authoring and execution is a place where
  unverified artifacts accumulate silently.
- **Never let CI be the first execution of a test the plan itself wrote.** CI is a covering gate for
  a *timeout* or an *environment* gap; it is not a substitute for the author having run the thing
  once.
- ⭐ **The discriminating question at review is "has this test ever run?", not "does this test look
  right?"** A test that has never executed can be syntactically perfect, assert the wrong thing, and
  pass review — which is what happened here.
- Generalises to any artifact produced near a tier boundary whose verification lives on the other
  side of it.

## Impact

`phase-5-execute` task-yield mechanics, the orchestrator-tier boundary contract, and every plan whose
tasks author tests. Related: the pre-existing-tests-passed-against-the-defect finding on the same PR
— **a suite can be green for reasons unrelated to the code under test.**

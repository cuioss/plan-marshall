# Light-lane envelope never authors pr_title, so the 3-outline handshake capture fails

## Problem

The collapsed light-lane envelope (`phase-3-outline/workflow/light-lane.md`) folds refine + outline +
deliverable-derivation into one dispatch, but it does not perform two persistence steps that
`phase-2-refine` owns on the deep lane. Both gaps surfaced on the same plan
(`apply-the-cloud-plan-lane-contract-amendments`, 2026-09-04), and both are structural — they will
recur on every light-lane plan, not just this one.

### Gap 1 — `metadata.pr_title` is never authored

`phase-2-refine` Step 13 authors a commit-style PR title and persists it via
`manage-status metadata --set --field pr_title`. The light lane skips it.

The orchestrator's `phase_handshake capture --phase 3-outline` carries a `pr_title_present`
invariant, so the capture **refuses**:

```text
status: error
error: pr_title_missing
message: pr_title_present failed for phase '3-outline': metadata.pr_title is absent or empty
```

The failure is loud but late: it fires at the orchestrator's post-outline handshake, after the
light-lane envelope has already returned `status: success`. The orchestrator must author the title
itself to get past it, which puts a refine-phase artifact in the orchestrator's hands.

### Gap 2 — `track` is never persisted

`track` is unset in both `manage-references` and `manage-status metadata` after a light-lane run.
`manage-execution-manifest compose` requires it, so `phase-4-plan` has to infer it
(`track=simple` inferred from the already-resolved `planning_lane=light`) and log the inference.
An inferred value that happens to be right is still an inference standing in for a persisted fact.

## Directive

Make the light-lane envelope persist both fields before it returns, so the deep and light lanes
leave the same post-refine state behind:

- Author and persist `metadata.pr_title` (the refine Step 13 obligation) inside `light-lane.md`.
- Persist `track` (`simple` on this lane) rather than leaving `phase-4-plan` to infer it.

The alternative — relaxing the `pr_title_present` invariant for light-lane plans — is the wrong
direction: the invariant is doing its job, and the PR title is genuinely needed at finalize.

## Evidence

- Plan `apply-the-cloud-plan-lane-contract-amendments`, 2026-09-04: `phase_handshake capture
  --phase 3-outline` returned `error: pr_title_missing`; the orchestrator set the title by hand and
  re-captured successfully.
- The same run's `phase-4-plan` return reported `track` genuinely unset in both stores and recorded
  its `track=simple` inference to `decision.log`.

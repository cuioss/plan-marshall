# declared_set_closure compares absolute declared paths against repo-relative stored step targets

## What happened

Plan `register-corpus-group-contamination`, phase 4-plan: the `declared_set_closure` check of
`plan-marshall:manage-tasks:qgate-mechanical-checks` raised four warnings (hashes 351522, 4288a4, 882b9e, c5eb12)
for two files, each reported twice in opposite directions:

- deliverable 1 declares `/Users/oliver/git/plan-marshall-mcp/.plan/temp/pm-mcp-core-corpus-group-contamination/doc/plans/README.adoc`
  (absolute) "but no task targets it";
- TASK-001 targets `.plan/temp/pm-mcp-core-corpus-group-contamination/doc/plans/README.adoc` (repo-relative)
  "which deliverable 1 never declares";
- the same pair for `doc/plans/corpus-group-contamination.adoc`.

Both sides name the same file. The task store normalised the step target from absolute to repo-relative on
`batch-add`, while the declared set kept the absolute path from the solution outline. The check compares the two
strings verbatim, so a file that is both declared and targeted is reported as missing from both sides. All four
were resolved `taken_into_account` as false positives.

The trigger is a deliverable that edits files in a checkout of another repository placed under `.plan/temp/`
(here a clone of `pm-mcp-core`), which the outline names by absolute path.

## Fix

Normalise both sides through the same function before the set comparison: resolve each declared path and each
step target against the repository root (the same absolute-to-repo-relative rule the task store applies on write),
then compare. A test should declare a file by absolute path, target it by the stored repo-relative form, and assert
no `declared_set_closure` finding in either direction.

## Until fixed

When a Q-Gate `declared_set_closure` finding comes as a mirrored pair (one "declared but not targeted", one
"targeted but not declared") and the two paths differ only in absolute versus repo-relative form, resolve both as
`taken_into_account` with the path-normalisation reason; do not rewrite the outline or the tasks to chase it.

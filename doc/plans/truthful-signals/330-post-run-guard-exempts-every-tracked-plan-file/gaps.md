## G2 — Site 2 exempts a dirty tracked `.plan/` path whose porcelain rendering is quote-escaped

- **Kind:** bug
- **Severity:** high
- **Where:** `marketplace/bundles/plan-marshall/skills/plan-marshall/scripts/_git_helpers.py:70-98` — `git_dirty_files`, consumed by `_invariants.py:676` `_capture_main_dirty_files` → `_filter_main_dirty_paths` → `_plan_state_exemption.partition_plan_state_exemption`
- **What is wrong:** The two sides of the trackedness comparison use different path encodings. `git_dirty_files` runs `git status --porcelain` **without `-z`**, so with git's default `core.quotePath=true` a path containing a non-ASCII byte (or a space/quote) comes back C-quoted and octal-escaped; the helper strips the surrounding quotes but leaves the escapes. `tracked_plan_paths` runs `git ls-files -z`, which emits raw bytes. The escaped string is therefore never found in the tracked set and falls into the **exempted** branch. Reproduced on a purpose-built repo at HEAD: with a committed-then-dirtied `.plan/ünï.json`, `partition_plan_state_exemption(git_dirty_files(repo), repo)` returned `retained=['.plan/marshal.json']`, `exempted=['.plan/\\303\\274n\\303\\257.json', '.plan/local/']` — a **tracked** `.plan/` file dropped as untracked. Site 1 is immune because `post_run_source_guard.py` observes with `-z` and decodes via `parse_porcelain_z`.
- **Why it matters:** It is a false-clean of precisely the defect class this plan exists to close: the layer-D drift capture silently drops a tracked `.plan/` leak, so `_check_main_dirty_drift` can never see it and the boundary reports no drift. It fires only when a tracked `.plan/` path carries a character git quotes (none of the repo's current 13 tracked `.plan/` paths do), which bounds the blast radius but not the wrongness — and the same encoding mismatch applies to any tracked source path with a space or non-ASCII byte, since those reach `partition_plan_state_exemption` too (they are retained there, but the captured *string* is the escaped form, so the baseline/observed set comparison is done on a different spelling than `ls-files` uses).
- **Fix:** Make the two observations speak one encoding. Either switch `git_dirty_files` to `git status --porcelain -z` and decode with the existing `phase-6-finalize/scripts/post_run_source_guard.py::parse_porcelain_z` logic (extract it to `script-shared` so both sites share it, matching D1's own "one predicate, not two copies" principle), or run both git calls with `-c core.quotePath=false`. Add a regression test alongside `test_capture_main_dirty_files_reports_tracked_plan_state` that commits a tracked `.plan/` file with a non-ASCII name, dirties it, and asserts it is retained.
- **Done when:** with a committed tracked `.plan/ünï.json` dirtied in a throwaway repo, `_capture_main_dirty_files` returns a list containing that path, and a test pinning it fails against today's `git_dirty_files`.
- **Module/topic:** `plan-marshall:plan-marshall` scripts — `_git_helpers` / layer-D drift capture / `script-shared:_plan_state_exemption`.

## G3 — Publish the examined population at the second confirmed guard site

- **Kind:** omission
- **Severity:** medium
- **Where:** `marketplace/bundles/plan-marshall/skills/plan-marshall/scripts/_invariants.py:615-679` — `_filter_main_dirty_paths` / `_capture_main_dirty_files`; persisted field list at `plan-marshall/scripts/_handshake_store.py:35`
- **What is wrong:** D2 requires that **each** guard's own output state the paths considered, the paths exempted, and why. Only the post-run source guard does: its TOON carries `considered_paths` / `exempted_paths` / `offending_paths`. The layer-D capture discards the exempted half — `_filter_main_dirty_paths` returns `retained` and drops `_exempted` on the floor — and the handshake row persists only `main_dirty_files`. An empty `main_dirty_files` at a boundary is therefore indistinguishable from "every observed path was exempted", which is the epic's standing "a zero must carry its population" rule applied to the very guard the plan fixed.
- **Why it matters:** The layer-D no-drift verdict is the one an operator is told to trust at every planning-phase boundary, and it is the site whose exemption arm actually fires in production (its porcelain includes untracked paths, unlike site 1's). Without the exempted population, a wrong exemption there is unobservable after the fact — including G2's.
- **Fix:** Capture the exempted set alongside the retained one — e.g. add a `main_dirty_exempted` list field to `HANDSHAKE_FIELDS` / `HANDSHAKE_LIST_FIELDS` in `_handshake_store.py` and have `_capture_main_dirty_files` return both halves — and document the new column in `plan-marshall/references/phase-handshake.md` § the invariant table (next to the `main_dirty_files` row at :127). If the field is deliberately not persisted, say so in `_filter_main_dirty_paths`'s docstring with the reason, so the omission is a recorded decision rather than a silent drop.
- **Done when:** a phase-boundary capture over a tree with a dirty untracked `.plan/` write records that path in an exempted-population field (or the docstring states why it is not recorded), and `phase-handshake.md` describes the field.

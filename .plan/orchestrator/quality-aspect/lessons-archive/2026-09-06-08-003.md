# Compare a symmetric pair written in the same edit against each other, not only each against the requirement

## Context

While remedying the dominant failure class of plan `domain-post-plan-narrow` (PLAN-03, epic
`operator-ux`, PR #1422), the orchestrator wrote a pair of sibling guards **in one commit**. One
tested the value with `.strip()`; the other stopped at bare truthiness. A whitespace-only value
therefore passes the second guard and fails the first: two siblings disagree about what
*"supplied"* means, in code authored together, by one author, in one edit.

## Root cause

This is a different shape from the *"missed the Nth site"* defect the same run also produced
(finding `7f14d3`, the fourth site of a three-site fix). There, a site was never touched — so a
*"did I find every site?"* sweep would have caught it.

Here **both sites were touched in the same edit and still diverged**, so no completeness sweep
reaches it. The check that catches this one is *"do the sites I just wrote agree?"*, not *"did I
find them all?"*.

The symmetric-pair detector already exists in `ext-self-review-plan-marshall`. The gap is that it
fires on **structural** divergence between paired sites and not on a **strength** difference
between two guards that are structurally alike.

## Proposed action

When a change writes a symmetric pair — two guards, two mirrors, two lanes — compare the two
written forms **against each other** before the round closes, not merely each against the
requirement. Extend the existing symmetric-pair detector from structural divergence to guard
strength: a pair where one member tests a normalized value (`.strip()`, a parse, a cast) and the
other tests the raw value is a divergence even when both are syntactically well-formed.

## Impact

The divergence was introduced **into the remedy for the very class it belongs to**, which is what
makes it worth a detector rather than more care. It is the ninth of the nine instances enumerated
in `2026-09-06-08-001`.

# Persist each task's changed_files so per-task artifact emission stays measurable

## Context

The logging-gap aspect's strongest check — ARTIFACT_EMISSION, which asks what fraction of change-qualified completed tasks emitted at least one per-task `[ARTIFACT]` line — could not run at all on this plan. `change_attribution` came back `unavailable` with the reason that no completed task record carries a `changed_files` list. The check that would independently have caught this plan's real emission gap was disabled by missing data, and the gap surfaced only through the weaker OUTCOME_COVERAGE rule.

## Root cause

phase-5-execute Step 8 already computes each task's diff against its `task_start_sha` in order to decide whether to emit `[ARTIFACT]` at all. That diff is used for the branch decision and then discarded. Nothing persists it, and the per-task SHA range is not written anywhere stable, so an offline reader has no way to reconstruct which tasks changed files.

## Proposed action

Write the computed diff to the task record as a `changed_files` list at the point Step 8 already holds it. A present-but-empty list is a measurement ("this task changed nothing") and is what makes a compliant no-op task distinguishable from an unrecorded one — which is precisely the distinction the ARTIFACT_EMISSION population rule needs in order to qualify M and N honestly.

## Evidence

- aspect: logging_gap_analysis — `change_attribution: unavailable`, reason "no completed task record carries a changed_files list"; the eligible-task keys are absent rather than zero, so the rule correctly emitted no finding and correctly reported that it could not look
- aspect: log_analysis — artifact_emission.completed_tasks 13, tasks_with_artifacts 7, tasks_without_artifacts [TASK-003, TASK-005, TASK-007, TASK-010, TASK-012, TASK-013]; without change qualification none of those six can be told from a compliant no-op
- aspect: llm_to_script_opportunities — complexity low, the value is already computed and thrown away

## Recurrence — 2026-09-06 (every-test-runs-and-the-suite-does-not-slow-down, PR #1426)

Reproduced unchanged over a larger task population. `change_attribution: unavailable`, with
the same reason: "no completed task record carries a `changed_files` list, so no task diff
could be attributed". The ARTIFACT_EMISSION rule again could not run, and again correctly
emitted no finding and reported that it could not look.

The un-qualified counts this run: 12 completed tasks, 10 with per-task `[ARTIFACT]` lines,
`tasks_without_artifacts: [TASK-001, TASK-008]`. Both of those are **verification-profile**
tasks — TASK-001 derived and classified the skip inventory, TASK-008 wrote the before/after
report — and both are expected to have empty diffs, so both are almost certainly compliant
no-ops rather than emission gaps. But "almost certainly" is the point: without the
`changed_files` list, the retrospective can only infer that from the task profile, which is a
weaker signal than the measurement the rule was designed around. On a plan where a
change-bearing task had silently skipped emission, the same 10-of-12 shape would have been
indistinguishable.

Three runs in a row (`plan-145`, `plan-150`'s sibling observations, and this one) the
strongest logging-gap check has been disabled by a value Step 8 already computes and
discards.

## Recurrence — 2026-09-09 (close-the-runtime-slice-parametrization, PR #1455)

Four in a row. `change_attribution: unavailable`, same reason verbatim: "no completed task
record carries a `changed_files` list, so no task diff could be attributed". ARTIFACT_EMISSION
again could not run, and again correctly emitted no finding while reporting that it could not
look.

This run makes the cost concrete rather than hypothetical. The sibling OUTCOME_COVERAGE rule
DID fire — TASK-007 completed with a non-empty diff and no `[OUTCOME]` line — and the
un-qualified counts were 12 completed tasks, 9 with artifacts,
`tasks_without_artifacts: [TASK-006, TASK-007, TASK-008]`. TASK-006 and TASK-008 are
verification-profile tasks with expected-empty diffs, so they are near-certainly compliant
no-ops. **TASK-007 is not** — it is a `module_testing` task the extractor separately places in
`tasks_with_diff_no_outcome`. So one of the three was a real gap and two were compliant
silence, and the only reason that is knowable here is a second rule happening to fire on the
same task. The measurement this lesson asks for would have separated them directly.

The previous entry's caveat — "on a plan where a change-bearing task had silently skipped
emission, the same shape would have been indistinguishable" — is no longer hypothetical. That
plan is this one.

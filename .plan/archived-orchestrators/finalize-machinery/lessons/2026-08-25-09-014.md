# 2026-08-25-09-014 — review_completeness --measured-diff-size is the one flag the empty-is-safe guarantee does not cover

component: plan-marshall:automatic-review
category: bug
status: moved-to-epic (corpus original retired 2026-09-17: completely_covered — contract correct at HEAD, verified by PR #1507 run)
source: corpus lesson 2026-08-25-09-014, moved into finalize-machinery per operator direction

## Context

A `review_completeness check` call was rejected by argparse when
`--measured-diff-size` was interpolated with an empty value. The executor strips an
empty-string argument, so `--measured-diff-size ""` reaches the parser as a bare
`--measured-diff-size` with nothing after it, and a scalar option with no `nargs`
rejects that with "expected one argument".

The rejection is exit 2 — the script body never runs, so the whole completeness check is
lost rather than degraded.

## Root cause

Verified in source. `review_completeness.py` declares `--measured-diff-size` with
`default=''` and **no** `nargs='?'`. Every one of the eight LIST flags on the same
sub-parser does take an optional value, and the module docstring states the guarantee
for "every list flag". `--measured-diff-size` is a scalar and sits outside it — and
the flag's own help text says "Omit it (the default) when unmeasured", which reads as
an assurance that an unmeasured value is safe to pass through.

## Proposed action

Give `--measured-diff-size` `nargs='?'` with `const=''`, so a bare flag reads as the
documented unmeasured default. Then state the guarantee over the flag set rather than
over the list flags.

## Evidence

- `review_completeness.py` — `--measured-diff-size`, `default=''`, no `nargs`
- module docstring — the empty-is-safe guarantee, scoped to "every list flag"
- observed: exit 2, argparse usage on stderr, the check never ran

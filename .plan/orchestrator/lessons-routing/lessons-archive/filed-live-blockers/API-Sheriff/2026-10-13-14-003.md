# Finalize steps with no implementor in a Maven consumer project record done instead of skipped

# Candidate lesson: phase-6 finalize steps assume the marketplace repo and do not fit a Maven consumer project

**Source:** plan-28-jwks-refresh-follow-ups, phase 6-finalize. Component candidates: plan-marshall:phase-6-finalize (pre-submission-self-review, pre-push-quality-gate, branch-cleanup).

## What happened

- **pre-submission-self-review could not do anything.** This project (API-Sheriff, Maven/Java) has no self-review surfacer registered. The only one that exists is pm-plugin-development:ext-self-review-plan-marshall, which is aimed at the marketplace repo. The step still recorded `outcome=done`, so the work log looks the same as a real review.
- **The pre-push-quality-gate and branch-cleanup docs are written for the marketplace repo** (python / pyprojectx commands). The gate had to be adapted by hand to the Maven equivalent, a whole-tree `verify -Ppre-commit`.

## Proposed rule

A finalize step that finds no implementor for this project should record `skipped` with a reason (for example "no self-review surfacer registered for this project's domains"), not `done`. A step doc that names build commands should resolve them through the build-system abstraction (`architecture resolve` / the canonical commands) instead of naming python/pyprojectx inline. Then a Maven, Gradle or npm consumer gets the right gate without adapting it by hand.

## Evidence

- Work log: `[STEP] ... Completed step: pre-submission-self-review (outcome=done)` at 11:15:35Z and 12:35:54Z, with no review activity in between.
- pre-push-quality-gate ran as an orchestrator-tier whole-tree `verify -Ppre-commit` (5987 tests, success) after manual adaptation.

## Scope hint

The likely target is the plan-marshall marketplace (a foreign store from this repository). The orchestrator should route it upstream.

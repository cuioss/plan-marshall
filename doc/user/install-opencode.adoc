Plan Marshall installs into OpenCode as native skills, agents, and commands. Installation is performed directly from the published `dist-opencode` distribution branch or immutable release tags (`opencode/v*`), either via a one-line installer script or manual clone.

== Prerequisites

[IMPORTANT]
====
Python 3 must be available as `python3` in your PATH.

[source,bash]
----
python3 --version
----
====

=== Supported platforms

The platform requirement is assistant-independent and stated once in xref:install-claude.adoc[Installation (Claude Code) › Supported platforms]: a single POSIX runtime, macOS and Linux native, Windows exclusively inside WSL2. On Windows, install OpenCode inside the WSL distro alongside the rest of the runtime.

== Fast Installation (Recommended)

Run the one-line installer script directly in your terminal:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash
----

This script automatically downloads the latest snapshot from `dist-opencode` and deploys the components into the standard OpenCode configuration directory:
`~/.config/opencode/{skills,agents,commands}/`

The installer performs the necessary singular-to-plural mapping (`skill/` -> `skills/`, `agent/` -> `agents/`, `command/` -> `commands/`) and manages only Plan Marshall components via `.plan-marshall-manifest.json`. Any custom, non-Plan Marshall components already present in your OpenCode configuration are safely preserved.

Restart OpenCode or open a new session. OpenCode automatically discovers the installed skills and agents.

== Selective Bundle Installation

Plan Marshall supports installing only the domain modules needed for your project or workflow:

* **Mandatory Core**: `plan-marshall` is always installed and provides the runtime foundation, stewards, and architecture tools.
* **Domain Bundles**: Tailored skill and agent bundles for specific tech stacks.

=== Domain Aliases and Bundles

The installer provides shorthand aliases for domain bundles:

[cols="1,2,2",options="header"]
|===
| Alias | Bundles | Description
| `core` | `plan-marshall` | Core execution context, stewards, and architecture tools (mandatory).
| `java` | `pm-dev-java`, `pm-dev-java-cui` | Java, JUnit 5, Quarkus/CDI, Maven, and CUI Java standards.
| `python` | `pm-dev-python` | Python 3.10+, pytest, pyprojectx, and import linting.
| `frontend` | `pm-dev-frontend`, `pm-dev-frontend-cui` | TypeScript/JavaScript, CSS, Lit, ESLint, and CUI frontend standards.
| `oci` | `pm-dev-oci` | Container images, Dockerfile standards, and container security.
| `docs` | `pm-documents` | AsciiDoc and documentation verification tools.
| `reqs` | `pm-requirements` | Requirements engineering and traceability.
| `plugin-dev` | `pm-plugin-development` | Plugin maintenance and doctor tools.
| `all` | All available bundles | Default installation set.
|===

[NOTE]
====
Dependency closure is automatic: selecting `pm-dev-java-cui` automatically includes `pm-dev-java`, and selecting `pm-dev-frontend-cui` automatically includes `pm-dev-frontend`.
====

=== CLI Options

You can specify bundle selection directly via CLI flags:

* `--core-only`: Install only the mandatory core bundle.
* `-b, --bundles <csv>`: Install specific bundles or aliases (e.g. `--bundles python,docs`).
* `--without-bundles <csv>`: Exclude specific bundles or aliases from the full set (e.g. `--without-bundles java,frontend`). Core cannot be excluded.
* `--all`: Install all bundles.

Example with specific bundles:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash -s -- --bundles python,docs
----

Example with core only:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash -s -- --core-only
----

=== Interactive Selection

When `install.sh` is executed in an interactive terminal without bundle flags, it prompts you to choose bundles:

[source,text]
----
Plan Marshall Bundle Selection:
  Core: plan-marshall [MANDATORY]
  Available domain aliases: java, python, frontend, oci, docs, reqs, plugin-dev
Install [A]ll (default), [C]ore only, or comma-separated bundles/aliases:
----

In non-interactive or CI environments (`CI=true` or `PLAN_MARSHALL_NON_INTERACTIVE=1`), the prompt is bypassed and all bundles are installed by default.

== Pinned Release (Specific Version)

For reproducible installations, download the installer directly from the desired immutable release tag:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/opencode/v0.1.0/install.sh | bash -s -- --ref opencode/v0.1.0
----

== Workspace-Scoped Installation

To install Plan Marshall into a specific project repository rather than globally, pass `--workspace` (or `-w`):

[source,bash]
----
cd /path/to/my-project
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash -s -- --workspace
----

This installs into `<project-root>/.opencode/{skills,agents,commands}/`.

== Manual Installation (Clone or Download)

If you prefer to inspect the files before installing:

[source,bash]
----
git clone -b dist-opencode https://github.com/cuioss/plan-marshall.git /tmp/plan-marshall-opencode
/tmp/plan-marshall-opencode/install.sh
rm -rf /tmp/plan-marshall-opencode
----

== Updating

=== Atomic Update (`-U, --update`)

To update an existing installation, pass `-U` or `--update`:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash -s -- --update
----

Or via local script:

[source,bash]
----
~/.config/opencode/plan-marshall-install.sh --update
----

* **Preserves Installed Selection**: If no bundle flags are provided with `--update`, the existing bundle selection recorded in `.plan-marshall-manifest.json` is preserved.
* **Modifying Bundles on Update**: You can change your installed bundles by passing `--bundles` or prune bundles with `--without-bundles` alongside `--update`.
* **Atomic Rollback**: If an error occurs during update, all managed files, `opencode.json`, and `.plan-marshall-manifest.json` are automatically rolled back from an in-memory backup snapshot.

=== Snapshot Users

Re-run the installer script:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash
----

=== Pinned Users

Run the installer directly from the new release tag:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/opencode/v0.1.1/install.sh | bash -s -- --ref opencode/v0.1.1
----

== Uninstallation

=== Full Uninstallation

To remove Plan Marshall components while keeping your other custom OpenCode skills and commands untouched, pass `--uninstall`:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash -s -- --uninstall
----

For a workspace-scoped install:

[source,bash]
----
curl -fsSL https://raw.githubusercontent.com/cuioss/plan-marshall/dist-opencode/install.sh | bash -s -- --workspace --uninstall
----

Or if you have the local installation file:

[source,bash]
----
~/.config/opencode/plan-marshall-install.sh --uninstall
----

=== Selective Bundle Uninstallation

To remove specific domain bundles while keeping the rest of Plan Marshall and custom files installed, use `--uninstall --bundles <csv>`:

[source,bash]
----
~/.config/opencode/plan-marshall-install.sh --uninstall --bundles python,docs
----

[NOTE]
====
The mandatory core bundle (`plan-marshall`) cannot be uninstalled selectively. Similarly, base bundles cannot be removed while a dependent child bundle remains installed (e.g. `pm-dev-java` cannot be removed without also removing `pm-dev-java-cui`).
====

== Execution Context & Model Selection

Plan Marshall uses dynamic execution context variants (`execution-context-level-1` through `level-7`) for subagent dispatches across project phases.

In OpenCode:

* **Session model inheritance**: All subagents run using your currently active OpenCode session model (`inherit` behavior). Level variants do not switch models automatically across tiers in this release.
* **Architecture**: Subagents are static markdown files deployed under `~/.config/opencode/agent/`. They omit hardcoded model pins so they work reliably across whichever model provider (Anthropic, OpenAI, local Ollama, etc.) you have configured in OpenCode.
* **Future custom ladders**: Machine-local effort ladder customization for OpenCode via `.plan/local/effort-ladder.json` will be supported in an upcoming update with a local in-place rewriter.

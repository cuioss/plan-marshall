# An outline success criterion copied from a work package named a Traceability entry that does not exist

- Component: pm-mcp-core (work packages under `doc/plans/`, `doc/Traceability.adoc`); process: plan-marshall:phase-3-outline
- Category: improvement (project-local)
- Signal: corpus-group-contamination (PR #86), found at the functional review, not by the outline Q-Gate

## Observation

Deliverable 5 of the outline said: "in the entries of PM-WORK-6 and PM-TEST-6 [of `doc/Traceability.adoc`],
extend the implementation scope text, `Verified by:` and `Documentation:` lines", and its success criterion
required both entries to name the new members. The wording came from the work package file
(`doc/plans/corpus-group-contamination.adoc`). `Traceability.adoc` has no PM-TEST-6 entry, and the change does
not implement PM-TEST-6. Nothing checked this until the functional review.

The outline Q-Gate checked that every listed path exists, and `doc/Traceability.adoc` does. It did not check that
the entries the deliverable names inside that file exist, or that the change implements the requirements named.

## Root cause

A work package file is a task list written before the work, and since the redistribution of the work packages
(#85) it can name requirements, entries or files that are wrong for the change. The outline copied its claims as
facts. Checking file existence does not catch a wrong id inside a file that exists.

## Suggested correction

- When the outline names an entry inside a file (a requirement id in `Traceability.adoc`, an anchor, a section of
  a specification), open the file and check that the entry exists before writing the deliverable. A missing entry
  is a decision for the outline: create it, because the change implements the requirement, or drop it, because it
  does not.
- For every requirement id taken from a work package, check against the requirement text in
  `plan-marshall-documentation` that this change implements, verifies or documents it. A work package's list of
  requirements is a starting point to check, not a fact to copy.
- Write success criteria from the checked list, not from the work package text.

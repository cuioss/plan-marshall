# The weakened_test integrity check counts phantom removals around raw U+2028 and re-files an operator-accepted verdict on every review firing

## Problem

The test-integrity check (the `weakened_test` verdict of the phase-6 functional-review and code-review firings) reported 27 assertions gone across 14 test identities in `InsufficientScopeChallengeParserTest` (PLAN-28, PR #892). The real diff against the base removes one assertion line and adds nine, and the only genuine removal is the operator-decided inversion `shouldAcceptUnquotedScope` to `shouldRefuseUnquotedScope`. The other 13 identities are untouched by the diff.

The most likely cause (not run, a reading of the finding) is the check's line-based parsing of a base file that holds raw U+2028 characters: Java treats them as ordinary characters in a string literal, but a Unicode-aware line splitter treats them as line breaks, which shifts the assertion counter.

The finding then recurred three times for one root cause, each time needing a separate triage:

- Q-Gate finding 3a2142, functional-review firing, resolved by an operator AskUserQuestion acceptance as a check artifact.
- Finding a994eb, code-review firing against base e61ceb42, the identical 27 / 14 verdict re-derived and re-filed (it named Bounds, DuplicatesAndQuoting, SecondScheme and Statelessness identities the diff does not touch).
- Finding 565027, functional-review re-fire after HEAD advanced to 7d929659, the third identical verdict, accepted again under the same decision.

## Solution

Two framework-side changes, for the plan-marshall maintainers (the repository cannot fix either):

1. The assertion counter should split on `\n` only, or parse the Java source, not split on Unicode line separators (U+2028, U+2029, U+0085), so a file with a raw separator in a literal cannot produce phantom removals.
2. An accepted `weakened_test` disposition should be carried forward for the same file when its diff against the base is unchanged, across review firings and HEAD advances, instead of being re-derived and re-asked.

Project side, already done in PLAN-28: the raw U+2028 literals were replaced by ` ` escapes (see lesson on raw invisible Unicode characters in test literals), which removes the trigger for this repository.

## Impact

Three triage rounds, two of them operator questions, for a finding that was a counting artefact. The deliberate-inversion part of the same finding is a separate cause (see the outline lesson: declare a deliberate test inversion in Tests-to-remove).

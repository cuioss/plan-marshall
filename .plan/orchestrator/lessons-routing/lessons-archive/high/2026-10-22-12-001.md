# Declare every flag a workflow passes, or stop passing it

## Context

A plan that measured OpenCode tokens (PLAN-LB-49, 2026-10-22) logged 41 `ERROR` entries in its `script-execution.log`, most of them argparse rejections at the flag level, and the same shape recurred on many scripts within one plan: `manage-change-ledger query --plan-id` (7), `manage-tasks get --field` (5), `platform-runtime harness bash-timeout-ceiling --plan-id` (3), `manage-architecture resolve … --plan-id` (2), plus `manage-adr scan --plan-id`, `run_config commit-trailer --plan-id`, `manage-references list`, `manage-tasks read --task-id`, `manage-findings --hash_id` and an invented `manage-change-ledger read` verb. Every rejection cost a round trip, and in three cases the calling step fell back to a weaker evidence path rather than retrying with the right shape. The plan's own lesson quoted slightly different counts (6 and 7 for the first two); the pattern, not the count, is the finding.

## Root cause

`--plan-id` is treated as universal routing state, but each script declares it in a different place: router-level on `ci`, subcommand-level on `manage-config` and `manage-architecture`, and not at all on `manage-change-ledger`, `manage-logging read` or `manage-tasks get`. Workflow prose that says "forward `--plan-id` to every script call" is wrong as written, and an agent quoting it verbatim produces a rejection the script's own parser could have predicted. The "never append `--plan-id` by rote" instruction already exists in `agents/execution-context.md`; it did not prevent the pattern.

## Proposed action

Make the mismatch unreachable at runtime: give `execute-script.py` a validation mode that builds the target script's real argparse parser and parses the requested argv without executing it, returning the accept-set on rejection (the executor already returns `accepted:` on a rejection). In parallel, sweep the workflow docs for `--plan-id` on the scripts whose parser does not declare it and delete the flag from those call sites. Not found in source at `3baf825e4`: the parse-only mode.

# The star-unpacked load_script_module idiom is a loader-guard blind spot that propagates by copying

## Directive

Never call `load_script_module` with a star-unpacked tuple:

```python
# WRONG — the guard cannot see this registration
_GIT_WF = ('plan-marshall', 'workflow-integration-git', 'git-workflow.py')
git_workflow = load_script_module(*_GIT_WF)
```

Pass the three arguments as module-level string constants instead:

```python
# RIGHT
_BUNDLE = 'plan-marshall'
_SKILL = 'workflow-integration-git'
_SCRIPT = 'git-workflow.py'
git_workflow = load_script_module(_BUNDLE, _SKILL, _SCRIPT)
```

Runtime behaviour is bit-identical. Only **static readability** changes.

## Mechanism

`_positionals_are_indexable` rejects a `Starred` node at index 0 (`0 > SCRIPT_ARG_INDEX` is false), so the script position is statically unreadable. The call then falls into the unresolved-call-site tally guarded by `test_unresolved_call_sites_are_reported_not_hidden` in `test/plan-marshall/script-shared/test_conftest_loader_contract.py` — which means **the collision guard cannot see that registration at all**. It is not merely untidy; it is a hole in a guard. Read the bound's own module-level docstring for how it is expressed today rather than trusting any restatement of it here.

## How it propagates — the part worth guarding

Observed 2026-08-27 in PLAN-TRUTH-114: a **new** test file acquired the defect by *copying* the idiom from its sibling `test_worktree_move_lifecycle.py`, tipping the bound from 90 to 91 and failing the build.

That is the mechanism worth remembering. The idiom looks like tidy DRY, so it spreads between sibling test files by copy-paste, and **each copy silently widens the guard's blind spot**. The bound only catches it once the accumulated copies push the guard past its threshold — the earlier copies never announced themselves.

## When the bound trips

Fix the call site the way the guard's own message prescribes — hoist the argument. **Never raise the bound to admit your own new site.** Establish which site is yours by running the guard's own detector (`_scan_test_tree` from `_loader_contract_fixtures.py`) and diffing against the branch's test footprint; do not eyeball the diff.

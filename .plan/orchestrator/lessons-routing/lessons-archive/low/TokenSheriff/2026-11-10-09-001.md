# Review-bot triage commits a source fix in 6-finalize without a sanction and is refused

## Problem

The review-bot triage in the finalize wait region tried to commit a source fix for two CodeRabbit findings (CLAUDE.md and doc/validation/security-reference.adoc) and the git workflow refused it:

```
Source-tree commit refused in 6-finalize: no step id from the composed phase-6 manifest, no open loop-back fix task and no review-rubric section-6 inline-correction record. Route the fix through a loop-back to 5-execute (open a fix task), pass --step with a composed phase-6 manifest step id, or record the section-6 inline correction, then retry.
refused: true, reason: no_sanction, phase: 6-finalize, step: null
```

The triage commit carried no `--step` and no loop-back fix task, so the sanction guard rejected it and the run only recovered through loop-back iteration 1/5, which committed the fix as `abef336e`. The guard was discovered by failure.

## Solution

The review-bot triage path should pass the composed phase-6 step id, or open the loop-back fix task, before it commits a source fix, instead of learning about the sanction guard from a refused commit. A refusal that names its three remedies is correct for a hand-driven commit; an automated triage step should select one up front.

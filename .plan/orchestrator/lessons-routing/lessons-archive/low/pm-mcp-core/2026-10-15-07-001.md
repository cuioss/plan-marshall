# A docs PR left open while upstream rewrites the same specification keeps spec text it should have deleted as implemented

- Component: pm-mcp-core (pm-workflow `composition-rules.json`, `PruneReason`); process: documentation PR in plan-marshall-documentation
- Suggested category: improvement
- Signal: plan-24-plan-instance (PR #67, merged as 2ebec2a)

## Observation

The plan-instance work shipped `composition-rules.json` and the closed `PruneReason` set with the values
`recipe_override` and `auto_merge_off`. While the plan ran and its documentation PR stayed open, upstream
rewrote the same specification (plan-marshall-documentation #76). After that rewrite the specification
targets `plan_default` and `merge_by_operator`, with axes, overrides and phase sub-workflows. The code and the
specification now name different things, and the gap is recorded in PM-IMPL-5 and in the Remaining list of the
roadmap. Operator decision of 2026-10-15: the alignment is a follow-up work package, not part of this plan.

A documentation PR that sits open while the upstream specification is rewritten ends up keeping the
specification text it should have deleted as implemented: the text it was written against no longer exists, so
a rebase resolves the conflict in favour of the text that is still there.

## Suggested correction

- Before a documentation PR that deletes "implemented" specification text is merged, re-read the specification
  it edits at its current HEAD, not at the commit the plan started from.
- When the upstream rewrite moves the target (new names, new axes), do not delete the text as implemented. Keep
  it, mark the gap in the implementation watch (PM-IMPL-n) and the roadmap Remaining list, and file a work
  package for the alignment.
- Keep a documentation PR short-lived: merge or rebase it right after the code PR, so the window for an
  upstream rewrite stays small.

Related: lesson 2026-10-13-06-001 (code drifting from a specification that changed while the plan ran). This
one is the documentation-side counterpart: the specification text, not the code, is what goes stale.

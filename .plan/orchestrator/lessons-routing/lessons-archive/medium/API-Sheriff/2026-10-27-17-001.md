# When main moves during a long finalize, a sibling plan can change a cross-cutting contract without touching your lines: re-run the affected ITs on the merged result

Source: PLAN-V02-05 (#526), candidate lesson 004; extends the finalize-main-drift memory.

## Observation

`main` moved twice during finalize. The second move (#528, the uniform 404 for untrusted callers) did not conflict textually but did semantically: this PR's `ErrorContractIT` still expected 405 and 401 for those callers. A code-review test-integrity check also reported a weakened test that was only base drift (an assertion added by #527 after the branch's merge base).

## Rule

- When main moves during finalize, re-run the integration tests the other change could affect against the merged result, not only the textual merge. A cross-cutting contract (status codes for untrusted callers, header sets, config keys) can change under a branch that never touches those lines.
- For a long branch, prefer one `merge origin/main` resolution over replaying many commits by rebase; the squash merge makes the merge commit irrelevant.
- Compare a weakened-test finding against current `origin/main` before treating it as real.

## Apply

Every plan whose finalize outlasts a merge of a sibling plan; check the sibling's landing for contract changes first.

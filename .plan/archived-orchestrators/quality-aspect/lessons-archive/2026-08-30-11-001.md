# Zero-overlap self-absorb is structurally blind at first phase-5 entry, so a relocating upstream commit is absorbed as no-overlap

## Symptom

`phase-5-execute` Step 3 detected baseline drift, ran `git-workflow baseline-reconcile --no-emit`, got `conflict_count: 0`, and took the self-absorption branch — writing `main_sha`/`worktree_sha` metadata and logging "Absorbed N upstream commits with zero overlap", asserting that "the request narrative, solution outline, task list, and confidence score remain valid".

They did not. The absorbed commit had **relocated the plan's primary target files out of the module the plan targets**. The very first task load revealed its `step_target` did not exist on the new baseline.

## Why the predicate said zero

`baseline-reconcile` computes overlap with `git merge-tree` against `HEAD` and `origin/{base}`, and reports `conflict_count` — the number of files where a three-way merge would conflict. Conflicts are only possible against **in-flight worktree changes**.

At the *first* entry into phase 5 the worktree has, by construction, zero in-flight changes: no task has run yet. The reconcile output made this explicit with `in_flight_files[0]:` (empty). So `conflict_count: 0` was arithmetically correct and semantically empty — it said *"nothing you have written conflicts"*, not *"your plan is still grounded"*.

The predicate is therefore **structurally blind on every plan's first phase-5 entry**. It cannot fire there, no matter how destructive the upstream commit is to the plan's premise.

## Concrete instance

Plan `plan-170-make-the-attribution-usable`, worktree HEAD `b510ef29`, upstream `b758d5c02` (#1366).

The absorbed commit moved the spec-parser module:

| Plan's declared path (present at worktree HEAD) | On `origin/main` |
|---|---|
| `marketplace/bundles/pm-plugin-development/skills/tools-epic-surface-partition/scripts/_epic_spec_parser.py` | deleted → `marketplace/bundles/plan-marshall/skills/script-shared/scripts/epic_spec_parser.py` |
| `test/pm-plugin-development/tools-epic-surface-partition/test_epic_spec_parser.py` | deleted → `test/plan-marshall/script-shared/test_epic_spec_parser.py` |
| `test/pm-plugin-development/tools-epic-surface-partition/test_epic_spec_parser_notation.py` | deleted → `test/plan-marshall/script-shared/test_epic_spec_parser_notation.py` |

Three of eleven declared `affected_files` were deleted from their declared locations — and those three are the entire target set of deliverable 1 (tasks 1 and 2).

The blast radius is wider than the file paths: the module **changed bundles**, from `pm-plugin-development` to `plan-marshall`. Task 1's stamped verification command was `compile pm-plugin-development`, which after the move does not even build the module containing the code the task is supposed to change. A task could therefore have gone green while touching nothing that mattered.

Had execution continued, the deliverable would have added marker rules to a file `main` deletes. `finalize-step-sync-baseline` would have hit a modify/delete conflict, and the real parser at `script-shared` would have been left untouched — the "buildable-but-valueless artifact" the infeasible-deliverable contract explicitly prohibits.

## Fix

`conflict_count` is a necessary but not sufficient overlap signal. Add a **path-existence check** to the self-absorption branch that does not depend on in-flight state:

> Before absorbing, intersect the upstream commits' changed-path set with the plan's declared footprint (`references.json:affected_files` ∪ the deliverables' `affected_files`). For each path in the intersection, verify it still **exists** at `origin/{base_branch}`. Any declared path that the upstream commits deleted or renamed away is drift with overlap, regardless of `conflict_count`.

This is cheap (`git ls-tree`/`git diff --name-status` against the already-fetched ref), deterministic, and — unlike `merge-tree` — is fully sensitive at first entry, when no in-flight changes exist. A rename (`R` status) is the highest-signal case: it means the plan's target moved rather than vanished, so refine can re-anchor rather than re-plan.

Two supporting changes:

1. `baseline-reconcile`'s `classification: no_overlap` should be qualified when `in_flight_files` is empty — an empty in-flight set makes `no_overlap` unfalsifiable, so it should be reported as *not measurable* rather than as a clean negative. This mirrors the `could_not_look` / `footprint_resolved: false` discipline already used by `scope_creep_check` and `verify_failure_scope`, where an unmeasurable comparison is deliberately distinguished from a measured zero.
2. When absorption is rejected on path-existence grounds, return the existing `error: baseline_drift` shape so the orchestrator's drift-recovery branch re-dispatches `phase-2-refine`. No new terminal outcome is needed.

## Recurrence signature

Any plan whose first phase-5 entry follows an upstream commit that touches its footprint. The failure is silent and self-congratulatory — it logs a success-shaped "Absorbed N upstream commits with zero overlap" decision line — so it is only caught if the executor independently notices the missing target on task load. Relocation-heavy commits (module extractions, bundle moves) are the highest-risk trigger, because they delete every declared path at once while conflicting with nothing.

# A subagent dispatch seam that answers prompt_not_found must log a script_failure marker and be fixed, not bypassed

When the platform-runtime subagent dispatch seam answers `prompt_not_found` for an installed agent, the seam must log a `script_failure`-class marker, and the cause (a variant-suffixed agent name against a bare-name lookup, or the bundle cache path against the worktree path) must be fixed, because every bypass with the host Agent tool skips what the seam guarantees and hides the defect from later runs.

## What happened

In plan client-refresh-verification-discovery-cache the orchestrator asked the platform-runtime subagent dispatch seam to dispatch the `execution-context` agent. The seam returned `prompt_not_found`. The dispatcher bypassed the seam and dispatched with the host Agent tool directly, and dispatch then worked: the work log shows the `execution-context-level-3/4` targets running normally, so the agent definition was installed and reachable. Only the seam's prompt lookup failed. The work log carries no `[ERROR]` marker for the event, so the signal-scan cannot see it.

## Why it matters

- A workaround skips whatever the seam guarantees: model and effort pin resolution, dispatch logging and target-specific prompt shaping.
- An unlogged fallback means the seam defect recurs in every run without a trace.

## Rule

- Log a `script_failure`-class record whenever the seam returns `prompt_not_found`.
- Investigate why the lookup misses the `execution-context-level-N` variant prompts; the two causes named by the lane are hypotheses, not findings.

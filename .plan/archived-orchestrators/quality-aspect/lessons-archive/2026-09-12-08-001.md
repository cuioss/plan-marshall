# CI timeout with check still in progress is infrastructure noise, not a code defect

Source: build-path-evidence (tooling-truthfulness), PR #1469. Owed architecture
hint, recurrence x2 (two `[ci_timeout] verify / verify failed` findings, both
resolved `taken_into_account`).

## Problem

A `verify / verify` CI timeout filed as a failure while the check was still
`IN_PROGRESS` (pending) on the PR — no failing check, no code defect to fix.
The failure-shaped signal invites a fix task for transient infrastructure noise.

## Guidance

Treat a verify-timeout-with-check-still-`IN_PROGRESS` as transient: re-poll the
check before filing any fix task. Only a settled failed check (not a timed-out
poll against a pending one) justifies defect-shaped work.

# Light lane cannot satisfy the pr_title_present invariant — no writer on that path

## Problem

On the **light planning lane**, `plan-marshall:plan-marshall/workflow/planning.md` § "Light-lane branch" step 2 requires the orchestrator to close `2-refine` **pre-dispatch** with three calls: `manage-status transition --completed 2-refine`, `manage-metrics phase-boundary`, and `phase_handshake capture --phase 2-refine`.

The third call fails:

```
status: error
error: pr_title_missing
message: "pr_title_present failed for phase '2-refine': metadata.pr_title is absent or empty —
          phase-2-refine Step 13 must author and persist a commit-style PR title"
```

The `pr_title_present` invariant is armed at the `2-refine` boundary, but its **only writer is `phase-2-refine` SKILL.md Step 13** — a phase body the light lane never dispatches. The light lane therefore cannot reach its own documented pre-dispatch capture without a manual, undocumented orchestrator-side write.

Observed on plan `pre-push-gate-mutation-coherence` (planning_lane=light, routed by `manage-status planning-lane route`), repo `plan-marshall`, HEAD `fa5a7cdce`.

## Why it matters

The workflow doc already anticipates exactly this class of gap for the sibling call and resolves it explicitly — it says of the `transition` call that it "has **no orchestrator-side deep-lane counterpart to mirror** … so the call in (a) is written from the verb's own contract rather than copied from a deep-lane seam." The same reasoning applies to `pr_title`, but the doc never says so, so an orchestrator following the light-lane branch verbatim hits a hard `status: error` at step 2(c) with no prescribed handling.

The failure is **loud** (an error TOON, not a silent skip), which is the good case. The defect is that the documented happy path cannot complete.

## Directive

Close the gap at the **contract layer**, not by having each orchestrator improvise a title:

1. Name `pr_title` explicitly in `planning.md` § "Light-lane branch" step 2, alongside the existing paragraph that explains why the `transition` call has no deep-lane seam to copy — the same paragraph is the natural home. State that the orchestrator authors and persists `pr_title` from the clarified request before the capture, using the authoring rules that `phase-2-refine` SKILL.md Step 13 already owns (conventional-commit shape, <=72 chars, imperative, distinct from the plan's human `title`), and cross-reference that step rather than restating them.
2. **Or** — the alternative worth weighing — move the `pr_title` authoring into the light-lane envelope (`phase-3-outline/workflow/light-lane.md`) and move the `2-refine` capture to after the envelope returns. This conflicts with the two structural reasons the doc gives for keeping the capture pre-dispatch (metrics attribution by spawn timestamp, and the envelope's own Phase Entry Protocol verifying the row it would otherwise have captured), so option 1 is the cheaper fix.

Whichever is chosen, add a regression test that walks the light lane end to end and asserts `phase_handshake capture --phase 2-refine` returns `status: success` — the current test surface evidently does not cover the light lane's pre-dispatch closure, or this would have been caught.

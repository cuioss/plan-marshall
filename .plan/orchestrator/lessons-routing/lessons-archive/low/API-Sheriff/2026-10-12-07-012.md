# Two guards written in this plan checked less than their own description claimed

## What happened

Plan plan-25-integration-test-evidence (PR #408). The CodeRabbit re-review of the fix commits found two guards whose predicate was weaker than the property stated next to them. Both were verified in triage and fixed.

- 5d3b7a - `StubIdentityProviderWiringTest.PINNED_REFERENCE`: the Javadoc states an exact release tag plus digest, but the tag part of the pattern admitted any tag name, so `wiremock/wiremock:latest@sha256:<64 hex>` matched. Fixed (TASK-25): tag narrowed to a dotted numeric version of at least major.minor with optional suffix (three components would have refused the nginx pin `1.27-alpine`), and a control added that refuses `latest`.
- 930f38 - `pending_login_flood.js`, phase B age guard: the start time was taken after the login form had come back and the age was read before the completing callback, although the pending record lives from the first request to the end of the callback. The 30 s margin below the five-minute lifetime was an assumption, not a measurement. Fixed (TASK-24): the measured span now contains the whole life of the record; the limit stays at 270 s.

## Rule

- For every guard, write down the one input it exists to refuse and add that input as a negative control. A pattern guard without a refused-variant control for its headline property is unproven.
- A timing guard must measure the whole span of the thing it bounds, from before the first request that creates it to after the last call that reads it.
- When the description and the predicate disagree, fix the predicate and bring the description in line with what the predicate holds.

# With use_merge_queue=true the conflict gate forces a costly rebase for an overlap without a content conflict

With use_merge_queue=true the conflict gate should let an overlap with no content conflict proceed to the merge queue instead of forcing a local rebase and force-push, or the cost of the default threshold must be documented so operators choose it knowingly.

## What happened

In plan client-authorization-request-seam (PR #901), with use_merge_queue=true the gate returned overlap_no_content_conflict. Under the default threshold no_overlap_only that forced queue_wait=forbidden, an operator question, and an immediate rebase plus force-push. The rebase rewrote every commit SHA, which invalidated every head-dependent verdict (functional-review, code-review, pre-push gate) and cost a full re-review round, although there was no content conflict and the queue could have done the rebase itself.

## Rule

- For a queue-enabled project, a file-level overlap without a content conflict is what the queue resolves safely. Default the threshold to auto_resolvable, or document the re-verification cost beside the knob.
- Reserve the local rebase path for genuine content conflicts.

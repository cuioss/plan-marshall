# ci checks status omits a reusable-workflow caller's nested checks (review / changes, review / review) that GitHub shows as successful

On plan-marshall #1651, `ci checks status --pr-number 1651` listed 11 checks and none of them came from the "cuioss-review-bot Review" workflow. GitHub itself (`gh run list --workflow "cuioss-review-bot Review" --branch feature/plan-13-finalize-mechanism-defects`) shows run 36423408452 (pull_request, success) with jobs `review / changes` and `review / review`, both successful. The same verb DID list those jobs on #1639.

## Impact

The omission reads as "the reviewer never ran". It led to a wrong startup_failure hypothesis that suggested a fleet-wide outage, and to a request for an operator exception to the no-direct-gh rule. The omission is the absence of evidence, and no field reports whether the check list is complete.

## Solution

Find out why the status verb drops these check runs: likely check-suite pagination or dedup, or it only reads the latest suite per app. Make the verb enumerate every workflow run for the head SHA, or report that it truncated the list. Add a run-list-by-workflow verb, so this verification needs no direct gh.

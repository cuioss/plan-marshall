# Test speed-ups must keep the failure path: deadlines and fail-on-no-tests guards

## What happened

Two edits made to speed up the test cycle removed a safety property. Both passed the local builds, because the local builds only exercise the success path. Both were rated Major by the external reviewer on PR #795 and fixed in a later round.

**1. `failIfNoSpecifiedTests=false` in `token-sheriff-quarkus-parent/pom.xml`.** The surefire run was split into two executions (two reused forks). To let `-Dtest=SomeClass` work when the class is in only one of the two groups, `failIfNoSpecifiedTests=false` was hard-coded for both executions. The setting was not part of the outline. Result: a mistyped `-Dtest` finished green with zero tests run (review finding d16687). Fix in 8b6a383b: a `-Dtest` selection activates a profile with one strict execution, and `SurefireForkGroupGuardTest` fails if the lenient setting comes back.

**2. Deadline removed from `HttpJwksLoaderLockFreeStatusTest`.** A real wait in the observer loops was replaced by a completion signal. The signal was only given on the success path, and the time bound was dropped with the wait. Result: when start-up fails, the observers spin forever and `ExecutorService.close()` hangs, so the test hangs instead of failing (review finding 18f492). Fix in a6c46e2f: deadline restored as a backstop, signal released in `finally`.

## Rule

When an edit makes a test or a test run faster, check the failure path before the success path:

- **A wait replaced by a signal keeps its deadline.** The signal makes the normal case fast; the deadline is what ends the test when the signal never comes. Release the signal in `finally`.
- **A lenient build setting needs a guard for the case it relaxes.** If a setting stops the build from failing on "no tests matched", something else must still fail when nothing matched at all.
- **A setting that was not in the outline is a scope change.** If it weakens a gate, raise it with the operator before it ships, not as a note afterwards.
- **Ask for each such edit: what happens now when the thing under test is broken?** If the answer is "it hangs" or "it is green", the edit is not done.

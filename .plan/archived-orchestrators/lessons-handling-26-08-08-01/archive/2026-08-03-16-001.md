# cmd_enrich persistence loop hardcodes the four usage fields instead of deriving them from _FOUR_FIELD_USAGE_LABELS

Three latent defects in pre-existing `manage-metrics` code, surfaced by CodeRabbit
as outside-diff-range comments on PR #1086. None was introduced by that PR — it
merged `origin/main`, and CodeRabbit's review range for the merge commit swept in
already-landed upstream code.

## 1. Hardcoded four-field mirror in `cmd_enrich` (Major)

`manage-metrics.py` `cmd_enrich` persists the four `message.usage` fields through a
hardcoded tuple, introduced by #739:

```python
for field in (
    'input_tokens', 'output_tokens',
    'cache_read_input_tokens', 'cache_creation_input_tokens',
):
    if field in bucket:
        phase_row[field] = bucket[field]
```

`_FOUR_FIELD_USAGE_LABELS` is documented as the single source the render loop and
the contract test both read from, precisely so a field "cannot slip in unlabelled".
The persistence loop is not wired to it. A fifth usage field added to
`_FOUR_FIELD_USAGE_LABELS` would render under the group heading but never reach
`phase_row`, so the row would report it permanently absent — and absent-is-not-zero
makes that a silent under-count rather than a visible break.

Fix: iterate `_FOUR_FIELD_USAGE_LABELS` in the persistence loop.

## 2. Inline classification keys on sum truthiness, not field presence (Major)

The `inline_main_context` guard (arrived with #1083) tests the truthiness of the
summed inline fields before assigning `inline_main_context_tokens` and
`POPULATION_INLINE`. When the three summed fields are all present and all zero, the
row is classified `dispatched` and the **measured** inline zero is lost — the exact
absent-is-not-zero inversion the surrounding contract exists to prevent.

Fix: test field PRESENCE, not sum truthiness. Add an all-zero inline bucket test;
the existing tests only zero the exploration counters and leave inline non-zero
(`_INLINE_SUM == 6000`), so the case is untested.

## 3. Lattice completeness guard has false-pass paths (Major)

The token-field population lattice sweep checks only `derived - named`, so a stale
or mistyped field in `data-format.md` is never caught. It also hardcodes
`_RETURN_ONLY_USAGE_FIELDS` rather than reading the authoritative producer, its
`_derive_phase_row_fields()` does not match the dynamic
`phase_row[field] = bucket[field]` assignments (so it does not reliably discover
`cache_read_input_tokens`), and its raw-source regex can count a comment or
docstring as an executable assignment.

Fix: assert BOTH directions empty (`derived - named` AND `named - derived`), source
from shared production constants or syntax-aware extraction, and add a negative
control that removes `cache_read_input_tokens` and expects failure.

**Why these travel together**: all three are the same archetype — a set-guarding
detector or persistence site that mirrors an authoritative definition instead of
deriving from it. Each permits drift in a direction its own passing test cannot see.

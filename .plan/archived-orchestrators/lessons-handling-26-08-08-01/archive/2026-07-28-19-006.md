# A new regression detector's non-degeneracy anchor omits the very member the fix just added, and its guards skip-on-missing rather than fail — three instances shipped inside one plan's own tests

## Context

PR #1036 (PLAN-10, epic `test-suite-quality`) shipped three new population-derived regression
detectors — one per defect archetype it closed — each advertised as carrying "a non-degeneracy
anchor and a bites-check". CodeRabbit reviewed the final tree and posted five findings
**2m42s after the merge**; three were confirmed against merged main by the orchestrator. All
three are the same shape, and all three are **inside the plan's own new detectors**.

The epic's standing rule was already *"every set-guarding detector MUST be
population-derived"*. These three show that population-derivation is necessary but not
sufficient: the population can be correct while the **anchor** that proves it non-degenerate
is stale or absent.

## The three confirmed instances

**1. The anchor omits the member the fix just added.**
`test/plan-marshall/phase-6-finalize/test_step_completion_emission.py`,
`test_enumeration_finds_the_known_bypass_sites` anchors on `('4b', '4c', '5d')`. PLAN-10's D3
found **four** structural bypasses, and the fourth — item 5's dispatch-timeout path — was
found by pre-submission self-review and fixed in the plan's own **second commit**. That commit
did not extend the anchor. So the non-degeneracy check protects the three bypasses that were
known before the fix and not the one the fix added: if item 5's classification silently breaks,
the anchor stays green.

**2. The guard skips on missing input instead of failing.**
`test/plan-marshall/plan-retrospective/test_registered_aspects_render.py:100-102`:

```python
path = _SKILL_DIR / rel
if path.is_file() and path not in docs:
    docs.append(path)
```

A roster row naming a document that is not on disk is silently skipped, removing that
document's dispatches from the scanned population — so the registerability guard passes
vacuously. The docstring **rationalises it**: "A row naming a document that does not exist on
disk is skipped here; the roster-vs-disk consistency of those paths is not this guard's
concern." That is defending-documentation around a vacuous path. The guard exists to detect
roster drift; a roster row pointing at a missing file *is* roster drift.

**3. The assertion does not bind to the thing it verifies.**
`test/plan-marshall/phase-5-execute/test_execute_phase_markers.py`:

```python
_METADATA_SET_RE = re.compile(r'manage-status\s+metadata\b[\s\S]{0,200}?--set\b')
```

This accepts **any** `metadata --set` anywhere in Step 4. The deliverable (D2) was specifically
the `phase_5_first_entry_logged` marker write in the first-entry branch. Remove that write,
leave any other metadata `--set` in the section, and the test still passes.

## Corrective rule

**A detector's population must be derived, AND its non-degeneracy anchor must be derived or
re-checked whenever the population changes. An anchor is a hardcoded claim about the
population; a fix that widens the population invalidates it.**

1. **Extend the anchor in the same commit that widens the population.** When a fix discovers
   the member set is larger than believed, the anchor listing known members is stale by
   construction. Treat "the fix found a new member" as an automatic trigger to re-check every
   anchor over that population — the second commit is the highest-risk moment, not the safest.
2. **A guard must fail, not skip, when its input is missing.** `if path.is_file()` over a
   population source is a silent population reduction. Assert existence; a missing member of a
   derived population is the drift the guard exists to catch. (Same shape as
   `2026-06-24-18-003` — a missing input must be inconclusive-and-loud, never silently benign.)
3. **Bind the assertion to the specific artifact the deliverable creates**, not to its general
   syntactic family. `--set` is a family; `phase_5_first_entry_logged=true` in the first-entry
   branch is the artifact. A regex loose enough to match a sibling write is not a regression
   test for this deliverable.
4. **A detector's own bites-check must mutate the exact thing the deliverable fixed.** All
   three tests carried bites-checks and all three passed — they proved the detector fires on
   the *pre-fix shape*, not that it fires on *removal of the fix*.

## Impact

Every population-derived detector this epic standardised on — the pattern is now the house
style (`test/_shared/_dispatch_roster.py` and its descendants), so the failure mode propagates
with the pattern. The archetype's prior occurrence was inside PLAN-08's own regression test;
these three make it six occurrences, and the recurrence is now concentrated in the tests
written *to prevent* it.

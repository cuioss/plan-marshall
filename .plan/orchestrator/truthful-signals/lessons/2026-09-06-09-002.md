# triage.md prescribes deliverable: 0 for a FIX task, which manage-tasks commit-add rejects

## Problem

`plan-marshall/workflow/triage.md` § Step 3c prescribes `deliverable: 0` when allocating a FIX task. `manage-tasks commit-add` **rejects** it:

```text
Missing required field: deliverable
```

`0` is falsy, so the presence check treats it as absent. `manage-tasks/SKILL.md` separately specifies a **positive integer** for the field, so the two documents disagree and the script sides with the second.

## Why it is worse than a typo

**Any agent following `triage.md` verbatim hits a hard stop on its FIRST fix-task allocation.** The triage workflow is the sole path from a review-bot or Sonar finding to a fix task, so the defect blocks the entire finalize feedback loop for any plan whose review produces an actionable finding — precisely the plans that most need it. It fails at the moment the run has already spent a full review cycle.

## Archetype

Doc-contract-divergence: a workflow document prescribing an argument the script it calls does not accept. Same shape as this epic's recorded `argparse_rejection` recurrence signatures, one level up — the value rather than the flag name.

## Directive

Decide which side is authoritative, then make the other match:

1. If a deliverable-less FIX task is legitimate, `commit-add` must accept a sentinel that survives a falsy check — `None`/omitted with an explicit `--no-deliverable` flag, or a distinguished value — and `manage-tasks/SKILL.md` must document it.
2. Otherwise `triage.md` § Step 3c must stop prescribing `0` and instead say what the working run did: attach the fix task to the deliverable owning the cited file.

Whichever is chosen, add a test asserting that the value `triage.md` prescribes is one `commit-add` accepts, so the two cannot drift apart again silently.

## Observed

Encountered during plan `one-format-several-implementations-that-disagree`, finalize triage over PR #1427's CodeRabbit findings. Worked around by attaching each of the three fix tasks to the deliverable owning its cited file (6, 5, 5); the workaround is recorded as a WARNING in that plan's decision log.

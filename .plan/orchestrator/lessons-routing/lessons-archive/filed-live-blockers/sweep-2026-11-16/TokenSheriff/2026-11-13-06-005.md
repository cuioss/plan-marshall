# Reactor module-tests canonical 'mvn test' cannot resolve a sibling test-jar

A reactor-wide test canonical must run a phase that packages test-jars (`verify`, or `test-compile` plus `jar:test-jar`), or detect test-jar consumers and scope accordingly. A green `verify` on the same HEAD must not be the only way the gap is discovered.

## What happened

In plan validation-public-seams (PR #899), the phase-5 module-tests step resolved to plain `mvn test` over the whole reactor. The `test` phase never packages the `token-sheriff-validation` test-jar, so `token-sheriff-client` (test) and `benchmark-core` (main) failed to compile (package `de.cuioss.sheriff.token.validation.test` missing). 2577 tests passed before the reactor stopped; all seven failing paths were outside the plan footprint, and the Q-Gate finding was rejected as "not a plan defect" because the whole-tree `verify -Ppre-commit` was green on the same HEAD. The pre-push gate later hit the same failure. The project-side repair was `<type>test-jar</type>` on the consuming dependencies in four poms (commit 62b7f847, disclosed in PR #899); the plan-marshall build-maven canonical is NOT fixed.

## Rule

Resolve the reactor `module-tests` canonical to a phase that satisfies test-jar consumers, or make the build-maven script report the unsatisfiable consumer instead of a compile failure.

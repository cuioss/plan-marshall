# An edge end-path change checks the governing end-path ADRs first

When an outline plans a change to how a response or stream ends on the edge, it first reads the ADRs that govern the end path (ADR-0066: every response end passes one seam with one reset code; per-case marks are rejected) and either stays inside them or plans the amendment as a deliverable.

PLAN-V02-45's outline planned a dedicated reset code for admission-refused HTTP/2 streams, contradicting ADR-0066 without reconciling it. The Q-Gate caught it; the operator kept ADR-0066 and the per-case code was dropped (ADR-0060 Amendment A2 records why).

How to apply: for any deliverable touching `edge/end/`, `ResponseEnds`, a reset code or an end status, list the governing ADRs in the outline and name the amendment if one is needed.

# Cross-references into a doc anchored to an older external-taxonomy version (OWASP 2021) must use that doc's version numbers, not a newer version (2025) slipped in by the executor or a Boy-Scout fix

When a skill's document set spans **two versions of an external taxonomy**, every
cross-reference that points INTO an older-version document must cite that document's
own (older) version numbers. Slipping the newer version's numbers into those
cross-references — whether the executor does it while authoring, or a Boy-Scout
"consistency fix" does it after the fact — produces same-document and cross-document
numbering contradictions.

## Symptom

In the security skillset, `owasp-top-ten.md` was authored against the **OWASP 2021**
category numbering, while newer security docs in the same skill use the **OWASP 2025**
numbering. Cross-references that point INTO `owasp-top-ten.md` must use its 2021
category numbers. During this run, 2025 numbers leaked into those cross-references
(from the executor's drafting and from a Boy-Scout normalization pass), creating:

- **Same-document contradictions** — a cross-reference cited a 2025 number for a
  category that the same document defines under its 2021 number elsewhere.
- **Cross-document contradictions** — a reference from a 2025-numbered doc pointed at
  a 2021-numbered category using the 2025 number, so the link target's heading did not
  match the cited number.

The defect was caught **only** by the pre-submission structural self-review, and only
after **three iterations** — every other in-house gate (plugin-doctor, build, tests)
passed because each document is individually well-formed; the contradiction is purely
in the cross-reference numbering, which no deterministic gate validates.

## Root cause

A mixed-taxonomy-version cross-reference hazard. The taxonomy version a number
belongs to is **a property of the TARGET document**, not of the citing document or of
"the newest version the author happens to be thinking in." When the author defaults to
the latest version's numbering for every reference, references into older-version docs
silently acquire wrong numbers. Individual-document validation cannot catch it because
each doc is internally consistent; the contradiction lives in the cross-document
numbering relation.

## Durable fix

When a doc set spans two versions of an external taxonomy:

1. **Cross-references use the TARGET document's taxonomy version.** A reference into
   `owasp-top-ten.md` (2021-anchored) cites 2021 category numbers, regardless of which
   version the citing document is written in.
2. **OR carry an explicit dual-version annotation** at the reference site (e.g.,
   "A03:2021 / A02:2025") so the version each number belongs to is unambiguous and the
   two numbering systems never silently collide.
3. **Do NOT "Boy-Scout" older-version numbers up to the newest version.** A
   consistency sweep that rewrites 2021 numbers to 2025 numbers in cross-references is
   itself the defect — it breaks the link-target match in the older-version document.

## Impact

Applies to any plan-marshall skill whose document set straddles two versions of an
external taxonomy or standard (OWASP Top 10 2021 vs 2025, CWE revisions, any
versioned external category scheme). The reviewer/author must treat the citing-side
version as load-bearing and validate cross-reference numbers against the target
document's version, because no deterministic in-house gate does.

## 2. Verdict — the deficit is real, structural, and caused by OUR OWN configuration

⛔ **PR-Agent posted ZERO inline review threads across all 52 pull requests. Every one of the ~68+
threads in both repositories was opened by CodeRabbit.**

**The cause is verified, not inferred.** `cuioss-organization/.github/workflows/reusable-pr-agent-review.yml`
defaults `auto-improve: false`, and `/improve` is the only PR-Agent tool that emits inline committable
suggestions. `/review` emits exactly one PR-level "PR Reviewer Guide" comment. So PR-Agent is
**structurally incapable** of producing an inline finding in this setup.

⭐ **The toggle's own documented rationale is falsified by this window.** It reads: *"committable
suggestions are already CodeRabbit's job, so enabling this duplicates findings and roughly doubles the
token cost."* That rests on CodeRabbit being available. In this window:

- CodeRabbit produced **no** substantive review on **19 of 36** plan-marshall PRs;
- Sourcery refused on nearly all of them.

⇒ On a large share of PRs the "already covered by CodeRabbit" premise was simply false, and nothing
inline covered the diff at all.

## 3. ⛔⛔ CORRECTION — `API-Sheriff-PR-133.md` is REFUTED, and it is feeding a staged plan

**PR-Agent DID review API-Sheriff #133.** Comment posted `2026-07-30T11:23:46Z`, produced by a
**successful `issue_comment` run at 11:22:29Z**. The existing document records "⛔ Nothing at all — 0
comments, 0 reviews" and scores the run *unassessable — required reviewer never triggered*.

**Two independent errors, and the second is the one that matters:**

1. **Staleness** — the document was written before the review arrived. This is the epic's own
   *true-when-written-false-when-read* archetype, recurring.
2. ⭐ **A structurally blind evidence query.** The doc's oracle was
   `actions/workflows/pr-agent.yml/runs?branch=feature/plan-15-security-pipeline-modes` → `total_count: 0`.
   That query **cannot ever see a `/review` run**: GitHub records `issue_comment`-triggered runs with
   `head_branch: main`, never the PR's branch. Re-running it today still returns `total: 0` while the
   review demonstrably exists. And `/review` is the **ONLY** re-review path — the workflow has no
   `synchronize` trigger by design.

⚠ **What is NOT refuted, and must not be swept along:** zero `pull_request`-event runs genuinely did
exist on that branch. The epic Watch on `mergeable_state: dirty` suppressing `pull_request` runs is
**untouched** by this correction.

**Consequences:**

- #133 reclassifies from *unassessable — never triggered* to a **deficit** — and a severe one: the canned
  no-op plus `🔒 No security concerns identified` on a 3349-line change to a security filter pipeline,
  against a CodeRabbit baseline of 3 reviews and 7 threads.
- ⛔ **PLAN-PR-007 loses its confirming instance for the `not_triggered` taxonomy member.** That member
  was admitted on this PR alone. Its D1 population is **not** known to be ≥3 on this evidence.
- ⭐ **Method rule earned, now added to `review-practice.md` § 1**: never score a bot's silence from a
  branch-filtered workflow query.

## 5. Could we have found it ourselves?

Answered only over findings that carry a posted answer on the PR.

### ⭐ Two families recur, BOTH against detectors that already exist ⇒ fourth answer shape

**Family 1 — a literal that mirrors a runtime-discoverable set.**

| Finding | Detail |
|---|---|
| #1067 `835226` | "one of those **nine**" vs eleven established two lines above |
| #1067 | hardcoded live resolver count `1` in a doc that mirrors `discover_derivation_resolvers()` |

`_detect_count_prose` **exists and ran**, but scans only `SKILL.md` and matches a closed five-noun set.
Both misses fall outside those bounds — #1067's second instance is in a `standards/*.md`, and its noun is
neither a count word nor in the set. ⛔ **WIDEN the existing detector; never add a second one beside it.**
⚠ The widening must be **derived**: the population here is *doc literals asserting the cardinality of a
set the code discovers at runtime*, which is narrower and more checkable than "any noun".

**Family 2 — contradiction between normative statements.**

| Finding | Detail |
|---|---|
| #1066 | "Line 46 contradicts line 42" — same document, opposite rules about the same gate |
| #1066 | compose-result shape contract disagrees across **two** documents |

⛔ **`default:pre-submission-self-review` advertises both a "same-document contradiction" and a
"source-of-truth drift" detector, and it runs at `lane: standard` — so it was almost certainly ACTIVE and
did not fire.** That makes this a widening question, not an activation one — but the activation must be
confirmed from #1066's archived manifest before the widening is scoped, because the two remedies are
opposite and this epic has already been bitten by exactly that confusion.

### Answered "No — semantic; the bot's job; drop"

Resolver identity validation (#1067) · merge-time discarded-edge notes (#1067) · the docstring-vs-code
title-filter claim (#1049) · the unset-`change_type` doc claim (#1049) · the canonical candidate-list

⚠ The one instance that still troubles: API-Sheriff **#133**, a 3349-line change to a *security filter
pipeline*, drew `No security concerns identified` while CodeRabbit opened 7 threads (see § 3).

### The local security audit is gated at the HIGHEST lane — verified in config

`manage-config plan phase-6-finalize get` returns, for this repository:

```
default:finalize-step-security-audit:
    lane: full
```

Every other finalize step sits at `minimal` or `standard`; only `default:sonar-roundtrip` shares
`lane: full`. So on plan-marshall the security audit runs **only** on plans routed to lane `full`.

⚠ **OWED — deliberately NOT answered: how many of this window's plans actually reached lane `full`.**
`review-practice.md` § 3 requires verifying against the archived plan and checking **both** drop paths
(`execution_profile` / `lane_dropped` **and** the `security_class_omitted` ceremony pre-filter). No script
surface reachable from the orchestrator carve-out enumerates archived plans — `manage-status list`
returns only live plans, and `manage-execution-manifest read --plan-id …` did not resolve an archived
plan. ⛔ **Asserting a count without that artifact is exactly the inference this epic forbids**, so it is
recorded as owed with the artifact named.

⛔ **And the third answer shape applies pre-emptively**: if the audit turns out to have been dropped by
lane on most plans, that is an **activation** question. **Do NOT add a self-review detector to
compensate** — that is how the local review acquires a second, weaker copy of a check it already has.

## Recommendations

Ranked by evidence strength, each naming what would refute it.

**A. Enable `/improve` for plan-marshall and API-Sheriff.** ⭐ Strongest recommendation in this sweep.
The zero-inline-findings result is **fully** explained by `auto-improve: false`, and the toggle's stated
rationale ("CodeRabbit's job") is falsified — CodeRabbit produced nothing on 19/36 plan-marshall PRs and
Sourcery is effectively absent. It is a **caller input**, so a single repository can opt in without an
org-wide change. Accepted cost, per the workflow's own note: roughly double the tokens per PR, and some
duplicate findings where CodeRabbit did run. ⚠ Overlap costs one duplicate comment; suppression costs the
finding — the charter in `.pr_agent.toml` already settles that trade in the same direction.

**B. Stop tuning the charter blind — the next change must be measured on a FIXED diff.** Charter #13 did
not move the measured rate. The org already owns the right instrument and has used it once (the
`/review`-on-#1027 controlled run recorded in `.pr_agent.toml`'s own comments). Before any further
charter edit, re-run `/review` on the PRs where CodeRabbit found Majors and PR-Agent said nothing —
**#1065, #1066, #1068, API-Sheriff #133** — and compare against the same diff. ⛔ This also settles the
epic's open question of whether an explicit re-review trigger still recovers a review on a **merged** PR,
at zero extra cost. This is `PLAN-PR-004`'s scope almost exactly.

**C. Stop counting Sourcery as a third reviewer in any coverage claim.** It refused ~33/36. It is already
classified `optional`, so nothing gates on it — but any prose that says "three reviewers" is describing a
configuration, not a measurement. ⚠ Note the two refusal shapes differ in whether waiting helps.

**D. The response path, not the detectors, is where findings were lost.** 6 findings (3 Major) merged
unanswered across #1066, #1049, #1042 — while other PRs in the same window answered every thread. Feeds
the staged barrier work; needs no new mechanism.

**E. Local review — WIDEN two detectors, add none.** The two families in § 5, with the population derived
rather than guessed. ⛔ Confirm `pre-submission-self-review` was actually active on #1066 first.

**F. Security — settle the lane-activation question before deciding anything.** § 6's owed measurement
decides between an activation remedy and a detector remedy, and those are opposites.

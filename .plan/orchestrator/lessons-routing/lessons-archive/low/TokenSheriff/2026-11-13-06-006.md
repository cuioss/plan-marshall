# scope_creep_check should carry an accepted residual forward and exclude files named in a fix task's own scope

Files touched by an earlier deliverable's own commit, by a fix task's own scope, or by an operator-sanctioned out-of-footprint fix should enter the declared scope (or an explicit sanctioned-residual list) when they are committed, and an accepted residual should carry forward so a grown residual set needs a disposition only for its delta.

## What happened

In plan validation-public-seams (PR #899), `scope_creep_check` reported seven files outside declared scope (threshold 5): four were the operator-requested test-jar pom fix (62b7f847), three belonged to earlier committed deliverables that functional and code review had already covered (qgate 21958e, accepted with a manual explanation). About an hour later it fired again with eleven files (residual_set changed from 395d43514c6f to c8823bc536cb): the same seven plus `ClaimMappingException.java` (an earlier fix task), `AGENTS.md` and `doc/README.adoc`, which TASK-17 was written to correct (qgate 151153, accepted again with a near-identical explanation).

## Rule

When a new residual set is a superset of an accepted one, only the delta needs a disposition. Files named in a fix task's own scope are not scope creep.

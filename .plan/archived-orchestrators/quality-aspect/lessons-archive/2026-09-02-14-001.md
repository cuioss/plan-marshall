# Verify a delete-to-one-home fix by re-searching the literal, not by enumeration

## Context

`pre-submission-self-review` ran seven rounds on this plan and filed 25 findings, every one `defect_class contract_drift` against documentation restating the `domain-detect` contract. By round 3 the prescriptions had converged on the right shape — DELETE the restatement, keep one authoritative home, xref it from everywhere else — and every subsequent fix was a deletion, not a reword. The mechanism lesson `2026-09-02-13-001` prescribes was being followed.

Round 6 applied it at scale. It found the phrase *"unconditional union"* — a composition formula the plan's new branch falsifies — asserted by six documents, deleted it from five, deleted the single load-bearing word `unconditional` from the sixth (`skill-domains.md:350`, the authoritative home), and its commit message stated the formula now *"lives there and nowhere else"*.

Round 7 found a seventh site. Finding `7abe34` records it verbatim:

> That commit claimed the formula 'lives there and nowhere else'; this is a SEVENTH site, findable by `architecture search --content --pattern 'unconditional union'` (count 2, file_count 1). Round 6's sweep enumerated sites rather than re-searching the phrase.

The seventh site was `phase-1-init/SKILL.md:746` — a file rounds 1, 3, 4 and 5 had each already opened and edited.

## Root cause

A "this now lives in exactly one place" claim is a statement about the whole inventory, but it was verified against the round's own working set: the sites the round had already collected while investigating. That set is built from the previous round's findings, so it is complete for the proposition the *previous* round held and complete for nothing else. Enumerating it again confirms only that the round finished its own list.

The check that would settle the claim is one command and was available the whole time — `architecture search --content --pattern '<the deleted literal>'`, which is what round 7 actually ran. Deletion is the right fix (that is `2026-09-02-13-001`'s rule, and it was obeyed); this lesson is about the *verification* of a delete-everywhere fix, which is a separate and unguarded step.

The cost is one full review round: round 7 spent a dispatch to find a defect round 6's own tooling would have surfaced for the price of a single search.

## Proposed action

1. When a self-review fix's prescription is DELETE-and-xref — i.e. the fix asserts a claim now lives in exactly one authoritative home — the fix is not complete until the deleted literal has been re-searched over the inventory: `architecture search --content --pattern '<literal>'`. Assert `file_count == 1` and that the one file is the named authoritative home.
2. The claim belongs in the commit message only *after* that search. A commit that says "lives there and nowhere else" without a recorded search result is asserting inventory coverage it did not measure.
3. Prefer a distinctive multi-word literal as the search key (`unconditional union`, not `union`). Note that `architecture search --content` patterns are regexes — see lesson `2026-08-25-09-011` — so escape metacharacters or a false zero is the result.
4. Sequence check: run the search BEFORE the round closes, not as the next round's first act. Round 7 is the proof that the next round will run it eventually; running it one round earlier is the whole saving.

## Impact

One avoided review round on this plan. Round 7 consumed a full `execution-context-level-5` dispatch to file a single finding, inside a phase that cost 2.28M tokens — 55% of the plan's 4.18M total, and more than phases 1-5 combined.

# A user-facing example kept four configuration keys the governing ADR lists as inert

# Candidate lesson: user-facing example still carried config keys that act on nothing

Source: automatic-review signal, PR #433 CodeRabbit inline comment, finding 82b88f (fixed in fceb918e).

## What happened

`doc/user/endpoint-routes.adoc:141` removed the inert `circuit_breaker` block but left `retry.max_attempts`, `retry.idempotent_only`, `connect_timeout_ms` and `read_timeout_ms` in the same `upstream` example, all of which ADR-0064 lists as parsed-but-inert (only `retry.enabled` acts; dispatch runs under the guard's fixed 30 s timeout). An operator copying the example would believe a policy the gateway does not run. Fixed by marking each key inert in place with a pointer to ADR-0064 "What this decision does not settle".

## Candidate rule

When a plan retires or documents one inert configuration key, sweep every user-facing example for the full inert-key list in the governing ADR in the same change. This is the CLAUDE.md "a configuration key that parses is not a configuration key that acts" rule applied to documentation examples, not only tests.

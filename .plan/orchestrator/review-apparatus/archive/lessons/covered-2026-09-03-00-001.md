## Why it matters

This is the repo's standing rule — *every set-guarding detector must be population-derived*
— and the same plan already paid for the adjacent instance of the class: four consumers
enumerate the taxonomy, two were missed when the twelfth member (`STATE_UNREGISTERED_KIND`)
was added, and only the whole-tree test run caught them.

## Directive

Every set-guarding detector in this component must be population-derived:

- Derive the population from the live declaration, never restate it.
- Assert equality against that population, in both directions.
- Refuse to pass vacuously over an empty population — a check that can return 0 from an empty
  population must say so.
- Copy the shape from `test/_shared/_dispatch_roster.py`, the canonical population-derived
  detector in this repo.

## Recurrence — 2026-09-03 (misconfigured-reviewer-name-reads-missing-review)

A second instance of this archetype occurred in the **same plan**, on a sibling detector, and
it is worth recording because **the fix reproduced the defect it was fixing.**

`_STALE_COUNT_RE` in `test/plan-marshall/automatic-review/test_unknown_bot_kind_escalation.py`
is a stale-count guard whose docstring declares its boundary as \"any cardinal restated beside
closed non-participation members\". Three passes were needed and it is still open:

1. **Pass 1** — `pre-submission-self-review` filed Q-Gate finding `81f0d9` at `00:03:52Z`: the
   alternation matched only the number *words* `nine..thirteen`, so the likeliest future stale
   form — a digit, `the 12 closed non-participation members` — passed silently. Fixed at
   `00:05:38Z` by widening to `(nine|ten|eleven|twelve|thirteen|[0-9]+)[ -](closed|member)`,
   with both controls verified against the live tree.
2. **Pass 2** — the *next* firing of the same step filed `b70840` at `16:13:41Z` against the
   fix: the widened pattern still misses `eight`, `fourteen` and `a dozen` (it enumerates a
   five-word window around today's taxonomy size — exactly this lesson's archetype), **and**
   the added `[0-9]+` alternative introduced a new false positive, matching `508 closed` and
   `2 member` in unrelated prose across a 1,222-line SKILL.md, because the pattern never
   requires the `non-participation` noun phrase the docstring names.
3. **Pass 3** — CodeRabbit's review of the merged tree independently raised nitpick 1 of
   `f05460`: widen `_STALE_COUNT_RE` and add negative controls. Dispositioned `accepted`,
   deferred as a Trivial source edit at a green merge gate. So the guard shipped still
   enumerating a cardinal window.

The generalisation this adds to the lesson: a set-guarding detector whose population is
enumerated rather than derived does not merely fail later — **its remedy attracts the same
mistake**, because widening an enumeration feels like fixing it. The directive above already
says \"derive the population, never restate it\"; pass 1 restated a longer list and passed its
own controls. A fix for this class is only complete when the pattern anchors on the invariant
noun phrase and derives its cardinal side, and when it carries a *matched negative control*
proving it does not fire on unrelated prose.

Evidence: Q-Gate findings `81f0d9` and `b70840` (`artifacts/findings/qgate-6-finalize.jsonl`,
both now `fixed`); `review-retrospective.md` § \"Acknowledged-vs-false-positive sanity check\",
item `f05460`."

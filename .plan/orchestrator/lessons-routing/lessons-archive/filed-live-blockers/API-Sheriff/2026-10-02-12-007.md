# Documentation asserted that logout revokes tokens at the identity provider while production binds the revocation seam to a no-op

## Observed (API-Sheriff PR #369, plan-23-session-route-scope-parity, 2026-10-02)

The security re-check at commit 84c5d0be compared a paragraph that commit had just added to the
threat model (BFF-09) with the production wiring. The paragraph said the logout endpoint revokes the
session's tokens at the identity provider per RFC 7009. Production binds the revocation seam to a
no-op, so nothing is revoked. Three older statements in the documentation made the same claim and had
been false before this plan started (decision 6401ef, finding bd0ad3). All four were corrected before
the push.

No gate had caught the three older statements: they are prose, no test reads them, and every earlier
review had compared documents with documents.

## Root cause

The new paragraph was written to agree with the existing documentation. The existing documentation
was wrong, so the new text repeated the error and gave it a fourth site. A sentence of the form "the
gateway does X on logout" is a claim about a binding in the runtime producer, and it was never traced
there.

## Directive

- Before writing or keeping a sentence that says a security control acts (revokes, validates,
  refuses, rate-limits, expires), open the production binding that would make it true: the producer
  that wires the seam, not the interface and not another document. This is the rule "a configuration
  key that parses is not a configuration key that acts" from `CLAUDE.md`, applied to prose.
- A seam that production binds to a no-op must be described as not in effect wherever it is
  mentioned.
- When one such statement is found false, search the documentation for the same claim and correct all
  sites in one change, as was done here.

## Open item

Wiring real RFC 7009 revocation into logout is a feature and was left for a follow-up by decision
6401ef. Until it lands, logout ends the gateway session only, and tokens already issued stay valid at
the identity provider until they expire.

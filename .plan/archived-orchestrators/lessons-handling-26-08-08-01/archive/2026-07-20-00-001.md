# plan_logging.log_entry does not validate client-supplied plan_id (path-influence risk)

Discovered during the PLAN-03 (marshalld interaction audit logging) finalize security audit — filed find-only as finding 5f7133 and accepted-deferred because the fix reaches far outside that plan's footprint.

## Problem

`plan_logging.log_entry` resolves the log path via `get_store_dir` / `get_log_path` from a caller-supplied `plan_id` **without** running it through `input_validation.is_valid_plan_id` first. The sibling entry points `log_work` and `log_decision` in the same module DO validate. So a crafted `plan_id` containing path segments could in principle influence the resolved log path (a path-traversal-shaped risk at a logging boundary).

This is a **pre-existing, system-wide** gap: `log_entry` (and `get_log_path`) are shared by many callers — e.g. `log_script_execution` via `extract_plan_id`, and now the build-server-client `_audit_log` added by PLAN-03. It is not newly introduced by any one plan.

## Recommended fix (dedicated plan)

Add an `is_valid_plan_id` guard at the shared choke point (`log_entry` / `get_log_path` in `plan_logging.py`), matching the `log_work` / `log_decision` precedent, so every caller is protected at once rather than each caller validating independently. A dedicated plan is warranted because it touches the shared logging module and must be regression-tested against all existing callers.

## Why deferred, not fixed in PLAN-03

PLAN-03's footprint is the build-server client/server audit surface. Correcting a shared-logging choke point means touching many pre-existing call sites outside that footprint, which the plan's scope-deviation discipline says to defer rather than absorb. The PLAN-03 client path was left as-is (it inherits the same shared behavior as every other logging caller); this lesson tracks the root-cause fix.

## Impact

Low practical risk today (plan_ids are internally derived, not attacker-controlled in normal flows), but it is a defense-in-depth gap at a trust boundary that should be closed at the shared layer.

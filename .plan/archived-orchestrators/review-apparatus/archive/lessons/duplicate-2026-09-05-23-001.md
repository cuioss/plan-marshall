title: review_commitments reconcile returns verdict clear over an empty commitment population without saying the population was empty
content: "## Problem

`review_commitments reconcile` returned:

```toon
verdict: clear
commitments_considered: 0
```

while the plan held three resolved `build-error` findings anchored to lines in the very file the
simplify pass was editing. The verdict was computed over an empty commitment population and rendered
under the same word — `clear` — as a verdict computed over a populated one.

The two are not the same claim. A `clear` over a populated set means *\"every commitment was checked
and none was touched.\"* A `clear` over an empty set means *\"nothing was checked.\"* At the call site
they are byte-identical, so the caller cannot tell which it received.

## Why it matters

This is the archetype the surrounding plan exists to remove, one layer up in the tooling: *not
looking* renders identically to *looked and found nothing wrong*. The gate is advisory
(`gates_merge: false`), which bounds the damage but does not make the signal honest — a simplify
pass that trusted the verdict would delete a line the review process had committed to and report a
clean reconciliation while doing it.

The near-miss was real. The three commitments were `verdict: dict = ...` / `text: str = ...`
local-annotation-then-return shapes that satisfy mypy's `no-any-return`. They read as pointless
temporaries — exactly the shape a simplify pass removes — and deleting one both reintroduces a build
error and reverses a commitment made earlier in the same run. Only a hand corroboration caught that
the population was empty and the verdict therefore vacuous.

## Directive

Establish why the population was empty when three resolved `build-error` findings existed on the
edited file: whether the verb queries a finding type or resolution state that excludes them, whether
it scopes to the diff rather than to the plan, or whether the anchor form did not match.

Whatever the cause, the return must make an empty population legible at the call site. A verdict
computed over nothing must not render as `clear`; either publish the population size as a field the
caller is obliged to read, or return a distinct third token for the empty case, mirroring what the
`fresh` / `exempt` split does for the freshness gate.

## Verification

A reconcile run against a plan with a known non-empty commitment set must report that set's size, and
a run against a genuinely empty one must be distinguishable from it by the return alone — not by
reading the caller's own knowledge of the plan. Assert both directions: a test that only exercises
the populated case passes today and proves nothing about the empty one."

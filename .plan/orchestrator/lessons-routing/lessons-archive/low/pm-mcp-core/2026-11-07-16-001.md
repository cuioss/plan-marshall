# Bound a no-copied-helper criterion to data helpers so the functional review can close

## Context

PLAN-V2-90 (PR #314) froze the deliverable-2 success criterion "no test class of the scope declares a helper that a second class copies". The functional review ran five rounds on it. Rounds 1 to 3 looped back to execute for copied data helpers (`jobId(Kind)`, `planId()`, `lowerLetters()`), which was right. Round 3 also counted pre-existing non-data helpers (`git`, `alive`/`awaitDead`, `schema`). Round 4 accepted, saying lifecycle hooks and near copies with different bodies are outside the wording. Round 5, on the same code plus four review-fix lines, declined on the same residuals (identical `delete()` hooks, copied `refused()`/`verified()`). The loop-back budget was spent and the operator closed the review by override.

## Root cause

The criterion says "a helper" without saying which kind. Test lifecycle hooks (`tearDown`, `delete`, `closeProbes`), pre-existing helpers the plan did not create, and near copies with different bodies all match the words, so each review round drew its own line and the verdict depended on the round, not on the code.

## Proposed action

When a conformance spec or outline states a no-duplication criterion, bound it in the criterion itself:

- name the kind: test-data draws (values from `Generators`) that two or more classes need, which must live in the module's generator artifact;
- exclude by name: JUnit lifecycle hooks, helpers bound to one class's fixture, and helpers that exist unchanged on `origin/main`;
- give the check: an identical body of more than N characters in two classes of the scope (round 5's author used 40 characters).

The remaining duplicates of other kinds go into the code review as advisories, where they do not block closing.

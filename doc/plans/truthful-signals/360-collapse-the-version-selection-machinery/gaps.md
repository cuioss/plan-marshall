## G1 — Widen the D6(d) marker-write guard to the shapes the retired test covered

- **Kind:** missing-test
- **Severity:** high
- **Where:** `test/plan-marshall/tools-script-executor/test_marker_free_resolution.py:238` — `_writes_marker` (consumed by `test_no_production_source_writes_the_shared_marker` at `:269`)
- **What is wrong:** the detector flags a `write_text`/`write_bytes` call only when the `.orphaned_at` string literal sits inside that call's own target expression — i.e. exactly `(version_dir / '.orphaned_at').write_text(...)`, the shape the deleted `_mark_superseded_version_dirs` used. Executing the helper on six shapes: the literal inline form is caught; an alias-bound write (`marker = version_dir / '.orphaned_at'` then `marker.write_text(...)`), a named-constant write (`(d / ORPHAN_MARKER_NAME).write_text(...)`), `open(path, 'w')`, `.touch()`, and a write **inside an emitted-code template string constant** are all missed. The retired `test_orphan_marker_existence_only.py` handled the first four by design (`d01edfdf^:test/plan-marshall/script-shared/test_orphan_marker_existence_only.py:93`, `:335-345` `_assigned_alias`/`_check_alias_uses`, `_CONTENT_PARSE_CALLS`, `_METADATA_PROBE_ATTRS`) and descended into `_CLAUDE_RESOLVER_TEMPLATE` explicitly. The alias-bound form is live in this repository today at `marketplace/bundles/pm-plugin-development/skills/plugin-doctor/scripts/_plugin_pin_trap.py:554`.
- **Why it matters:** report-01.md § Deliverables D2 states the retired test's "no marker write" guarantee is "**re-established, not dropped**". It is not. A reintroduced marker write in any of five plausible spellings — including inside `_CLAUDE_RESOLVER_TEMPLATE`, the constant whose body ships into every generated executor on every user machine — passes CI green. That is a guard that reports a guarantee it does not enforce, which is the exact class this epic exists to catch.
- **Fix:** in `_writes_marker`, (1) resolve alias bindings — when a `.orphaned_at` path expression is assigned to a `Name`, treat `write_text`/`write_bytes`/`touch`/`open(..., 'w')` on that name within the same scope as a write; (2) resolve module-level string constants whose value is `.orphaned_at` so `ORPHAN_MARKER_NAME`-style indirection is covered; (3) add a template descent — for each module-level `Assign` whose value is a string Constant containing `.orphaned_at`, `ast.parse` that string and run the same detector over it, labelling hits with the enclosing constant's name. Port the three helpers verbatim from `d01edfdf^:test/plan-marshall/script-shared/test_orphan_marker_existence_only.py` rather than re-deriving them. Add a negative-control test asserting the detector flags each of the five currently-missed shapes on synthetic source (the retired test had one at `:793`).
- **Done when:** a unit test over synthetic source asserts `_writes_marker` returns a hit for the alias-bound, named-constant, `open()`, `.touch()`, and template-embedded shapes, and `test_no_production_source_writes_the_shared_marker` still passes over the real tree.
- **Module/topic:** `plan-marshall` / `tools-script-executor` — marker-free resolution test suite.

## G3 — Re-scope the pin-trap detector's loader model and saturation axis

- **Kind:** stale-statement
- **Severity:** medium
- **Where:** `marketplace/bundles/pm-plugin-development/skills/plugin-doctor/scripts/_plugin_pin_trap.py:269-289` — `loader_selected_version`; also `:368-372` (`SHAPE_1_SATURATION`) and the module docstring `:2-45`
- **What is wrong:** `loader_selected_version`'s docstring says it "Mirrors `marketplace_bundles.select_live_version_dir`: the newest-on-disk dir is retention-pinned and its marker is ignored outright; among the resulting live set (unmarked dirs plus that pin) the numerically-highest version-key wins; when every dir is marked the newest overall is the degraded fallback." All three clauses describe machinery deleted by PR #1223 — there is no pin, no live/marked partition, and no degraded fallback. Executing the function on four configurations (`[(0.1.100,unmarked),(0.1.200,marked)]`, both marked, both unmarked, and a three-dir case) returns the newest-overall dir every time, because `pinned` is unconditionally a member of `live`. Separately, `:368-372` still raises `SHAPE_1_SATURATION` ("repair before the fuse burns") as a `fail`-contributing GC exposure, though our resolver no longer consults the marker at all, so saturation can no longer affect which version a session loads.
- **Why it matters:** this is the residue `report-01.md` declares and `plan.md` defers ("re-scope it after this lands"). Left as is, a detector that exists to catch false-green pin states carries a stale model of the code it audits, and escalates a condition — full marker saturation — that after #1223 is a pure foreign-GC observation with no bearing on load safety. That is a false signal shipped by the very check meant to catch false signals.
- **Fix:** rewrite the `loader_selected_version` docstring to state the actual post-#1223 model — "the loader selects the numerically-newest *eligible* version dir; the `.orphaned_at` marker is not consulted" — and simplify the body to `max(dirs, key=_version_key).name` (the `live`/`pool` computation is provably a no-op), keeping the divergence consequence sentence at `:277-280`. Then re-rank `SHAPE_1_SATURATION`: keep it as a reportable GC-exposure observation but demote it out of the "repair before the fuse burns" tier and out of the load-safety `fail` conjunct, since the loader no longer reads the field. Update the module docstring at `:2-45` accordingly and the accompanying fixture expectations in `test/pm-plugin-development/plugin-doctor/test_plugin_pin_trap.py:269`.
- **Done when:** `_plugin_pin_trap.py` contains no reference to retention pinning or a degraded fallback, `loader_selected_version` documents newest-eligible selection, saturation no longer contributes to the load-safety failure verdict, and `test_plugin_pin_trap.py` passes.
- **Module/topic:** `pm-plugin-development` / `plugin-doctor` — pin-trap detector (the sibling-plan re-scope this plan declared as residue).

## G5 — Align the cache-retention prose with the post-#1223 selector

- **Kind:** doc-drift
- **Severity:** low
- **Where:** `marketplace/bundles/plan-marshall/skills/marshall-steward/scripts/cache_retention.py:19-20` and `:31-33`
- **What is wrong:** two statements in the module docstring predate #1223 and were not revisited when D3 deliberately left this file unchanged. (a) `:19-20` describes keep-rule 3 as "the newest-on-disk dir — **the version the highest-version-wins resolver actually selects**". After D1 the resolver selects the newest *eligible* dir, which is not the newest-on-disk dir when the newest carries no `skills/` tree — the shape `test_marker_free_resolution.py:135` fixtures explicitly. (b) `:31-33` calls `.orphaned_at` "**advisory only**", which reads as "we still write it advisorily"; after D2 nothing under this repository writes the field at all, and the only producer is Claude Code's plugin GC.
- **Why it matters:** a reader tuning `plugin_cache_keep_versions` is told rule 3 keeps whatever the resolver picks. It does not, in the eligibility-mismatch case, so an operator could conclude the resolved dir is unconditionally protected from the sweep when it is protected only by the newest-`N` and younger-than-`D` arms.
- **Fix:** at `:19-20` state rule 3 as "the newest-on-disk dir — a superset of what the newest-*eligible* resolver selects in the common case, but not identical to it"; at `:31-33` replace "advisory only" with "written **only** by the foreign Claude Code plugin GC — nothing under this repository writes or reads it", keeping the existing sentence about why a marker-driven oracle would be unsafe. Mirror the same correction in `marketplace/bundles/plan-marshall/skills/manage-config/standards/data-model.md:507` where the union is documented canonically.
- **Done when:** neither `cache_retention.py` nor `data-model.md` describes the marker as something this repository writes, and neither equates the newest-on-disk dir with the resolver's selection.

# Nullable bare String return in a @NullMarked package ships three SonarCloud bugs the local sonar gate cannot see

## What happened

Plan `config-surface-traps` ran a finalize simplify pass over
`nifi-cuioss-common/src/main/java/de/cuioss/nifi/jwt/config/IssuerConfigurationParser.java`.
The pass extracted a private helper whose signature returned a bare `String`
and used `null` to mean "no value". The enclosing package is annotated
`@NullMarked` (JSpecify), so every unannotated reference type in it is
implicitly non-null.

Three SonarCloud issues followed on PR #561, all in that one file:

| Rule | Line | Severity | What it said |
|------|------|----------|--------------|
| `java:S2637` | 509 | warning | non-null-annotated return value is `null` |
| `java:S2583` | 286 | error | condition is always true/false (the caller's `!= null` check is dead) |
| `java:S2583` | 523 | error | same, second call site |

The PR quality gate failed on them. The fix was to return `Optional<String>`.

## The corrective rule

In a `@NullMarked` package, a helper that models "no value" MUST NOT return a
bare reference type with `null`. Use `Optional<T>` (project standard: see
`pm-dev-java:java-null-safety` and the project's "no null returns" convention
in CLAUDE.md). The two failure modes compound: S2637 flags the null return, and
every downstream `!= null` guard becomes provably dead, so one bad signature
multiplies into several findings.

This applies with extra force to *simplify / refactor* passes. Extracting a
helper is exactly the moment a new signature is authored, and a refactor pass
is psychologically framed as "not adding behaviour", so the null-safety
contract of the enclosing package is easy to skip.

## The gate gap that let it through

`verify -Psonar` run locally did **not** catch any of the three. Only
server-side SonarCloud analysis on the PR did. Local `-Psonar` therefore cannot
be treated as a proxy for the SonarCloud gate on this class of finding
(JSpecify-aware nullness dataflow).

Practical consequence: a nullability-touching change is not "verified" by a
green local `-Psonar`. Either self-review the signature against the package's
`@NullMarked` contract before pushing, or expect a post-push loop-back round.

# 2026-09-05-14-001 — head_sha_verified is unreachable on the issue-comment publish path, so a current review reads as declined

component: plan-marshall:workflow-integration-github
category: bug
status: moved-to-epic (corpus original retired 2026-09-17: completely_covered by PR #1510)
source: corpus lesson 2026-09-05-14-001, moved into finalize-machinery per operator direction

## The defect

`github_re_review` reports `head_sha_verified` only on the review path. Bots publishing
persistent issue comments (cuioss-review-bot) can never reach `true`. Observed on PR
#1409: Guide comment named the merge candidate exactly
(`0709a6dedf49f114d249e2361b6c52f6e3ac17ae`); returned `matched: true,
head_sha_verified: false`. Separately, review-path signal requires `submittedAt`
post-dating the trigger, so an already-complete review can never satisfy it.

## Why dangerous

Consumer reads `matched && head_sha_verified` as "reviewed this HEAD" → classifies both
bots declined → prescribed remedy is weakening the gate (optional-ize / authorize) for
bots that demonstrably reviewed correctly. A gate recommending its own weakening on a
false negative. Second instance (with 17-016) of the proxy shape: path-specific flag
for "did this bot review this commit".

## Remedy

Consult `_references_head_sha` on the comment path; where no SHA exists verdict
`undecidable`; don't require `submittedAt` post-trigger when an existing review names
the candidate.

## Coverage (finalize-machinery)

Remedy shipped by PLAN-03 / PR #1510 (`_github_ci.py` reachable head_sha_verified,
`_github_checks.py` carries the verdict). Corpus original retired as completely_covered.

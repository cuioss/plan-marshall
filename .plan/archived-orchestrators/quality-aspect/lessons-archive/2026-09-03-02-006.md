# Read step params from the plan-local manifest snapshot, not global marshal.json

## Context

`review-retrospective.md`, the artifact this step persists, opened with a headline claim about plan-170's merge authorization: that `required_bots` was `pr-agent` and `optional_bots` was `coderabbit,sourcery`, and therefore that **pr-agent alone satisfied the merge quorum** while CodeRabbit — the only reviewer that produced findings on the PR — was optional and its silence would not have blocked the merge.

That was wrong for this run. At the start of the unattended finalize phase, plan-local step-params had been set to `required_bots=pr-agent,coderabbit` and `optional_bots=sourcery`, precisely so CodeRabbit's quota window would be awaited. The pre-merge review-completeness barrier was evaluated against that list, and **both** required bots proved participation. The merge was not authorized by pr-agent alone.

The error was caught only because a later step re-derived the values via `step-params get` and noticed the disagreement; a correction was filed to `decision.log` (`35b2dc`).

## Root cause

The step read the **global** `marshal.json` when the authority for a run's step params is the **plan-local manifest snapshot** (`execution.toon` `phase_6.step_params`). Global config states the project default; the manifest snapshot states what this run actually executed with. For any plan carrying step-param overrides — which is exactly the interesting case, since overrides are what make a run non-default — the two disagree, and the global read produces a confident, well-formed, wrong statement about the run's own behaviour.

The failure is silent by construction: both sources parse, both yield a plausible bot list, and nothing in the read reports which one it consulted.

## Proposed action

- Change the step to read `phase_6.step_params.automatic-review` from the plan's `execution.toon` via `manage-execution-manifest read`, falling back to global `marshal.json` only when the manifest carries no entry — and **state the provenance in the rendered artifact** ("step params: plan-local manifest" vs "step params: project default").
- Generalize: any finalize-phase artifact that makes a claim about *this run's* configuration must read the manifest snapshot. Global config may only be cited as "the project default", never as "what this run did".
- The underlying observation the artifact drew is still worth acting on **as a statement about the default**: by default `coderabbit` is optional, so on a plan without overrides the only reviewer that produced findings here would not have gated the merge.

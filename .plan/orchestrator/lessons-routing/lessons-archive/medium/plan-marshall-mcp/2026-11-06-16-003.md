# git-workflow commit --step reports FETCH_FAILURE when the changed file is unstaged

## What happened

During plan `tool-schemas-single-source`, a `git-workflow` commit call made with `--step` failed
with `FETCH_FAILURE` (exit 1) while the changed file was still unstaged. The same call succeeded
after the file had been staged. Nothing was wrong with fetching from the remote.

## Defect

The error code names the wrong cause. "Nothing staged / the change is unstaged" comes back as
`FETCH_FAILURE`, so the caller looks into network or remote problems instead of staging the file.

## Corrective action

- In `workflow-integration-git`, before committing, check whether the commit has anything to take
  (the targeted paths have no staged change). Report that state with its own error code, for
  example `nothing_staged` or `unstaged_changes`, together with the unstaged paths. If the step
  contract says the verb stages the paths itself, it should stage them instead of failing.
- Return `FETCH_FAILURE` only when an actual fetch call fails.

## Workaround until fixed

Stage the changed paths before calling commit with `--step`.

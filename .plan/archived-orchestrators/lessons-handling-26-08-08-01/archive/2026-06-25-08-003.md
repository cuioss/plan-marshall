# finalize-step-simplify dispatched prompt omits the changeset-scope boundary, so the review deletes pre-existing out-of-scope code (imports, helpers, docstrings)

During phase-6-finalize, the `finalize-step-simplify` dispatched cognitive
review deleted **pre-existing code outside the plan's changeset** — `import
json`, the `_json_dump` helper, and pre-existing docstrings that the plan had
never touched. The orchestrator had to revert the out-of-scope edits.

The step's `--scope changeset` contract is unambiguous in the standards doc:

```
# finalize-step-simplify.md, ~line 65 (--scope definition)
changeset (default) — review the diff hunks of each modified file against the
base SHA. The agent reasons about the lines the plan added or changed, NOT the
file's pre-existing content.
```

But the **dispatched prompt body never restates that boundary.** The Step 3
prompt (`instructions:`) says only:

> Review the plan's change surface for surplus structure and delete it.
> Scope: {scope} ({changeset} = diff hunks vs base SHA; {artifact} = each
> modified file in full). The files to review are the footprint `files` list …
> never touch a file outside that list. Apply the "minimum viable code"
> anti-patterns … delete unused parameters, thin re-export shims, … signature-
> restating docstrings, …

The prompt enforces a **file-level** boundary ("never touch a file outside that
list") but NOT a **line-level / hunk-level** boundary. Under `changeset` scope
the agent is told *which files* to review but not that, within those files, only
the plan-added/changed lines are in bounds. So a reasonable agent reads the whole
file, spots a pre-existing signature-restating docstring or an unused-looking
`import json`, and deletes it — a textbook "minimum viable code" deletion that is
nonetheless **out of scope** because the plan never added or touched those lines.

## Why it matters

`changeset` is the **default** scope (line 58), so this is the common-case
behavior, not an edge case. A simplify step that silently deletes pre-existing,
working code outside the plan's diff is a scope-violation defect that:

- expands the PR's blast radius beyond the plan's intent (unrelated churn the
  reviewer must scrutinize),
- can break callers of the deleted pre-existing symbol that the changeset review
  never examined (the deletion's callers live outside the reviewed hunks), and
- is caught only by an orchestrator/human reviewing the simplify commit against
  the plan's actual changeset — exactly what happened here (revert required).

## Solution / guard

Make the line-level changeset boundary **explicit in the dispatched prompt body**
(Step 3 `instructions:`), so the dispatched agent — which loads ONLY the three
domain-invariant foundation standards and has no other context — cannot read it
as a whole-file mandate under `changeset`:

> When `scope == changeset`: only the lines the plan ADDED or CHANGED relative
> to the base SHA are in bounds. Pre-existing lines (imports, helpers,
> docstrings, parameters the plan did not introduce or modify) are OUT OF SCOPE
> even when they look like minimum-viable-code violations — leave them untouched
> and, at most, record them as a finding. Reviewing a file does NOT license
> editing its pre-existing content.

The `artifact` scope (whole-file review) is the only mode under which pre-existing
content is in bounds; the prompt must gate the whole-file license on
`scope == artifact`.

## How to catch this class

A dispatched prompt that consumes a `{scope}` selector must restate the
operational boundary of EACH scope value in the prompt body, not assume the
dispatched leaf has read the standards doc's `--scope` definition. The leaf loads
only its declared `skills[]` — it never sees the surrounding standards doc. Any
selector whose semantics live only in the doc (and not in the prompt) is a
silent-divergence trap: the leaf behaves per its own reasonable reading, which
diverges from the documented contract. The fix pattern generalizes: **inline the
selector's per-value operational instruction into the dispatched prompt body**
(the same gather→expand→consume discipline the coverage-gathering contract
mandates for the coverage cell).

## Impact

Affects every plan whose finalize runs `finalize-step-simplify` under the default
`changeset` scope. Until the prompt restates the line-level boundary, the
dispatched review may delete arbitrary pre-existing code that merely *looks*
surplus, producing unrelated PR churn and potential breakage that only a
post-hoc orchestrator/human diff review catches.

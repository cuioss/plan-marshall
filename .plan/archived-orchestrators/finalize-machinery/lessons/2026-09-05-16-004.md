# 2026-09-05-16-004 — The merge mutex survived a session boundary far past its hold budget with a waiter queued, and nothing reclaimed it

component: plan-marshall:manage-locks

## Context

Mutex acquired 15:25:39Z for branch-cleanup with merge_hold_budget_seconds=3600;
session restarted mid-merge; at 15:43 the lock was STILL HELD, far past budget, with
a waiter queued. Released only because recovery logic happened to check. A budget
honoured only by a cooperative still-running holder is documentation, not a bound —
and a dead holder is indistinguishable from a slow one from the waiter's side. The
lock file already carries plan liveness; nothing consults it against the budget.

## Proposed action

Waiter-side reclaim when hold age exceeds budget AND liveness fails (record
`reclaimed_from`); publish hold age + budget on check; release before yielding a
session (release-and-re-enqueue already exists).

## Impact

One waiter blocked ~18min past a 60min ceiling, indefinitely absent the restart; stalls
every concurrent plan on the machine.

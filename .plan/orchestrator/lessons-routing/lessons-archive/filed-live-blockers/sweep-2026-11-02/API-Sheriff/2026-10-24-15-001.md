# A retired LogRecord id is not free

Source: PLAN-V02-23 (#515). A new WARN record was given `ApiSheriff-123`, an id retired earlier. `NoCertificatePlainHttpOptInIT` still asserts that `ApiSheriff-123` is NOT in the gateway log (an absence assertion on the old meaning), so the reuse turned it red and cost an extra task. The refusal landed under another id.

## Rule

- Allocate the next id above the highest ever issued in the range, never the lowest gap. The catalogue has gaps by design (at `bd730f5a` the ids `110` and `123` are absent).
- Before allocating, search `doc/LogMessages.adoc` AND the unit and IT test trees for the candidate id. A hit anywhere means it is not free, including an absence assertion.
- An id's meaning is a public contract: alert rules and IT log assertions key on it.

# Retiring a configuration key: derive the exit search from the retired statements, sweep tracked files outside the inventory, and list the deliberate residuals in the criterion

Source: PLAN-V02-20 (#527), candidate lessons 001, 002 and 004; three Q-Gate findings at outline and plan.

## Observation

Removing `oidc.session.encryption_key` hit three planning defects, each costing a re-opened phase or a late fix:

- The exit regex named identifiers only (`encryption_key|encryptionKey|SESSION_ENCRYPTION_KEY|passed key`). Two documents still carried the retired shape in prose ("may name the same file", "passed sealing key"), so the exit condition could pass with stale sentences in place, and both were classed survey-only.
- The architecture inventory does not walk `*.yaml`, `*.yml`, `*.json` or `.github/**`, so a content search over it missed the schema, a test overlay and a workflow that set the retired variable.
- The exit criterion said count 0 everywhere, while the plan itself mandated residual hits (the unknown-key refusal test, the "no service sets it" assertion, the migration note, the ADR that records the replaced field). The criterion was unreachable and cost a re-opened plan phase and a second criteria re-freeze.

## Rule

- Derive the exit search from the retired statements (prose paraphrases), not only the identifiers, and put every sweep hit into the mutate set.
- Sweep tracked files directly (`git grep` on the base ref) over resources, workflows, benchmarks, deployment and the demo client. Treat an inventory search as a lead.
- Split the removal criterion: retired statements count 0 everywhere; retired identifiers count 0 only in production sources, overlays, compose and workflows, with a named allow-list (refusal test, migration note, ADR) for the rest.

## Apply

The outline and plan of any plan that removes or renames a configuration key, environment variable or documented concept.

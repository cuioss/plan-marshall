# Code-gen template rendered-output contract change must sweep test-local render helpers, not just the template — per-task quality-gate and test-compile validate the template in isolation while whole-tree module-tests are the only gate that catches the desynced renderers

## Context

During plan `finalize-lane-materialization` (PR #896), deliverable D4 changed the
executor-bootstrap template's `{{SHARED_MODULE_DIRS}}` contract: the placeholder's
rendered form went from a sequence of statements to tuple entries inside a list
literal. The production template was updated correctly, but the change did NOT
migrate the pre-existing **test-local render helpers** — the render functions inside
`test_executor_integration.py` and `test_executor_runtime.py` that reproduce the
executor-bootstrap rendering in-test. Those helpers still emitted the old statement
shape into the new list-literal context, producing a `SyntaxError` in the rendered
executor.

The desync passed every per-task gate:

- The scoped `quality-gate` (ruff + mypy) validated the changed template source in
  isolation — the template file itself was well-formed.
- `test-compile` compiled the changed module without touching the stale renderers.

Only the **whole-tree `module-tests`** run surfaced the break — 28 test failures,
all downstream of the rendered executor's `SyntaxError`.

## The bug

A code-generation template is a contract with more than one renderer. When the
production template is the single obvious edit site, it is easy to forget that
**test-local render helpers duplicate the template's emit logic** and are a second
renderer of the same contract. Changing the rendered-output shape in the template
without migrating those helpers desyncs them silently: the helpers keep emitting the
old shape into the new structural context, and the rendered output is broken only
when the two are combined — which per-task gates never do.

## How to apply

- **When you change a code-gen template's rendered-output contract (the SHAPE of what
  the placeholder expands to — statement vs expression, list entry vs bare line,
  quoting, indentation context), enumerate EVERY renderer of that template and migrate
  each in the same change.** Test-local render helpers that reconstruct the template
  output in-test are renderers and MUST be swept.
- **The sweep is broader than render helpers** (2026-07-16 recurrence): sibling test
  files also pin the template contract through content assertions (`assert '...' in
  source`) and through direct synthetic calls into template-emitted functions
  (constructed-argv / synthetic-Namespace invocations of `_append_build_ledger_record`
  and friends). Any test that asserts on the template's emitted text or calls an
  emitted function's signature is a contract consumer and must be migrated in the same
  change.
- **The class generalizes past code-gen templates to ANY function contract change**
  (2026-07-17 recurrence): a plain function's return shape, side-effect timing, or
  signature is a contract with direct-call-site tests that pin the old form. Those
  tests are consumers and must be swept in the same change.
- **Cheap discovery**: grep the test tree for the placeholder name, for the helper
  functions that assemble the rendered artifact, AND for the names of template-emitted
  functions/markers; each hit is a renderer or contract-pinning consumer to check.
- **Gate expectation**: do NOT trust a clean per-task `quality-gate` + `test-compile`
  to certify a rendered-output OR function contract change — those validate the source
  in isolation and NEVER execute the test bodies. A whole-tree `module-tests` run is
  the gate that exercises the artifact/function end-to-end. This is the authoring-side
  complement to lesson 2026-06-20-23-001 (run full verify when a plan changes a
  widely-consumed default): the executor-bootstrap template IS a widely-consumed
  default, so its contract changes need both the renderer sweep AND the whole-tree
  verify.

## Recurrence signature

- A code-gen template placeholder's rendered SHAPE changes (statements to list
  entries, etc.), or the emitted function surface changes (new required parameter,
  new import in the emitted preamble), OR any plain function's return shape /
  side-effect timing / signature changes.
- The production template / function is updated; test-local render helpers,
  contract-pinning assertions, or direct-call-site tests reproducing the same
  contract are NOT.
- Per-task `quality-gate` + `test-compile` pass (source validated in isolation).
- Whole-tree `module-tests` fails with a `SyntaxError`/parse error, an
  `AssertionError` on emitted-text content, or a `TypeError`/assertion regression on
  the changed function's signature/return, plus a cluster of downstream test failures.

## Recurrence — 2026-07-16 (background-build-kill)

Deliverable D1 of plan `background-build-kill` (PR #912) changed the
executor-template build-ledger contract: the emitted `_append_build_ledger_record`
gained a required `stdout` parameter and the template's ledger preamble switched to
importing `append_entry` + `build_record` from the `manage-change-ledger` `_ledger_core`.
The template and its primary tests were updated, but TWO sibling test files were
missed:

- `test/plan-marshall/tools-script-executor/test_generate_executor.py:960` —
  contract-pinning assertion `assert 'from _ledger_core import append_entry,
  build_record' in source` failed against the emitted text.
- `test/plan-marshall/tools-script-executor/test_generate_executor_behavior.py:536,564`
  — synthetic calls to `_append_build_ledger_record(...)` failed with
  `TypeError: missing 1 required positional argument: 'stdout'`.

Exactly per the signature: per-task gates green, only the orchestrator-tier
whole-module `module-tests` run caught the desync; fixed via follow-up TASK-6/TASK-7.
This recurrence widens the sweep surface from "render helpers" to all
contract-pinning sibling tests (text assertions + synthetic signature calls).

## Recurrence — 2026-07-17 (execution-manifest-gaps)

This recurrence generalizes the class beyond code-gen templates to a **plain
function contract change**. TASK-12 of plan `execution-manifest-gaps` (P4)
refactored `_route_task_verification_commands` in `manage-execution-manifest` to
RETURN a tuple and DEFER persistence instead of persisting inline — a return-shape +
side-effect-timing contract change. The five pre-existing deliverable-4 tests in
`test_compose_execution_tier.py` asserted the OLD return/persistence contract and
regressed. The fix agent ran only the scoped `quality-gate` (mypy + ruff) — which
validated the changed function in isolation and stayed green — and did NOT run
`module-tests`, so the five-test regression slipped to the orchestrator-tier build.

The durable rule this reinforces: `quality-gate` (mypy + ruff) can NEVER observe a
test-behavior regression because it does not execute the test bodies — only a
`module-tests` run does. A fix agent that changes a function contract (return shape,
side-effect timing, or signature) MUST run `module-tests` over the changed module
before declaring the fix done; a clean `quality-gate` is not sufficient evidence.
This is the mirror of 2026-06-21-00-003 (the inverse leg — running only module-tests
and missing the ruff/mypy gate); together the symmetric rule is: verification must
run BOTH `module-tests` and `quality-gate` — neither leg subsumes the other.

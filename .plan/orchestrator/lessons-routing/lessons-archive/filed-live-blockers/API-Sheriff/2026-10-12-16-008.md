# Maven has no narrow test scope, so the pre-push gate records module-tests as degraded although all tests ran


Source: observation from the orchestrating session of plan `jwks-unknown-kid-refresh` (PR #430).

Three facts about the Maven build integration, as seen in this run:

- `resolve-test-scope`, and with it a narrow unit-test scope, is unsupported for Maven. Calling it is an argument-parser rejection (see the separate candidate on the two rejections of the Maven build script).
- At default scope no `module-tests` canonical command and no `test-compile` canonical command exists for Maven.
- The pre-push gate therefore recorded `module-tests` as degraded.

The whole-tree `verify -Ppre-commit` did run, and it ran all tests. The degraded mark describes the missing canonical command, not missing test coverage.

## Candidate lesson

The gate conflates "this build system offers no narrow test command" with "the tests were not fully run". For a build system without a narrow scope, a whole-tree run that executed every test satisfies the module-tests requirement and should be recorded as satisfied, with a note that it was satisfied by the wider command.

Alternatively, give Maven the missing canonical commands. API-Sheriff's own instructions already document a working form for module tests (`test -pl <module> -am`) and a targeted form (`-Dtest=...`), so the commands exist; only the canonical mapping at default scope is missing.

Until then: a degraded `module-tests` entry on a Maven project is expected when `verify -Ppre-commit` ran green, and is not a reason to re-run tests.

## Impact

A misleading degraded mark on every Maven plan's pre-push record, which a reader can take for a real coverage gap. Also the direct cause of one of the two rejected calls in this plan's script-failure cluster.

## Context
Splitting an over-budget test module into behaviour-cluster files (module-budget
campaign, slice 040, task 8: `test_fetch_findings.py` -> 3 clusters). The source
module loaded the script under test with an explicit registration name and the
tests patched it through string targets:

```python
sonar_mod = load_script_module('plan-marshall', 'workflow-integration-sonar', 'sonar.py', 'sonar_mod')
...
with patch('sonar_mod._sonar_credential_missing', return_value=''):
```

## Problem
`load_script_module` registration REPLACES any existing `sys.modules` entry, so
repeating the load line in every cluster file executes the script N times and
leaves N distinct module objects, with only the last-imported file's object
reachable as `sys.modules['sonar_mod']`. Every `patch('sonar_mod....')` string
target then resolves to that one object while the other files' tests call
functions bound to stale objects. Symptom: all tests in the non-last files fail
with the unpatched behaviour (here: `unconfigured` statuses, `KeyError:
'stored_hash_ids'`, uncalled mocks) while the last-imported file passes fully.
Object-attribute patching (`monkeypatch.setattr(mod, ...)` on the locally held
object) is immune; only `sys.modules`-indirected string targets break.

## Fix
Exactly one cluster (the core file) performs the load and registers the name;
sibling clusters drop their local `sonar_mod = load_script_module(...)` line and
use `from test_fetch_findings_core import sonar_mod` instead (acyclic: the core
cluster imports nothing from its siblings; the directory has no `__init__.py`
so pytest's sys.path insertion makes the sibling importable). All aliases
(`cmd_x = sonar_mod.cmd_x`) and string-target patches then resolve to the single
registered object regardless of collection order. Verified: 86 passed in both
default and reverse directory order.

## Companion pitfalls found in the same split
- `@pytest.mark.parametrize` decorators must travel with their test function.
  A splitter that slices at `def` lines leaves the decorator in the previous
  block, and the test is collected with a missing fixture (`stderr`, `value`,
  `post_merge_state`, `argv`).
- `@pytest.fixture` defs (autouse or consumed by an external contract module
  such as `_ci_wait_contract`, whose tests import into the split files) must be
  kept in every cluster file: fixtures are consumed by name at collection time,
  never by textual reference, so usage-pruning drops them.
- Unused imports duplicated into every cluster trip the F401 lint gate; prune
  imports per used name in each emitted file.

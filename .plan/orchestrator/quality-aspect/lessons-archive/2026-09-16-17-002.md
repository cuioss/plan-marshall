# Break the flag loop when refreshed analyzer scope is unknown

# Candidate body for 2026-09-16-17-002 (from operator-ux inbox implement-plan-09-interaction-mode-003.md)

Source: PR #1496 inline coderabbitai comment 453c3f on `marketplace/bundles/pm-plugin-development/skills/plugin-doctor/scripts/_analyze_argument_naming.py:1044` (fixed in-run by TASK-6, shipped in #1502).

Defect: when `_refresh_entry` returned unknown root or subcommand scope, `continue` skipped only the current flag while `allowed` still held the stale set; since `refreshed` blocks a second refresh, a later flag could false-positive from the stale set.

Rule: break the current invocation's flag loop when either refreshed scope is unknown; independent invocations continue. A scope refresh that cannot establish scope must not leave the stale allow-set in force for subsequent flags.

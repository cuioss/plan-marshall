# compute-footprint diffs against stale local main after a worktree-only rebase

`manage-references compute-footprint` (consumed by `pre-push-quality-gate`) computes
`git diff --name-only {base_ref}...HEAD` against the LOCAL `main` branch ref in the
main checkout, not `origin/main`. `finalize-step-sync-baseline` (order 3) rebases only
the WORKTREE's feature branch onto `origin/{base_branch}` — it never touches the main
checkout's own local branch ref. On plan-truth-157 this meant local `main` was 2 commits
behind `origin/main` at the moment `pre-push-quality-gate` (order 5) ran, and the live
footprint came back as 100 files instead of ~10 — the two upstream commits' entire file
sets folded into the plan's own footprint, because the diff base was stale.

This does not corrupt correctness (an inflated footprint over-gates rather than
under-gates), but it wastes real build time: `derive_gate_bundles` runs `quality-gate`
over every bundle the inflated footprint touches, most of which the plan never changed.

## Directive

Have `finalize-step-sync-baseline` (or a step immediately after it) fast-forward the
main checkout's local base-branch ref to match `origin/{base_branch}` whenever it
rebases the worktree branch — a `switch-and-pull`-equivalent call, gated on the main
checkout actually being behind and on a clean, fast-forwardable state. Alternatively,
have `compute-footprint` resolve its `base_ref` against `origin/{base_branch}` directly
rather than the local branch ref, so no separate synchronization step is required.

## Recovery applied

Ran `workflow-integration-git switch-and-pull --plan-id plan-truth-157 --base main`
before deriving gate bundles (clean fast-forward, 2 commits pulled, no conflict).

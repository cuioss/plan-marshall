# Check a review-bot suggestion that changes a bounded structure against the spec row that states the bound before committing it

Before applying a review-bot suggestion that changes a data structure on a bounded or specified path, check it against the spec rows and requirements that state the bound, because a bot argues from local code and does not read the specification.

## What happened

In plan plan-07-public-helper-hygiene (PR #908), CodeRabbit suggested replacing the per-chunk `List<byte[]>` in `BoundedBodyHandler.BoundedSubscriber` with one `ByteArrayOutputStream`. The suggestion was applied in a fix commit (323601d9). The next code-review round then raised a blocking finding: one growable buffer made the documented memory bound (`doc/commons/specification/transport.adoc`, requirement COMMONS-17: the byte ceiling plus one in-flight chunk) no longer true. The change was reverted (5e179faa) and the thread was answered as declined with that reason. The round at 323601d9 was discarded, and the revert moved HEAD again, which forced more review rounds. CodeRabbit accepted the decline on the thread and stored a learning for the file.

## Why it matters

- The fix cost a discarded review round, a revert commit and a further full re-review, because every new HEAD makes both review steps and the pre-push gate stale again.
- The check that caught it was the second review round, after the commit. The spec row was available before the commit.

## Rule

- Before committing a bot-suggested change to a structure on a path that a requirement or specification row bounds (memory, size, time, count), read that row and confirm the suggestion keeps the bound. If it does not, decline on the thread with the requirement id and do not commit.
- A thread that names a data structure is a signal to look for a bound, not only a style point.

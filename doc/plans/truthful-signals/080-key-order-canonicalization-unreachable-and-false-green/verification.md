## Report accuracy

Checked every claim-table row, every deliverable row, the build-gate figures, the Findings, and the Residue. Contradictions found:

1. **The contested write-site count is under-derived.** The report states "5 marshal.json write sites … Two routed, **three bypass**", and the corrected `order_config_keys` docstring enumerates the bypass writers as `ext_defaults_set`, `ext_defaults_set_default`, and "the OpenCode runtime seed". Re-derived at HEAD there are **six** sites, **two routed / four bypass**: the fourth bypass is `_claude_runtime_impl.py:44` `ClaudeRuntime.project_initial_setup`, which writes `.plan/marshal.json` through `claude_runtime._write_json` (`claude_runtime.py:1205`) with top-level `runtime` and `project_dir` keys and no ordering. That site predates the plan (`55cf61f1`, 2026-07-05, an ancestor of `10de4d12`), so it was present and missable at re-derivation time. Because the docstring presents its list as the exhaustive set of paths `order_config_keys` does not reach, the omission is a stale statement in production code, not merely an arithmetic slip. See G2.
2. **The residue's enumeration of unguarded writers is incomplete.** It names the three bypass writers as what "remain unguarded whole-document writes". `manage-providers`' `write_provider_config` → `_save_marshal` is equally an unguarded whole-document read-modify-write (and non-atomic), and is not named anywhere in the report. See G6.
3. **The `/plugin update plan-marshall` row overstates what was confirmed.** The plan's claim table required "confirm before shipping it as guidance". The report's evidence column offers "validated by the Step-6 cold-read sub-agent" — but a cold read tests whether a reader follows the wording, not whether the command exists or is the right recovery in this repository. The repository's own user documentation prescribes a different procedure (`doc/user/installation.adoc:57-64`, `README.md:46`: `/plugin marketplace update plan-marshall`, reinstall, then restart or `/reload-plugins`). See G5.

Immaterial: the report cites `_config_core.py:717-731` for the pre-fix `normalize_keys`; at `10de4d12^` the function spans `715-729` (a two-line offset). All other line citations I re-checked at the parent commit were exact: `order_config_keys` at `:96`, `save_config` at `:117`, `REMEDIATION` at `cache_freshness.py:76-79`, `test_sync_defaults.py:296`/`:307`, `upgrade.py` `_STAGE_SPECS` emitting only `reconcile-marshal-json`.

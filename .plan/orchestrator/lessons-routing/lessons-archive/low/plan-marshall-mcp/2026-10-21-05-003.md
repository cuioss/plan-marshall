# manage-status metadata --get invoked without its required --field

## What happened

Plan `question-corpus-ask-rate`, 2026-10-20T20:18:13Z: the call

`plan-marshall:manage-status:manage-status metadata --plan-id question-corpus-ask-rate --get`

was rejected by argparse (exit 2, `reason: missing_required_flag`, `rejected: --field`). The caller wanted to read
the plan's metadata without naming a field. The run continued, so the cost was one failed call and a
script-failure cluster that triggered the lessons-capture signal gate.

## Rule

`manage-status metadata` reads or writes one field: `--field` is required for `--get` as well as for `--set`.
There is no form that returns all metadata. Name the field you need (for example `--field worktree_path`), one call
per field, or use `manage-status read --plan-id {plan_id}` to read the whole status document. Take the flag set
from the script's canonical-invocation block or its `--help`, not from the surrounding workflow prose.

## Possible improvement

Either let `metadata --get` without `--field` return the whole metadata object, or name `read` in the
`missing_required_flag` message as the way to read all of it.

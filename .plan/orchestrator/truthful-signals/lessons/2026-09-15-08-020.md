# A bare snake_case identifier matched an unrelated taxonomy and became a declared deliverable step

Source: Q-Gate finding c5df62 (5-execute, resolution=rejected — confirmed no-op).

D2 directed updating the content_search status vocabulary in q-gate-validation.md. Both
of that file's content_search occurrences are section 2.12's OWN query-type enum
(find_pattern / sibling_group / content_search / directory_enum) and its resolution line
mapping content_search to `architecture search --content`. They are a NAME COLLISION with
the capabilities entry, not a reference to its status vocabulary. The file carries no
available/unavailable literal and does not consume the capabilities verb at all —
architecture search --content --literal --pattern 'architecture capabilities' returns 5
hits across 3 files, none of them this one.

## Solution

No edit was made: renaming the validator's query type would have been a fabricated change
to an unrelated taxonomy, made only because a deliverable step said so. When a declared
step turns out to rest on a name collision, the correct outcome is a recorded no-op, not
a cosmetic edit that satisfies the checklist.

## Impact

The outline's consumer sweep over-matched on the bare identifier and promoted the
collision into the declared Expected Surface.

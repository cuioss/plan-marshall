# Write U+2028/U+2029 in Java source as Unicode escapes, never as raw characters

## Problem

Tests that check line-separator sanitization (for example the U+2029 coordinate test added in TASK-008 of plan-05-jwe-ecdh-es) need the characters U+2028 (LINE SEPARATOR) and U+2029 (PARAGRAPH SEPARATOR). Writing them raw into Java source causes two problems:

- Sonar java:S2479 flags raw control or whitespace-like characters in literals.
- The Edit tool cannot reliably reproduce or match these invisible characters, so edits that try to insert or locate them fail or silently produce something else.

## Rule

Always write these characters as Unicode escapes in string or char literals: `" "` / `" "` (and `\r`, `\n` for CR/LF). Never paste the raw character. The same applies to any other invisible or bidi character (for example U+200B, U+202E) used in adversarial test data.

## Note

Java turns `\uXXXX` escapes into characters before lexing, even inside string literals. That is fine for U+2028/U+2029, which are not Java line terminators. But never write CR/LF as `\u000d` / `\u000a`, because they break compilation even inside a literal. Use the escape sequences `\r` / `\n` for those.

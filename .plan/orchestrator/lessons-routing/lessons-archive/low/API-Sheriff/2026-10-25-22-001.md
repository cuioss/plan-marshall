# A before/after coverage figure from `verify -Pcoverage` without `clean` reads a union of runs

Source: PLAN-V02-27 (#520), finalize functional review (residual D4.R3) and the code-review finding on `AnchorRules`.

`pom.xml` and `api-sheriff/pom.xml` configure the JaCoCo executions with `<append>true</append>` and a fixed `target/jacoco.exec`. The coverage command in `CLAUDE.md` has no `clean`. The merged report and `jacoco:check` therefore read every test JVM session since the last `clean`, so a figure taken before a change and one taken after it share old sessions. On their own, the two figures cannot show a coverage drop in a class whose bytecode did not change.

The plan fell back on a probe-level comparison of its own sessions against the union, from a scratchpad script that is not kept. A reviewer could check the reported outcome but could not re-run it. The comparison did surface a real one-probe drop in `AnchorRules`, a class the plan never touched.

## Rule

- Measure before and after with `clean verify -Pcoverage -pl api-sheriff -am`, or delete the module's `jacoco*.exec` files before each measured run. One figure then describes one tree.
- Keep a comparison script that a plan relies on as evidence inside the plan directory, not in a session scratchpad.
- Whether the coverage profile should reset its own exec data is a build change and needs its own plan.

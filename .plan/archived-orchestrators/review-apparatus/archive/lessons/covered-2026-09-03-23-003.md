title: "Gate participation on a bot that read the diff, not on required-bot quorum alone"
content: "## Context

Plan `misconfigured-reviewer-name-reads-missing-review` was written to stop a misconfigured
reviewer name from reading as a missing review. **Its own finalize reproduced the false green
it was written to close**, three times out of four.

For iterations 1-3 of `automatic-review` on PR #1392, the step reported
`participation_complete: true` with `proves: participation_only` while **no reviewer had read
the diff**:

- `cuioss-review-bot` satisfied the required-bot quorum with an **empty** review — the
  `## PR Reviewer Guide` boilerplate asserting \"PR contains tests / no security concerns /
  no major issues\", plus \"No code suggestions found\". `review_completeness` classified it
  `participated_but_empty` on **every one of the four iterations**.
- `coderabbit` was refusing on quota at 17:00Z, 18:48Z and 20:07Z.
- `sourcery` had refused structurally (150,000 diff-character ceiling against 1,924 changed
  lines) and could never clear — no backoff makes that refusal reviewable.

The quorum was true and the review was absent. An operator, not a gate, caught it at 18:27Z:

> \"Operator correction: coderabbit is REQUIRED, not optional. The prior run settled
> `participation_complete=true` only because coderabbit's `refused_awaitable` sat in
> `optional_bots`, where the rate-window recovery is scoped out.\"

Only after that correction did a real review happen — and it found a Major
(`cuioss-review-bot.md:64`, a rename-compatibility defect backed by reproducible static
analysis).

## Root cause

The participation predicate composes two facts that are each individually true and together
prove nothing: *every required bot is accounted for* and *at least one bot is not in a refusal
state*. It never asks whether any bot produced content about this diff. `participated_but_empty`
already exists as a distinct state — the run recorded it four times — but it is not consulted
at the pre-merge barrier, so an empty review is indistinguishable from a substantive one at the
only point where the distinction matters.

**The state refinement this plan shipped does not close this.** `unregistered_kind` refines
`absent` for a token that matches no registered `bot_kind`. `coderabbit` is a *registered*
kind that was merely placed in the wrong list, so the new state never applies. A
correctly-named bot in `optional_bots` still buys `participation_complete: true` with zero
diff-readers. This is residue of the shipped change, not a defect the shipped change created.

## Proposed action

1. Add a **diff-reader predicate** to the pre-merge barrier: at least one enabled bot must be
   in a state that proves it read this HEAD's diff and produced content.
   `participated_but_empty` must not satisfy it. This is a strictly stronger gate than the
   required-bot quorum and is orthogonal to it — keep both.
2. Make `proves: participation_only` a **blocking** value at the barrier rather than an
   informational label. The field already names the weakness of its own evidence; nothing acts
   on it.
3. Validate `required_bots` / `optional_bots` placement at config-read time against whether
   the named bot has ever produced content on this repository, and surface a placement that
   makes the quorum satisfiable without a reader. The `marshall-steward` config-read report
   this plan added is the natural home.
4. Record that the durable half of this run's correction is still **owed**: the manifest
   snapshot was fixed, tracked `.plan/marshal.json` was deliberately not (to avoid re-staling
   a green push-freshness gate). The next plan in this repository starts from the uncorrected
   tracked config unless `/marshall-steward` is run.

# Finding: light-lane pre-dispatch 2-refine closure is refused by the bare-transition guard

## What happened

Plan `issue-1697` routed `planning_lane=light` (signal_set, no fired signals,
`scope_estimate=single_module`). Following `planning.md` § Action: init
light-lane branch step 2a, the orchestrator attempted the pre-dispatch
closure:

`manage-status transition --plan-id issue-1697 --completed 2-refine`

before dispatching the collapsed light-lane envelope. The transition was
refused:

`error: refine_bare_transition — no phase artifact found (a
clarified/confidence record (request.md ## Clarified Request or
status.metadata.confidence)). Complete the phase artifact first, or re-run
with --allow-bare-transition --bare-reason REASON.`

Per the branch contract the orchestrator stopped: no `phase-boundary`,
no `phase_handshake capture`, no envelope dispatch.

## Why it matters

The light lane never dispatches `phase-2-refine`, so the phase body that
would write the clarified/confidence artifact never runs — yet the
pre-dispatch closure demands that artifact. Taken literally, a light plan
with no pre-existing refine artifact cannot enter its own envelope without
an explicit `--allow-bare-transition` exemption, which the workflow does not
authorize at this site.

## What is owed (process-compliance)

- Either the light-lane pre-dispatch closure carries an explicit,
  workflow-authorized bare-transition exemption (with the mandated
  `--bare-reason`), or the `refine_bare_transition` guard recognizes the
  light-lane pre-dispatch closure as a legitimate artifact-free close.
- No workaround applied: the `--allow-bare-transition` escape was not used
  unilaterally; the run stopped instead.

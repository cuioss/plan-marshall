# A new outcome-classifier seam ships fail-open on multiple independent axes (optional scoping key, classify-before-exactly-once-gate) — all in-house gates green, only post-push review bots caught them

## Context

Plan `background-build-kill` (PR #912) introduced a new outcome-classifier seam:
`manage-change-ledger classify-outcome` (decides whether a detached job's
`killed`/0-byte outcome is `externally_killed` vs `success`/`undecidable` by
cross-checking the build ledger) plus its consumer, the shared
`await-long-running.md` wake path. The seam shipped with unit tests, per-task
quality-gate, and whole-module module-tests — all green. Post-push, the review
bots found **multiple independent real fail-open defects in the same new
seam**; all were fixed in-run via TASK-8..11. The axes this lesson carries:

1. **Optional scoping key → stale-match false positive** (gemini, 6 comments
   tracing to this one root defect): `--worktree-sha` was optional on
   `classify-outcome`; omitting it let the classifier match the most recent
   ledger row from a DIFFERENT worktree state, classifying a freshly killed
   job as `success`. Fix: make the scoping key required (and sweep every doc
   / epilog / canonical-invocation site that showed it optional).
2. **Classification ordered before the exactly-once gate** (coderabbit): the
   wake path mandated "classify first" while the exactly-once no-op branch
   (cleared `build-busy` token) came later, so a repeated wake could re-run
   the classifier and re-surface a mandatory `externally_killed` verdict.
   Fix: read the state gate first; only the state-present branch classifies.

## The pattern

A classifier that adjudicates success/failure is a fail-open magnet: every
axis on which it can be under-constrained (an optional scoping input, a gate
evaluated after instead of before the classification) defaults toward the
*permissive* verdict. In-house tests written by the same plan encode the
author's happy-path model and exercise none of these axes, so the defects are
invisible to every in-house gate and surface only under adversarial post-push
review.

## How to apply

When shipping a NEW classifier/adjudicator seam (outcome mapping, gate
predicate, freshness check), run an explicit fail-open sweep before push:

- **Scoping inputs**: every input that scopes the evidence lookup (sha, plan
  id, worktree) must be required, or its absence must yield the conservative
  verdict — never a broader match.
- **Gate ordering**: any exactly-once / short-circuit guard must be evaluated
  BEFORE the classification it suppresses (same ordering class as lesson
  2026-06-28-13-001).

## Recurrence signature

- A plan introduces a new classifier / outcome-contract seam plus its own
  tests; all in-house gates pass.
- Post-push review bots file findings on the SAME seam: stale/over-broad
  evidence match, or guard-after-classify ordering.

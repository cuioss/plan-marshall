# Count a rename source as realized in the footprint comparisons

## Context

Plan `unified-sync-all-harnesses` moved three scripts and seven test files to new locations. Three retrospective checks reported the same 10 old paths as declared but never realized:

- `check-artifact-consistency`: `affected_files_recall` 86 of 96 (89.6%), `outline_only[10]`.
- `check-manifest-consistency`: rule M6 `declared_vs_realized_set` **fail**, "10 declared-but-unrealized".
- `check-outline-vs-shipped`: `include_unrealised` 10 of 78, "may be a silent descope".

Nothing was descoped. The outline declared all 10 with intent `delete`, and the task log records 8 of them as `Renamed {old} -> {new}` and 2 as `Deleted` with the content re-created under `marketplace/targets/claude/`. The same deliverable also declared 5 pure deletions (two `__init__.py` files, three retired entry points); none of those 5 was flagged.

## Root cause

OBSERVED: the realized footprint (tier `realized_capture`, 89 paths) holds the destination of a rename and not its source, while it does hold a plain deletion. A declared `delete` path that git pairs with a new file therefore reads as untouched.

HYPOTHESIS (the resolver was not read): the footprint is captured as a name list with rename detection on, which reports one path per rename.

## Proposed action

- Capture both sides of a rename in the realized footprint (name-status with the source path kept), or capture with rename detection off.
- Until then, have the three comparisons treat a declared `delete`-intent path as realized when the footprint contains a path whose rename source it is.
- Add a fixture with one rename and one plain deletion, and assert neither is reported as unrealized by any of the three checks.

## Evidence

- artifact_consistency: `missing[10]` and `outline_only[10]` list the same 10 paths; `read_intent_excluded: 4`.
- manifest_decisions: check `declared_vs_realized_set` fail, `outline_only_count: 10`, footprint tier `realized_capture`.
- outline_vs_shipped: `include_unrealised` count 10, denominator 78, same members.
- work.log 2026-10-02T14:42:52Z: seven `Renamed test/sync-*/... -> test/sync-harnesses/...` lines and `Renamed .claude/skills/sync-plugin-cache/scripts/reconcile_daemon.py -> marketplace/targets/claude/reconcile_daemon.py`; `Deleted test/sync-opencode/__init__.py` and `Deleted test/sync-plugin-cache/__init__.py` are absent from every `missing` list.
- request_result_alignment: deliverable 1 reads 66.7% coverage against the footprint for this reason alone, below the 70% bar for `fulfilled`.

This is a different population error from lesson `2026-10-02-10-007` (read-intent paths counted as expected modifications); both inflate `include_unrealised`.

# Run a Sonar/quality pass on the diff before push on large plans to catch new-code gate failures locally

Re-homed from the TokenSheriff consumer store 2026-07-16 ([[feedback_manage_lessons_cwd_store_resolution]]).

**Context:** TokenSheriff plan `client-code-review-fixes` (a large, 47-finding OIDC/OAuth client security remediation). The **SonarCloud new-code quality gate** (`new_reliability_rating`) failed only in CI, *after* push. The trigger was an S3077 finding — a `volatile` non-primitive field introduced by one of the in-plan fixes. Because the gate evaluates *new code* on the diff and only runs server-side after push, the failure cost a full CI cycle to discover something determinable from the diff locally.

**Why it slipped:** New-code quality gates (SonarCloud `new_*` metrics) are diff-scoped and evaluated server-side, so they are invisible to a local `verify`/`test` run. On a large plan the diff touches many files and the odds of introducing at least one gate-blocking reliability finding rise with diff size — yet nothing local surfaces it before push.

## How to apply

**When a plan is large, run a Sonar / static-analysis quality pass over the diff BEFORE push**, so gate-blocking new-code reliability findings are caught locally instead of costing a full CI round-trip:

1. Run the analyzer against the working diff prior to the `push` barrier — either a local Sonar scanner pass or the `sonar-roundtrip` / `pre-push-quality-gate` step scoped to the changed files.
2. Pay particular attention to *reliability*-rated rules on new code (S3077 volatile non-primitive is the concrete case) — these drop `new_reliability_rating` below the gate threshold and block the merge.
3. Fix or justify the findings in the same commit series, so the first CI run after push already reflects a clean new-code gate.

## Impact

Applies to any large-diff plan on a project with a SonarCloud/SonarQube new-code quality gate. The pre-push local Sonar pass converts a post-push CI-cycle failure into a cheap local fix, most valuable when the diff is big enough that a blocking new-code finding is likely.

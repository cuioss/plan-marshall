# Full 6-phase pipeline cost ~2.3M tokens / 4h wall for a trivial doc rename+move — right-size the planning lane to the task

A documentation-only task — relocate 8 conceptual docs under `doc/validation/`, rescope 3 titles, and rewrite inbound/outbound links — was run end-to-end through the full deep-lane 6-phase pipeline. The actual edits (a `git mv` plus find/replace across links) are a few minutes of work, yet the run cost **2,260,310 total tokens, 931 tool uses, 2h21m worked / 4h2m wall** (plan `doc-validation-capability-split`, shipped as PR cuioss/TokenSheriff#524).

## Root cause: framework overhead dominates, not the editing work

1. **Every phase/step is a separate subagent that reloads large SKILL.md bodies into context each turn.** The per-phase `cache_read` figures (12.7M in refine, 28M in outline) are the plan-marshall skill documents being re-read on every turn of every dispatched agent. The pipeline is sized for substantial multi-module code changes; applied to a doc move it is almost pure overhead.
2. **The lane router sent a trivial task down the deep lane.** `planning_lane` resolved to `deep` (the conservative default — scope/change_type signals were not yet set at init), which runs the full refine-loop → Complex-Track outline → q-gate-validation → per-envelope execute → full finalize. A bounded, localized doc rename/move is the archetypal light-lane (or even skip-the-pipeline) candidate.
3. **Avoidable rework (~400K) from incomplete initial planning.** The plan scoped only AsciiDoc/Markdown links; two link classes it missed (119 Javadoc `<a href>` links across 47 files, and the relocated docs' own outbound/image links) surfaced *during* execution and forced mid-flight scope additions (deliverable 5 + an added task), each re-running heavy agents.
4. **Idle wall-clock (1h41m of 4h)** was mostly CI waits (a >10-min Maven+Sonar build, requiring a second wait cycle) plus orchestrator polling cadence between background agents.

## Corrective rule

For tasks that are bounded, localized, and mechanically simple — pure rename/move, find/replace, doc relocation, single-file edits with no cross-module behavioral change — the orchestrator should NOT default to the full deep-lane pipeline:

- **Strengthen lane routing at init for low-complexity change types.** A `tech_debt`/`docs` change with `scope < module` and no code-logic delta should route to the light lane (collapsed refine+outline+derive envelope) rather than defaulting to `deep`. The deep default is conservative but, for these inputs, expensive by ~10x.
- **Prefer a scripted fast-path over per-step subagent dispatch for mechanical edits.** A `git mv` + a scripted link-rewrite pass + one build delivers the same result in minutes at near-zero tokens; reserve the full pipeline (q-gate loops, CI/Gemini/Sonar, freshness gate) for changes whose value is traceability + adversarial review of real logic.
- **Front-load link/scope discovery for relocation plans** so the outline is complete before execute (see sibling lesson `2026-06-30-00-001`) — this eliminates the mid-flight re-dispatch rounds that were a large fraction of the outline/execute cost here.

### The optimal path that would have produced the identical merged outcome

`init (minimal)` → **skip refine** (1-shot premise check at most, given 99% first-pass confidence) → `outline` **with complete inbound+outbound+Javadoc link-class enumeration up front** (eliminates all 3 re-dispatches) → **collapse 4-plan** into a single linear task list (no envelope bin-packing for a linear move; and it would not have minted the wrong verify command) → `execute` **in ONE envelope** → finalize with a **scripted CI-green check instead of a ci-verify agent**, `automated-review` (keep — it found real defects), **skip sonar** for a no-code-logic change, then merge.

That path removes the four lowest-value spends (refine ~103K, the 4-plan defect-introducing decomposition, ci-verify-as-agent ~101K, sonar ~113K) and the avoidable iteration (~320K of outline re-dispatches + the ~execute drift re-dispatch), collapsing ~16 agent dispatches to roughly 4–5. Rough order-of-magnitude: the same merged PR for well under a third of the tokens, with the two checks that actually mattered (outline scope-validator + automated-review) retained.

### Generalizable signal

The steps that added value on this run were the **adversarial/validation** ones (outline scope-criterion validator, automated-review) — they found things. The steps that added little were the **transform/confirm** ones applied to an input that didn't need them (refine on a complete spec, task-decomposition of a linear change, ci-verify/sonar on a no-logic change). Right-sizing should therefore be driven less by "doc vs code" and more by: **skip transform/confirm steps when their input is already high-confidence or their output is structurally guaranteed empty; always keep the adversarial validators.**

## What the cost bought (the trade-off, stated honestly)

The pipeline route did deliver real value the fast-path would not: it caught both scope gaps (Javadoc + outbound links) via the q-gate scope-criterion validator, enforced the module quality gate on the Javadoc edits, triaged 8 review-bot comments, and produced a reviewed+merged PR with full metrics/lesson traceability. The lesson is not "never use the pipeline for docs" — it is "the orchestrator should match pipeline weight to task complexity, and the operator should be able to see the ~100x cost multiplier before committing a trivial task to the deep lane."

## Recurrence — 2026-06-30 (plan-marshall `integrate-sonar-finalize`, PR cuioss/plan-marshall#806)

Second data point, and an important one because it **breaks the "trivial task misrouted to deep lane" framing**: this run was a *correctly* deep-routed plan — a genuine 4-deliverable change (two real tool-layer bug fixes + a credentials surface + Sonar wiring). The lane router was right to pick `deep`. Yet it still cost **3,779,867 tokens / ~3h47m worked / ~8h28m wall** to land **14 files / 1047 insertions / 82 deletions**, of which only **~240 lines are production logic** (the rest is ~843 lines of tests + ~75 of docs/config). That is **~15,700 tokens per line of real logic**. So the overhead this lesson identifies is **structural, not merely a routing mistake** — a properly-scoped deep plan pays the same per-dispatch floor.

### What actually drove the cost (in priority order)

1. **The single most *fixable* miss — envelope batching was defeated by `task_complete_returned_verbatim`.** phase-4-plan's bin-packer put **all 7 tasks into ONE envelope** (`envelope_count: 1`) precisely so a single phase-5-execute dispatch would load context once and loop through all 7. Instead the execute leaf returned the bare `task_complete` **after the first task on every dispatch** — so the orchestrator re-dispatched **7 times** (+2 more for the loop-back fix tasks), each reloading persona + `execute-task` + domain skills + re-reading task state. This is the *same* drift the original lesson flagged as "1 wasted re-dispatch," but here it hit **every task**, turning a planned 1-dispatch execute into ~9. This alone likely accounts for the bulk of the ~1.63M execute spend. **Fixing the leaf to run its envelope loop (or having the orchestrator force-batch the remaining same-`envelope_id` tasks instead of re-dispatching) is the highest-leverage change for this class of plan.**
2. **The finalize floor (1.34M, 35%) is structural and worse for the meta-project.** No lane/recipe knob touches finalize; the meta-project set adds plugin-doctor, deploy-target, sync-plugin-cache, and three retrospective-class steps (review-retrospective, plan-retrospective at 13 aspects ≈ 153K, lessons-housekeeping over a 49-lesson corpus). The orchestrator and each step also re-load 600–1000-line workflow docs (`phase-6-finalize/SKILL.md` ~1000, `branch-cleanup.md` ~880, `execution.md` ~625).
3. **New cost class this run added — avoidable *rework* (~200K+ a wasted build).** The `finalize-step-security-audit` agent applied a `PLUGIN_CACHE_PATH` hardening **inconsistent with its own *accepted* sibling finding** (`PLAN_MARSHALL_CREDENTIALS_DIR`), which broke 2 test-isolation tests. Caught by the orchestrator's pre-push re-verify and reverted — but it cost the audit dispatch (~140K), a wasted ~11-min `verify`, and a second verify after the revert. An audit that checks its own dispositions for self-consistency before applying an edit would have saved all of it.
4. **New cost class — merge-staleness rebases (2 extra full CI cycles).** `main` advanced (parallel sessions: #807, etc.) *during* the ~11-min CI waits, so the up-to-date branch-protection requirement bounced the merge twice; each retry was rebase + force-push + a full ~11-min CI wait. The early-baseline-rebase step does NOT close this — the vulnerable window is the CI wait itself, not plan start.
5. **Serial adversarial iteration — self-review ran 3× and automated-review looped once.** Each was *legitimate* (self-review found 2 real doc-drift gaps; automated-review's loop-back fixed a real secret-key-leak bug → lesson `2026-06-29-23-001`), but they re-ran heavy agents serially.

### The optimal path that produces the identical merged PR #806

`init` → `refine` (1 round — it earned its keep) → `outline + q-gate` (keep the validators) → `plan` **giving D4 a real implementation task** (no verification-only deliverable → no `triage_required` recovery) → **`execute` in ONE envelope** (fix the leaf loop / force-batch same-`envelope_id` tasks → ~9 dispatches collapse to ~2) → finalize keeping the **adversarial finders** (self-review, security-audit-as-finder, automated-review — they found 3 real defects) but with **security-audit checking self-consistency before applying** (no PLUGIN_CACHE_PATH revert + no wasted re-verify) and **lessons-housekeeping short-circuited** when the footprint touches no lesson component, then a **merge-queue that holds `main` steady across the CI wait** (eliminating both staleness rebases).

That removes: ~6–8 redundant execute dispatches (envelope defeat), the security-audit revert + its extra `verify` build (~140K + ~11 min), the 2 merge-staleness CI cycles, and the D4 `triage_required` recovery — plausibly **halving the spend** while retaining *every* step that found a real defect.

### Generalizable signal (extends, does not replace, the original)

The original lesson's rule — *skip transform/confirm steps when the input is high-confidence or the output is structurally empty; always keep the adversarial validators* — held up perfectly here: the adversarial steps (refine clarifications, self-review, automated-review, security-audit-as-finder) **found 3 real defects + 1 security bug**, fully earning their cost. The new finding is that **on a correctly-deep plan the dominant cost is no longer misrouting — it is (a) the execute envelope loop not actually batching (a reliability bug, not a sizing choice) and (b) the per-dispatch fixed cost of re-loading large SKILL/workflow docs**, neither of which any lane/recipe/effort knob addresses. Right-sizing the *lane* is necessary but insufficient; the deep lane itself needs (1) a reliable single-envelope execute loop and (2) leaner per-dispatch context, plus rework-avoidance (self-consistent audits) and a merge-queue to kill staleness rebases.

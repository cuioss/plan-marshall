# Prescribe a hook-compatible generate call in the sync-harnesses command

## Context

PR #1684 added the `sync-harnesses` command in three harness-local files (`.claude/skills/sync-harnesses/SKILL.md`, `.opencode/commands/sync-harnesses.md`, `.agents/skills/sync-harnesses/SKILL.md`). Step 1 of each prescribes three `./pw generate-*` calls. The enforcement hook's R4 rule denies a direct `./pw` call inside a plan context (an execution-context subagent, or a working directory under `.plan/local/worktrees/`). The command's own `--from-worktree` note says the regeneration "belongs in that worktree", so the denied case is one the command documents.

CodeRabbit raised this (finding `d27a5d`, thread `PRRT_kwDOQ3xasM6oeiyt`). It was declined at triage and the thread resolved; the limit shipped.

## Root cause

The triage declined on the ground that the suggested remedy could not be written: `architecture commands` lists no `generate` canonical, and the project instructions prescribe the `./pw` wrapper for the generator. That ground is weaker than it reads. Earlier in the same plan the orchestrator generated every target inside the worktree through the build wrapper, `pyproject_build` with `generate --target all --output target` (decision `12c560`), which is a form the hook accepts.

The decline was a triage judgement and was not operator-confirmed. The finding is stored with resolution `accepted` while its text opens "Declined - false positive on the remedy"; the review retrospective flagged that mismatch.

## Proposed action

Pick one and apply it to all three entry points plus `finalize-step-deploy-target`, which the parity test pins to the same command sequence:

- Prescribe the build-wrapper form for the generate step, the form decision `12c560` used; or
- add a `generate` canonical to the architecture resolver and prescribe the resolved command; or
- give R4 a documented carve-out for the generator verbs.

Then settle the stored resolution of `d27a5d` so the label and the text agree.

Not verified here: whether the build-wrapper form works on OpenCode and Antigravity, where the generated executor may be absent.

# Doc body prose carries non-portable tokens (dates/versions, machine-specific paths) violating house conventions — caught only by PR bots, no in-house gate enforces it

## Context

The `security-skills-reorganization` plan authored seven new
`persona-security-expert` standards sub-documents (`owasp-top-ten.md`,
`threat-modeling-stride.md`, `secrets-handling.md`, `secure-logging.md`,
`input-validation-trust-boundaries.md`, `authentication-authorization.md`,
`secure-design-principles.md`) plus the owning `SKILL.md`. The clarified
request mandated web research for "current (2024-2025) security best
practices". The research sources — OWASP releases, NIST SP 800-63 revisions,
FIDO/WebAuthn pages — are inherently version- and date-stamped, and that
framing was carried verbatim into the authored standards.

The result: the docs shipped with embedded dates, edition labels, historical
rank-change prose, and protocol-version numbers that violate the marketplace
documentation convention "No version history / No timestamps — current state
only" (CLAUDE.md § Documentation Standards).

Concrete violating shapes that landed on the PR (#777):

- `OWASP Top Ten (2021)`, `2025 update changes`, `A01:2025` — edition/version labels
- `July 2025`, `since 2021`, `1975`, `Rev 6 draft`, `v1r1` — embedded dates and revision IDs
- Historical rank-change prose and a dated "update section" (turning a standard into a history page)
- `TLS 1.2+/1.3` — a hardcoded protocol-version number where "modern TLS" was the versionless intent

## How it slipped through

Every in-house gate was clean: phase-5 authoring, the scoped plugin-doctor
quality-gate, AND the pre-submission self-review all passed the docs. There is
**no in-house gate that enforces the no-timestamps / no-version-history
documentation convention** — plugin-doctor has no rule for dated/versioned
prose, and the pre-submission self-review surfacer has no candidate class for
it. The convention is documented as a house rule but not mechanically checked.

The defect surfaced only when the external PR review bots read the docs:
CodeRabbit raised **seven** inline findings against this exact root cause
(every new standards doc plus SKILL.md was flagged), two of them rated
**Major / heavy-lift**, all tagged "Source: Coding guidelines". Remediating
them required a full late finalize loop-back — TASK-008 "Fix PR review
findings — timestamps, ..." (9 sub-steps).

This is the same "in-house gates clean, only the adversarial PR bot caught it"
family as lessons `2026-06-22-13-001` (ruff RUF select gap), `2026-06-21-12-002`
(MD040 not in markdown gate), and `2026-06-22-12-001` (placeholder-expansion
length blind spot) — but the root cause here is distinct from all of them: it
is an **authoring-convention violation triggered by the source material**, not
a lint-rule-coverage gap or a hidden-computation blind spot. The trigger is
specific: content sourced from inherently date-stamped web research carries its
provenance framing into the doc body unless the author actively strips it.

## Corrective rule (do X, not Y)

When authoring or rewriting any marketplace skill/standards/reference document
— and **especially** when the content is sourced from web research (which is
always version- and date-stamped at the source):

1. **Apply the no-timestamps / no-version-history convention proactively at
   authoring time, not reactively after a PR-bot flag.** Before writing the
   first line, treat "current state only — no dates, no edition labels, no
   version numbers, no rank-change history, no dated update sections" as a hard
   authoring constraint, equal in weight to the technical accuracy of the content.

2. **Separate the normative content from its provenance.** Keep the security
   guidance (the category, the control, the principle) in the doc body
   versionless; push the version/date/edition into the external source *link*
   only. "OWASP Top Ten per-category A01–A10" in the body; the `(2021)` edition
   lives in the cited URL, not the prose. "modern TLS" in the body; the exact
   `1.2+/1.3` floor lives in the platform-specific standard.

3. **Do NOT transcribe the research's framing.** Web pages narrate "in 2021 this
   moved from A6 to A1", "the 2025 revision changed X", "Rev 6 draft". That
   narration is provenance, not normative guidance — it is exactly the
   version-history framing the convention forbids. Extract the *current* rule
   and drop the historical narrative.

4. **Self-check before submission**: grep the authored docs for four-digit years
   (`19\d\d`, `20\d\d`), edition/version tokens (`vN`, `RevN`, `:20\d\d`,
   `Top Ten (`), and protocol-version literals (`TLS 1.`, `1.2+`) — any hit in
   doc *body* prose (as opposed to a citation URL) is a likely violation.

## Why in-house gates miss it

No deterministic in-house gate reads doc prose for dated/versioned framing:
plugin-doctor's rule set has no `no-version-history` / `no-timestamps` analyzer,
and the `ext-self-review-plan-marshall` surfacer enumerates no candidate class
for dates/editions/version-numbers in markdown body text. The convention is
enforced only by the external CodeRabbit reviewer (which carries it under
"Coding guidelines"). Until an in-house surfacer or plugin-doctor rule
implements a body-prose date/version detector, the only defenses are (a)
proactive authoring discipline per the corrective rule above and (b) the
authoring-time self-check grep — both must run BEFORE the PR, because otherwise
this defect costs a guaranteed PR-bot round-trip and a late finalize loop-back.

## Impact

All seven occurrences were caught and fixed in-run before merge, so nothing
non-conforming shipped — but at the cost of a full TASK-008 loop-back. Affects
**every** future skill/standards authoring or rewrite task in the marketplace,
and disproportionately any task whose clarified request mandates web research
for "current best practices" — the research mandate and the no-timestamps
convention pull in opposite directions, and the author must hold both
simultaneously. The general mitigation is to add a body-prose date/version
detector to plugin-doctor (or the self-review surfacer) so the check runs
in-house rather than relying on the PR reviewer.

## Recurrence — 2026-06-28 (measure-uncompressed-output)

Recurred on PR #791, which shipped a single self-authored analysis report
(`doc/analysis/uncompressed-output-measurement.md`) — **not** a marketplace
skill/standards doc, and **not** web-research-sourced. The report embedded a
literal scope-window date (`2026-06-14`) in its Scope prose. Every in-house
gate was clean again; CodeRabbit caught it as a `📐 Maintainability` inline
finding tagged "Source: Coding guidelines" — the same external-bot-only catch
this lesson predicted, now confirmed on a second, structurally different doc.

This recurrence **broadens the lesson** along two axes:

1. **Scope is all repo docs, not just marketplace standards docs.** The
   no-timestamps / no-version-history convention applies to `doc/analysis/`
   reports and every other authored markdown body in the repo, not only
   `marketplace/bundles/**` skill/standards files.

2. **The trigger is not only web-research provenance.** A self-authored
   analysis doc naturally reaches for a factual date as a scope boundary
   ("the window ending 2026-06-14"). The defect arises whenever any concrete
   date/version *needs* expressing — the fix is to describe the window
   relatively ("the recent ~2-week window") or push the provenance into
   metadata, never to inline the literal date in body prose.

### Sibling facet — machine-specific paths in committed doc bodies

The same PR also leaked a machine-specific local path
(`~/.claude/projects/-Users-oliver-git-plan-marshall/{uuid}.jsonl`) into the
report body, exposing the OS username and home-directory layout. CodeRabbit
caught this as a `🔒 Security & Privacy` finding — again, no in-house gate
reads doc prose for it. This is the **same meta-defect** as the dated-prose
facet: a non-portable, environment-specific token lands in a committed doc
body, no in-house surfacer detects it, and only the external PR bot does.

Corrective rule for the path facet (do X, not Y): when an authored doc must
reference a Claude Code transcript or other local file location, use a generic
placeholder source reference (`~/.claude/projects/<project>/<uuid>.jsonl`, or
prose like "the Claude Code session transcripts") — never the literal expanded
path that embeds the real username/home layout. Extend the authoring-time
self-check grep to flag `/Users/`, `/home/`, and `-Users-`/`-home-` slug
fragments in doc *body* prose, alongside the four-digit-year/version checks
already listed above. Both facets share one root mitigation: an in-house
body-prose detector (plugin-doctor rule or self-review surfacer) for
non-portable environment-specific tokens — dates, versions, AND machine paths.

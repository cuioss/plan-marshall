# Give pre-submission-self-review a computed convergence signal

component: plan-marshall:phase-6-finalize
category: improvement
confidence: high

## Context

On this plan `pre-submission-self-review` fired 7 times, looped back 6 times, and produced 19 findings across 8 rounds before it stopped. It did not stop because it converged — it stopped because the operator was asked and answered "Fix these 3, then push". The run's own gate question records the shape precisely: every round found a few more, all small, and none about whether the feature works. Finalize consumed 3,282,984 tokens, 48.5% of the plan's 6,765,189 total and more than execute's 2,197,227, on a plan whose `single_module + bug_fix` anchor puts the error threshold at 1.3M for the whole run.

## Root cause

The step has a loop-back edge and no stop predicate. Nothing computes whether round N found less than round N-1, whether the findings are in the same class as the previous round's, or whether the remaining findings bear on the change under review at all. With no measured signal, the only available terminator is an operator judgement — so the loop runs until a human notices the cost.

## Proposed action

Publish a per-round finding delta the step can gate on: new-findings-this-round over total-findings-this-round, plus the per-round class distribution, from the findings store the step already writes to. Then either stop on a declared convergence condition (for example, a round that finds nothing outside the classes already fixed) or escalate to the operator with the delta attached rather than with a free-text question. The inputs are already machine-parseable; the missing piece is that nobody computes them.

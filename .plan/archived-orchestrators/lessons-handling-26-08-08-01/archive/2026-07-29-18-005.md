# A discriminator over a derived collection's keys cannot separate unknown from empty

## Observation

`architecture files --category X` had to answer two questions the spec presented as distinguishable:
"this category name is not in the taxonomy" (error) versus "this category is valid but empty for this
module" (success, empty list). Q-Gate proved they are the **same condition on identical input**.

The files block is built with `categorised.setdefault(category, []).append(...)`, so **only categories
that actually have files ever become keys**. An in-taxonomy-but-empty category is therefore absent from
the block, making the two answers indistinguishable. The deliverable was not implementable as written.

## Root cause

**No category-vocabulary constant existed.** The category names were bare string literals returned by
`_classify_marketplace` / `_classify_generic`. With no declared vocabulary, the only set available was
the derived collection's keyset — and a collection built by `setdefault(...).append(...)` structurally
cannot represent an empty member.

## Rule

When a verb must answer *"is this name wrong, or is this name right but the answer is empty?"*, the
authority for **right** must be a **declared vocabulary constant**, never the keyset of a lazily
populated aggregation. `setdefault` / `defaultdict` / `groupby` accumulators all share the shape:
absence and emptiness are the same state.

**The absence of a vocabulary constant is itself the smell.** If the category names exist only as
return-statement string literals, no correct discriminator can be written — introduce the constant
first, then discriminate against it.

Pin the vocabulary against its published documentation with a test asserting the error payload's
listed values **equal** the constant. On `manage-architecture` that drift was already live: the
published list carried a `config` category neither classifier could ever emit.

## Where to look

Any `manage-*` script whose CLI takes a `--{dimension}` selector over classifier-produced values.
The signature: a validation branch testing membership in a **computed dict** rather than in a
module-level constant.

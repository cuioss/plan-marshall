# Operator answers to an outline-time prompt were recorded in the decision log but not written back into solution_outline.md

Source record: quality-check finding d880a3 (phase 3-outline, severity info, resolved `taken_into_account` in-run) of plan `plan-30-early-answer-upstream-port-exhaustion` (PLAN-30, PR #448, merge commit b7b98699).

## What happened

The operator answered the four outline-time questions, and the decision log recorded the answers (entry 87fa29, 2026-10-13T20:41:06Z): abortive close, the whole HTTP/1.1 client, an ADR-0066 amendment, no extra benchmark aspect. `solution_outline.md` was not updated to match. Its Summary and its SO_LINGER risk still said the choice was "put to the operator in the prompt below", although the document had no such prompt, and deliverable 7 kept a dead "if the operator chooses a new ADR instead" branch. Phase 4 derives its tasks from the outline, not from the decision log, so the tasks would have carried the alternative the operator had rejected.

## Resolution in this run

The Summary was rewritten to record the four decisions as settled; the pending-prompt wording and the new-ADR branch were removed. The deliverable set did not change.

## Rule

When the operator answers an outline-time prompt, write the answers back into `solution_outline.md` in the same step: replace the pending-choice wording and delete the branches that were not chosen. A decision recorded only in the decision log does not reach phase 4.

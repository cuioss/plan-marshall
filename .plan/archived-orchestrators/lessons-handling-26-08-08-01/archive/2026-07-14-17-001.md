# Presence check by narrow key (id-only) hides a wrongly-shaped existing record and unfiltered external-API list elements corrupt the merged payload

## Context

While shipping the `merge-queue-bypass-actors` plan (PR pending), `_self_heal_merge_queue_bypass` in `marketplace/bundles/plan-marshall/skills/workflow-integration-github/scripts/github_ops.py` gained the ability to re-grant a configurable bypass actor on the merge-queue ruleset when GitHub's GH013 misconfiguration state is detected. The implementer, self-review, and phase-5 q-gate-validation all shipped the surface clean — module-tests and quality-gate green, plugin-doctor clean. CodeRabbit's PR review then caught **two distinct correctness bugs** in the same function that every in-house gate missed.

## The two defects

1. **Unfiltered echo of untyped external-API list elements into an outbound payload.** The existing `bypass_actors` list fetched from the GitHub ruleset-detail API was assumed to be a list of dicts and echoed straight into the merged PUT body (`existing_actors = existing if isinstance(existing, list) else []`). A non-dict element anywhere in that list (a malformed/legacy ruleset entry) would be echoed verbatim into the merged payload, corrupting it. Fix: filter to dict entries only (`[a for a in existing_raw if isinstance(a, dict)]`) before using the list for anything beyond the type check.

2. **Presence check by a narrow key (`actor_id` only) instead of the full identity the code actually grants.** The self-heal's whole purpose is to correct a GH013 misconfiguration where an actor_id is present on the ruleset but with the WRONG `actor_type`/`bypass_mode`. The original presence check built `present_ids` from `actor_id` alone (`{a.get('actor_id') for a in existing_actors if isinstance(a, dict)}`), so an actor present with the wrong shape was counted as "already granted" and silently skipped — exactly the misconfiguration the self-heal exists to fix. Fix: only count an id as present when its entry carries the *exact* granted shape (`actor_type == 'Integration' and bypass_mode == 'always'`); treat any other shape as missing, drop the wrong-shaped entry, and re-grant the correct one.

## Root cause

Both bugs share one root cause: a membership/type check that validates a **narrower identity** than the one the surrounding logic actually depends on.

- Bug 1: the code checked "is this a `list`?" but the logic downstream depends on every *element* being a `dict` — the check validated the container, not the elements it echoes.
- Bug 2: the code checked "is this `actor_id` present?" but the logic downstream depends on the **full granted shape** (`actor_id` + `actor_type` + `bypass_mode`) — the check validated a subset key, not the identity the function is actually reconciling against.

Both defects are invisible to a happy-path test corpus: a fixture where every existing actor is already a well-formed dict with the correct shape makes the narrow check and the correct check produce identical output. Only a fixture with an element that satisfies the narrow key but NOT the full identity (a non-dict list element; an actor_id present with a different type/mode) exposes the gap — this is the same "positive-only corpus gives false confidence" shape already generalized in `2026-06-24-14-003` Bug C (filter-predicate needs a negative-case test), specialized here to *membership/presence* checks rather than list-comprehension filters.

## How to apply

- **When a function's downstream logic depends on a full-shape identity (multiple fields), the presence/membership check must test the SAME full shape — never a single subset key.** Ask: "if this function corrects a wrong-shaped record, does my presence check use the same fields that make a record wrong?" If the check uses fewer fields than the correction logic cares about, a wrong-shaped-but-key-matching record will be misclassified as already-correct and skipped.
- **When echoing elements from an untrusted/external API list into an outbound payload, filter to the validated element type BEFORE using the list, not just gate on the container type.** `isinstance(x, list)` says nothing about the type of `x`'s elements; validate (and filter) at the element level whenever elements are echoed downstream.
- **Test corpus for a self-healing/reconciliation function must include a "wrong-shaped-but-key-present" fixture.** A test suite where every existing record is already correctly shaped cannot distinguish a full-identity check from a narrow-key check — add a fixture where the key matches but a dependent field diverges, and assert the record gets corrected, not skipped.
- **Test corpus for any function that echoes a fetched list must include a malformed/non-dict element.** Add a fixture with a non-dict (or otherwise mistyped) element in the source list and assert it is filtered out of the outbound payload, not echoed.

## Impact

Had these bugs shipped, the self-heal would have silently no-op'd on exactly the misconfiguration it exists to fix (an actor present with the wrong bypass shape) and risked corrupting the PUT payload on any ruleset carrying a malformed existing entry — both failure modes are silent (no exception, no log signal), so they would only surface as a recurring GH013 merge-queue block that the "fix" never actually resolved.

# Reconcile pre-submission-self-review mutates_source with its actual edit behaviour

## Context

The `pre-submission-self-review` step declares `mutates_source: false` in its frontmatter. On this
plan the dispatch edited 10 files and then returned without calling `mark-step-done`. Two contract
violations in a single dispatch.

The dispatcher's completion guard caught the missing handshake, and the orchestrator committed the
edits rather than discarding them — the right call, since the work was verified. But the recovery
worked because a guard happened to be watching, not because the contract held.

The declaration matters beyond bookkeeping: `mutates_source` is what tells the finalize machinery
whether a step's return can invalidate a downstream freshness verdict. A step that edits source
while declaring it does not is invisible to exactly the checks that exist to notice source moving.

## Root cause

The step's frontmatter describes an earlier, read-only shape of the step. The self-review has since
grown a fix-application path, and the declaration was never updated to match. The missing
`mark-step-done` is a separate defect in the same dispatch: the edit path returns before reaching
the handshake tail.

## Proposed action

Two independent fixes. First, set `mutates_source: true` on the self-review step, or split the
fix-application into a separately-declared step if the read-only declaration is load-bearing
somewhere. Second, move the `mark-step-done` call onto the path the edit branch actually takes, so
the handshake is not skipped when the step does work.

## Evidence

- aspect: execution_context_dispatch_audit — the step appears in `dispatched_steps[7]` and its

  `failed`, `loop_back`, `loop_back`, `done`, `done`, `loop_back`.
- aspect: logging_gap_analysis — the finalize dispatch ledger records 26 rows and the audit's
  `channel_completeness` confidence is `low`, so a silently-missing handshake is not reliably
  visible from the channel alone.

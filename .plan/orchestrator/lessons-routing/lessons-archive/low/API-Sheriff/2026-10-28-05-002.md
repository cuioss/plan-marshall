# Guard a retired key with an exact key-set assertion, not with negative checks that spell the retired name

Source: PLAN-V02-09 (#530), candidate lesson 006; functional-review residual D4.R1.

## Observation

Retiring the `issuer_reachability` metric key left `SheriffMetricsTest` spelling the retired name five times as `assertNull` guards. The functional review flagged it: the retired name stays in the codebase and a later grep still finds it, and a negative check catches only that one spelling, so any other unexpected key passes unnoticed.

## Rule

When a key, metric or tag is retired, assert the exact expected key set (`assertEquals(Set.of(...), actual.keySet())`) instead of one `assertNull(map.get("<retired>"))` per retired name. It catches the retired key and any other unexpected one, and it does not spell the retired name.

## Apply

Any plan that retires a config key, metric, tag or JSON field and keeps a test around the surface.

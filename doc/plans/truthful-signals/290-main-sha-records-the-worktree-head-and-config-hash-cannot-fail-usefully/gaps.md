## G3 — Stop calling the `None` return "fail-closed"

- **Kind:** doc-drift
- **Severity:** low
- **Where:** `marketplace/bundles/plan-marshall/skills/plan-marshall/scripts/_invariants.py:1524-1526` — `_capture_config_hash` docstring; echoed in `test/plan-marshall/plan-marshall/test_invariants_behavior.py:232`.
- **What is wrong:** The docstring calls returning `None` on an absent / unreadable / non-dict `marshal.json` "fail-closed". At the **boundary gate** it is the opposite: `capture_all` (`_invariants.py:1893-1894`) skips any invariant whose capture returns `None`, so the `config_hash` column is written empty and `_diffs` (`_handshake_commands.py:495-498`) skips any column whose captured value is `''` — so the next boundary raises no blocking diff and the plan advances. Closed behaviour holds only in the verify direction, where a *captured* value against an observed `''` does raise a blocking diff.

  **Corrected during adversarial review — "no diagnostic" was overstated.** An earlier draft of this gap said the invariant "simply disappears with no diagnostic". That is false: `config_hash` is a member of `_CORE_INVARIANTS` (`summarize-invariants.py:49-56`), and `cmd_run` emits a severity-**`error`** finding `Phase {p} missing invariant config_hash` for every blank column (`:341-350`), locked by `test_summarize_invariants_behavior.py::test_missing_core_invariant_flagged_per_phase` (`:276-292`). The accurate defect is narrower and still real: the diagnostic is **post-hoc**, raised by the retrospective summarizer after the run, not by the boundary the docstring's word "fail-closed" points at.
- **Why it matters:** A reader auditing this epic's "signal absent" archetype would read "fail-closed" and stop looking, when a `marshal.json` unreadable at capture time lets the boundary the docstring names pass unblocked. Severity stays `low` precisely because the absence is not silent end-to-end — the retrospective summarizer does raise it as an `error` — so the cost is a misleading word, not a lost signal.
- **Fix:** Replace "fail-closed" with an accurate statement of both directions: at capture the invariant is recorded as not-applicable (empty column, no signal) rather than as a false "config emptied" drift; at verify a value that becomes unreadable diffs against the captured hash and blocks. Mirror the wording in the test docstring.
- **Done when:** `grep -n "fail-closed" marketplace/bundles/plan-marshall/skills/plan-marshall/scripts/_invariants.py test/plan-marshall/plan-marshall/test_invariants_behavior.py` returns zero hits inside `_capture_config_hash` / its tests, and the replacement prose names all three directions: capture (column left empty, boundary not blocked), verify (captured-vs-`''` blocks), retrospective (`invariants_missing` → severity `error`).

## G5 — `build-decision`'s documented `--audit-plan-id` alias is unreachable through the mandated executor path

- **Kind:** bug
- **Severity:** medium
- **Where:** `marketplace/bundles/plan-marshall/skills/manage-config/SKILL.md:1428` — "`--audit-plan-id` is accepted as an alias for `--plan-id`"; the declaration at `marketplace/bundles/plan-marshall/skills/manage-config/scripts/manage-config.py:388-392`; and the fallback that reads it at `marketplace/bundles/plan-marshall/skills/manage-config/scripts/_cmd_build_map.py:160`.
- **What is wrong:** `extract_audit_plan_id` (`tools-script-executor/templates/execute-script.py.template:1221-1253`, applied at `:1417`) strips `--audit-plan-id` from `argv` **unconditionally, for every notation**, before the target script is dispatched. `.plan/execute-script.py` is the mandated invocation path for every marketplace script (CLAUDE.md § Script Execution Convention), so `args.audit_plan_id` is **always `None`** in `_cmd_build_map.py:160`, the `or getattr(args, 'audit_plan_id', None)` fallback is dead, and the documented alias never works. Executed at HEAD: `python3 .plan/execute-script.py plan-marshall:manage-config:manage-config build-decision --audit-plan-id VERIFY-ADV-290` returns **`status: error` / `build-decision requires --plan-id (or --audit-plan-id)`** — the error message names the very flag the caller just passed — while the control `… build-decision --plan-id VERIFY-ADV-290` returns `status: success` with a `decision: unknown` verdict. `argparse_surface.py:213-215` states the contract this declaration violates: `audit-plan-id` is "injected and consumed by the executor wrapper BEFORE the target script's argparse runs". The `sync-defaults` declaration (`manage-config.py:419-423`) is inert rather than broken — no code reads `args.audit_plan_id` there — but it is dead for the same reason.
- **Why it matters:** This is the *same* executor-stripping mechanism G1 establishes, applied to the one noun that genuinely declares the flag — so the two gaps are the two halves of one misunderstanding, and fixing G4 by "naming `build-decision` and `sync-defaults`" without this would document a contract that does not hold. Concretely: a caller following `SKILL.md:1428` gets a `status: error` from the sole build/no-build authority (ADR-004) and, per ADR-009, a gate reading an unsubstantiated verdict must fail toward inclusion — so the cost is a spurious build, on a flag the docs promised.
- **Fix:** Pick one direction and make the three sites agree. Preferred (contract-preserving): delete the `--audit-plan-id` declarations at `manage-config.py:388-392` and `:419-423`, delete the `or getattr(args, 'audit_plan_id', None)` fallback at `_cmd_build_map.py:160`, change the error string at `_cmd_build_map.py:162` to `build-decision requires --plan-id`, and delete the alias sentence from `manage-config/SKILL.md:1428`. Alternative (if the alias must live): have `extract_audit_plan_id` re-append `--audit-plan-id {value}` for notations whose parser declares it — but that contradicts `argparse_surface.py:213-215` and should not be chosen without amending that comment.
- **Done when:** `python3 .plan/execute-script.py plan-marshall:manage-config:manage-config build-decision --audit-plan-id X` and the `--plan-id X` control agree — either both succeed, or the failing one's error text names only flags that can actually reach the parser — and `grep -n "audit-plan-id" marketplace/bundles/plan-marshall/skills/manage-config/scripts/manage-config.py marketplace/bundles/plan-marshall/skills/manage-config/scripts/_cmd_build_map.py marketplace/bundles/plan-marshall/skills/manage-config/SKILL.md` returns nothing that promises an affordance the executor strips.
- **Module/topic:** `plan-marshall:manage-config` — `build-decision` CLI surface; `plan-marshall:tools-script-executor` — the `--audit-plan-id` stripping contract.
- **Scope note:** found while confirming G1's mechanism, not while checking a deliverable of plan 290. It is recorded here because it is the same defect class at the site G4 sends the next reader to; an implementer may legitimately route it to a `manage-config`-owned plan instead.

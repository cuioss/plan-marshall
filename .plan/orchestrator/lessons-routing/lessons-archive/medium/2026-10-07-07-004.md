# Record real spend and the right cause on cancelled and operator-blocked dispatches

## Context

Plan `plan-pr-078-review-bot-fleet-opt-in` recorded 10 dispatch-boundary rows for `5-execute`. One row, stamped `harness_cancellation` at 2026-10-06T14:19:03Z, carries `total_tokens=0`, `tool_uses=0`, `duration_ms=0`. The work log shows that dispatch started at 12:59Z, opened three foreign pull requests, waited on checks and was still logging at 13:36Z. Five further rows are stamped `voluntary_checkpoint`; each of those dispatches ended because the leaf needed an operator decision or an orchestrator-tier build (pack-table confirmation, the org release, the schema gate, `verify plan-marshall`, a stale executor).

## Root cause

A cancelled dispatch returns no usage envelope, and the recorder's three usage flags default to `0`, so "nothing was measured" is written as a measured zero. For the cause, the orchestrator picks `voluntary_checkpoint` for any non-completion that hands control back, although the accepted set already contains `blocked_user_review` for exactly the operator-decision case and has no value for "orchestrator-tier build owed".

## Proposed action

- Give `--total-tokens` / `--tool-uses` / `--duration-ms` on `record-dispatch-boundary` the same no-numeric-default treatment the four context-load columns already have: an omitted flag writes `unmeasured`, never `0`.
- In `plan-marshall/workflow/execution.md`, map a leaf return carrying `escalate_ask` / `prompt_options` to `blocked_user_review`, and decide explicitly which cause an "orchestrator-tier step owed" return takes.
- Until then, read `retryable_total_tokens: 0` and the voluntary-checkpoint share as lower and upper bounds respectively, not as measurements.

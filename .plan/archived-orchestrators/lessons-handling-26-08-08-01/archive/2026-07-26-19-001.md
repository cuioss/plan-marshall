# Equality-based sentinel-tuple emptiness check treats numeric 0/0.0 as empty (False == 0), so a non-empty-payload guard silently drops the content it exists to detect

The plan added `_fragment_has_payload()` to `plan-retrospective/scripts/compile-report.py` — the
discriminator that distinguishes a benign omission (an aspect genuinely produced nothing) from a
loud drop (an aspect produced content the emit gate refused). The whole point of the plan was to
stop `compile-report` from returning `success` while silently dropping non-empty sections.

The predicate shipped as:

```python
for key, value in fragment.items():
    if key in ('status', 'aspect'):
        continue
    if value not in (None, '', [], {}, False):   # defect
        return True
return False
```

`in` on a tuple is **equality**-based, and in Python `False == 0` and `False == 0.0`. So a fragment
whose only real content is a numeric zero — a count of `0`, a ratio of `0.0` — matched the `False`
sentinel and was classified as carrying no payload. The guard that existed to make silent drops loud
silently dropped exactly the zero-valued payloads that a retrospective most needs to report (`0`
starting markers, `0.0` architecture-lookup ratio — the very anomalies the checks fire on).

Every in-house gate was green: ruff, mypy, module-tests, plugin-doctor, and the plan's own new
behavior tests all passed, because no fixture carried a zero-valued payload field. The CodeRabbit PR
review bot was the only signal that caught it.

## Corrective rule

Never express an empty-sentinel set as an equality-membership test that mixes `False` with
container/`None` sentinels. Check `False` (and `True`) by **identity**, and let equality handle only
the non-boolean sentinels:

```python
if value is False:
    continue
if value not in (None, '', [], {}):
    return True
```

Generalized: any newly-authored **presence / non-emptiness predicate** must be validated against the
full falsy domain of the language before it is trusted — `0`, `0.0`, `False`, `''`, `[]`, `{}`,
`None`, `Decimal('0')`. Enumerate the falsy domain explicitly and decide, per member, whether it is
payload or envelope. `if not value:` and `value in (…falsy tuple…)` are the two shapes that collapse
that decision by accident.

## Why it matters beyond the one call site

This is the confident-signal-hides-a-caveat archetype turned on itself: the fix for a
silent-omission defect contained the same silent-omission defect one layer down. When a plan's
deliverable *is* a truthfulness guard, the guard's own edge-case domain is the highest-value place
to spend verification effort — a test matrix over the falsy domain costs minutes and is the only
in-house mechanism that would have caught this before push.

## Test obligation

A payload/emptiness discriminator needs a parameterized case per falsy value, asserting the intended
classification for each — including the `0` / `0.0` / `False` triple that the equality trap conflates.
Without that matrix the predicate is untested precisely where it is wrong.

# Docs-only deliverable that changes a pinned script call-shape breaks narrative-contract module-tests, but plugin-doctor-only verification never runs them

A docs-only deliverable edited `architecture-refresh.md` to move the top-level
`--project-dir` flag ahead of the `enrich module/package/skills-by-profile`
subcommand — the correct call ordering mandated by lesson `2026-07-07-20-001`.
That mechanical, structurally-clean doc fix broke a **narrative-contract unit
test** (`test_architecture_refresh.py`
`TestNarrativeContract::test_documents_enrich_call_in_auto_branch`) that
asserts the literal adjacency `architecture enrich module` as a substring of the
doc. Moving the flag between the verb and its subcommand changed that literal
adjacency, so the assertion failed.

The break did not surface at the deliverable boundary: the D1 task's declared
verification was the plugin-doctor quality-gate (the default for a docs-only
deliverable), which does **not** run module-tests. The failing narrative-contract
test only appeared in the orchestrator's end-of-phase comprehensive module-tests
sweep — after the deliverable had already been marked done.

## Rule

When a doc change alters the **shape** of a script invocation it narrates
(flag position, verb/subcommand adjacency, argument order, notation form),
treat it as a change to a pinned contract, not as free-text prose:

1. **Sweep the narrative-contract tests** that pin that call shape as a literal
   string. In this meta-project those live in `TestNarrativeContract` classes
   (e.g. `test_architecture_refresh.py`) and assert exact substrings like
   `architecture enrich module`. Any doc edit that moves a token across that
   pinned boundary will break the assertion. Grep the touched call shape's
   literal adjacency across the test corpus and update the pinned string in the
   same deliverable.
2. **Do not trust plugin-doctor-only verification for such a doc change.**
   plugin-doctor validates structure, not doc *content* asserted by
   module-tests, and a docs-only deliverable's default verification does not run
   module-tests. When a doc edit changes a call shape that a module-test pins,
   the deliverable's verification scope must include those module-tests (scope
   the test module into the per-deliverable verify), or the break slips to the
   comprehensive end-of-phase run.

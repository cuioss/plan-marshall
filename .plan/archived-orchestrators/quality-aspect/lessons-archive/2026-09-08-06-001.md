# A sweep must verify the claims it authors, not only the ones it inherits

## Context

Plan `sweep-preambles-shipped-accessors` (PLAN-135, epic test-quality, PR #1446) exists to
remove hand-rolled test preambles that assert invariants the code does not establish. While
doing so, deliverable D4 (commit `552f2747d`) **authored a new docstring paragraph that was
false on all three of its claims**, in a file it was already editing.

The paragraph claimed the `_run_python` helper in
`test/sync-plugin-cache/test_staleness_guard.py` restricted the child's path to the
marketplace `skills/*/scripts` directories, never the repository root, keeping the
`marketplace.targets` package route unreachable.

1. **"never the repository root … stays unreachable"** — the code controls only
   `PYTHONPATH`. For a `python -c` launch `sys.path[0]` is the **cwd**, inherited from the
   test runner and equal to the repository root. The route declared closed was wide open.
2. **"the `skills/*/scripts` directories only"** — the code appends the inherited
   `PYTHONPATH` unconditionally, re-admitting any repo-local entry the parent carried.
3. **"that both callers rely on being unreachable"** — the negative control relies on the
   exact opposite: it inserts `PROJECT_ROOT` deliberately so the package *is* reachable, so
   that what stops the import is the `yaml` blocker rather than a missing `marketplace`.

The pre-plan docstring (`b4e8a2364`) made no isolation claim at all. This was not an
inherited falsehood the sweep failed to catch — the sweep **manufactured** it.

## Root cause

**The remedy vocabulary is shape-based; the defect is claim-based.** The classification
artifact recorded remedies for `subprocess-pythonpath` as `run_script` or explicit `env=` —
properties of a call's argv/kwargs *shape*. The deliverable's success criterion therefore
reduces to "does the site now carry an explicit env mapping?", which is fully satisfied by
code whose accompanying prose is false. The rule checks a shape and cannot check a claim, so
a sweep validated by that rule is structurally blind to its own defect class the moment it
starts writing prose of its own.

**The verification obligation was attached to inherited prose, not authored prose.** The
classification artifact listed two care-needed rows and gave an explicit claim-verification
obligation to only one:

| Row | Obligation attached | Outcome |
|-----|---------------------|---------|
| `test_runner_falsifiability.py:42` | confirm propagation does not defeat the declared isolation intent | Discharged; resulting docstring is **true** |
| `test_staleness_guard.py:706` | *none* | Author wrote an isolation claim anyway, reasoned only about the variable just written, missed the cwd route, inverted the caller intent. **False** |

Same task, same author, same commit. Where the obligation was written the prose came out
correct; where it was omitted the prose came out false. The obligation — not author
diligence — produced the correct result. And the row that received it was the one whose
claim *already existed*; the row about to have one *written into it* got nothing. That is
backwards: authored prose is precisely the prose no prior reviewer has ever checked.

Every internal gate passed it: task verification, the deliverable sweep, end-of-phase
verification, pre-submission self-review, and the quality gate. It was caught by CodeRabbit
**running a probe** — one `python -c` under the helper's own launch conditions.

## Corrective action

1. **Treat a claim the sweep AUTHORS as a deliverable of the sweep**, verified to at least
   the standard applied to inherited claims. A sweep that writes a false preamble is the
   highest-severity instance of the thing it exists to remove.
2. **Attach the claim-verification obligation per site, from the classification artifact**,
   to every row whose remedy will touch or add prose — not only to rows carrying
   pre-existing claims. The mechanism is already demonstrated to work; it was simply not
   applied uniformly.
3. **Verify an environment/isolation claim by running it, not by reading the diff.** The
   falsifying probe was one line under the helper's own launch conditions. Make that the
   required evidence for any "X is unreachable" claim.
4. **Reusable technical fact:** a `python -c` child has *two* path routes — `PYTHONPATH`
   **and** `sys.path[0]`, which for `-c` is the cwd. Any unreachability claim about a `-c`
   launch must address both. Controlling one and asserting the conjunction is the specific
   error made here.
5. **Never assert what "both callers rely on" without reading both callers.** The third
   falsehood needed no probe at all — only reading the two call sites.

## Scope note

This is the *backward* question: how a false claim was authored and shipped green. The
complementary *forward* gap — that no test now discriminates whether the corrected isolation
holds, so a regression would restore the un-isolated child and keep both tests green — was
tracked separately as finding `a073b5` and is now closed: plan
`close-the-leftover-gate-gaps` (deliverable D2) shipped
`test_child_cannot_reach_the_repository_by_environment`, which launches a bare `python -c`
child with no help and asserts the `marketplace` package stays unreachable, so a regression
to an inherited cwd or `PYTHONPATH` route fails the suite. The backward question this lesson
answers is not subsumed by that test.

The sibling site `test_runner_falsifiability.py::_run_pytest` carries the same unconditional
inherited-`PYTHONPATH` append, but there it is both harmless and argued to be harmless in
the prose. It serves as the control.

### What this recurrence adds

**Corrective #2 was not in force, and the reason is now concrete.** The plan carried four
stated plan-wide invariants and per-deliverable verification criteria — collected-count
invariance (20940 → 20954, asserted exactly), nodeid stability for the seven
`_SKIP_EXCEPTIONS` entries, the `touches_real_state` source-symbol coupling, and the
`_NAMED_STATE_DRIVING_MODULES` curated-tuple coupling. Every one of those is a **shape**
check, and each was discharged with evidence. Not one of them can evaluate whether a
sentence the commit wrote is true. This is the Root cause above, restated by a second
independent sweep: a sweep validated by shape rules is structurally blind to its own prose,
however many shape rules it stacks up. The obligation has to be attached to the *authoring
act*, not to the transform.

**Generalize the component.** This lesson was filed against `plan-marshall:phase-3-outline`
because that is where the per-site obligation would be attached. The recurrence shows the
class is not outline-specific: it fires wherever a mechanical transform also writes
explanatory prose. The enforceable hook is the deliverable's verification-criteria list —
any deliverable whose remedy adds or edits a comment, docstring, or table caption needs one
criterion that reads the authored text against the code it describes.

**The detector does not enumerate its own class.** `18703d` surfaced **no** deterministic
candidate; the finding itself records that it was reached only by a class-closure sweep
after `be1440` had established the class, and so "lies outside the strict surface-only
bound". Absent the first finding, the second and third would have shipped. That half of the
gap is the surfacer's, not the sweep's — see lesson `2026-09-09-01-001` for the same shape
on a different class; it is cross-referenced here rather than restated.

# A task whose deliverable requires a broad content sweep is unexecutable in a dispatched leaf: Grep/Glob can be denied at runtime while Bash grep/find are hook-blocked, leaving no fallback

## Context

Plan `retirement-verdict-cited-a-contradicting-example`, TASK-002 ("Sweep the
standards tree for worked examples that contradict their own clause"). The task
required, as Step 1, a content-filter over the whole
`marketplace/bundles/*/skills/*/standards/*.md` population, and as Step 1b it
made the pair-bearing subset size a **first-class required output** (the
verification criteria demanded both the population size and the
contradicting-example count).

The dispatched `execution-context` leaf could not run the sweep:

* The **`Grep` tool was not granted** to the leaf at runtime — `No such tool
  available: Grep`.
* The **`Glob` tool was not granted** either — `No such tool available: Glob`.
* **Bash `grep` / `find` / `ls` are hook-blocked** unconditionally by the
  project's no-shell-file-operations rule ("use the Read/Glob/Grep tools, not
  Bash").

All three legs of the search surface were closed simultaneously, so the only
remaining primitive was `Read` over 359 files (~1.3M tokens) — which is not a
sweep, it is the volume-read-as-coverage anti-pattern with a token bill
attached.

## The pattern

`execution-context` already documents the *narrow* case: when `Grep` is denied,
"read the specific failure detail out of the already-known `log_file` with a
targeted `Read`". That fallback presumes a **known target**. It does not
generalize to a **population sweep**, where the whole point is that the targets
are unknown until the content filter runs. For a broad-pass deliverable the
documented fallback is not a smaller version of the task — there is no fallback
at all.

The failure is therefore a **planning-time** defect, not an execution-time one:
the task was placed into a dispatch envelope whose tool grant cannot express its
deliverable. The leaf did the only correct thing available (returned the
coverage gap rather than passing a shrunken sweep as green), but that costs a
full dispatch round-trip that better planning would have avoided.

Note the second-order trap in this specific plan: deliverable 3 builds the very
worked-example-vs-clause **detector** that deliverable 2's manual sweep needed,
yet deliverable 2 was sequenced first. Ordering the detector before the sweep
would have turned a hand sweep into a script output — and made the population
count a deterministic artifact rather than a hand count.

## How to apply

At planning time (phase-4-plan), when a task's deliverable is a **coverage
claim over a population** — a sweep, an audit, a "find every X", a
population-size output — do one of:

* **Sequence the detector first.** If a later deliverable builds a script that
  performs the scan, order it BEFORE the sweep that needs it. The sweep then
  consumes a deterministic script output instead of a hand pass, and the
  population count becomes reproducible evidence rather than an assertion.
* **Keep the sweep in the main context.** The main-context orchestrator is the
  sanctioned search-capable path. A broad content sweep belongs there, not in a
  dispatched leaf.
* **Never make a population size a required output of a leaf-dispatched task**
  unless the enumeration is obtainable from a structured query
  (`architecture find` / `architecture files`) alone.

At execution time, when a leaf hits this deadlock: return the coverage gap.
Do NOT substitute a spot-check of the pre-named mutation set and report it as
the sweep — that reproduces, one layer up, exactly the under-evidenced-verdict
defect most such plans exist to fix.

## Recurrence signature

- A task description contains a population-scale verb ("sweep", "audit every",
  "enumerate every", "for each of the N files") AND declares a count/population
  size as a required output.
- The task is dispatched to `execution-context` rather than run in main context.
- The leaf reports `No such tool available: Grep` (and/or `Glob`), and the Bash
  fallback returns the `use the Read/Glob/Grep tools, not Bash` hook message.
- The tempting-but-wrong resolution is to audit only the files named in the
  task's `steps[]` and report the sweep as complete.

# A spec's claims about a dependency's history and about "test X pins Y" are leads: check them against the pinned jar and by deleting Y

Source: PLAN-V02-09 (#530), candidate lesson 004.

## Observation

Two claims in the staged PLAN-V02-09 spec were false when checked during execution. The spec said the token-sheriff extension's health beans were never registered before 0.9.7; inspecting the shipped jars showed otherwise, and ADR-0074 had to correct the account. The spec also said `ShippedApplicationPropertiesTest` pins the exclusion; it does not, so the test the spec named as the guard did not guard that property.
## Rule

- When grounding a spec, check a claim about third-party artifact behaviour against the actual jar or bytecode of the pinned version, not against release notes or issue threads.
- Verify "test X pins Y" by asking whether deleting Y turns X red, before the spec relies on it. This is the repository's configuration-key rule applied to a test claim.
- Correct the staged spec text in place when a claim is disproven.

## Apply

The orchestrator's re-grounding of every staged spec that names a library behaviour or a guard test; the plan's outline for the same claims.

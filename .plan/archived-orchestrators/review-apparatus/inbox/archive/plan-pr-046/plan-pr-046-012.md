# The participation-marker admission test is an unanchored substring match, and its target layout has never been sampled

Filed as its own finding because plan-pr-046 declined it twice and carried it only as a
trailing aside inside `plan-pr-046-001.md` § "recorded not filed" — a message whose stated
subject is the refusal *detector*. An epic draining that message for its titled sections has
no reason to open work here. This message is the proper carry.

## The code, as shipped on main

`marketplace/bundles/plan-marshall/skills/workflow-integration-github/scripts/github_pr.py`,
`_is_participation_evidence`, lines 295-299 (verified present on `main` at `77cb2e251`):

```python
kind = comment.get('kind') or 'inline'
if kind not in bot_registry.participation_evidence(bot_kind):
    return False
marker = bot_registry.participation_evidence_marker(bot_kind, kind)
return not marker or marker in str(comment.get('body') or '')
```

The CONTENT gate is a bare `in` test over the whole body. Any occurrence of the declared
literal anywhere in the comment — including inside quoted PR text, a nested block, or a
user-authored excerpt the bot echoes — satisfies it.

## Why this was declined, and why the decline does not close it

CodeRabbit raised it twice on PR #1477: `b131a3` (round 1, Major) and `c847ec` (round 3,
Major, adding the quoted-PR-text vector). Both were resolved `taken_into_account`, not
`rejected` — the observation was never disputed. The decline rested on one argument:

> Tightening an unanchored match fails **CLOSED**. A verdict comment that does not match
> resolves a clean review as `absent`, which BLOCKS a merge. The declared
> `recent_review_start` marker is **absent from CodeRabbit's live summary comment on
> #1477**, so the canonical layout is pinned by no observation at all. Anchoring against a
> layout nobody has sampled risks a merge-blocking false negative.

That argument is about the **risk of the proposed remedy**, not about the validity of the
finding. Both directions are still open:

- **Unanchored (today):** a walkthrough or echo carrying the literal credits participation
  the bot has not performed — the exact fail-open plan-pr-046 existed to remove, surviving
  in the fix for it.
- **Anchored (the declined remedy):** a layout drift silently blocks merges.

The gate cannot be evaluated in either direction until the layout is sampled. **That is the
actual owed work, and neither declined comment named it.**

## The load-bearing gap: the shipped gate is unexercised in production

`recent_review_start` is declared in `automatic-review/standards/coderabbit.md` and consumed
here, but it did not appear in CodeRabbit's live summary comment on the very PR that shipped
the gate. So:

- no production observation pins the canonical layout;
- the `issue_comment` arm of the gate has never fired against a real marker-bearing comment;
- the plan's own regression coverage asserts against fixtures the plan authored, not against
  a sampled artifact.

A gate whose only evidence is its own fixtures is the vacuous-authority archetype this epic
already tracks.

## Proposed work

1. **Sample first.** Collect the real CodeRabbit verdict-comment bodies across several
   recent PRs and establish whether `recent_review_start` appears, where it sits, and whether
   its position is stable. This is the blocking prerequisite — do not tighten before it.
2. Decide the admission rule on that evidence: anchor to body start, anchor to a structural
   position, match a regex, or keep the substring test and document why it is sufficient.
3. If the marker is genuinely absent from the live shape, the declaration itself is wrong and
   the fix is in `coderabbit.md`, not in `github_pr.py`.
4. Add a negative control for the echo vector specifically: a body carrying the literal only
   inside quoted PR text must not credit.

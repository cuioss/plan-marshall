# A documented derived value assumed a framework setting the code never configured

# A documented value derived from another setting assumed a setting the code never configured

Source: kidicap-gateway-requirements PLAN-32 (plan-32-early-answer-it-timeouts, PR #466), functional-review findings 1fbd73 and 0ddd51.

## What happened

`doc/user/endpoint-routes.adoc` and `doc/architecture.adoc` both stated the inbound HTTP/2 connection-window default as per-stream window x 100 concurrent streams. The gateway did not configure the stream count, and the Quarkus 3.40.1 default is different, so the deployed value was not the documented one. The fix was to configure the cap explicitly in `EdgeHardeningOptions`. It cost one finalize loop-back plus a CI re-proof.

## Rule

When a document states a value derived from another setting ("X = per-stream window x N streams"), check that N is configured in code. Compare it with the framework's real default for the version in use, and pin N in a unit test. When two documents state the same derived value, check both against that one source of truth (the configured option and its test), not each document on its own.

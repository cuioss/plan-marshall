# Re-trigger a required bot left participated_stale by a new HEAD

## Context

On PR #1690, after a loop-back fix commit moved HEAD to 691cadf9f, `review_completeness check` returned `participation_complete: false` because the required `cuioss-review-bot` was `participated_stale` (its only comment predated the new HEAD). The step recorded `loop_back` to 6-finalize, and the leaf reported that a plain re-dispatch would reach the same state again. It needed an operator-directed re-run and `--force` on `mark-step-done` to get past it.

## Root cause

Trigger B chooses which bot to re-trigger only from staged bot-authored findings. cuioss-review-bot's comment is filtered as noise, so it never has a staged finding, and neither documented trigger path posts its `/review`. The `participated_stale` remedy in the doc names a re-trigger that no code path reaches.

## Proposed action

Have trigger B also select every required bot whose participation state is `participated_stale` at the current HEAD, and call `github_re_review re-review --bot-kind {bot}` for it before the buffer wait.

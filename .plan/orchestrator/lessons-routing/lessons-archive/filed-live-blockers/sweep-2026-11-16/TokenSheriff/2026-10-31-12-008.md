# Handle every OpenRewrite marker immediately: fix it, or suppress it in the sanctioned form, before the commit

## Problem

The `-Ppre-commit` OpenRewrite run injected a `/*TODO: Catch specific not RuntimeException. Suppress: // cui-rewrite:disable InvalidExceptionUsageRecipe*/` marker into `holdsNewerGrant` (plan-02, PR #832) and it was committed. Nothing in the build or the early review rounds flagged it; only the closing code-review round surfaced it, and it is still in `TokenLifecycleManager.java` on main, where Sonar reports it as an open INFO `java:S1135` issue. `AGENTS.md` ("OpenRewrite Markers") already says never to commit code with markers present; the marker was a request-to-act that was left unanswered.

## Solution

Every OpenRewrite marker is handled immediately, in the same task that produced it, before the commit. Fixing the code is the preferred answer. Suppression is allowed only in the sanctioned form from `AGENTS.md` (`// cui-rewrite:disable <Recipe>` plus a comment recording the specific reason) and only where that section permits it. For `InvalidExceptionUsageRecipe` it permits it solely for an open set of SPI implementations that declare no `throws`; otherwise narrow the caught type. After every `-Ppre-commit` run, scan the diff for newly injected markers (the `search-markers` tooling) before committing, and treat a marker as an unanswered finding, not as formatting noise.

## Impact

An unresolved marker ships in committed code, is found only by a late review, and leaves an open Sonar issue behind.

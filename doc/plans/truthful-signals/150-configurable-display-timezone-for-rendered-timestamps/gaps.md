## G1 — Make the D5(c) storage-invariant test assert the digits, not a format literal

- **Kind:** vacuous-test
- **Severity:** high
- **Where:** `test/plan-marshall/manage-run-config/test_display_time_render.py:120` — `test_stored_timestamp_is_utc_under_any_knob_value`
- **What is wrong:** The test sets `display_timezone: 'Asia/Kolkata'`, asserts the knob reads back, then asserts `now_utc_iso().endswith('Z')`. The `Z` is a literal character inside the format string at `marketplace/bundles/plan-marshall/skills/tools-file-ops/scripts/file_ops.py:91` (`datetime.now(UTC).strftime('%Y-%m-%dT%H:%M:%SZ')`), so it survives any timezone conversion. Mutation-confirmed: rewriting `now_utc_iso` to `datetime.now(UTC).astimezone(ZoneInfo('Asia/Kolkata')).strftime('%Y-%m-%dT%H:%M:%SZ')` — precisely the defect the test names — leaves it **green** (`uv run python -m pytest …::test_stored_timestamp_is_utc_under_any_knob_value -o addopts="" -q` → `1 passed`).
- **Why it matters:** `plan.md` § Verification marks D5(c) with ⛔ as *the* invariant test — the refusal in the Problem section expressed as an assertion. As written it certifies an invariant it cannot observe: a future change that let the display zone reach the write path would ship with this test green, which is this epic's namesake false signal. (The D4 guard would still catch the realistic form of that change, because it scans for the knob-consumer symbols; D5(c) adds no independent protection today.)
- **Fix:** Assert the value, not the suffix. Parse the produced stamp and compare it against an independently computed UTC clock, e.g. `parsed = datetime.strptime(now_utc_iso(), '%Y-%m-%dT%H:%M:%SZ').replace(tzinfo=UTC)` then `assert abs((parsed - datetime.now(UTC)).total_seconds()) < 60`. Better still, freeze the clock (monkeypatch `file_ops.datetime`) and assert the exact expected string, so the test is deterministic. Add the same shape for at least one other store primitive that is written *and* later compared — the lesson-identifier prefix built at `marketplace/bundles/plan-marshall/skills/manage-lessons/scripts/manage-lessons.py:148-150` is the plan's own named STORE trap and its date/hour digits would visibly move under a converted clock.
- **Done when:** Applying the `astimezone(ZoneInfo('Asia/Kolkata'))` mutation to `file_ops.now_utc_iso` (and to the `manage-lessons` prefix derivation) turns the D5(c) test RED, and the unmutated tree is green.
- **Module/topic:** `plan-marshall:manage-run-config` — display-timezone tests (`test/plan-marshall/manage-run-config/`)

# Executor generation must order tree-bound script dirs before user-global opencode roots

## Status

The guarded failure mode no longer occurs. The generated OpenCode resolver
is tree-first — root 0 is the live `marketplace/bundles` tree above the
executor file, and the user-global roots are deprioritised behind it, so a
stale user-global copy can never shadow tree code. The ordering is stated
as tree-first rather than alphabetical in the executor template, and
`test/plan-marshall/tools-script-executor/test_executor_tree_first.py`
guards it.

## Root cause

Path assembly had no tree-before-cache ordering rule, so discovery order
leaked directly into sys.path precedence. An alphabetical sort is a silent
choice rather than a safe default: `.config` sorts before `git`, so a
deployed root wins on name alone.

## Proposed action

Codify the precedence where behaviour is loaded, not only in generator
comments. `tools-script-executor/SKILL.md` section "Self-healing path
resolution" still enumerates steps 1-4 (direct embedded hit, prefix/substring
shim, target-aware resolver, cwd/executor-file upward walk) and never states
that tree-bound paths outrank user-global roots; that section also carries no
worked example, which is why this lesson is retained rather than retired.
Keep the negative control that rides with the rule: a generated executor must
import the tree's own `_manifest_validation`, never a same-named cache copy.

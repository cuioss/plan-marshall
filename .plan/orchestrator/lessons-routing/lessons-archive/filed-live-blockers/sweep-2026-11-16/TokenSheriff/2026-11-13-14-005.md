# Triage should prefer a code fix over a suppression for a Sonar finding on plan-authored lines

For a Sonar finding on lines the plan itself wrote, triage must propose a code fix first; a suppression is allowed only with an explicit justification that the finding is a false positive and no reasonable rewrite exists, and is otherwise the fallback for legacy or out-of-footprint code.

## What happened

In plan client-authorization-request-seam, the unified triage proposed `@SuppressWarnings` for a new-code Sonar S2589 (condition always true or false) on lines the plan had written. The dispatcher overrode it with a real fix (a null-safe `MoreStrings.isBlank`) because suppressing a new-code issue violates the Java suppression standard. The proposal was wrong and only the dispatcher's override prevented it.

## Rule

- Located on plan-authored (new-code) lines: propose a code fix first.
- Propose a suppression only with an explicit false-positive justification and a statement that no reasonable rewrite exists.
- Suppression is the fallback for legacy or out-of-footprint code, not the default for new code.

# Derive pre-push gate scope from the active build system, not marketplace bundles alone

On a Maven project, the pre-push module-tests arm degraded: no module-tests canonical resolves at default scope, and footprint paths matched a build_map glob but resolved to no bundle (`derive_gate_bundles` derives from marketplace bundles — always zero on Maven; `build-maven` has no `resolve-test-scope` verb). The honest-degradation rendering worked (whole-tree verify still ran green), but the scoped-vs-whole-tree divergence class went ungated, twice (PLAN-10 and PLAN-12 recurrence).

## Solution

Derive the gate scope from the active build system (or `architecture which-module`), and record module-tests as covered when the configured verify already ran the full suite. Scope: marketplace half only — the cui-http project-config half (register a default-scope canonical) stays epic-local.

## Impact

Every non-marketplace consumer project: a silently ungated divergence class per push until the scope derivation is build-system aware.

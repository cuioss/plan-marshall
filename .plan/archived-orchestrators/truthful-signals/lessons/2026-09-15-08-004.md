# Amend the declared file surface when an operator authorises a mid-run widening

## Context

Two operator decisions widened this plan mid-execute: deliverable 2 was extended to cover `marshall-steward/references/menu-derivation-resolvers.md` (a doc D2's own change had falsified), and a 12th deliverable was added for `execute-task`'s `assert_test_identifiers`. Both were recorded as gate decisions in the session. Neither amended the outline's declared file surface.

## Root cause

The declared footprint is captured from the solution outline at outline time and is never re-derived when an operator authorises additional scope during execute. There is a write path for the realized footprint but none for an authorised amendment to the declaration, so every declared-vs-realized comparison downstream treats sanctioned work as drift.

## Solution

Give the mid-run authorisation path a declaration amendment — either a `manage-references` verb that appends an authorised path to the declared footprint with the decision that admitted it, or a phase-5 step that re-derives the declaration from the outline after an operator-approved deliverable is added. The three-way reconciliation already compares declaration / derivation / realization; it needs the declaration to be amendable for that comparison to mean anything after a widening.

## Impact

Four separate aspects of this retrospective reported the authorised work as divergence: 17 scope-creep files, 28 references-only paths, 79 of 79 touched-but-unassessed, and a `affected_files_exact_match` set mismatch deferred to the manifest aspect. A reader cannot tell the authorised widening from genuine drift without replaying the chat transcript.

- aspect: artifact_consistency — `affected_files_exact_match: warn, references_only[28], outline_only[1]`

- aspect: chat_history_analysis — three operator pivots, all after 3-outline completed

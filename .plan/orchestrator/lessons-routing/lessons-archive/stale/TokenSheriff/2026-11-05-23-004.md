# Required review bot on a one-review-per-hour plan stays stale at every new HEAD; wait out the window before re-triggering

## Problem

With automatic-review and a required review bot (coderabbit) on a plan that gets one review per hour, the bot stays "stale" at every new HEAD: it reviewed an earlier head and, being rate-limited, will not review the new one. In plan-22 the decision log records the state at head 69ac41e7 (21:56:23Z): required bot coderabbit unproven (refused_awaitable quota refusal plus stale inline review, rate-limited); the optional bot sourcery refused for size (150000-character cap, diff of 3915 lines); `review_rate_window_await=false`, so the step did not wait, posted no re-trigger into the quota refusal and was returned to the dispatcher unmarked.

(The remainder is reported by the finalize orchestrator, not visible in the decision log: waiting about 25 minutes before re-triggering worked once.)

## Solution

For an operator running a required bot under a one-review-per-hour quota:

1. Do not re-trigger the bot inside the quota refusal window; the re-trigger is itself refused or wasted.
2. Wait out the rate window (about 25 minutes worked once here) and then re-trigger once.
3. Prefer fewer HEAD advances after the first bot review: batch the remaining documentation fixes into one commit (see the documentation-only fast-path lesson for the finalize pipeline side).
4. For a very large diff, expect the optional size-capped bot to refuse structurally; that is not a failure of the plan.

Tooling follow-up: let `review_rate_window_await` default to waiting when the required bot is the only unproven gate and the window is known.

## Impact

Each stale-at-new-HEAD cycle blocks the automatic-review step and, with it, the merge gate for the remaining time of the rate window.

# re_review_await_timeout_seconds above 600s cannot be honoured by a dispatched leaf

## Context

To run plan-170's finalize unattended, the operator's directive was applied as four plan-local step-param overrides on `plan-marshall:automatic-review`, one of which raised `re_review_await_timeout_seconds` from 600 to 1800 so a slow re-review would be waited out rather than abandoned.

The leaf then awaited **540s**, not 1800s, and the timeout fired (`decision.log` `a1885a`, "no fresh review landed within the 540s await ... configured re_review_await_timeout_seconds=1800"). The configured value was silently unreachable.

## Root cause

`automatic-review` runs inside a dispatched `execution-context` leaf, and two constraints bind there:

- the synchronous Bash ceiling is 600s, and
- a dispatched leaf must not background result-bearing work (`run_in_background` for a result the next step needs loses the result when the harness reaps the wait).

So the only compliant await is a synchronous Bash call under 600s. Honouring 1800s would have required backgrounding, and the harness kill would have destroyed the whole envelope — **including the refusal record**, which is the one artifact the recovery path needs. Ignoring the knob was the correct call; the defect is that the knob accepts a value whose only faithful implementation is worse than ignoring it.

The knob's range and the leaf execution model were designed against different assumptions and nothing reconciles them. A reader of the config has no way to know 1800 means 540.

## Proposed action

- Clamp `re_review_await_timeout_seconds` to the leaf's synchronous ceiling at read time, and **log the clamp** (`configured=1800, effective=540, reason=leaf_bash_ceiling`) so the reduction is visible rather than inferred from a later timeout message.
- Document the ceiling in the step-param table beside the knob, with the reason — not merely a max value, but why exceeding it is unimplementable in this envelope.
- If waits beyond the ceiling are genuinely wanted, they belong to the orchestrator tier via the `await-long-running` seam, not to the leaf. That is a design change, not a config change; record it as such rather than letting the knob imply the capability exists.

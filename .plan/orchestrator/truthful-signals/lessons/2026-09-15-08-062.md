# ci_verify was called three times wrong in three different ways

Source: script-failure cluster, notation plan-marshall:phase-6-finalize:ci_verify
(exit_code=2, failure_kind=argparse_rejection). 3 occurrences, 6-finalize.

- 04:03:47 — missing required flags: ['provider', 'wait-outcome'].
- 04:03:53 — `--wait-outcome` given an invalid choice ('wait_s...'); declared choices are
  {completed, deadline_exceeded}.
- 16:47:20 — the plan id passed as the POSITIONAL command_name: "invalid choice:
  'architecture-store-query-truthfulness' (choose from 'run')".

## Solution

Three different malformations of one call, six required flags deep: --plan-id,
--pr-number, --worktree-path, --provider, --final-status, --wait-outcome. The second
occurrence six seconds after the first shows the flags were added from the usage block
but the VALUE was still invented; the third, twelve hours later in a re-entry, shows the
shape was not retained.

For a verb with six required flags and two constrained enums, composing the call from
memory is not viable. This is the strongest case in the run for a step's workflow doc
carrying the literal invocation rather than describing it.

## Impact

Three rejections on the step that gates the whole CI-verification handshake.

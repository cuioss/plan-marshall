# The plan worktree's executor resolved an older plan-marshall bundle than main's, so documented verbs and flags were missing

## Pattern

A plan worktree gets its own copy of `.plan/execute-script.py`. That copy is fixed to the plan-marshall bundle version that was current when it was generated or copied in. When the bundle on the machine is upgraded later, the copy on main is regenerated and the copy in the worktree is not. Scripts started through the worktree executor then run the older bundle, while the loaded skill documents describe the newer one.

The result looks like caller error, but it is not. Calls copied word for word from the canonical-invocation blocks are rejected by argparse, or a documented notation does not exist at all.

## What the record shows

- The worktree executor resolved bundle 0.1.1890; main's executor resolved 0.1.1905.
- The notation `pre_merge_gate` did not exist in the worktree executor. It had to be run through main's executor.
- Flags documented in the current skills were rejected by the worktree executor: `merge_lock acquire --wait-seconds`, `review_completeness trigger-bot --required-bots`, `github_pr bot_completion --wait-seconds`, and the `manage-findings` verbs `stamp-fix-commit` and `resolve --task-number`.
- Together these made one of the two script-failure clusters of the run.

## How to recognise it next time

- A call that matches the canonical-invocation block exactly fails with `unrecognized arguments`, `invalid choice`, or "notation not found".
- The same call works through main's `.plan/execute-script.py` but not through the worktree's copy.

## Corrective action

- At the start of finalize (and after any bundle upgrade during a plan), compare the bundle version of the worktree executor with main's. If they differ, refresh the worktree copy from main's executor before running more steps.
- When a documented flag or verb is rejected, first check the executor version before treating it as a wrong guess (compare lesson 2026-10-03-06-006, which is the caller-side case).
- For the tool (plan-marshall, for routing by the lessons mode): the worktree executor should resolve the same bundle as main, or warn when it is older.

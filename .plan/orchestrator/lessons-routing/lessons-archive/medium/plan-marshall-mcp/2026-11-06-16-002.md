# Outline Affected files missed a transient cherry-picked file and sibling files carrying the same defect

## What happened

The outline Q-Gate of plan `tool-schemas-single-source` raised two gaps in the deliverables'
`**Affected files:**` lists:

1. **A transient file nobody declared** (finding 26b7b8). Deliverable 1 created
   `doc/plans/tool-schemas-single-source.adoc` by cherry-picking commit dc45d03, and deliverable 4
   deleted it with `git rm`. Neither deliverable listed the file, because the net change of the
   pull request is zero. The phase-4 declared-set closure rejects any task step that targets an
   undeclared path, so the file had to be declared as created in deliverable 1 and as deleted in
   deliverable 4.
2. **Siblings with the same defect** (finding 1a299a). Deliverable 2 removed the scope properties
   `plan_id` and `epic_id` from `pm_skill.json`, because the specification says skill tools take no
   scope. `pm_skills.json` and `pm_skill_file.json` carried the same leftover. They were added to
   the plan only after the plan had already moved to 5-execute, which forced a loop back
   (5-execute -> 3-outline -> 4-plan, with all five tasks removed and recreated).

## Rule

When writing deliverables in phase-3-outline:

- List every path a deliverable touches, including transient files that a cherry-pick, a
  generator or a move creates and a later deliverable deletes. Mark each one as created in one
  deliverable and deleted in the other, and note that the net change is zero. Never leave such a
  file out because the final diff does not show it.
- When a deliverable fixes a defect in one member of a file family (the tool files under
  `pm-mcp-server/src/main/resources/pm-mcp/tools/`, sibling schemas, sibling configs), check
  every member of that family for the same defect before the outline goes to the Q-Gate. Then
  either include the affected siblings or name them explicitly as out of scope. Settle that scope
  question at outline time, not after 4-plan.

## Why

Each of these gaps that the outline misses costs a full outline -> plan loop. In this run the
sibling gap cost one loop after execute had already been entered.

# Phase-4-plan re-dispatch to address a finding must touch ONLY plan artifacts, never source, and the re-dispatch prompt must not conflate scope-expansion with doc-correction

The primary hazard this lesson guarded — a planning-phase re-dispatch
stranding a stray source edit on the MAIN checkout — is now ENFORCED at
the phase boundary (plan `planning-phase-checkout-guard`), so the
"planning phases never mutate source" invariant no longer relies on prose
alone. What remains live is the **re-dispatch prompt-authoring** residue
the guard does not encode.

## Now enforced (was root cause 1)

The no-main-mutation invariant is codified: `planning-outline.md` Step 2c
asserts a clean main checkout after phase-3-outline
(`outline_contract_violation`) and Step 4b asserts it after phase-4-plan
(`plan_contract_violation`), refusing to advance on a dirty main tree; the
plugin-doctor `_analyze_phase2_refine_contract.py` analyzer emits the
`outline-contract-violation` / `plan-contract-violation` static complement.
A stray planning-phase source edit on the MAIN checkout is therefore now
caught loudly at the phase boundary instead of being reverted reactively
before finalize.

## Rule (still live — the guard catches the effect, not a conflated prompt)

- A finding-driven re-dispatch of a planning phase (2-refine / 3-outline /
  4-plan) MUST update ONLY the plan artifacts (`solution_outline`
  deliverables + `TASK-*.json`), never implement source edits. The eventual
  source change is deferred to phase-5-execute against the expanded task.
- The orchestrator's re-dispatch prompt MUST be framed as a plan-artifact
  instruction ("expand deliverable N's scope / task to cover X"), NOT a
  source-correction instruction ("correct `some-doc.md`"). Do not name a
  production doc as an edit target in a planning-phase re-dispatch prompt —
  a conflated prompt now trips the enforced clean-main guard, so the safe
  path is to never author one.

## Impact

Applies to every finding-driven re-dispatch of a planning phase. The
correctness hazard (a stranded MAIN-checkout source edit) is now guarded;
this residue is the prompt-authoring hygiene that keeps a re-dispatch from
tripping that guard in the first place.

## Recurrence — 2026-10-13 (issue-801)

The same root cause hit the finalize pre-push quality gate, in a wider form.

- The whole-tree `test-compile` has no default-scope target in this project. The gate's fallback "widening" drops `-pl/-am` and runs a reactor-wide `test-compile`. That also cannot resolve the `token-sheriff-validation` test-jar, so it fails in modules the change never touched (`benchmark-core`, `token-sheriff-client`).
- According to the orchestrator of the run, the failed `test-compile` run filed 139 build-error findings. All of them had to be resolved as accepted by hand before the merge gate would pass. The second run recorded the arm as un-gated instead (work log 2026-10-13T19:52:02Z, `fc2827`). The test sources were still compiled and run inside the green whole-tree `verify -Ppre-commit` (3035 tests).
- The same gate also logged that the changed Maven module paths resolve to no gate bundle (work log 2026-10-13T19:47:47Z, `b7fd04`), and that no module-tests command resolves in this project (2026-10-13T19:52:03Z, `101633`).

### Broadened scope

The fact is not limited to module-scoped commands. In this repository, **no `test-compile` below `package` works**, whether module-scoped or whole-tree. The only working test-compile check is a `verify` (whole tree: `verify -Ppre-commit`).

Suggested replacement hint text for the owed `tip`, recorded on `default` because it is now project-wide:

"No `test-compile` or `test` run below the `package` phase works in this repository, module-scoped (`-pl <module> -am`) or reactor-wide: the `token-sheriff-validation` generators test-jar does not resolve. Use `verify -pl <module> -am` for one module and `verify -Ppre-commit` for the whole tree. A gate that runs a separate `test-compile` arm here fails in untouched modules and files one build-error finding per error; treat that arm as un-gated and rely on the `verify` run."

### Rule for the next run

When the pre-push quality gate reaches its `test-compile` arm in this repository, do not run the widened reactor-wide `test-compile`. Record the arm as un-gated and point to the green `verify -Ppre-commit` that already compiled the test sources. This avoids filing a batch of findings that must then be closed by hand.

### Follow-up owed outside this project

The plan-marshall side (the gate widening into a reactor-wide `test-compile` that is known to fail here, and Maven module paths resolving to zero gate bundles) is a plan-marshall defect. It is not recorded in this project's lesson store.

### What this adds

- `package -pl <module> -am` works as well as `verify -pl <module> -am` as the module-scoped check, and is faster because it skips the integration and coverage steps. Add it to the owed hint as an accepted alternative.
- The task plan still stamps `test -pl ... -am` for test tasks. Until the owed hint is written, each test task has to find the substitution again.

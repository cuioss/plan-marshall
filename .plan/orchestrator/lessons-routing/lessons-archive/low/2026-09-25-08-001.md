# Campaign carve tasks must declare a per-emission write set, not a whole-tree glob

DEFERRED SCOPE CARRIED FROM PLAN module-budget-campaign-completion (PLAN-182 continuation emission, epic test-quality).

What happened: the operator approved a FULL-CAMPAIGN outline whose carve tasks declared whole-tree survey globs (TASK-005 'Carve slice 070' declared 'test/**/*.py'; TASK-006 'Carve slice 080' declared 'test/marketplace/targets/**' + 'test/pm-plugin-development/**'). Execution re-derivation showed TASK-005's true remaining set was 404 over-budget modules, not a 70-slice. The 'slice' labels did not match their declared write sets. Operator decision: land the verified progress, re-emit the remainder as N=1 successor emissions.

The anti-pattern to avoid: a campaign carve task must declare a PER-EMISSION write set (one ownership source, or one re-derived bounded cluster), never a whole-tree or module-tree glob. A glob that expands to 1000+ files is a campaign, not a task, no matter what the title says. The Q-Gate 'declared_scope_reconciliation' finding class already detects this shape (declared scope wide, write set narrow) -- it must NOT be dispositioned as 'campaign_sweep_residue' when the glob is the effective write set; that disposition was wrong here and execution evidence proved it.

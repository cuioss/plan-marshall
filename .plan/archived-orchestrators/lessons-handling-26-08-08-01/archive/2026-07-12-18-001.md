# New manage-config parsing-boundary read (config knob OR CLI arg) fails to distinguish absent from present-but-invalid/empty — silent fallback or unguarded crash, only the PR bot caught it

When this plan added two new constrained project knobs to `DEFAULT_PROJECT`
(`pr_strategy`, an enum of `compact|distinct`, and `pr_compact_max_changed_files`,
a non-negative int), the reader in `_cmd_system_plan.py` fetched them with the
pervasive `project_config.get(key)` + silent-default-fallback idiom. An invalid
type in `marshal.json` (a typo'd enum value, a string where an int is expected, a
negative count) was silently swallowed and coerced back to the default. All
in-house gates passed clean; only the PR review bot flagged that a constrained
knob must be validated at the parsing boundary and fail loud.

## Defect

The `.get(key)` + fall-back-to-default read is correct for *unconstrained*
optional knobs, but it is wrong for a knob whose domain is constrained (a closed
enum set, or an int with a range invariant). Silent fallback hides operator
misconfiguration: an invalid `pr_strategy: "compat"` (typo) behaves exactly like
the default `compact`, so the operator's intent is silently lost with no signal.

## Corrective rule

When adding a **constrained** config knob (closed enum, or int with a
range/sign invariant), validate its value at the manage-config parsing boundary
and raise a clear, user-facing error on a type/domain mismatch — do NOT silently
fall back to the default on an invalid input. Distinguish absent (→ default is
correct) from present-but-invalid (→ fail loud). For an int knob, reject `bool`
explicitly (`isinstance(x, bool)` is `True` for `int` in Python) and reject
negative values.

```python
strategy = project_config.get('pr_strategy')
if strategy is not None and strategy not in ('compact', 'distinct'):
    raise ValueError(f"Invalid pr_strategy: {strategy!r}")

max_changed = project_config.get('pr_compact_max_changed_files')
if max_changed is not None:
    if isinstance(max_changed, bool) or not isinstance(max_changed, int) or max_changed < 0:
        raise TypeError(f"pr_compact_max_changed_files must be an int >= 0, got {max_changed!r}")
```

## Recurrence shape

This recurs every time a new *constrained* knob is added to `DEFAULT_PROJECT` /
`marshal.json`, because the `.get()` + default-fallback pattern is the path of
least resistance and no in-house gate distinguishes constrained from
unconstrained knobs. Treat "absent → default; present-but-invalid → raise" as
the standing contract for any enum- or range-bounded config knob at the
manage-config read boundary.

## Recurrence — 2026-07-13 (domain-multivalue-detection)

The multi-valued domain-detection plan added a new manage-config verb
(`set-inclusion`) and a new optional CLI arg (`--affected-files`), and BOTH
slipped the same parsing-boundary-validation defect this lesson documents —
caught in-run only by the Gemini PR bot, not by any in-house gate. This is the
third independent occurrence of the pattern, confirming the "Recurrence shape"
prediction above:

1. **Unguarded type read → crash (HIGH).** `set-inclusion` indexed a
   `skill_domains` sibling entry as a dict without an `isinstance(..., dict)`
   guard. `skill_domains` holds heterogeneous siblings — domain entries are
   dicts, but sibling keys such as `active_profiles` are not — so passing a
   non-domain sibling as `--domain` raised `TypeError` instead of a clear
   user-facing rejection. This is the crash-on-invalid variant of the same
   "present-but-invalid not distinguished at the boundary" root cause: the
   original defect silently fell back; this one crashed. Both are the missing
   present-but-invalid branch.

2. **Truthiness conflates present-but-empty with absent (MEDIUM).** The
   `--affected-files` optional arg was tested with `if affected_files:` rather
   than `if affected_files is not None:`, so an explicit empty string (present,
   intentionally empty) was silently treated as absent and fell back to
   narrative extraction. This is the CLI-arg mirror of the config-knob "absent
   vs present" distinction: an empty string is PRESENT, not absent.

## Generalized corrective rule

The contract generalizes beyond constrained *config knobs* to EVERY value read
at a manage-config parsing boundary — config knob or CLI arg alike:

- **Distinguish absent from present.** Use `is not None`, never truthiness, so a
  present-but-empty value (empty string, `0`, empty list) is not silently
  conflated with absent. Truthiness is only correct when empty and absent are
  genuinely equivalent for that field.
- **Type-guard before you index.** A value read from a heterogeneous container
  (e.g. a `skill_domains` sibling that may or may not be a dict) must be
  `isinstance`-guarded before member access, and reject present-but-wrong-type
  with a clear user-facing error rather than crashing or silently defaulting.
- Either failure mode — silent fallback OR unguarded crash — is the same missing
  present-but-invalid branch. No in-house gate catches it, so a newly-authored
  manage-config verb or arg reliably reproduces the defect until the PR bot
  flags it. Grep new manage-config readers for bare `.get()`-plus-default and
  bare truthiness on optional args as the standing self-review target.

## Recurrence — 2026-07-19 (marshalld-registration-scope-population)

The contract generalizes beyond `manage-config`/`marshal.json` to **any config-file
parsing boundary**. This plan's fix lived in `manage-build-server`, reading the
machine-global `registry.json` — a different skill, a different config file, the
identical root cause.

The register/enable path added a helper that seeds each scope field's default
from an existing registry entry: `stored = existing.get(field)` followed by
`list(stored)`. Because `list()` on a `str` splits it into individual characters
(`list("/path") == ['/', 'p', 'a', 't', 'h']`), a hand-edited or corrupted
`registry.json` whose `worktree_containers` / `notation_allowlist` field held a
bare string would be silently coerced into a garbage per-character list rather
than falling back to the intended defaults. In-house gates were clean; only the
Gemini PR bot (PR #941, comment `PRRC_kwDOQ3xasM7XNGkE`) flagged it. Fix:
`isinstance`-guard the value before converting —

```python
if existing:
    stored = existing.get(field)
    if isinstance(stored, list) and stored:
        return list(stored)
# else fall through to the defaults
```

This is the fourth independent occurrence and the first outside `manage-config`,
confirming the generalized rule is boundary-shaped, not skill-shaped: **every
reader of an externally-editable config/registry file must `isinstance`-guard a
value before indexing or type-converting it, and fall back to the default only on
absent-or-wrong-type — never blindly convert.** Add `registry.json` readers (and
any other JSON-config parsing boundary) to the standing self-review grep target
alongside the `manage-config` readers.

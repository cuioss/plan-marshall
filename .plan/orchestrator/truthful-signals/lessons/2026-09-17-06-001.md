# A tolerant read is void when a stricter read of the same artifact runs first on the same path

## What happened

`_read_pre_state` (manage-architecture) deliberately tolerates an unparseable `enriched.json`: it records
the document's bytes so the delta classifier can return `CLASS_UNCLASSIFIED`, letting the selective
`--apply` modes report `undecidable` and write nothing — a documented, deliberately honest outcome.

The regeneration loop then re-reads the SAME file through `load_module_enriched_or_empty`, whose
`_read_json` is a bare `json.load`. It raises before `classify_delta` is ever called. The tolerant
recording is therefore never consumed for a malformed document, the documented `undecidable` outcome is
unreachable, and the classifier's `pre.unreadable_documents` branch is a guard no production input can
enter.

Found by CodeRabbit (`e87384`, Major) on PR #1501 and fixed in-run as TASK-10 — after four in-house
self-review rounds over the same file had not surfaced it.

## The rule

**Two reads of ONE artifact on ONE path: the order decides, and the stricter read is the policy that
actually applies.** A tolerant read placed upstream of a strict one is dead code wearing the appearance of
policy — the recorded bytes, the dedicated class, and the documented verdict all look live, and nothing in
the tolerant read's own vicinity reveals that it is void.

When authoring or reviewing a tolerance (a fallback, a degraded-mode branch, a "we record it and decide
later" path), trace **every** read of that artifact on the path between the tolerance and the consumer that
acts on it. If any of them is strict, the tolerance is unreachable.

## How to check it

- Ask which production input reaches each member of a classification vocabulary. A member no input can
  reach is a defect, not a spare case. (The same file carried a second such member: a module with a
  readable document but no `_project.json.modules` entry also landed in `CLASS_UNCLASSIFIED`, so
  `--apply plan` refused on `undecidable` and the missing entry could never be repaired — finding
  `8afb08`, Major, fixed as TASK-11.)
- A tolerance is only proven by a test whose input is the intolerable artifact, asserting the documented
  degraded verdict — not by the tolerant function's unit test, which never exercises the downstream read.

## Generalizes

Beyond parsing: any guard, default, or degraded-mode branch whose precondition a later step on the same
path re-checks more strictly. The upstream branch reads as the component's policy; the downstream one is
the policy.

# The build daemon's default timeout (1800 s) is shorter than a full Docker integration run in API-Sheriff


Source: observation from the orchestrating session of plan `jwks-unknown-kid-refresh` (PR #430).

The build daemon's default timeout is 1800 s. A full Docker integration run of this repository (`verify -Pintegration-tests`: native image build, then the compose stack and the integration suites) took about 36 to 59 minutes in this plan. Every such run therefore exceeds the default.

## What happened in this run

The first full integration run hit the default timeout. It produced no verdict, neither pass nor fail, and it left the Docker stack running. A later run with `--timeout 4500` completed.

## Candidate lesson

For a full Docker integration run in API-Sheriff, pass `--timeout 4500`. The default cannot finish the run.

Two defects sit behind that workaround:

- The timeout is not derived from the command. A run known to take 36 to 59 minutes is started under a 30-minute limit with no warning.
- A timed-out run does not tear down what it started. The compose stack stays up, and it must be cleaned before the next native run (see the project's `run-integration-tests` skill, cleanup-before-native checklist).

A timed-out run is also "no verdict", not "failed": nothing about the code can be concluded from it.

## Impact

One lost integration run of 30 minutes, a leftover Docker stack, and a run whose outcome could be misread as a test failure.
